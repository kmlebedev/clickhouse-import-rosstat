# Главный редактор публикаций в clickhouse-import-rosstat

**Назначение.** Роль «главный редактор»: собрать числа из витрин через MCP, проверить семантику рядов, пересчитать производные, перепроверить каждое утверждение статьи, собрать или обновить публикацию по шаблону на текущую дату и выдать рекомендации к шаблону. Скил — надстройка над `AGENTS.md` и [KEY_RATE_PUBLICATIONS.md](../../../docs/KEY_RATE_PUBLICATIONS.md), а не их замена.

**Канонические документы.** Шаблон и чек-лист — [KEY_RATE_PUBLICATIONS.md](../../../docs/KEY_RATE_PUBLICATIONS.md) §2/§4/§6/§7/§9/§10; каналы и ряды — [KEY_RATE_CHANNELS.md](../../../docs/KEY_RATE_CHANNELS.md) §3/§8; модель и метрики — [KEY_RATE_MODEL.md](../../../docs/KEY_RATE_MODEL.md) §4/§6; кейс-эталон — [2026-10-18-key-rate.md](../../../docs/publications/2026-10-18-key-rate.md) и [checklist.md](../../../docs/publications/2026-10-18/checklist.md); ресерч роли — [2026-10-21-editor-in-chief-skill.md](../../../docs/research/2026-10-21-editor-in-chief-skill.md).

## 1. Когда применять

- Предзаседание, постзаседание, «после резюме», недельный разбор, опорное заседание.
- Пост-апдейт и сверка факта после решения ЦБ.
- Ревью или факт-чек готовой статьи; жалоба «число не сходится».
- Предложение изменений в `KEY_RATE_PUBLICATIONS.md` (скил даёт рекомендации, правки — отдельный пункт).

**Когда не применять:** прод-код, DDL, витрины, гранты (→ `go-engineer`); ML-эксперимент и бэктест (→ `ml-engineer`); разведка нового источника (→ `research-engineer`); не-ML Python-тулинг (→ `python-engineer`).

## 2. Что прочитать перед стартом

1. [AGENTS.md](../../../AGENTS.md) — правила 1–12, окружение, приёмка.
2. Владеющий роадмап и issue пункта — [ROADMAP_INDEX.md](../../../docs/ROADMAP_INDEX.md); публикации — фаза 4 [ROADMAP_KEY_RATE.md](../../../docs/ROADMAP_KEY_RATE.md).
3. [KEY_RATE_PUBLICATIONS.md](../../../docs/KEY_RATE_PUBLICATIONS.md): §2 (тезисы), §4 (шаблон), §6 (контракт данных), §7 (порядок прогона), §9 (чек-лист), §10 (чего не делаем).
4. [KEY_RATE_CHANNELS.md](../../../docs/KEY_RATE_CHANNELS.md) §3 (11 каналов) и §8 (канал → ряд в БД).
5. Текущая статья, её `checklist.md`, предыдущая публикация и запись журнала.
6. [2026-10-21-editor-in-chief-skill.md](../../../docs/research/2026-10-21-editor-in-chief-skill.md) §2.2 — 12 классов дефектов, которые скил обязан ловить.

## 3. Границы роли

| Делает | Не делает |
|---|---|
| Читает витрины через MCP `mcp__clickhouse__run_query` (`kimi_reader`) | Не пишет в ClickHouse, не делает `CREATE/INSERT/ALTER/GRANT` |
| Пересчитывает производные и строит таблицу «утверждение → SQL → вердикт» | Не пересчитывает ML/LLM-модели и не подставляет их вместо статистики |
| Собирает статью и чек-лист по шаблону | Не публикует пост и не выпускает статью — выпуск за владельцем (шаблон §7 п. 7, §10) |
| Проверяет журнал через `make ml-live-check` | Не пишет в `forecast_log` и не правит журнал вручную |
| Готовит рекомендации к шаблону | Не правит шаблон «попутно» — отдельный пункт роадмапа |

**Жёстко:** каждое число в статье имеет ряд, дату ряда и единицу; «нет обновления» ставится только после повторного запроса `max(date)`; текст и сноски используют один и тот же ряд.

## 4. Рабочий цикл (12 шагов)

**Режим ревью (только чтение):** шаги 2–6 и 8–10; шаг 1 (issue), 11 (сборка текста) и 12 (повторный снимок) не выполняются — статусы не меняются, статья не правится.

1. **Пункт.** Назови `<slug>/<item-id>`, issue, формат публикации, дату заседания; переведи issue в `In Progress`.
2. **Снимок.** Зафиксируй `version()`, `timezone()`, `now()`, пользователя и `data_version` (sha256 снимка, если он собирается). Время — в шапке отчёта.
3. **Инвентарь входов.** Для каждого нужного ряда: `max(date)`, `argMax(value, date)`, свежесть против естественного цикла (недельные — неделя, месячные — месяц). Витрины могут содержать дубли строк: считай по `SELECT DISTINCT series, date, value` или `GROUP BY series`. Собери таблицу «ряд → max(date) → статус».
4. **Семантика.** Для каждого ряда прочитай `v_series_catalog` (`title`, `unit`, `frequency`, `origin`, `description`) и `DESCRIBE` витрины. Не выводи смысл из названия ряда. Проверь привязку даты: у квартальных рядов дата — **1-е число квартала, следующего за отчётным** (2026-04-01 = I кв. 2026, 2026-07-01 = II кв. 2026); у зарплатных и части месячных — сдвиг; у опросов волна ≠ месяц данных. Если `description` пуст или нечитаем — семантика подтверждается `title`/`origin` и перекрёстным рядом, иначе «не проверено».
5. **Производные.** Пересчитай: г/г, реальную ставку, спреды, `P(cut)`, E[step], суммы вероятностей, доли. Формулу покажи рядом с числом. Недельная медиана — `median(value − 100)` по **дедуплицированным** товарным рядам, агрегат «Индекс потребительских цен (недельная оценка)» исключается (иначе 112 рядов вместо 111).
6. **Верификация утверждений.** Построй таблицу «утверждение статьи → SQL → значение в БД → пересчёт → вердикт (✓/×/не проверено)». Пройди текст и каждую сноску; отдельно проверь пары «текст ↔ сноска». Каждый блокер перед публикацией отчёта подтверди вторым запросом: ложный блокер — тоже дефект рецензии.
7. **Три трека.** Статистика, LLM, ML — только из артефактов (`key_rate_model_forecast.json`, `key_rate_llm_forecast.json`, `cpi_*_forecast.json`). Канонический артефакт — тот, у которого `forecast_date` (или дата прогона) совпадает с датой среза публикации; копии в `.worktrees/` с другой датой не брать. Проверь модель, `prompt_version`, `data_version`, суммы, знаки, ожидаемый шаг; отсутствующий артефакт — «не проверено», не выдумывай.
8. **Рыночный контур.** `settle`, `volume`, `openposition`, `expected_change_bp` — **только на `max(date)`**, не на удобную дату; `P(cut 25 б.п.) = (key_rate − settle) / 0,25`; ликвидность — рядом со значением; серия с `volume = 0` — индикатив, не ожидание. То же для ОФЗ и RGBI: последняя дата, а не дата из предыдущей версии текста.
9. **Пороги.** Пересчитай пороги §6 статьи против текущих значений; назови, какие сработали и что это меняет.
10. **Журнал.** `make ml-live-check` (при LLM-треке `ARGS="--require-llm"`). Прямое чтение `forecast_log` закрыто (`ACCESS_DENIED`); читаемый слой — `v_key_rate_dashboard`, контур `forecast` (`as_of`, `model`, `data_version`, `probabilities`). Сравни `as_of` и `data_version` с датой и версией статьи: более новый `as_of` — это новый прогон, а не те же строки; публикуй актуальный и назови расхождение. При невозможности проверить — «не проверено»; публикация без production-строки не выпускается (шаблон §7 п. 5).
11. **Сборка.** Текст по §4 шаблона: заголовок, подзаголовок, 8 разделов, сноски. Разделяй факт / режим / решение. Расхождение треков публикуй, а не усредняй.
12. **Чек-лист и повторный снимок.** Пройди §9 шаблона; за 24 часа до выпуска повтори шаги 2–4 и 6 — всё, что изменилось, обнови в тексте. Итог — `checklist.md` со статусами.

## 5. Матрица проверок

| Класс | Что проверять | Ловушка из кейса #199 |
|---|---|---|
| Свежесть | `max(date)` на дату выпуска, не на дату снимка | USD, золото, RUONIA, KEYRATE, ОФЗ обновились за 3 дня |
| «Нет обновления» | повторить запрос перед выпуском | недельный ИПЦ за 12.10 уже был в БД |
| Существование ряда | `v_series_catalog`, `system.tables`, `DESCRIBE` | «агрегата недельного ИПЦ нет» — ряд есть с 2019; «`v_key_rate_dashboard` не готова» — витрина есть |
| Семантика | `description`: охват, период, группа | `minfin` — федеральный (месяц), `minfin_mesyats` — консолидированный (месяц), а не «кумулятив» |
| Группа ряда | физлица vs ИП vs организации | «депозиты физлиц» 68,14 трлн ≠ «депозиты населения» 70,94 трлн |
| Дата периода vs публикации | волна опроса ≠ месяц данных; квартал = 1-е число следующего квартала | ИБК SA −2,26 — это июль, не август; ВВП «I кв. +0,95 %» — это IV кв. 2025, I кв. 2026 = −0,15 % |
| Текст ↔ сноска | одно число — один ряд | 68,14 в тексте, 70 937 232 в сноске |
| Единицы и знаки | % / п.п. / б.п.; млн / млрд / трлн; знак шага | шаг −5 б.п. = ставка ниже ключевой |
| Дубли строк | `SELECT DISTINCT series, date, value`; медиана — по 111 рядам, агрегат исключён | без дедупликации доля подорожавших 71,6 % вместо 72,1 % |
| Производные | пересчитать формулу | г/г кредита, реальная ставка, `P(cut)` |
| Вероятности | сумма 100 ± 0,1; округление объяснено; E[step] — взвешенное среднее классов | 81,65 / 16,24 / 2,12 |
| Артефакт трека | `forecast_date` = дата среза; копии из `.worktrees/` не брать | прогон 19.10 vs статья 18.10 |
| Журнал | `v_key_rate_dashboard` (`forecast`): `as_of` + `data_version` | 19.10: 10/86/4, 13,975 vs 18.10: 12/83/5, 13,95 |
| Статусы | проверять запросом, а не памятью | витрина, ряд, PR, ingest |
| Ликвидность | `volume`/`openposition` рядом с settle | KKV6: 3/124 → 240/324 меняет силу вывода |

## 6. Редакционные практики

1. **Due accuracy.** Все утверждения опираются на первоисточник и, где возможно, подтверждены вторым рядом или пересчётом ([BBC, §3.2.2](https://www.bbc.co.uk/editorialguidelines/guidelines/accuracy)).
2. **Честно о незнании.** Несопровождённое — атрибутируется или помечается «не проверено»; не выдавай оценку за факт.
3. **Ошибки исправляются быстро, ясно и видимо** (BBC §3.2.4). Правка выпущенного текста — с пометкой «обновлено» и записью в журнал исправлений; никакой тихой замены.
4. **Скептический читатель.** Текст должен выдерживать читателя, который знает, как он собран ([NYT Ethical Journalism, ch. 1](https://www.nytimes.com/editorial-standards/ethical-journalism.html)).
5. **Integrity и независимость.** Не выбирать удобный трек; расхождение статистики, LLM и рынка публикуется ([Reuters Trust Principles](https://www.thomsonreuters.com/en/about-us/trust-principles.html)).
6. **Provenance.** Ряд + дата ряда + единица + дата снимка; «Росстат, 05.10» без ряда — недостаточно.
7. **Show your work.** Каждый тезис воспроизводится SQL; SQL — в отчёте.
8. **Заголовок держится на сильнейшем утверждении**, а не на самом ярком; подзаголовок — распределение и дата среза.

## 7. Формат отчёта рецензии

```markdown
## Рецензия: <файл>, срез <дата/время>, data_version <...>
### Блокеры (публикация не выпускается)
- <утверждение> — <что в БД> — <SQL> — <что меняем>
### Важное
### Мелкое
### Что воспроизвелось
### Рекомендации к шаблону
### Что не проверено
```

Severity: **блокер** — ложное утверждение о данных или публикация по устаревшему входу; **важное** — число изменилось и вывод сдвигается; **мелкое** — округление, стиль, статус.

## 8. Definition of Done

- [ ] Снимок (время, версия, пользователь, `data_version`) и инвентарь входов с `max(date)`.
- [ ] Семантика каждого ряда прочитана из `v_series_catalog`, а не из названия.
- [ ] Таблица «утверждение → SQL → значение → вердикт» покрывает текст и сноски.
- [ ] Производные пересчитаны; вероятности нормированы; ликвидность рядом с рынком.
- [ ] Пороги пересчитаны и названы сработавшие.
- [ ] Журнал проверен через `make ml-live-check` или явно «не проверено».
- [ ] Повторный снимок за 24 ч до выпуска; изменения внесены.
- [ ] Чек-лист §9 шаблона заполнен; «нет обновления» подтверждено запросом.
- [ ] Статья по §4; рекомендации к шаблону — отдельным списком.
- [ ] `make docs-check`; ссылки разрешаются; Go/Python/схема не менялись.

## 9. Частые ошибки

| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| «Нет обновления» по памяти | Ряд обновился — текст врёт | Повторный `max(date)` перед выпуском |
| Семантика из названия ряда | «Кумулятивный» оказывается месячным консолидированным | `description` в `v_series_catalog` |
| Один «факт» из двух рядов | Текст и сноска расходятся | Один ряд на число, проверка пары |
| Взят не тот ряд-близнец | «до востребования» без «Всего:» даёт 4,82 % вместо 17,88 % | Сверь `title`/`origin` с охватом утверждения (`Всего:`, `СМП:`) |
| Квартальная дата прочитана как месяц | «I кв. +0,95 %» — это IV кв. 2025 | Дата — 1-е число следующего квартала |
| Дубли строк витрины | Медиана и доля считаются по 218 строкам вместо 111 | `SELECT DISTINCT series, date, value` |
| Рынок взят на удобную дату | Оговорка о ликвидности устарела | Только `max(date)` |
| Артефакт из чужого worktree | Прогноз не на дату среза | Сверь `forecast_date` |
| Статус витрины/PR по памяти | Ложное «не готово» | `system.tables`, `DESCRIBE`, git |
| `P(cut)` без ликвидности | Неликвидная серия выдана за ожидание | `volume`/`openposition` рядом |
| Усреднение треков | Скрывает расхождение | Публиковать все три и объяснять |
| Правка после выпуска без следа | Нарушает «не переписывать задним числом» | Пометка «обновлено» + журнал исправлений |
| Пересчёт ML/LLM «на глаз» | Другая модель/версия | Только артефакт, иначе «не проверено» |
