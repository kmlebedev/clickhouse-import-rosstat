# Дорожная карта: от конвейера статистики к живой DCF-модели Полюса с NAV-прогнозом

**База:** проект [clickhouse-import-rosstat](https://github.com/kmlebedev/clickhouse-import-rosstat), аналитическая практика — [«Золото Q3-2026: итоги и прогноз Q4-2026»](Золото_Q3-2026_итоги_и_прогноз_Q4-2026.md)
**Дата:** 8 октября 2026 г.
**Сопутствующие документы:** [ARCHITECTURE.md](../ARCHITECTURE.md) (паттерны и схемы БД), [AGENTS.md](../AGENTS.md) (инструкции для AI-ассистентов)

---

## 1. Целевая постановка

Превратить ETL-проект в **аналитический контур замкнутого цикла**:

> Источники → ClickHouse (сырые ряды + витрины) → MCP-доступ для Kimi → регулярный сценарный прогноз золота → DCF → NAV акции PLZL → журналирование прогнозов и проверка точности.

Статья Q3-2026 уже содержит методологическое ядро: сценарную рамку с вероятностями (бычий 25% / базовый 40% / медвежий 35%), календарь триггеров (FOMC 9 декабря, CPI 10 ноября, истечение запрета на экспорт дизеля 1 ноября), дашборд верификации с порогами (crack spread >$50, запасы дистиллятов EIA, шансы FedWatch >80%) и практику проверки прошлых прогнозов. Дорожная карта институционализирует это: каждый индикатор из «дашборда верификации» становится таблицей в БД, каждый триггер — записью в календаре событий, каждый прогноз — версией в журнале.

## 3. Целевая модель данных

Канонические DDL — в [ARCHITECTURE.md](../ARCHITECTURE.md) §6.2 (единый источник истины, здесь не дублируются). Ключевые сущности:

- **Сырые ряды:** `macro_series` (FRED/EIA/WGC/CME), `gold_prices`, `gold_forecasts` (версионированный консенсус + собственные сценарии), `events_calendar` (ядро оркестрации).
- **Модель:** `model_runs` (каждый пересчёт NAV — версия с триггером, сценариями, обоснованием), `forecast_log` (прогноз vs факт — автоматизация рубрики «проверка прошлого прогноза»).
- **Рыночный слой:** `news_events`, `index_weights`, `dividend_events`, `ofz_curve`, `mmf_aum`, `tax_events`.
- **Витрины для агента:** `v_model_inputs` (срез входов DCF одной строкой), `v_gold_dashboard` (дашборд верификации с флагами порогов), `v_forecast_accuracy`.

## 4. Дизайн DCF-модели Полюса

### 4.1 Структура

```
Выручка_t  = Production_t (koz) × GoldPrice_t ($/oz, сценарно) − royalties/прочие вычеты
OPEX_t     = Production_t × TCC_t;  TCC_t = TCC_base × эскалация(ИПЦ РФ, доля RUB-затрат)
EBITDA_t   ≈ Production × (GoldPrice − AISC_t)
НДПИ       = база + 10% × max(GoldPrice − 1900, 0)   ← ценовая надбавка, действует с 2025
FCF_t      = EBITDA_t − налоги (НДПИ/прибыль) − capex_t (sustaining + Сухой Лог) ± ΔWC
EV         = Σ FCF_t / (1+WACC)^t + TV;  Equity = EV − NetDebt;  NAV/акция = Equity / shares
```

### 4.2 Ключевые связи макро → модель

| Макропараметр | Вход в модель | Источник ряда |
|---|---|---|
| Сценарная цена золота (прогноз $4,000–4,600, Q4-2026) | Выручка, основной сценарный рычаг | `gold_forecasts` (own) + `gold_prices` (факт) |
| USD/RUB | Трансляция рублёвых затрат в USD-себестоимость; чувствительность маржи | `cbr_currency_usd` |
| Ключевая ставка ЦБ | RF-компонент WACC (ставка + премии) | `cbr_key_rate` |
| Ставка ФРС / реальные доходности | USD-компонент WACC; драйвер сценарной вероятности золота | `macro_series` (FRED) |
| ИПЦ РФ | Эскалация TCC/AISC (зарплаты, ГСМ, взрывчатка) | `ipc_mes` |
| Дизельный crack (двойная роль!) | 1) индикатор инфляции США → ставка → золото; 2) прямой драйвер рублёвых топливных затрат Полюса | `macro_series` (EIA) |
| Brent | Прокси дизельного канала + бюджетное правило РФ (отсечка $59 → операции ФНБ с золотом) | `stock_prices`/новый ряд |

### 4.3 Выходы

- NAV/акция по трём сценариям + вероятностно-взвешенная;
- **NAV-матрица чувствительности**: золото ($3,750–5,000, шаг $250) × USD/RUB (75–110) × WACC (±200 б.п.) — публикуется как Grafana-таблица;
- upside/downside к рыночной цене PLZL (MOEX ISS);
- журнал `model_runs` — полная история пересмотров с обоснованиями.

## 5. MCP-интеграция с Kimi

### 5.1 Готовый сервер — не писать свой

Официальный [mcp-clickhouse](https://github.com/ClickHouse/mcp-clickhouse) покрывает нужный минимум: `list_databases`, `list_tables`, `run_select_query`. Альтернатива — [Altinity MCP](https://github.com/Altinity/altinity-mcp) (написан на Go; есть JWE-аутентификация и OpenAPI-режим).

### 5.2 Рекомендуемая конфигурация

```bash
# Docker, HTTP-транспорт, токен-авторизация, read-only
docker run -d --name ch-mcp \
  -e CLICKHOUSE_HOST=clickhouse -e CLICKHOUSE_PORT=8123 \
  -e CLICKHOUSE_USER=kimi_reader -e CLICKHOUSE_PASSWORD=*** \
  -e CLICKHOUSE_MCP_SERVER_TRANSPORT=http \
  -e CLICKHOUSE_MCP_AUTH_TOKEN=<uuid> \
  -p 8000:8000 mcp/clickhouse
```

Правила безопасности:

1. Отдельный пользователь `kimi_reader` в ClickHouse: **только SELECT**, только база витрин; сырые таблицы и системные — закрыть.
2. MCP-сервер **строго read-only** — запись прогнозов (`model_runs`, `forecast_log`) делает не агент через MCP, а отдельный ingest-endpoint/скрипт по итогам сессии (контроль качества данных).
3. Токен в env, не в коде.

### 5.3 Чтобы агент понимал данные

- `COMMENT ON TABLE`/`COMMENT ON COLUMN` для каждой витрины — MCP отдаёт комментарии в `list_tables`, это и есть «документация для Kimi»;
- сниппет-шпаргалка (skill/prompt) с описанием модели: где лежат входы DCF, как считается NAV, какие пороги у триггеров, формат записи прогноза;
- представления с человекочитаемыми именами (`v_*`), чтобы агент не строил запросы по сырым таблицам.

## 6. Оркестрация обновлений: календарь + новости

### 6.1 Календарный контур

`events_calendar` наполняется один раз на квартал из известных расписаний (CPI 14 окт, PPI 15 окт, FOMC 28 окт и 9 дек, NFP 6 ноя / 4 дек, EIA — каждая среда, WGC GDT — конец октября, запрет дизеля — 1 ноя, совет директоров ЦБ РФ, отчётности Полюса). Планировщик:

- **ежедневный ETL** (cron → `make run` с фильтром `CLICKHOUSE_IMPORT_STAT` по дневным источникам: золото, DXY, USDRUB, crack, PLZL);
- **еженедельный** (среда, после EIA; пятница — недельный ИПЦ);
- **по событию**: в день `event_date` запускается соответствующий импортёр + сессия Kimi «обнови прогноз»: агент читает свежий релиз через MCP, сверяет с порогами из `events_calendar`, пересчитывает сценарные вероятности → новая запись `model_runs` → обновлённый NAV.

### 6.2 Новостной контур (в моменте)

1. **Простой (стартовый):** ручной триггер — новость в чат («запрет на дизель продлён», «FOMC повысил на 25 б.п.»), агент по MCP подтягивает текущие данные, пересчитывает сценарии и NAV, пишет в `model_runs` с `trigger_type='news'`.
2. **Продвинутый (фаза 5):** импортёр `news_watch` — RSS/парсинг ключевых лент (ЦБ РФ, Минфин, ФРС, WGC, EIA, IR Полюса) в `news_events`; свежие события сами становятся триггерами сессии пересчёта.

### 6.3 Петля обратной связи

После каждой контрольной даты агент сверяет `forecast_log.predicted` с фактом — «проверка прошлого прогноза» становится автоматической метрикой точности, её динамика — отдельной панелью Grafana.

## 9. Риски и допущения

| Риск | Митигация |
|---|---|
| FedWatch/WGC не имеют открытого API (парсинг хрупок) | Старт — ручной ввод через `gold_forecasts`/`macro_series`; автоматизация в фазе 5 с мониторингом сломов |

## 10. Дополнительные каналы давления на цену акции PLZL (рыночный слой поверх NAV)

NAV из DCF — это «справедливая» цена; биржевая цена PLZL формируется ещё и потоками, настроениями и правилами игры на рынке. Ниже — шесть дополнительных каналов давления, все сводятся к измеримым рядам и добавляются в модель как корректирующий слой «рыночный дисконт/премия к NAV».

### 10.1 Каналы, их индикаторы и источники данных

| # | Канал давления | Механика для PLZL | Измеримые индикаторы → таблицы | Источник |
|---|---|---|---|---|
| 1 | **Новостной фон и индекс настроений** | Поток публикаций (СМИ, телеграм, раскрытия) двигает краткосрочный спрос розницы; резкие негативные всплески (дивиденды, налоги, capex Сухого Лога) вызывают гэпы | Таблица `news_events`: дата, источник, заголовок, тональность (−1..1 от LLM), объём публикаций/сутки; скользящий индекс настроений (7д/30д MA) | RSS/парсинг Интерфакс, РБК, Коммерсант, IR Полюса; расчёт тональности — сессией Kimi |
| 2 | **Индексные потоки и ребалансировки** | Вес PLZL в Индексе МосБиржи определяет механический спрос от индексных БПИФ/ПИФов; критерии — free-float ≥10%, коэффициент ликвидности ≥15%; ребалансировки — третья пятница марта, июня, сентября, декабря | Таблица `index_weights`: дата, вес PLZL, Δвеса, оценка пассивного притока/оттока (Δвеса × СЧА индексных фондов); флаги дат в `events_calendar` | MOEX (составы индексов, free-float), InvestFunds (СЧА БПИФ на IMOEX) |
| 3 | **Дивидендный канал и арбитраж против безрисковой ставки** | Дивдоходность Полюса (2,4–3,8% последних выплат) против ключевой ставки 14% и ОФЗ — неконкурентно; 9 июля 2026 СД принял к сведению рекомендацию менеджмента **приостановить дивиденды до 2030 года** (долг, издержки, Сухой Лог) | Таблица `dividend_events`; ряд `ofz_curve` (RGBI, доходности по срокам); метрика `div_yield_spread = дивдоходность − ОФЗ 5y` — при отрицательном спреде дивидендные покупатели уходят | MOEX ISS (ОФЗ, RGBI), раскрытия Полюса, `cbr_key_rate` |

### 10.2 Что меняется в модели и процессе

1. **DCF корректируется фактом приостановки дивидендов до 2030**: дивидендная составляющая обнуляется на горизонте модели, NAV формируется чистым FCF/NAV-мультипликатором, а не DDM; в `model_runs` — поле `dividend_status`.
2. **Налоговая функция становится эндогенной**: НДПИ от сценарной цены золота — при медвежьем $3,750 нагрузка снижается вместе с выручкой, при бычьем $5,000 — растёт.
3. **Новый выход модели — «рыночный мост» NAV → целевая цена**: NAV ± корректировки по каналам (отрицательный дивидендный спред к ОФЗ → дисконт; начало перетока из фондов ликвидности → снятие дисконта; всплеск негативного sentiment → тактический дисконт). Каждая корректировка фиксируется в `model_runs` для верификации.
4. **`events_calendar` дополняется**: заседания ЦБ РФ (23 октября и 18 декабря 2026 — ближайшие), ребалансировки индексов MOEX (третьи пятницы квартала), дедлайны бюджета и налоговых поправок в ГД, даты СД Полюса по дивидендам.
