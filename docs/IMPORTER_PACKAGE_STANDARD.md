# Стандарт пакета импортёров

**Дата:** 14 октября 2026 г.
**Статус:** нормативный документ. Применяется при **создании нового пакета импортёров** и при **рефакторинге существующего**.
**Откуда взят:** обобщение рефакторинга пакета `cbr/` (фаза 3 контура ключевой ставки, [ROADMAP_KEY_RATE.md](ROADMAP_KEY_RATE.md) §6) — единственного пакета репозитория, прошедшего эту работу целиком и принятого живой сверкой данных.
**Сопутствующие документы:** [ARCHITECTURE.md](../ARCHITECTURE.md) (паттерны кода, канонические DDL, схемы БД, расписания), [AGENTS.md](../AGENTS.md) (правила репозитория), [README.md](../README.md) (эксплуатация).

---

## 1. Область и статус

1.1. **ОБЯЗАТЕЛЬНО.** Документ описывает пакет импортёров целиком: состав файлов, транспорт, шаблон импортёра, разбор, имена, регистрацию, тесты, каталог и витрины, точку контроля публикации, расписание, документацию и порядок приёмки. Он не заменяет `ARCHITECTURE.md`: там — справочник по паттернам кода, каноническим DDL и схемам БД, здесь — чек-лист устройства пакета и порядок его приёмки.

1.2. **ОБЯЗАТЕЛЬНО.** Ссылка на разделы этого документа используется вместо пересказа: спека или план работы по импортёрам пишет «стандарт §6.3», а не копирует правило. Пересказ правила в спеке расходится с оригиналом и теряет силу нормы.

1.3. **ОБЯЗАТЕЛЬНО.** Ссылки из входных точек репозитория: `AGENTS.md` — правило 7 и порядок начала сессии; `ARCHITECTURE.md` §3 — шаблоны импортёров; `README.md` — раздел про импортёры и структуру пакетов.

1.4. Правило, помеченное **ОБЯЗАТЕЛЬНО**, проверяется на ревью и, где это возможно, автоматически — тестом пакета (§8.3, §11) или приёмочным чек-листом (§16). Правило, помеченное **РЕКОМЕНДОВАНО**, применяется, если не мешает конкретному источнику; отказ от него называется в спеке пункта с причиной.

1.5. Отступление от ОБЯЗАТЕЛЬНОГО правила допустимо только как явное решение владельца, названное в спеке и в приёмочном блоке роадмапа. Молчаливое отступление — дефект.

## 2. Термины

| Термин | Значение |
|---|---|
| **Пакет импортёров** | Go-пакет верхнего уровня (`cbr/`, `rosstat/`, `wgc/`, …), который регистрирует один или несколько импортёров через `chimport.Stats` |
| **Импортёр** | Значение, реализующее `chimport.ImportStat` (`Name()` + `Import(ctx, conn)`), запускаемое по `CLICKHOUSE_IMPORT_STAT=<Name()>` |
| **Реестр** | Единственный файл пакета (`importers.go`), откуда импортёры попадают в `chimport.Stats` |
| **Производные** | Данные, которые импортёр публикует после точек ряда: описания рядов в `series_catalog` и витрины |
| **Точка контроля публикации** | Объявление «файл источника обновляется реже расписания»: HEAD-отпечаток + строка версии в `source_publications` (§9) |
| **Версия артефакта** | Строка `source_publications`: ключ источника, имя и отпечаток файла, число точек ряда на момент записи |
| **Винтажный архив** | Сохранённые версии файлов источника в объектном хранилище (пакет `archive/`) плюс реестр версий `registry.jsonl`; вход будущего восстановления базы (§9.6) |
| **Фикстура** | Урезанная копия **реального** артефакта источника в `testdata/`, на которой тесты разбирают данные офлайн |

## 3. Состав пакета

3.1. **ОБЯЗАТЕЛЬНО.** Роли файлов:

| Файл | Роль | Пример |
|---|---|---|
| `importers.go` | Реестр: тип записи, список импортёров, единственный `init()` | `cbr/importers.go` |
| `<источник>.go` | Импортёр и его парсер; по файлу на источник | `cbr/credit_m2x.go`, `rosstat/salaries_mes.go` |
| `<источник>_parse.go` | Отдельный файл разбора, если парсер большой (> ~150 строк) или переиспользуется несколькими импортёрами | `cbr/mp_survey_parse.go` |
| `series_meta.go` | Каталог рядов пакета: `var <xxx>SeriesMeta = []util.SeriesMeta{…}` на импортёра | `cbr/series_meta.go`, `rosstat/series_meta.go` |
| `views.go` | Витрины пакета (`util.View`) и общий хелпер `afterXxxMacro(meta)` | `cbr/views.go`, `rosstat/series_meta.go` (до рефакторинга) |
| `links.go` | Хелперы ссылок со страниц — **если пакет старше появления `util.GetPage`/`util.FindLink`**; новые пакеты используют `util` (§4) | `cbr/links.go` (удалён при выносе в `util`) |
| `testdata/` | Фикстуры: XLSX, HTML-страницы, XML-выгрузки источника | `cbr/testdata/` (22 файла), `rosstat/testdata/` |
| `*_test.go` | Тесты: разбор на фикстурах, каталог, реестр | `cbr/*_test.go` (24 файла) |

3.2. **РЕКОМЕНДОВАНО.** Один импортёр — один источник; два импортёра одного пакета, пишущие в одну таблицу под одним `Name()`, — дефект (прецедент: `cbr/avgproc_stav.go` возвращал `Name()` = `cbr_currency_usd` и писал в чужую таблицу, из-за чего `make import` запускал два импортёра; файл удалён в фазе 3).

3.3. **ОБЯЗАТЕЛЬНО.** В пакете нет мёртвого кода: файл, чьё значение никто не регистрирует и не вызывает, удаляется (прецеденты фазы 3: `cbr/queries.go` с мёртвым `DatasetId: 0`, `cbr/purcb.go`, мёртвый скрапер cbr в `financial/` с DDL `cbr_rates`).

## 4. Транспорт

4.1. **ОБЯЗАТЕЛЬНО.** Все сетевые обращения — через хелперы `util`. Прямая работа с `net/http` и `colly` в пакете импортёров запрещена. `util.HttpClient` — единственный клиент: системные CA плюс `CERT_FILES` (национальные сертификаты РФ), cookie-jar для `rosstat.gov.ru`, ротация User-Agent, дедлайны.

| Тип источника | Хелпер | Что делает |
|---|---|---|
| HTML-страница (нужен только href на файл) | `util.GetPage(url)` + `util.FindLink(page, selector)` | скачивает страницу, отдаёт href первой ссылки по CSS-селектору; пустое совпадение — ошибка |
| HTML-страница (нужен разбор содержимого) | `util.GetPage(url)` + `goquery` | как в `cbr/key_rate.go`, либо `BodyFunc` шаблона — когда артефакт должен попасть в винтажный архив (§9.6) |
| XLSX (ссылка стабильная) | `util.GetXlsx(url)` | скачивает и открывает книгу `excelize` |
| XLSX (ссылка вычисляется) | `util.GetPage` + `util.FindLink` → `DataUrl` → шаблон | §5.4 |
| XML-фид | `util.GetXML(url, &out)` / `util.ParseXML(body, &out)` | проверяет HTTP-статус, читает windows-1251, блокирует пустое тело |
| JSON-API | `util.GetJSON(url, &out)` | проверяет HTTP-статус, блокирует пустое тело |
| CSV | `util.GetCSV(url)` | разделитель `;` |

4.2. **ОБЯЗАТЕЛЬНО.** `util.GetFile` (и, значит, `GetXlsx`) **не проверяет HTTP-статус ответа** — в отличие от `GetJSON`/`GetXML`: заглушка WAF приходит с любым кодом (200, 403, 426) и телом HTML, поэтому вызывающий видит только ошибку разбора книги от `excelize`, в которой нет ни кода ответа, ни имени файла. Симптом не называет причину, и разбираться с ней приходится по контексту, поэтому парсер обязан падать быстро и громко на первом же признаке: пустой разбор или отсутствие ожидаемого листа — ошибка с именем таблицы и листа (§6.4), а не «0 строк».

4.3. **ОБЯЗАТЕЛЬНО.** Сетевых вызовов в `init()` нет. Адрес страницы и ссылку на файл импортёр вычисляет внутри `Import()`: регистрация импортёра не должна ходить в сеть.

4.4. **ОБЯЗАТЕЛЬНО.** Ошибка обхода страницы не проглатывается: если ссылка не найдена, `Import()` возвращает ошибку с доменом и ожидаемым именем файла, а не вызывает `GetXlsx("")`.

4.5. **ОБЯЗАТЕЛЬНО.** Селектор ссылки — константа пакета рядом с импортёром, а не литерал в теле функции: тот же селектор использует тест на HTML-фикстуре (§11.4).

## 5. Шаблон импортёра

5.1. **ОБЯЗАТЕЛЬНО.** Импортёр строится на `util.ClickHouseImport`. Поля и их смысл:

| Поле | ОБЯЗАТЕЛЬНО | Назначение |
|---|---|---|
| `TableName` | да | Имя таблицы; оно же `Name()` и `CLICKHOUSE_IMPORT_STAT` (§7) |
| `CreateTable` | да | DDL **в `%s`-форме**: `CREATE TABLE IF NOT EXISTS %s (…)`. Шаблон подставляет имя через `fmt.Sprintf`; литерал без `%s` даёт `%!(EXTRA…)` в имени таблицы |
| `ImportFunc` | для XLSX | `func(*excelize.File, driver.Batch) error` — разбор и запись точек |
| `BodyFunc` | если разбор не книги, а произвольных байтов (HTML) | `func(body []byte, batch driver.Batch) error`; полный цикл тот же, что у `ImportFunc`, включая архив версии |
| `CrawFunc` | для XML/HTML/JSON | `func(url string, conn driver.Conn) (int64, error)` — полный цикл «скачать → разобрать → записать» |
| `DataUrl` | если ссылка стабильна | Статический адрес артефакта |
| `BeforeImport` | если ссылка вычисляется | Вычисляет `DataUrl` в рантайме (законный способ, если импортёр не переопределяет `Import()`) |
| `PublicationCountPoints` | по §9 | SQL числа точек ряда; непустое значение включает точку контроля публикации |
| `PublicationSource` | только если `Name() != TableName` | Ключ версии в `source_publications` |
| `AfterImport` | да | Производные: `series_catalog` + витрина (§10) |

5.2. **ОБЯЗАТЕЛЬНО.** Полный цикл `Import` не переписывается вручную: DDL → `BeforeImport` → префлайт → точки → `AfterImport` → строка версии последней. Порядок «точки → производные → версия» — не косметика: сбой публикации каталога оставляет версию незаписанной, и следующий прогон повторяет полный путь (идемпотентно), а не уходит в no-op с устаревшим каталогом.

5.3. **ОБЯЗАТЕЛЬНО.** Вставка в ClickHouse — один `PrepareBatch` на прогон, `Append` с проверкой ошибки, `Send`. Построчный `conn.Exec` в цикле запрещён (правило 2 AGENTS.md). `conn.Exec` вне цикла допустим только для DDL — и то лишь там, где шаблон не подходит.

5.4. **ОБЯЗАТЕЛЬНО.** Если ссылка на файл вычисляется в рантайме, импортёр переопределяет `Import()`:

```go
func (s *XxxStat) Import(ctx context.Context, conn driver.Conn) (count int64, err error) {
	page, err := util.GetPage(xxxUrl)          // 1. страница
	if err != nil { return count, err }
	href, err := util.FindLink(page, xxxLinkSelector)  // 2. ссылка (ошибка при отсутствии)
	if err != nil { return count, err }
	s.DataUrl = xxxUrlPrefix + href            // 3. префикс домена
	return s.ClickHouseImport.Import(ctx, conn) // 4. полный цикл шаблона
}
```

Внутри `ClickHouseImport` шаблонный `Import` не вызывается напрямую, а импортёр — обёртка со встроенным `ClickHouseImport`; в реестр (§8) попадает обёртка.

5.5. **ОБЯЗАТЕЛЬНО.** Ошибки не проглатываются: каждый `strconv.Parse*`, `batch.Append`, `time.Parse` — с проверкой. Форма `v, _ := strconv.ParseFloat(...)` запрещена (правило 6 AGENTS.md).

5.6. **ОБЯЗАТЕЛЬНО.** Логирование — только logrus (`log.Infof("Imported %d rows of %s", count, s.Name())`). `fmt.Print*` в пакете импортёров запрещён: это не лог, а мусор в потоке, который читает оператор и dagu.

5.7. **ОБЯЗАТЕЛЬНО.** Ошибка `Import()` возвращается вызывающему, а не гасится: `main.go` по ней завершает процесс с ненулевым кодом, а dagu видит упавший шаг.

## 6. Разбор

6.1. **ОБЯЗАТЕЛЬНО.** Парсер отделён от сети: на входе `*excelize.File`, `[]byte` или разобранная структура, внутри — никаких обращений к `util.HttpClient`. Это то, что делает возможными офлайн-тесты на фикстурах (§11).

6.2. **ОБЯЗАТЕЛЬНО.** Значения ячеек читаются в **сыром** виде: `xlsx.GetRows(sheet, excelize.Options{RawCellValue: true})`. Форматированная строка (значение `GetRows` по умолчанию) — не данные, а их представление: формат `#,##0` превращает `1017.35` в `1,017` (потеря копеек, а в локали с запятой-разделителем — и ошибка разбора), формат даты превращает дату в текст. Прецедент правила — `cbr/mp_survey_parse.go`: сырые значения обязательны, «форматированные строки теряют точность… и превращают дату в текст».

6.3. **ОБЯЗАТЕЛЬНО.** Разметка ищется **по признаку**, а не по магическому индексу строки/колонки: по подписи-якорю (`Наименование`, `к концу предыдущего месяца`), по шапке группы, по имени листа. Там, где индекс неизбежен (позиция шапки внутри листа), он выводится из найденного якоря, а не пишется числом. Состояние, размазанное по нескольким колонкам (год в первой колонке квартальной группы, месяц в шапке), переносится вперёд явно — с проверкой, что переносить есть что.

6.4. **ОБЯЗАТЕЛЬНО (fail-fast).** Ошибка, а не «0 строк», в случаях: ссылка на файл не найдена; ожидаемый лист отсутствует; шапка не найдена; значение не число там, где ожидалось число; разбор дал пустой результат. Текст ошибки называет таблицу и конкретную причину («лист 9 не найден», «значение ячейки … не число»).

6.5. **ОБЯЗАТЕЛЬНО.** `panic` в разборе запрещён: `panic("Invalid quarter")` на незнакомой подписи источника роняет весь процесс, тогда как обязан быть `return nil, fmt.Errorf(...)`. Индексация слайсов проверяется (`len(rows) > i`), а не предполагается.

6.6. **РЕКОМЕНДОВАНО.** Незнакомое **ожидаемое** изменение источника (новый товар в недельной выгрузке, добавленный лист) не должно валить прогон молча и не должно валить его громко: правило — «не падать на ожидаемом изменении источника» (§12.3). Решение фиксируется: warn и импорт, либо ошибка — с обоснованием от темпа источника и позиции шага в цепочке расписания.

6.7. **ОБЯЗАТЕЛЬНО.** Пустая ячейка (или литеральный `0`, означающий в источнике «данных не имеется») — не точка ряда. Решение о пропуске фиксируется в `description` ряда, чтобы агент MCP не прочитал пропуск как нулевое значение.

6.8. **ОБЯЗАТЕЛЬНО.** Имя ряда не берётся из заголовка источника, если заголовок может измениться: заголовки содержат годы, сноски и редакции («…в 1991-2026\*)гг.»), и смена заголовка создала бы **новый** ряд, оборвав старый. Имена рядов объявляет код (карта «лист/строка → стабильное имя»), приём — `cbr/Infl_exp.go` (`inflExpSeriesByRowLabel`). Источник при этом не игнорируется: изменение, ломающее поиск якоря, даёт ошибку (§6.4).

## 7. Имена и адресация

7.1. **ОБЯЗАТЕЛЬНО.** `Name()` импортёра и имя его таблицы начинаются с префикса пакета: `cbr_`, `rosstat_`, … Префикс делает `CLICKHOUSE_IMPORT_STAT=<имя>` однозначным в масштабе всего репозитория и не даёт ручному запуску попасть в чужой шаг.

Оговорка к 7.1 — **пакеты-агрегаторы нескольких эмитентов** (`bank/`, `polyus/`, будущий `metals/`): префикс имени здесь — идентификатор эмитента или артефакта из **утверждённого литерального набора** имён пакета, а не имя пакета. У `bank/` владелец утвердил шесть имён таблиц как есть (`domrf_mortgage`, `rus_vtb_group_ifrs`, `sber_finansovie_rezultaty`, `sber_consumper_spending_index`, `sber_izmenenie_trat`, `tbank_group_ifrs`) — отступление О1 [спеки рефакторинга](superpowers/specs/2026-10-16-bank-refactor-design.md): имена уникальны в репозитории и уже несут источник, а конвенция пакета — «компания — значение, а не схема» (персональных витрин `v_<эмитент>_*` не заводим, `ARCHITECTURE.md` §6.3). Цель 7.1 достигается тем же: набор держит тест-энфорсер реестра (§8.3(б)) — литералами, а не ссылками на константы, иначе проверка стала бы тавтологичной; переименование таблиц «ради префикса» — миграция §15.3 без функционального выигрыша.

7.2. **ОБЯЗАТЕЛЬНО.** `Name() == TableName`. Исключение — импортёр, пишущий в общую таблицу нескольких пакетов (`macro_series`): у него `Name()` — имя импортёра, `TableName` — общая таблица, и он перечислен в allowlist реестра (§8.2). Для такого импортёра дополнительно обязателен `PublicationSource`, если объявлена точка контроля публикации (§9.4).

7.3. **ОБЯЗАТЕЛЬНО.** Имя ряда (`Series`) в каталоге — стабильный идентификатор. Имя таблицы и имя ряда не зависят от даты, года и редакции файла.

7.4. **ОБЯЗАТЕЛЬНО.** Префикс пакета не переименовывается молча. Переименование таблицы — миграция данных: новые имена наполняются рядом со старыми, витрины переключаются после сверки, старые имена удаляются последними (§15.3).

## 8. Реестр и тест-энфорсер

8.1. **ОБЯЗАТЕЛЬНО.** Регистрация импортёров пакета — в одном файле `importers.go`, один `init()`, один цикл `append` в `chimport.Stats`. Персональных `init()` в файлах импортёров нет — это единственная точка, которую видит оператор, и она должна читаться целиком.

```go
type xxxImporter struct {
	chimport.ImportStat
	table       string // литерал таблицы
	countPoints string // литерал PublicationCountPoints ("" — точки нет)
}
var xxxImporters = []xxxImporter{ /* … */ }
func init() { for _, imp := range xxxImporters { chimport.Stats = append(chimport.Stats, imp) } }
```

8.2. **ОБЯЗАТЕЛЬНО.** В записи реестра таблица и запрос чека — **литералы**, а не ссылки на константы пакета. Ссылка сделала бы проверку префикса тавтологичной: тест сравнивал бы константу с самой собой и прошёл бы ровно на том переименовании, от которого обязан падать. Allowlist таблиц вне пространства имён пакета (например `macro_series`) — тоже литеральный набор имён владельцев.

8.3. **ОБЯЗАТЕЛЬНО.** Тест-энфорсер `Test<Пакет>ImportersPrefixedAndRegistered` в `importers_test.go` проверяет:

| | Проверка | Что ловит |
|---|---|---|
| (а) | `Name()` начинается с префикса пакета | ручной запуск в чужом пространстве имён |
| (б) | таблица — с префиксом, либо общая таблица только для известных владельцев; при `Name() != shared` — ещё и `Name() == table` | увод витрины пакета к чужим данным |
| (в) | имена уникальны и все зарегистрированы в `chimport.Stats` | дубль имени (фильтр выбрал бы произвольный) и забытая регистрация |
| (г) | каждая строка `CLICKHOUSE_IMPORT_STAT=` из `dagu/<пакет>.yaml` есть в реестре, **и обратно** — ключевые шаги есть в расписании | опечатка в расписании; пропавший шаг при зелёных тестах |
| (д) | набор импортёров с точкой контроля публикации равен ожидаемому литеральному набору, запросы совпадают с `Publication().CountPoints`, `Publication().Source == Name()`, у остальных объявления нет вовсе | расхождение реестра и объявления; «на всякий случай» объявленный префлайт |

8.5. **ОБЯЗАТЕЛЬНО.** В тесте нет ссылок на константы импортёра: ожидаемые имена, таблицы и запросы — литералами. Комментарий теста объясняет, от какой правки каждая проверка защищает.

## 9. Точка контроля публикации

9.1. **ОБЯЗАТЕЛЬНО.** Точка контроля публикации **объявляется**, если артефакт источника обновляется реже расписания шага: `PublicationCountPoints` (SQL числа точек) плюс, где нужно, `PublicationSource`. Импортёр при этом перестаёт скачивать файл на каждом прогоне: HEAD-отпечаток совпал и число точек сошлось → no-op. Отпечаток версии — md5 от `<url>|<имя>|<ETag>|<Last-Modified>|<Content-Length>` (отсутствующий заголовок — пустой компонент). URL в композите обязателен: два разных документа на разных URL с одним basename и без версионных заголовков иначе дали бы один отпечаток. Прецедент — `rosstat_ipc_weeks_bulletins`: живые `87.htm`/`130.htm` и Wayback-однофамильцы склеились в одну версию, и архивообъект живого документа был перезаписан.

9.2. **ОБЯЗАТЕЛЬНО.** Запрос чека заканчивается `FINAL`; у владельцев общей таблицы — ещё и `WHERE source = '<…>'`. Иначе чек считал бы несмёрженные части или чужие ряды.

9.3. **ОБЯЗАТЕЛЬНО.** Объявления **нет** у импортёра, для которого no-op недостижим или вреден:

| Случай | Пример |
|---|---|
| URL содержит сегодняшнюю дату — версия меняется каждый прогон | `cbr_key_rate`, `cbr_ruania`, `cbr_currency_usd`, `cbr_gold` |
| Темп файла равен темпу шага | `rosstat_ipc_weeks` (недельная выгрузка, недельный шаг) |
| Артефактов несколько (индекс + набор документов), отпечаток одного не отвечает на вопрос «что уже разобрано» | `cbr_mp_summary` |
| Ссылка ведёт не на разбираемый файл | `tbank_group_ifrs` (PDF; таблица заведена, пуста и вне расписания — О2 рефакторинга `bank/`) |

9.4. **ОБЯЗАТЕЛЬНО.** `PublicationSource` объявляется, если `Name() != TableName`: иначе версии двух импортёров одной общей таблицы слились бы в одну строку `source_publications`.

9.5. **ОБЯЗАТЕЛЬНО.** Строка версии пишется **последней** — после точек и производных; пер-источниковых таблиц версий не заводится, все версии лежат в общей `source_publications`. Механизм не защита от подмены, а ответ на вопрос «это тот же файл, что импортировали?».

9.6. **ОБЯЗАТЕЛЬНО.** Винтажная база: версия каждого скачанного файла сохраняется в **винтажном архиве** (термин §2) общим механизмом шаблона — парой «хранилище настроено (`ARCHIVE_BACKEND`) + объявлена точка контроля» (п. 9.1); собственного кода импортёра архивация не требует. Обязанность импортёра — качать артефакт **шаблонным** путём (`DataUrl`/`BeforeImport` + `ImportFunc`): тогда шаблон видит те же байты, что разбирает, и сохраняет ровно ту версию, по которой префлайт принимает решения. `BodyFunc`-импортёр ходит тем же шаблонным путём: шаблон видит его байты и сохраняет их в архив версии. `CrawFunc`, качающий файл внутри себя (пример — `customs/vneshn_torg_countries.go`), в архив не попадает: шаблон его байтов не видит, и на no-op-пути такая версия в архиве не спрашивается. Импортёра с точкой контроля и таким транспортом в репозитории больше нет: `bank/sber_fin_rez.go` (импортёр `sber_finansovie_rezultaty`) переведён рефакторингом пакета `bank/` на `DataUrl` + `ImportFunc`, и версия его файла архивируется. Новый источник с файлом на краулерном транспорте обязан назвать это отступление в спеке (п. 1.5). Детали механики, состав покрытия и семантика «версия известна ⇒ версия в архиве» — `ARCHITECTURE.md` §8 п. 13.

## 10. Каталог рядов и витрины

10.1. **ОБЯЗАТЕЛЬНО.** Каждый ряд каждого импортёра описан в `series_catalog` через `util.SeriesMeta` (правило 11 AGENTS.md): `title`, `unit`, `frequency`, `origin` (таблица/серия/строка API), `description` — что измеряет, как читать значение и считать темпы, как привязана дата.

10.2. **ОБЯЗАТЕЛЬНО.** Производные публикует `AfterImport: afterXxxMacro(<meta>)` — общий хелпер пакета: `util.UpsertSeriesCatalog(ctx, conn, meta)`, затем `util.CreateView(ctx, conn, <витрина>)`. Импортёр не занимается публикацией вручную.

10.3. **ОБЯЗАТЕЛЬНО.** Витрина пакета — long-форма (`source, series, date, value`) с комментарием таблицы и комментарием каждой колонки (`util.View.Comment` и `Columns`); `util.CreateView` создаёт `CREATE OR REPLACE VIEW … SQL SECURITY DEFINER` и пропускает витрину, пока не существуют все её исходные таблицы.

10.4. **ОБЯЗАТЕЛЬНО.** Витрина выдаётся `kimi_reader` грантом в `sql/mcp_kimi_reader.sql`; сырые таблицы пакета агенту **не** выдаются (ни таблицы, ни служебная `source_publications`).

10.5. **ОБЯЗАТЕЛЬНО.** `scripts/mcp_check.py` получает проверки пакета: витрина видна агенту и **непуста** (`count() > 0`), каталог содержит ожидаемое число рядов источника, сырые таблицы закрыты (отказ ClickHouse `497`). Проверка «витрина видна» без проверки непустоты проходит и на неотработавшем импортёре — то есть не проверяет ничего.

10.6. **ОБЯЗАТЕЛЬНО.** Ряд, которого нет в источнике, не остаётся в каталоге, и ряд, появившийся в источнике, не попадает в витрину без описания (правило 11: агент обязан понимать каждый ряд).

## 11. Тесты и фикстуры

11.1. **ОБЯЗАТЕЛЬНО.** Фикстуры — **реальные урезанные артефакты источника** в `testdata/` (XLSX, HTML-страницы, XML-выгрузки), а не синтетические книги, повторяющие допущения парсера. Синтетика кодирует предположения автора и остаётся зелёной ровно тогда, когда парсер разошёлся с источником (прецедент: `rosstat/series_meta_test.go` строил книги с заголовком в колонке B — и не заметил, что в реальном файле он в колонке A, а импортёр падал с `panic`).

11.2. **ОБЯЗАТЕЛЬНО.** Урезание фикстуры не меняет разметку: те же листы, шапки, якоря, форматы ячеек. XLSX урезается «хирургией» zip (удаление ненужных листов из архива), если книга велика; книги в десятки килобайт коммитятся как есть.

11.3. **ОБЯЗАТЕЛЬНО.** Тесты офлайн: ни один тест пакета не ходит в сеть. Ссылка на страницу проверяется на HTML-фикстуре (`util.FindLink` по тому же селектору, что и в коде).

11.4. **ОБЯЗАТЕЛЬНО.** Каталог проверяется **против разбора**, а не против самого себя:

| Контракт | Когда применяется | Что проверяет |
|---|---|---|
| Двусторонний | имена рядов объявлены кодом (§6.8) | разобрано ⊆ описано **и** описано ⊆ разобрано: забытое имя ряда в каталоге и забытый ряд в разборе |
| Односторонний | имена даёт источник | разобрано ⊆ описано: каждый разобранный ряд имеет описание; обратное направление недостижимо на урезанной фикстуре и потому не заявляется |

11.5. **ОБЯЗАТЕЛЬНО.** Кроме контракта каталога тесты проверяют: число разобранных точек, два-три **spot-значения** (значение из известной ячейки и его дата), и ветки fail-fast (отсутствующий лист, отсутствующая шапка, пустая книга — ошибка, а не пустой результат).

11.6. **ОБЯЗАТЕЛЬНО.** Харнесс записи (`appendRecorder`) подменяет `driver.Batch` и собирает `Append`-вызовы; тест разбора не требует базы и не пишет в неё.

## 12. Расписание

12.1. **ОБЯЗАТЕЛЬНО.** Расписание пакета — `dagu/<пакет>.yaml`: `id` шага равен `Name()` импортёра, `env: CLICKHOUSE_IMPORT_STAT=<Name()>`, `retry_policy` задан. `type: chain` означает, что падение шага останавливает последующие; добавление шага в середину цепочки меняет поведение соседей.

12.2. **ОБЯЗАТЕЛЬНО.** Покрытие расписания проверяется тестом-энфорсером (§8.3(г)) в обе стороны. Отдельного валидатора `dagu`-файлов в `make all` нет; `dagu validate dagu/<пакет>.yaml` запускается руками в приёмке.

12.3. **ОБЯЗАТЕЛЬНО.** Отсюда правило «не падать на ожидаемом изменении источника» (§6.6): в цепочке падение одного шага лишает данных все последующие. Ожидаемое изменение источника (новый товар, новый лист) обрабатывается warn-ом и импортом; ошибкой становится только то, что означает «источник сломан или подменён».
