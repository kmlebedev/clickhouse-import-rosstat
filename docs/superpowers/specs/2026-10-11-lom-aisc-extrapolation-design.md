## 1. Задача и контракт

Сегодня поактивный AISC выводится единым клином `TCC + 698 USD/oz` (`dcf/mine_plans_seed.go`), одинаковым для всех рудников и плоским на весь LOM. Задача — заменить его на структуру, откалиброванную по фактически опубликованным поактивным данным.

**Контракт:**

| | |
|---|---|
| **Вход** | PDF-фикстуры пресс-релизов 4Q/FY 2018–2021 (`scripts/testdata/`); `databook_polyus` через ClickHouse (факт добычи 2021–2025); константы политики TCC |
| **Выход** | `sql/dcf_mine_plans_seed.sql`; `polyus_lom_reconciled_long.csv` |
| **Побочные эффекты** | Нет. Скрипт **не пишет в ClickHouse** — только читает |
| **Запуск** | Только через `make` (env из `~/.config/rosstat/env`, `-include` в Makefile) |

**Почему не пишет в БД:** контур `kimi_reader` read-only (AGENTS.md, правило 11в), а ingest-endpoint принимает только тело прогона `model_runs`, не произвольный DML. Разделение «расчёт (Python, offline, тестируем) → вставка (SQL + `make ch-sql`)» даёт воспроизводимость и убирает пароли из скрипта.

**Границы объёма:** 5 действующих рудников — `OLIMPIADA`, `BLAGODATNOYE`, `NATALKA`, `VERNINSKOYE2`, `KURANAKH`. Вне объёма: `ALLUVIALS` (пробел №8), `Sukhoi Log` (проект развития), `TITIMUKHTA`/`ZAPADNOYE` (их добыча в датапаке нулевая).

## 2. Что установлено разведкой (вход в дизайн)

### 2.1 Режим раскрытия изменился после 2021

Проверено на фактических PDF за 2017–2025:

| Год отчёта | per-asset TCC | per-asset AISC |
|---|---|---|
| FY2018 | ✅ таблица + проза | ✅ таблица + проза |
| FY2019 | ✅ таблица + проза | ✅ таблица + проза |
| FY2020 | ✅ таблица + проза | ✅ таблица + проза |
| FY2021 | ✅ таблица + проза | ✅ таблица + проза |
| FY2024 | ✅ таблица + проза | ❌ только групповой ($767) |
| FY2025 | ✅ таблица-график | ❌ нет |

**Следствие:** клин `AISC − TCC` наблюдаем только за **2018–2021**. Поздние годы дают половину входа (TCC без AISC).

### 2.2 Формулировки прозы неоднородны и текст нужно нормализовать

Доказано на реальных файлах:

- предложения **рвутся переносом строки**: `AISC at Natalka increased\n to $626 per ounce`;
- **номер страницы вклинивается** внутрь предложения: `AISC at \n 6 \n Blagodatnoye increased to $658`;
- имя актива бывает вынесено вперёд: `At Kuranakh, AISC increased to $865`;
- россыпь — единственное число: `AISC at Alluvial increased to $1,277`;
- глаголы разные: `increased to`, `amounted to`, `were`, `remained almost flat at`;
- разделитель тысяч — запятая (`$1,277`) либо пробел (`$1 277`).

### 2.3 Перекрёстная сверка работает

Год присутствует в двух релизах — как отчётный и как сравнительный. Сверено вручную на 2019 (FY2019 против колонки 2019 в FY2020): Olimpiada 455, Blagodatnoye 566, Natalka 605, Verninskoye 636, Kuranakh 777 — совпадение до доллара.

### 2.4 Доли клина различимы по активам

Из FY2021: `r = (AISC−TCC)/TCC` — Olimpiada 0.675, Blagodatnoye 0.793, Natalka 0.701, Verninskoye 0.799, Kuranakh 0.520. Диапазон 0.52–0.80. Единый клин $698 даёт для Олимпиады отношение 1.81, для Куранаха 1.23 — то есть текущий сид **систематически искажает структуру**, а не просто «неточно оценивает».

## 3. Модель

### 3.1 Клин как доля от TCC

```
r_i,t = (AISC_i,t − TCC_i,t) / TCC_i,t        # наблюдение, t ∈ 2018..2021
r̄_i  = mean_t r_i,t                          # калиброванный вес актива
```

Экстраполяция на 2025–LOM:

```
AISC_i,t = TCC_i,t × (1 + r̄_i)               # до увязки
```

**Почему доля, а не доллары.** Фиксированный клин размывается относительно растущих затрат; доля сохраняет структуру. Это соответствует наблюдаемому поведению и делает `capex_sustaining` пропорциональным TCC.

### 3.2 Увязка (замкнутая форма)

Цель: взвешенный по добыче AISC = групповой AISC.

```
w_i = production_i / Σ_j production_j
m   = 1 + (AISC_group − Σ_j TCC_j·(1+r̄_j)·w_j) / (Σ_j TCC_j·r̄_j·w_j)
AISC_i = TCC_i × (1 + r̄_i · m)
```

**Поправка `m` применяется к клину, а не к AISC целиком.** TCC — наблюдённая величина, её не трогаем; `r̄` — оценка, её и корректируем. Смысл: увязка сдвигает то, что мы оцениваем, а не то, что измерили.

**Вырожденный случай:** `Σ_j TCC_j·r̄_j·w_j → 0` → `m = 1` + предупреждение (не делить на ноль).

**Свойства:** детерминировано (нет `x0`, нет сходимости); увязывает группу точно по построению; не перекладывает затраты между активами (общая скалярная поправка сохраняет откалиброванные веса). `scipy` не нужен.

**Оговорка о честности.** «Точно увязано» = точно на **групповом** уровне по построению, независимо от качества входов. Это не «per-asset AISC верен»: измерение есть только за 2018–2021, поздние годы — экстраполяция.

### 3.3 Аллокация capex

```
capex_sustaining_mn_usd = (AISC_i,t − TCC_i,t) × production_koz / 1000
```

Единицы: `koz × USD/oz / 1000 = USD млн`. Всё поддержание идёт в `capex_sustaining`; `capex_project = 0` у пяти рудников.

### 3.4 Эскалация

TCC эскалируется на 2025+ по ИПЦ (константы года). Движок эскалирует AISC только при непустом `Params.Ipc`, а он пуст (`dcf/params.go`) — ИПЦ в модель не входит. Скрипт считает эскалацию сам; при подключении `ipc_mes` источник констант заменяется чтением из БД, формула остаётся.

### 3.5 Годы

| Период | Роль |
|---|---|
| 2018–2021 | Калибровка: `r̄_i` по наблюдаемому клину |
| 2022–2024 | Валидация: увязка против группового AISC МСФО (там, где есть per-asset TCC) |
| 2025–LOM | План: 5 активов × 10/13/24/15/15 = 77 строк |

**Валидация ограничена.** FY2024 даёт per-asset TCC прозой (Olimpiada 303, Blagodatnoye 398, Natalka 475, Irkutsk BU 555, Kuranakh 567), но AISC — только групповой. Для 2025 TCC есть лишь графиком — разбор ненадёжен, год помечается «не проверено».

## 4. Парсинг PDF

### 4.1 Пайплайн

1. **Извлечение** — `pdftotext -layout` (уже используется в `polyus/`).
2. **Нормализация** (обязательна, доказана в §2.2):
   - склейка строк, устранение двойных пробелов;
   - удаление колонтитулов и одиночных номеров страниц, вклинившихся в предложение;
   - унификация `$1,277` / `$1 277` → одно число.
3. **Извлечение фактов** — по «годам-абзацам»: предложение `In <год>, AISC at …` задаёт год для своего абзаца; последующие предложения без явного года наследуют его. Покрывает `At Kuranakh, AISC increased to $865` и `AISC at Alluvial increased to $1,277`.
4. **Нормализация имён** — `Alluvial` → сегмент россыпи (отбрасывается с записью в отчёт); `Irkutsk business unit` → не рудник.
5. **Guard полноты** — для каждого года 2018–2021 обязаны найтись 5 активов × 2 метрики (AISC, TCC). Ненайденное — **ошибка с годом и именем**.

### 4.2 Перекрёстная сверка (главный guard)

Год сверяется между двумя релизами. Расхождение — **ошибка, не предупреждение**. Это единственный автоматический ловец опечатки при переносе чисел; без него калибровка держится на доверии к ручному вводу.

## 5. Структура кода

Файл: `scripts/extrapolation_aisc.py`. Стиль — как `scripts/mcp_setup_user.py`: `ROOT = Path(__file__).resolve().parent.parent`, module-level константы, `def main() -> int`, `if __name__ == "__main__": sys.exit(main())`, без `argparse`, без `logging`, русская проза, пароль не печатать, конфигурация только из env.

| Модуль | Ответственность |
|---|---|
| `config` | env (`CLICKHOUSE_*`, `CH_HTTP_PORT`); константы: `ASSETS`, `CALIBRATION_YEARS`, `VALIDATION_YEARS`, `PLAN_BASE_YEAR = 2025`, `MINE_LIFE_YEARS` (те же, что в `dcf/mine_plans_seed.go`), `ESCALATION` |
| `read_aisc_series` | Разбор PDF 2018–2021 (§4), перекрёстная сверка |
| `read_actuals` | Добыча из `databook_polyus` — предикат как в `dcf/mine_plans_import.go`: `table = :asset AND name = 'Total Dore gold output' AND data = 'ANNUAL' AND toYear(date) = :year`; ноль/отсутствие — норма, не ошибка |
| `calibrate` | `r_i,t`, `r̄_i`, разброс по годам |
| `extrapolate` | `TCC_i,t` и `AISC_i,t = TCC_i,t·(1+r̄_i)` на 2025–LOM |
| `reconcile` | Замкнутая форма (§3.2), невязка, `m` |
| `allocate_capex` | `capex_sustaining` в млн USD (§3.3) |
| `emit_sql` | `INSERT INTO mine_plans` — 10 колонок, `grade_gpt = NULL`, батчи по 500 |
| `emit_csv` | `polyus_lom_reconciled_long.csv` |
| `validate` | Guard'ы: невязка < 1 %; `aisc ≥ tcc`; `r̄_i > 0`; добыча ≥ 0; годы ⊆ `[2000, 2100)`; 5 активов; диапазоны `r̄` и AISC |

**Сопоставление имён.** `ASSETS` обязаны совпадать с `databook_polyus.table` и `dcf/mine_plans_seed.go` дословно (`VERNINSKOYE2` с двойкой). Расхождение — молча пропущенный актив, поэтому проверяется тестом.

## 6. Артефакты

**`sql/dcf_mine_plans_seed.sql`** — генерируется скриптом, коммитится как артефакт. Шапка: команда генерации, дата, контрольная невязка. Тело: `INSERT INTO mine_plans (...) VALUES ...` батчами.

**`polyus_lom_reconciled_long.csv`** — long-формат для ручного контроля.

**77 строк** = 5 активов × (10+13+24+15+15) лет.

**Порядок применения:**
```
databook_polyus → dcf_mine_plans (Go-сид) → dcf_mine_plans_seed (SQL поверх) → dcf_engine
```
Ключ `(company, asset, year)` в `ReplacingMergeTree`: SQL-сид перезаписывает строки Go-сида тем же ключом — это намеренно (уточнение поверх плато). Порядок фиксируется цепочкой в `dagu/dcf.yaml`.

## 7. Тестирование

`scripts/extrapolation_aisc_test.py`, stdlib `unittest`, как `scripts/mcp_setup_user_test.py`. Offline, без сети и БД.

1. Разбор каждого из 4 PDF → ожидаемые числа 2018–2021.
2. **Перекрёстная сверка** перекрывающихся годов (2018, 2019, 2020) — совпадение.
3. **Испорченная фикстура** (подменённое число) → сверка краснеет.
4. Вырожденный случай `Σ TCC·r̄·w = 0` → `m = 1`, предупреждение.
5. Отсутствующий актив в годе → ошибка с именем и годом.
6. Несовпадение имён активов с эталоном → ошибка.
7. Единицы capex: `koz × USD/oz / 1000` даёт млн USD на контрольном числе.
8. Увязка: невязка ≈ 0 на синтетическом входе.

**Фикстуры:** 4 PDF (~2.7 МБ) коммитятся в `scripts/testdata/`. Обоснование: без них перекрёстная сверка — главный guard калибровки — не автоматизируется, а калибровка держится на ручном вводе.

## 9. Решения и их обоснование

| Решение | Альтернатива | Почему так |
|---|---|---|
| Клин как доля от TCC | клин в USD/oz | поддержание растёт вместе с затратами; не размывается |
| `m` к клину | `m` ко всему AISC | TCC наблюдён, правим только оценку |
| Замкнутая форма | SLSQP | детерминизм, нет `x0`, точная увязка |
| PDF-фикстуры в git | текст или URL | проверяется сам парсер; тест offline |
| 5 активов | 8 + ALLUVIALS | ALLUVIALS — пробел №8, отдельный пункт |
| `SUSTAINING_SHARE` убран | доля SG&A из плана rev.3 | разбиение capex/SG&A непублично; допущение поверх допущения не нужно |
| Валидация 2022–2024 частичная | полная | AISC по активам после 2021 не публикуется |

## 10. Риски

| Риск | Митигация |
|---|---|
| Проза PDF хрупка, формулировки меняются | Нормализация + перекрёстная сверка; нераспознанный актив — ошибка, не молчание; фикстуры проверяют парсер |
| Измерение есть только за 4 года, дальше экстраполяция | Разброс `r̄` по годам печатается; валидация на групповом AISC 2022–2024 |
| Опечатка при ручном вводе | Перекрёстная сверка — обязательный guard (расхождение = ошибка) |
| Эскалация константами, не `ipc_mes` | Одна константа, замена в одном месте при подключении `ipc_mes` |
| SQL-сид перезапишет Go-сид | Намеренно; порядок цепочкой в `dagu/dcf.yaml` |
| Годы LOM разъедутся с Go-сидом | Те же константы + тест на таблицу годов |
| Ложное чувство точности | `aisc` остаётся `derived` в `DCF_DATA_COVERAGE.md`; в описаниях не называть «измеренным» |
