# cbr_mp_summary — резюме обсуждения ключевой ставки ЦБ (дизайн)

> Спека пункта **1.2** роадмапа [ROADMAP_KEY_RATE.md](../../ROADMAP_KEY_RATE.md) §6. План реализации — отдельным документом (`docs/superpowers/plans/2026-10-14-cbr-mp-summary.md`). На момент написания файл не закоммичен: по указанию владельца первые коммиты ветки — спека и план, после подтверждения плана.

## 1. Цель

Дать агенту (MCP) в ClickHouse всё содержимое «Резюме обсуждения ключевой ставки» ЦБ: по каждому документу с февраля 2024 — дата заседания, дата публикации, решение (действие и уровень ставки), дата вступления, дословный сигнал, полный текст пяти блоков и разметку по **11 каналам ЦБ** двумя слоями (детерминированные регексы + LLM-разметка с указанием модели). Это вход публикации «После резюме» (каденция в [KEY_RATE_PUBLICATIONS.md](../../KEY_RATE_PUBLICATIONS.md) §3: «какие каналы ЦБ считал главными (по резюме), где наши веса разошлись с его»). В тот же пункт входит автоматизация календаря заседаний: `events_calendar` обновляется из `cbr.ru/dkp/cal_mp/`, а не руками (критерий приёмки роадмапа).

## 3. Решения

### 3.1 Транспорт и дельта-прогон

1. Каждый прогон: `getPage(индекс)` → goquery-разбор карточек «Резюме обсуждения ключевой ставки» → список `(published, url)`. Известность документа — `url` в шапке **и** хотя бы одна строка блоков по его `meeting_date` (`cbr_mp_summary_block FINAL`), **и** хотя бы одна regex-строка каналов по `meeting_date` (`cbr_mp_summary_channel FINAL`, `method='regex'`; именно `regex` — иначе строки LLM-разметки замаскировали бы отсутствие слоя 1): частично записанный документ (сбой любого из трёх батчей слоя 1) перекачивается и дописывается идемпотентно.
2. Для отсутствующих — `getPage(url)` + разбор; строки раскладываются по батчам **по таблицам** (шапка, блоки, regex-каналы — три `PrepareBatch → Send` подряд: батч в clickhouse-go принадлежит одной таблице); LLM-слой — отдельным батчем (каналы, `method='llm'`) после успешной записи слоя 1 (см. §3.5). Сбой батчей слоя 1 = следующий прогон повторит (ключи Replacing идемпотентны); сбой LLM-батча = слой 1 уже записан, LLM догоняется следующим прогоном.
3. Обычный день: скачивается только индекс (~116 КБ), вставок ноль; новое резюме подхватывается в день публикации.
4. `source_publications`/HEAD-префлайт **не применяем** (механизм — для одного артефакта, здесь индекс+набор документов; дельта по ссылкам дешевле). В ARCHITECTURE §8 — оговорка, чтобы конвенцию не читали как обязательную для любого источника.

### 3.2 Разбор страницы (чистая функция, goquery)

- Обход документа в порядке следования: `h2` (блок), `div.title_20` (подзаголовок), `p` (абзац), `li` (пункт списка). Все пять известных `h2` обязательны — иначе ошибка (структура источника изменилась).
- Из блока «Выводы…» регексами (после нормализации NBSP/неразрывных дефисов/«ё»):
  - дата заседания — «Совет директоров Банка России DD месяца YYYY года (сохранил|повысил|снизил)»; фолбэк — «данных, доступных к DD месяца YYYY года»;
  - вторая закреплённая форма ядра решения — «Совет директоров Банка России DD месяца YYYY года принял решение установить ставку на уровне X% годовых с DD месяца YYYY года»: найдена живой пробой приёмки (2026-10-14) на двух страницах 2024 года (`…27022024`, `…01042024`), где глагола направления в решении нет. Направление читается по обороту «на уровне» (ЦБ пишет «на уровне» об неизменном уровне, «до» — о смене), то есть `hold`, а «с <дата>» отбрасывается, как у любого hold; форма «установить ставку **до** …%» не распознаётся намеренно (это была бы смена уровня — отдельное решение);
  - действие: `hold` («сохранил … на уровне», «установить … на уровне»), `hike` («повысил … до»), `cut` («снизил … до»);
  - ставка — `(\d+,\d+)\s*%\s*годовых` (запятая → точка);
  - `effective_from` — «с DD месяца YYYY года» для cut/hike (для hold — NULL; отсутствие даты у изменения — допустимо, NULL, фиксируется тестом);
  - сигнал — предложения, содержащие подстроку «сигнал» (регистронезависимо; дословно, несколько объединяются `\n`).
- Fail-fast: нет любого из пяти блоков / не распознано решение / ноль абзацев → ошибка до записи.
- Хранится нормализованный дословный текст (иначе сверка цитат LLM ломается на NBSP).

### 3.3 Хранение (три таблицы; канонический DDL — ARCHITECTURE §6.2, копии в коде)

```sql
CREATE TABLE IF NOT EXISTS cbr_mp_summary (
    meeting_date Date,
    published Date,                          -- дата публикации (из индекса; = дата в слаге URL)
    url String,
    decision_action LowCardinality(String),  -- 'hold'|'cut'|'hike'
    decision_rate Float64,                   -- % годовых
    decision_delta_bp Nullable(Int16),       -- шаг к предыдущему решению по meeting_date; NULL — нет предыдущего
    effective_from Nullable(Date),           -- «с …» для cut/hike; NULL для hold
    signal String                            -- дословные предложения про сигнал
) ENGINE = ReplacingMergeTree ORDER BY meeting_date;

CREATE TABLE IF NOT EXISTS cbr_mp_summary_block (
    meeting_date Date,
    block LowCardinality(String),       -- русское имя блока
    subsection LowCardinality(String),  -- 'Основные факты'|'Дискуссия'|''
    kind LowCardinality(String),        -- 'paragraph'|'bullet'
    seq UInt16,
    text String
) ENGINE = ReplacingMergeTree ORDER BY (meeting_date, block, subsection, kind, seq);

CREATE TABLE IF NOT EXISTS cbr_mp_summary_channel (
    meeting_date Date,
    channel LowCardinality(String),   -- slug из реестра 11 каналов
    kind LowCardinality(String),      -- 'risk_pro'|'risk_dez'|'prose'|'note'
    method LowCardinality(String),    -- 'regex'|'llm'
    model LowCardinality(String),     -- '' для regex; фактическое имя модели для llm
    prompt_version UInt16,            -- 0 для regex; версия промпта для llm
    seq UInt16,
    text String                       -- дословная цитата; для 'note' — краткий вывод модели по каналу
) ENGINE = ReplacingMergeTree ORDER BY (meeting_date, channel, kind, method, model, prompt_version, seq);
```

`decision_delta_bp` вычисляется в Go по порядку `meeting_date` из `decision_rate`. Дата ряда — **дата заседания** (`meeting_date`); дата публикации — атрибут (`published`).

### 3.4 Разметка каналов — слой 1 (детерминированные регексы)

- Реестр 11 каналов из [KEY_RATE_CHANNELS.md](../../KEY_RATE_CHANNELS.md) §3 — в Go: slug, русское имя, направление, набор ключевых регексов:

| slug | имя у ЦБ | направление |
|---|---|---|
| `current_inflation` | Текущий рост цен | проинфляционный |
| `core_inflation` | Устойчивая («базовая») инфляция | проинфляционный |
| `expectations` | Инфляционные и ценовые ожидания | проинфляционный при росте |
| `labor_market` | Рынок труда | проинфляционный, пока занятость жёсткая |
| `lending_transmission` | Кредитование и трансмиссия ДКП | дезинфляционный (ужесточение) |
| `output_gap` | Разрыв выпуска / перегрев спроса | проинфляционный |
| `budget_impulse` | Бюджетный импульс | проинфляционный/дезинфляционный |
| `money_supply` | Денежная масса | проинфляционный |
| `external_fx` | Внешние условия и курс | проинфляционный через курс и издержки |
| `savings_behavior` | Сберегательное поведение | дезинфляционный |
| `autonomous_factors` | Автономные (немонетарные) факторы | дезинфляционный |

- Источники совпадений: (а) **пункты и абзацы** блока «Инфляционные риски» → `kind='risk_pro'/'risk_dez'`: атрибуция идёт по порядку обхода — всё до дезинфляционной части списка проинфляционное, ввод дезинфляционной части и всё после него (включая абзац, которым эта часть изложена вместо списка — 06112024) дезинфляционное; служебные абзацы-вводы списков («Основные дезинфляционные риски включают:» — 23092026, «Основным дезинфляционным фактором является:» — 07052026) пропускаются — без матчей и без инкремента `Seq`; (б) предложения прозы остальных блоков (включая блок 5) → `kind='prose'`. Одно предложение может попасть в несколько каналов; текст — дословно.
- `method='regex'`, `model=''`, `prompt_version=0`. Слой работает всегда (офлайн, быстро, без ключей).

### 3.5 Разметка каналов — слой 2 (LLM, с указанием модели)

- **Транспорт:** официальный SDK `github.com/anthropics/anthropic-sdk-go` (Anthropic Messages API: `POST <base>/v1/messages`, обязательный `max_tokens`, ключ заголовком `x-api-key`); `LLM_BASE_URL` — base **без** `/v1` (путь SDK дописывает сам), User-Agent остаётся SDK-шным (`Anthropic/Go …`: ротация `randomUA` нужна сайтам РФ, а не API провайдера); клиент строится на каждый вызов — `option.WithAPIKey`, `option.WithBaseURL`, `option.WithHTTPClient(util.HttpClient)` (конвенция TLS проекта), `option.WithMaxRetries(0)` (повторы SDK выключены), дедлайн запроса — переменная `mpLLMTimeout` (65 с, по образцу `jsonTimeout`/`fileTimeout`); сетевых вызовов в `init()` нет. **Разграничение ошибок (ретрай формата — ровно один, максимум два вызова на документ):** без повтора уходят отказ провайдера (HTTP non-2xx, `*anthropic.Error` — тело режется до фрагмента `http status <код>: <тело ≤512 байт>` через `util.ErrorSnippet`) и ошибки **до чтения тела** — транспорт и дедлайн контекста; форматом (один повтор) считаются обрыв чтения уже начатого тела и обрезанный/неразобранный конверт — различить их по типам SDK нельзя (обе ветки дают `io.ErrUnexpectedEOF`), а матчинг по тексту SDK хрупок, поэтому повтор тут осознан: цена одного вызова ниже риска оставить документ без разметки из-за обрыва TCP (тесты `TestTagMPChannelsLLMBodyReadBroken`, `TestTagMPChannelsLLMBrokenJSON`, `TestTagMPChannelsLLMTimeout`). Свой POST-хелпер (`util.PostJSON`, OpenAI-совместимый `/chat/completions`) упразднён: base владельца Anthropic-совместим, и `/chat/completions` отдавал на нём 404. **Защита ключа (фактическая, достаточная):** ключ уходит только заголовком `x-api-key` — ни в URL/query, ни в тело, ни в репозиторий и логи он не попадает, поэтому маскировка по образцу `eia.maskKey` не реализована и не требуется (требование первой редакции снято по факту): SDK в тексте ошибки API печатает метод, URL, статус и тело ответа, но не заголовки, а ошибки транспорта приходят как `*url.Error` и тоже содержат только URL; отсутствие ключа в обоих текстах пинится тестами (`TestTagMPChannelsLLM500`, `TestTagMPChannelsLLMTransportError`).
- **Конфигурация:** `LLM_BASE_URL`, `LLM_API_KEY`, `MP_SUMMARY_LLM_MODEL` (все — `os.Getenv`; первичный провайдер — DeepSeek, Anthropic-совместимый base (`.../anthropic`) и путь `v1/messages`; ключ владелец кладёт в `~/.config/rosstat/env` сам; в код/логи значения не попадают). Фактическое имя модели пишется в данные (колонка `model`) — «с указанием модели».
- **Запрос:** система (роль + список 11 каналов с определениями) + текст документа; требование строгого JSON: `{"channels":[{"slug":"…","quotes":[{"kind":"risk_pro|risk_dez|prose","text":"дословная цитата"}],"note":"1–2 предложения, что ЦБ говорит про канал"}]}`.
- **Валидация (анти-галлюцинации):** каждая цитата обязана дословно присутствовать в нормализованном тексте документа, иначе отбрасывается с `warn`; `slug` — только из реестра; `note` сохраняется строкой `kind='note'`. Один ретрай на ошибку формата.
- **Идемпотентность:** LLM-строки пишутся только если для `(meeting_date, model, prompt_version)` их нет; смена модели/промпта добавляет новые строки, не затирая старые (в ключе таблицы). Ансамбль нескольких моделей включается добавлением модели в конфиг — без миграции схемы; на старте одна модель.
- **Порядок прогона:** батчи слоя 1 по таблицам (шапка, блоки, regex-каналы) → `Send` каждого → вызовы LLM для документов без строк текущей пары `(model, prompt_version)` → батч LLM-строк.
- **Деградация:** нет переменных / ошибка сети / невалидный JSON после ретрая → `log.Warnf`, документ остаётся со слоем 1; догон следующим прогоном; конвейер не блокируется.

### 3.6 Витрины и MCP-доступ

`util.View` по конвенции (комментарии таблицы и каждой колонки; образец — `v_cbr_mo_br`):

- `v_cbr_mp_summary` — шапка: даты, решение, дельта в б.п., дата вступления, сигнал, ссылка; оговорка: сигнал — дословная цитата; решение — факт ЦБ;
- `v_cbr_mp_summary_blocks` — полный текст: блок / подзаголовок / абзац-или-пункт;
- `v_cbr_mp_summary_channels` — разметка: канал / вид / метод / модель / версия промпта / цитата или заметка; оговорка: **разметка эвристическая** (слой regex) и модельная (слой llm), не позиция ЦБ; решение о «главных каналах» принимает читающий (агент), опираясь на цитаты.

Гранты — `sql/mcp_kimi_reader.sql`; `scripts/mcp_check.py` — три проверки чтения (шапка > 0, блоки > 0, каналы > 0) и закрытость сырых `cbr_mp_summary`, `cbr_mp_summary_block`, `cbr_mp_summary_channel` (ACCESS_DENIED 497). Каталог `series_catalog` не затрагивается (рядов нет; понимание источника дают комментарии витрин).

### 3.7 Календарь заседаний (cal_mp → events_calendar)

- `calendar/events.go`: `Import()` получает фетч `cal_mp` (+чистую функцию разбора, тестируемую офлайн) и upsert **канонических строк** заседаний: `category='cbr'`, `title='СД ЦБ РФ: заседание по ключевой ставке'`, `event_time='13:30'`, `threshold='{}'`, `status='pending'` — для всех карточек-заседаний с полной датой (в закоммиченной фикстуре `calendar/testdata/cal_mp.html` — 68 дат, 2020-02-07 … 2027-12-17, включая четыре внеочередных заседания); карточки не-заседаний (доклад о ДКП, комментарий к среднесрочному прогнозу, пресс-конференции Председателя) пропускаются. Фильтр карточки-заседания: **регистронезависимо** текст содержит «заседание» и «совета директоров» (в реализации — подстрока «заседание совета директоров» после нормализации `&nbsp;` и схлопывания пробелов; у внеочередных заседаний заголовок начинается со строчной «з»: «Внеочередное **з**аседание Совета директоров Банка России по ключевой ставке») **и** тема ∈ {«ключевой ставке», «денежно-кредитной политике»}; буквальный фильтр (AND по «денежно-кредитной политике») оставлял лишь **8 заседаний из 68** — потеря 60 (проверено на фикстуре `calendar/testdata/cal_mp.html` при приёмке 2026-10-14: карточек-заседаний с полной датой 68, из них с оборотом «денежно-кредитной политике» — 8, все восемь содержат и «ключевой ставке»; в отчётах T7/T8 это же число записано как «15» — неверно).
- Совместимость с ручным сидом: ручные строки-триггеры Окт/Дек-2026 («СД ЦБ РФ: ставка (14%) — снижение → флаг перетока ликвидности», threshold `{"cut_bp":">=25"}`) остаются: другой `title` — другой ключ ReplacingMergeTree; на дату два ряда («факт заседания» и «аналитический триггер») — различие документируется в ARCHITECTURE §7. Повторный прогон перезаписывает только канонические строки теми же значениями (идемпотентно). Если ЦБ перенесёт дату — добавится новая строка, старая останется историей (оговорка в доке).
- Новый DAG `dagu/calendar.yaml` (один шаг `events_calendar`, `schedule: "7 10 * * *"` — 10:07 МСК, вне существующих цепочек, retry 3 × 300 с). В `dagu/cbr.yaml` шаг добавить нельзя: тест реестра `TestCbrImportersPrefixedAndRegistered` требует, чтобы каждый шаг `cbr.yaml` был в `cbrImporters`.

## 7. Риски

| Риск | Митигация |
|---|---|
| ЦБ изменит разметку страницы резюме | Точные названия пяти блоков и регексы закреплены фикстурами трёх эпох; любой сбой — fail-fast до записи, ежедневный прогон заметит в день публикации |
| Сменится схема URL/индекс переедет | Ссылки берутся из индекса; пустой разбор индекса (0 резюме) — ошибка |
| LLM недоступен / ключ не добавлен / дорого | Слой 1 работает всегда; LLM — 1 вызов на новое резюме (≤ 22 в приёмке); деградация с warn и догоном; ответы валидируются (цитаты — дословно) |
| Галлюцинации модели | Цитаты обязаны присутствовать в тексте дословно; иначе отбрасываются; slug — только из реестра; в витрине — оговорка о модельной природе разметки |
| Формулировки решения варьируются по эпохам | Фикстуры hold/hike/cut трёх эпох + фолбэк по фразе «данных, доступных к…»; нераспознанное решение — ошибка, не тихая запись |
| Ключ в env и утечки | Только `os.Getenv`; значения не печатаются в логах/ошибках (ключ едет заголовком `x-api-key`, SDK его в тексты ошибок не подставляет); в репозиторий не попадают |
| Перенос даты заседания ЦБ | Канонические строки аддитивны: старая остаётся историей, новая добавляется (оговорка в ARCHITECTURE §7) |
| Путаница `published` ↔ `meeting_date` | Семантика закреплена колонками и комментариями витрин; слаг URL = дата публикации |
