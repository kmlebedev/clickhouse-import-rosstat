# Оркестрация импортов ClickHouse через Dagu — дизайн

Дата: 2026-10-08. Статус: инструмент заменён с Kestra на Dagu, ждёт подтверждения.

## 1. Цель

Перенести расписание наполнения и обновления ClickHouse из текущего неявного запуска
(ручной `make run` с `CLICKHOUSE_IMPORT_STAT`, план cron из `docs/ROADMAP_DCF_POLYUS.md` §6)
в self-hosted Dagu, установленный бинарником без Docker на выделенном сервере (32 GB RAM),
где уже работает ClickHouse.

Вне scope: новые импортёры (`fred`, `eia`, `lbma_gold`, `moex_iss`), витрины `v_*`,
MCP-сессии и аналитические сессии Kimi Work. Kimi Work остаётся для аналитики;
его cron-план больше не используется для запуска импортов.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Инструмент | Dagu (`github.com/dagucloud/dagu`), одиночный бинарник, без внешней БД. Kestra снята с рассмотрения |
| Структура флоу | Один флоу на домен: `cbr`, `rosstat`, `minfin`, `customs`, `fao`, `bank`, `craw`, `financial` (legacy) |
| Уведомления | Telegram, отправка из `handler_on.failure` в `base.yaml` |
| Хост | Выделенный сервер 32 GB RAM, ClickHouse уже стоит; Dagu ставится бинарником без Docker |
| Способ запуска импортёров | Шаги `run:` (shell) с предсобранным бинарником |
| Масштаб | Пока один сервер. При росте — отдельный дизайн |

## 3. Компоненты

### 3.1 Бинарник импортёра на хосте

- Сборка через `make build` (статический linux/amd64, `CGO_ENABLED=0`, `-ldflags="-s -w"`).
- Бинарник кладётся в `/opt/rosstat-import/bin/clickhouse-import-rosstat`, владелец `root`,
  режим `0755`. Пользователь `dagu` может читать и запускать, но не писать.
- Конфигурация через env: `CLICKHOUSE_URL`, `CERT_FILES`, `LOG_LEVEL`, `CLICKHOUSE_IMPORT_STAT`.
- Обновление: копирование новой сборки с сохранением предыдущей как `.prev` для отката.

### 3.2 Установка Dagu

- Бинарник релиза `dagucloud/dagu`, версия не ниже исправлений всех опубликованных
  уязвимостей (см. раздел 7). Контрольная сумма релиза проверяется перед установкой.
- Запуск `dagu start-all --dags /opt/dagu/dags` как systemd-сервис от пользователя `dagu`.
- Аутентификация: `DAGU_AUTH_MODE=builtin`. Режим `basic` и `none` не используются
  (`basic` имел обход аутентификации в версиях до 2.2.4).
- Веб-интерфейс и API: `DAGU_HOST=127.0.0.1` (значение по умолчанию). Наружу — только через
  reverse proxy с TLS и ограничением по IP (`ip_access`).
- Встроенный MCP-сервер (`/mcp`) отключается или остаётся только под `builtin`-аутентификацией
  с отдельным API-ключом, без записи. Решение фиксируется в Task установки.

### 3.3 Флоу Dagu

- Каталог `dagu/` в репозитории: `dagu/cbr.yaml`, `dagu/rosstat.yaml`, … Флоу хранятся в git,
  правятся через PR. Каталог DAG на сервере — `/opt/dagu/dags`, синхронизируется из репозитория.
- Имя файла = имя DAG. Один DAG на домен.
- Каждый шаг запускает ровно один импортёр:
  - `id: <имя таблицы>`;
  - `run: "$ROSSTAT_IMPORT_BIN"` с `env: CLICKHOUSE_IMPORT_STAT=<имя таблицы>`. Путь к бинарнику
    задаёт `base.yaml` (`env: ROSSTAT_IMPORT_BIN=...`), поэтому один DAG работает и в dev, и на сервере;
  - `shell: bash` задаётся в `base.yaml`, `set -euo pipefail` через `shell: ["bash", "-e", "-o", "pipefail"]`.
- `Name()` импортёра = имя таблицы ClickHouse, поэтому `id` шага = имя таблицы.
- Зависимости внутри домена (витрины после источников) — `depends:`.

### 3.4 Расписания

- Расписание задаётся на уровне домена: `schedule:` в YAML DAG, cron в формате Dagu.
- Для смешанной частоты внутри домена — один DAG на домен с самой частой частотой; медленные
  импортёры идемпотентны и выполняются ежедневно без вреда. Решение фиксируется в плане.
- `overlap_policy: skip` — не запускать новый прогон, пока предыдущий не завершился.
- `catchup_window` — догон пропущенных запусков, если сервер был выключен (значение задаётся
  в плане внедрения).
- Часовой пояс — `DAGU_TZ=Europe/Moscow`.

### 3.5 Секреты и конфигурация

- Секреты — в `base.yaml` через блок `secrets` с провайдером `file`:
  `/etc/dagu/secrets/<имя>` с правами `0600`, владелец `dagu`.
  Значения попадают в шаги через `secrets` и маскируются в логах.
- Переменные, которые не секретны (`TZ`, `LOG_LEVEL`), — в `env:` `base.yaml`.
- В YAML DAG и в git секретов нет. В коде только `os.Getenv`.
- `INVESTING_EMAIL`, `INVESTING_PASSWORD` удаляются вместе с соответствующими импортёрами.

### 3.6 Ретраи и уведомления

- `retry_policy`: `limit: 3`, `interval_sec: 300` (постоянная пауза 5 минут на каждом шаге).
  Экспоненциальная пауза по спецификации (1, 5, 15 минут) в документации Dagu не подтверждена,
  поэтому применяется постоянная. Ретрай срабатывает только при ненулевом коде выхода.
- Уведомление: `handler_on.failure` в `base.yaml` вызывает `curl` к Telegram Bot API
  (`sendMessage`) с токеном и `chat_id` из секретов и текстом с `${context.dag.name}` и
  `${context.run.id}`. Обработчик наследуется всеми корневыми DAG.
- Импортёры идемпотентны: `ReplacingMergeTree` и `CREATE TABLE IF NOT EXISTS` позволяют
  повторный запуск без порчи данных.

## 4. Обязательные изменения в коде

Блокируют использование Dagu и выполняются до подключения флоу.

1. **`main.go`: ненулевой код выхода при ошибке.** Сейчас ошибка импортёра только
   логируется (`log.Errorf`), процесс завершается с кодом 0. Требуется: собрать признак
   ошибки по всем импортёрам и вызвать `os.Exit(1)`, если хотя бы один упал.
   Остальные импортёры продолжают выполняться.
2. **`main.go`: фильтр `CLICKHOUSE_IMPORT_STAT`.** Сейчас при пустой переменной
   `strings.Split("", ",")` даёт `[""]`, и `slices.Contains` ни для одного импортёра не
   возвращает true — импорт «всех» ничего не делает. Требуется: пустая строка означает
   «все импортёры», список разбирается без пустых элементов.
3. **`main.go`: ошибка `clickhouse.ParseDSN`.** Сейчас она игнорируется. Требуется
   проверять и завершаться с `log.Fatal` с фиксированным текстом без значения DSN.
4. **`go.sum`.** Файл не закоммичен и неполон, сборка не проходит. Требуется дополнить
   через `go mod tidy` и закоммитить вместе с изменениями.

## 6. Тестирование и приёмка

Тесты в репозитории отсутствуют (AGENTS.md, правило 11). Проверка:

1. `go build ./... && go vet ./...` проходят.
2. Локально: `CLICKHOUSE_IMPORT_STAT=` импортирует все; неизвестное имя — ничего и код 0 с
   предупреждением; при падении одного импортёра процесс завершается кодом 1.
3. `dagu validate /opt/dagu/dags/<домен>.yaml` проходит для каждого флоу.
4. Ручной запуск одного DAG из UI → данные в ClickHouse: `SELECT ... FROM <таблица> FINAL LIMIT 5`.
5. Сбой: неверный `CERT_FILES` → шаг ретраится 3 раза, затем приходит сообщение в Telegram.

## 7. Риски

- **Уязвимости Dagu.** Опубликованы несколько уязвимостей в начале 2026 года:
  - CVE-2026-27598: обход пути при создании DAG (RCE). Исправление было неполным.
  - CVE-2026-33344: неполное исправление CVE-2026-27598, обход пути в `locateDAG`.
  - CVE-2026-31886: обход пути в эндпоинтах inline-DAG, критичный рейтинг, исправлен в 2.2.4.
  - CVE-2026-31882: обход аутентификации SSE в режиме `basic`, исправлен в 2.2.4.
  Меры: установить версию, где исправлены все перечисленные уязвимости (проверить по каждому
  advisory перед установкой), аутентификация `builtin`, доступ только с `127.0.0.1` или через
  reverse proxy, MCP под аутентификацией.
- **Шаги выполняются на хосте от пользователя `dagu`.** Процесс получает доступ к файлам
  секретов. Мера: права `0600` на секреты, отдельный пользователь без доступа к данным
  ClickHouse вне нужных прав.
- **Токен Telegram в аргументах `curl`.** Значение видно в списке процессов на короткое время.
  Мера: токен не пишется в YAML, маскируется в логах Dagu; при необходимости заменяется на
  вызов скрипта, читающего секрет из файла.
- **Постоянная пауза ретрая.** Для сетевых сбоев с длительным простоем источника 3 попытки по 5
  минут могут не покрыть простой. Решение: увеличить `limit` или `interval_sec` в плане.
- **Лимиты внешних источников.** Частые ретраи по rosstat.gov.ru и cbr.ru могут вызвать
  блокировку. Нужны паузы и ограничение параллелизма внутри домена.
- **Порядок зависимостей.** Витрины и производные таблицы должны считаться после источников.
  Порядок проверяется на реальных данных.
- **Ресурсы сервера.** 32 GB делятся между ClickHouse и Dagu. Dagu легковесен, поэтому
  отдельные лимиты не нужны, но мониторинг памяти обязателен.
- **Логи с DSN.** Вывод импортёра не должен печатать DSN с паролем. Проверяется при реализации
  пункта 4.3.
- **Init-вызовы в `cbr`.** Пакет `cbr` делает сетевые вызовы при старте (нарушение AGENTS.md
  правило 3). Каждый запуск обращается к cbr.ru. Исправляется отдельной задачей.

## 8. Открытые вопросы для плана внедрения

- Точная версия Dagu: выбрать последнюю стабильную после сверки с advisory.
- Точный состав импортёров по доменам (сверка `Name()` по пакетам).
- Расписания cron для каждого домена (частоты источников).
- Способ доступа к UI Dagu: VPN, reverse proxy или SSH-туннель.
- Нужен ли встроенный MCP-сервер Dagu, или он отключается.
