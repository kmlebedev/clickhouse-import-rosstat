# T+1 золото из bold.report: ETF-контур и цена — design

Дата: 2026-10-12. Пункт: `docs/GOLD_THESIS_DATA_ROADMAP.md`, фаза 3 — новый follow-up «T+1 золото из `bold.report` (ETF-контур и цена)».
Ветка: `feat/bold-t1-gold`.

Приёмка пункта: `make import STAT=bold_etf_flows` на пустых рядах пишет **21 054** точки ETF-контура и
**73** строки пер-фондового среза, `make import STAT=bold_gold_price` — **3 138** точек цены; повторный прогон идёт
инкрементом (≈8 точек + 73 строки) и идемпотентен; `v_gold_etf_flows_daily` за 2026-10-09 показывает поток
**+4,233 т / 573,75 млн $**, запасы **3520,318 т**, AUM **476,678 млрд $**, окна 7/30/90 дней **1,360 / 30,825 / 167,214 т**,
`v_gold_etf_funds_daily` — 73 фонда, `v_gold_prices` — площадка `bold`; `make all` зелёный; `make mcp-check` — ПРОВЕРКА ПРОЙДЕНА.

## 1. Пробел и место в роадмапе

В контуре золота нет **ежедневных** потоков ETF: месячный WGC (`wgc_etf_flows`, автоматизирован 12.10.2026 через
`fscdn.gold.org`) отстаёт на собственный лаг публикации 7–10 дней. Остававшийся пункт «ежедневный прокси по эмитентам
(топ-4 US ETF, ≈42,5 % мировой величины)» требовал трёх-четырёх парсеров ради неполного покрытия.

Публичный агрегатор закрывает задачу одним каналом: **73 фонда ≈ 83 % мировой величины, лаг T+1, без ключа**.
**План по эмитентам снимается** — это фиксируется здесь и в роадмапе; отдельного пункта «парсинг эмитентов» не будет.

## 2. Источник (проверено 2026-10-12 живыми запросами)

Оператор — ByteTree (на сайте указан контакт `bold@bytetree.com`). Страница данных: `bold.report/data-api`.

- Форматы: история `{version, updated, data:[…]}` и последний день `{version, updated, date, …поля}`; всё доступно
  и JSON, и CSV, HTTP GET **без ключа и авторизации**.
- Ограничения: «Excessive usage will be rate limited» → режим щадящий (5 запросов в сутки); `robots.txt` разрешает всё,
  кроме `/_astro/`. Атрибуция источника обязательна в каталоге и README.
- Обновление: **04:32 UTC (07:32 МСК)** ежедневно; выходные в рядах отсутствуют (документация: «weekends omitted»),
  поэтому «T+1» означает первый торговый день после отчётного.

| эндпоинт | формат | поля | живой объём/глубина |
|---|---|---|---|
| `gold/price.json` | история | `date`, `value` | 3 138 точек, 2014-10-01 … 2026-10-09, 117 КБ |
| `gold/price-latest.json` | последний день | `date`, `value` | 87 байт |
| `gold/funds/units.json` | история | `date`, `units`, `price` | 3 072 строки, 166 КБ; `units` — у 3 008 (2015-04-01…2026-10-09) |
| `gold/funds/units-latest.json` | последний день | `date`, `units`, `price` | 105 байт |
| `gold/funds/aum.json` | история | `date`, `aum`, `price` | 3 072 строки, 170 КБ; `aum` — у 3 008 |
| `gold/funds/aum-latest.json` | последний день | `date`, `aum`, `price` | 106 байт |
| `gold/flows/all.json` | история | `date`, `culm7day`, `culm30day`, `culm90day`, `price` | 3 138 строк, 293 КБ; `culm*` — у 3 008 |
| `gold/flows/all-latest.json` | последний день | те же поля | 143 байта |
| `gold/summary.json` | **только последний день** | `ticker`, `name`, `units`, `unitsChange`, `aum`, `aumChange`, `price`, `priceChange`, `shares`, `sharesChange` | 73 фонда, 15 КБ |

Первые 64 строки `units`/`aum` (2015-01-01 … 2015-03-31) несут только `price` — **точек нет, а не нули**.
У пер-фондового среза **нет поля даты** (только `updated` — время прогона, 11.10 для данных 09.10) — дата берётся из
`*-latest`, и расхождение дат между эндпоинтами обязано быть ошибкой, а не тихой записью под чужим числом.

## 3. Семантика рядов (проверено)

- `units` = «Total Units, Oz» — совокупный металл в 73 фондах (сток, унции), GLD 33 552 628 oz = 1043,6 т,
  IAU 14 772 036 oz = 459,5 т.
- `culm7day` / `culm30day` / `culm90day` = «N Day Flow, Oz» — **Δunits за N календарных дней**; проверено до унции:
  `culm7day` = Δ за 7 календарных дней (5 торговых строк; 43 740 = 43 740), `culm30day` = Δ за 30 календарных
  (22 строки; 991 060 = 991 060). Для `culm90day` конвенция источником не документирована и расходится с Δ за 90
  календарных дней на 1,8 % (5 376 055 oz против ≈5 475 000) — поэтому окна импортируются **как публикует источник**,
  без пересчёта из нашего дневного ряда.
- `price` = «**Futures Price**» (так в документации; конкретный метод — контракт, время снимка — не раскрыт).
  С нашим `comex_front` (GC=F, сессионный ввод) совпадает лишь частично: **3 из 13** контрольных дат, расхождения
  до **$42** (2026-10-08: у нас 4157,0, у источника 4199,4) → это **отдельная серия**, `comex_front` не подменяется.
- `aum` = AUM USD (совокупный, 476 677 811 738 на 2026-10-09).
- Знак: рост `units` — приток (плюс) — та же конвенция, что у WGC-рядов проекта.
- Покрытие: 113 180 843 oz = **3520,318 т** и **$476,678 млрд** против мировой величины WGC 4255,66 т / $574,23 млрд
  (30.09.2026) → **82,7 % по металлу и 83,0 % по AUM** (то есть «≈83 %»); в списке GLD, IAU, IGLN (iShares Physical Gold, LSE), GLDM, SGLD (Invesco), 4GLD (Xetra-Gold),
  PHYS, 518880 (Huaan, Китай), GOLD (Amundi), 1540 (Japan Physical Gold), ZGLD, SGOL.

## 4. Что пишем в БД

### 4.1 `macro_series`, `source='bold'` — 7 рядов

| ряд | единица | формула (у источника — унции) |
|---|---|---|
| `etf_bold_flow_tonnes` | тонны | `(units_t − units_{t−1}) / 32150,7465686` — дневной поток; у первой точки ряда потока нет |
| `etf_bold_flow_usd_mln` | млн USD | `(units_t − units_{t−1}) × price_t / 1e6` |
| `etf_bold_flow_7d_tonnes` | тонны | `culm7day / 32150,7465686` — как публикует источник |
| `etf_bold_flow_30d_tonnes` | тонны | `culm30day / 32150,7465686` |
| `etf_bold_flow_90d_tonnes` | тонны | `culm90day / 32150,7465686` |
| `etf_bold_holdings_tonnes` | тонны | `units / 32150,7465686` — сток |
| `etf_bold_aum_usd_bn` | млрд USD | `aum / 1e9` — сток |

Константа `31,1034768 г/унция` — та же, что в `gold/gold.go`; определяется в `bold/` локально с комментарием-ссылкой.

### 4.2 `gold_prices` — площадка `bold`

- `venue='bold'`, `date`, `usd=value`; DDL общей таблицы (`gold/`) не меняется.
- Каталог: запись `source='gold'`, `series='bold'` добавляется в `gold/series_meta.go` (ряд живёт в таблице цены, как
  `moex_fix_usd`/`comex_front`); unit «USD за тройскую унцию (фьючерс источника, метод детально не раскрыт)»,
  frequency `D`, origin — `bold.report/api/v1/gold/price.json`.
- Комментарий витрины `v_gold_prices` («Две площадки: …») расширяется до трёх — правка в `gold/series_meta.go`.

### 4.3 `bold_fund_snapshot` — новая таблица (пер-фондовый дневной срез)

```sql
CREATE TABLE IF NOT EXISTS bold_fund_snapshot (
      date Date32
    , ticker LowCardinality(String)
    , name LowCardinality(String)
    , units_oz Float64
    , units_change_oz Float64
    , aum_usd Float64
    , aum_change_usd Float64
    , price_usd Float64
    , price_change_usd Float64
    , shares Float64
    , shares_change Float64
) ENGINE = ReplacingMergeTree ORDER BY (date, ticker, name);
```

Ключ обязан включать `name`: тикер у источника **не уникален** — в живом срезе 73 строки при 71 уникальном тикере
(`GLD` встречается трижды: разные фонды на разных площадках, имена различаются), поэтому `(date, ticker)` схлопнул бы
два реальных фонда.

73 строки за прогон (все фонды источника), история накапливается с первого прогона — у источника пер-фондовой истории
нет, только последний день. Дата — из `*-latest` (§2), с fail-fast при расхождении дат.

### 4.4 Витрины (правило 11: комментарии таблицы и колонок, грант `kimi_reader`)

- `v_gold_etf_flows_daily` (над `macro_series`, `source='bold'`): `date`, `flow_tonnes`, `flow_usd_mln`,
  `flow_7d_tonnes`, `flow_30d_tonnes`, `flow_90d_tonnes`, `holdings_tonnes`, `aum_usd_bn` — одна строка на дату,
  порядок `date DESC`.
- `v_gold_etf_funds_daily` (над `bold_fund_snapshot`): `date`, `ticker`, `name`, `units_oz`, `aum_usd`, `price_usd`,
  `units_change_oz`, `aum_change_usd`, `shares`, `shares_change` — одна строка на (дата, фонд), порядок `date DESC, ticker, name`.

Тексты обязаны называть: агрегат по 73 фондам ≈ 83 % мировой величины WGC, «не складывать и не сравнивать напрямую
с `etf_holdings_tonnes_world`/`etf_flow_tonnes_world` (там все фонды мира и месячная частота)», окна — календарные
(7/30/90 календарных дней, сумма 5 торговых дней ≠ `culm7day`), метод цены источником не раскрыт, источник — bold.report
(ByteTree), ключей нет и режим щадящий.

## 5. Импортёры (пакет `bold/`)

Два импортёра, как в `wgc/`: `bold_gold_price` (таблица `gold_prices`) и `bold_etf_flows` (`macro_series` +
`bold_fund_snapshot`). Сетевых вызовов в `init()` нет; HTTP — только `util.GetJSON` (проверка статуса, дедлайн 60 с);
запись — одним батчем `PrepareBatch → Append (err) → Send`; каталог — после успешного `Send`.

**Режимы (инкремент вместо ежедневной перезаписи истории):**

- **Инкремент (обычный прогон).** Четыре запроса: `units-latest`, `aum-latest`, `flows/all-latest`,
  `summary` (≈500 байт суммарно; `price-latest` — отдельный импортёр цены, §5). Пишутся только точки новее сохранённого максимума (обычно один день):
  дневной поток считается как Δ к `units` предыдущего торгового дня, **прочитанного из ClickHouse**
  (`max(date)` ряда `etf_bold_holdings_tonnes`); окна берутся из `flows/all-latest` как опубликованы.
  «Сохранённый максимум» — свой у каждого импортёра: для `bold_etf_flows` это `max(date)` рядов `source='bold'`
  в `macro_series` и таблицы `bold_fund_snapshot`, для `bold_gold_price` — `max(date)` площадки `bold` в `gold_prices`.
  Если дата `*-latest` не больше сохранённого максимума — прогон пишет 0 строк и завершается успешно (идемпотентный no-op).
- **Полный (первый прогон или доказанный пропуск дней).** Если точек нет вовсе — файлы истории (`units.json`,
  `aum.json`, `flows/all.json`, `price.json`); если инкремент не может исключить пропуск дней
  (`latest.date − сохранённый максимум > 4 календарных дня`: сбой джобы, длинные выходные) — те же файлы истории,
  и из них пишутся **все** точки: перезапись идемпотентна и заодно лечит прошлые дыры (путь редкий, не ежедневный).
  На пустых рядах это ≈21054 точки ETF + 3138 цены + 73 строки фондов. Стоимость: полный путь — до 8 запросов
  (4 «последнего дня» нужны, чтобы вообще узнать дату для сравнения и получить пер-фондовый срез, плюс 3 файла истории
  и `summary`), обычный инкремент — 4; суточный итог контура остаётся ≤ 5 (4 ETF + 1 цена).
- Оба режима идемпотентны (`ReplacingMergeTree` по ключам), полный путь можно запустить руками.

**Fail-fast:** не-200, пустое тело, отсутствие нужного ключа, расхождение дат `*-latest`, ноль точек — ошибка
(уроки `eia`/`wgc`: тихий ноль оставил бы dagu зелёным, а ряды — без обновления). Ошибка диагностического запроса
максимума из ClickHouse — `log.Warnf` и продолжение (как в `wgc_etf_flows`).

## 6. Расписание

`dagu/bold.yaml`: `type: chain`, `schedule: "7 8 * * *"` (08:07 МСК — данные источника готовы к 07:32 МСК, слот свободен),
`overlap_policy: skip`, шаги `bold_gold_price` → `bold_etf_flows`, retry 3 × 300 с.

## 8. Тесты и приёмка

Офлайн-тесты (`httptest` + урезанные фикстуры: пять ответов «последнего дня» и фрагменты истории), пины фактов
на 2026-10-09: `units` 113 180 843 oz → **3520,318 т**; `aum` 476 677 811 738 → **476,678 млрд $**;
`culm7day` 43 740 oz → **1,360 т**; `culm30day` 991 060 → **30,825 т**; `culm90day` 5 376 055 → **167,214 т**;
`price` **4216,3**; дневной Δ (09.10 к 08.10) = 136 080 oz → **+4,233 т** и **573,75 млн $**.

Проверки конвенций: `culm7day` = Δunits за 7 календарных дней (сверка-тест), `culm30day` = Δ за 30 календарных;
`null` в первых 64 строках → точек нет; инкремент: пустая БД → полный путь, `latest` новее максимума на 1 день →
одна точка, разрыв 6 дней → полный путь (тесты с подменой базового URL и фейковым соединением для чтения максимума).

Приёмка: `make import STAT=bold_etf_flows` и `STAT=bold_gold_price` (полный, затем инкремент) с числами из шапки,
сверка через MCP по обеим витринам и `v_gold_prices`, `make all`, `make mcp-check`.

## 9. Отклонённые варианты

- **Парсинг эмитентов (топ-4 US ETF).** Снят: 42,5 % мировой величины против 83 % у агрегатора, и три-четыре парсера
  с фикстурами против трёх-пяти запросов без ключа.
- **CSV-эндпоинты источника.** Те же данные, но требуют своего разбора; выбран JSON (`util.GetJSON` уже есть).
- **Пересчёт окон из нашего дневного ряда.** `culm90day` расходится с Δ за 90 календарных дней на 1,8 %; публикация
  источника — авторитетнее любого нашего пересчёта.
- **Запись цены bold в `comex_front`.** Разные серии (3 из 13 совпадений, до $42) — была бы тихая подмена смысла
  исторического ряда; поэтому отдельная площадка.
- **Масштабирование агрегата до мировой величины** (×1/0,83). Отклонено: смешало бы оценку с фактом WGC; покрытие
  указывается текстом, ряды остаются честно частичными.

## 10. Вне объёма

Пер-фондовые **истории** (у источника их нет — только последний день), месячные пер-фондовые потоки
(`gold/flows/summary.json`, есть), bitcoin-часть BOLD, `combined/all*`, CSV-каналы, автоматизация `comex_front`
(остаётся сессионным вводом).
