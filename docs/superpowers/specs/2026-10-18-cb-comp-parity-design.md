## 1. Задача и рамка

Ответить строго, а не риторически: **статистически близок ли наш месячный nowcast ИПЦ к МП-модели `CB_COMP` (Кошкин–Крылов, 2025)** на одном и том же таргете, одном и том же тестовом окне и одних и тех же тестовых месяцах.

Строгий путь #190:

1. таргет берётся из архива авторов — `TARGET_FULL` (SA ИПЦ без коммунальных услуг, накопленный прирост за h месяцев, %), а не собирается из публичных рядов;
2. прогнозы `CB_COMP` берутся из архива per-period (`StfCpiCB` / `catboostVCB_IBK.xlsx`), **retrain CB_COMP не выполняется**;
3. наш nowcast обучается на том же таргете, на фиксированном сплите статьи, с признаками ML-трека v2 (с МП и без МП);
4. сравнение — DM-HLN, TOST с заранее зафиксированным margin, RMSE ratio с блочным бутстрапом;
5. вывод «близок / не близок» — строго по критерию из issue, а не по желанию.

Прокси-путь (собрать SA ИПЦ без КУ из публичных рядов) в этом пункте **не используется**: по правилу issue прокси не выдаётся за строгий. Если строгий путь где-то упирается в данные, это называется явно (§6), а не подменяется.

## 2. Что именно сравнивается

| Компонент | CB_COMP (архив) | Наш nowcast (этот пункт) |
|---|---|---|
| Таргет | `TARGET_FULL`: SA ИПЦ без КУ, накопленный прирост за h мес., % | тот же `TARGET_FULL`, читается из архива |
| Горизонты | h = 1, 2, 3, 6 (в архиве есть и 4, 5) | те же h; 1/2/3/6 — основные, 4/5 — дополнительные |
| Train | 2010-03…2018-12 (102 мес., факт) | 2010-03…2018-12 без выбросов 2014-12…2015-03 — **предзарегистрированное окно** (102 мес.); long-sample v2 держит все месяцы, `key_rate`/`usd_mm` до 2013 г. — NaN (§6.1) |
| Test | 2019-01…2024-07, 67 мес. | то же окно, те же 67 мес. |
| Normal-месяцы | 54: исключены 2020-04 и весь 2022 | тот же набор; сверяется с флагом `Учитывать` архива |
| Модель | покомпонентный CatBoost, дефолты, без валидации | CatBoost **direct** на h-таргете, дефолты, seed 20261018 |
| Информационные множества | с МП и без МП | две модели: `nowcast_v2_mp` (5 базовых + 7 МП) и `nowcast_v2_nomp` (5 базовых) |
| Сплит | один фиксированный train → test, без фолдов | тот же фиксированный сплит; walk-forward в этом пункте не используется |

Это **parity-адаптация** ML-трека v2: у v2 продакшн-цель — несглаженный м/м ИПЦ и walk-forward; здесь та же архитектура (CatBoost direct) и тот же набор признаков переносятся на таргет статьи, чтобы сравнение было «модель против модели», а не «две разные задачи».

Это зависимость от ещё не смерженного PR, она названа в отчёте и PR.

## 4. Модели

Для каждого h ∈ {1,2,3,6} (и дополнительно 4,5) обучаются две прямые модели:

- `nowcast_v2_mp` — `feature_names(with_mp=True)`;
- `nowcast_v2_nomp` — `feature_names(with_mp=False)`.

Конфигурация **фиксируется до прогона** и не подбирается:

```
CatBoostRegressor(
    loss_function="RMSE",
    random_seed=20261018,
    verbose=False,
    cat_features=["month"],
    allow_writing_files=False,
)
```

Остальные параметры — дефолты библиотеки (как у CB_COMP: без валидации, без early stopping, без перебора). Monotone-ограничения v2 в parity-модель **не переносятся** — это отдельная конфигурация v2, а здесь важна минимальная и одинаково названная конструкция. Train — 2010-03…2018-12 (фактически с доступного месяца, §6.1), test — 2019-01…2024-07; обучение один раз, прогноз на все тестовые месяцы.

**Bottom-up не строится.** Причина названа честно: таргет статьи — SA ИПЦ **без КУ** (`1 - 9470`); в архиве есть SA-уровни 50 кодов и отдельный прогноз ЖКУ, но покомпонентная агрегация требует весов СПР по винтажам и 92 компонентных моделей, а 16 групп публичной версии идут без BSU-привязки. Наши признаки v2 — агрегатные. Поэтому сравнение идёт **direct-моделью**, и в отчёте это написано; выдавать direct за bottom-up запрещено.

## 5. Метрики и критерий

### 5.1. Основные величины

Для каждого h на общих 54 normal-месяцах:

- `RMSE_ours`, `RMSE_cb`; ошибка `e = прогноз − факт` в п.п. накопленного прироста;
- `Δ = RMSE_ours − RMSE_cb` (положительное — мы хуже);
- `ratio = RMSE_ours / RMSE_cb`;
- DM-HLN: `eval_utils.diebold_mariano(err_ours, err_cb, h=1)` — основная конвенция (у авторов `forecast::dm.test` по умолчанию `h=1`); `h=h` — робастность. Потери — квадраты ошибок. Положительная статистика — мы хуже;
- TOST: `δ_h = 0.10 × RMSE_cb_h`; 90% CI для `Δ` — парный блочный бутстрап (блок 3 месяца, n = 2000, seed 20261018, циклические блоки, те же индексы для обоих рядов); 90% CI для `ratio` — тем же бутстрапом;
- `bootstrap_tail_low = P(Δ* ≤ −δ)`, `bootstrap_tail_high = P(Δ* ≥ δ)` — описательные хвостовые вероятности (не заменяют CI-критерий).

### 5.2. Margin, зафиксированный до прогона

`δ_h = 10% RMSE CB_COMP`. Для основных горизонтов значения фиксируются здесь и проверяются в прогоне против пересчитанного RMSE:

| h | RMSE CB_COMP (статья/архив) | δ = 10% |
|---|---:|---:|
| 1 | 0.158805 | **0.0158805** |
| 2 | 0.296655 | **0.0296655** |
| 3 | 0.443623 | **0.0443623** |
| 6 | 0.971459 | **0.0971459** |

Для h = 4, 5 δ вычисляется тем же правилом из пересчитанного RMSE архива **до** обучения наших моделей и печатается в отчёте; это дополнительные горизонты, на вердикт они не влияют.

Порядок в скрипте: сначала читается архив, считаются `RMSE_cb` и `δ`, печатаются; только потом строятся признаки и обучаются модели. Margin не зависит от наших результатов по построению.

### 5.3. Вердикт

По каждому горизонту:

- **equivalent** — DM p > 0.05 **и** 90% CI для Δ целиком внутри (−δ, +δ);
- **ours worse** — DM p ≤ 0.05 и Δ > 0;
- **ours better** — DM p ≤ 0.05 и Δ < 0;
- **inconclusive** — DM p > 0.05, но TOST-CI не внутри margin.

**Общий вердикт «близок»** — только если все четыре основных горизонта (1, 2, 3, 6) для основной модели `nowcast_v2_mp` дают **equivalent**. Иначе — **«не близок»**, с поимённым перечислением горизонтов и направлением различия. «Не близок» — законный результат: issue прямо допускает его, и отчёт не смягчает формулировку.

Модель `nowcast_v2_nomp` — сенситивность (вклад МП в нашей конструкции); её вердикт публикуется отдельно и на headline не влияет.

## 6. Ограничения и отклонения (названы до прогона)

1. **Доступность `key_rate`/`usd_mm` в начале train и выбросы train.** Предзарегистрированное окно — 2010-03…2018-12 без четырёх выбросов статьи (2014-12…2015-03), итого **102 месяца**, как у CB_COMP. Признаки v2 включают `key_rate` (ряд с 2013-09-17) и `usd_mm` (дневной USD с 2013-01-10), поэтому у месяцев 2010-03…2012-12 (и 2013-01…2013-09 для ставки) эти два признака — **NaN**, а не пропуск строки: так работает long-sample политика вендоренного `cpi_monthly.py` (v2 §8.2), и CatBoost обрабатывает NaN нативно. Обязательными остаются `y_lag1`, `y_lag2`, `fao_mm` и все МП-точки. Месяцы не выбрасывались сверх правил статьи и окно не сокращалось по результату.
2. **Retrain CB_COMP не выполняется.** Используются архивные per-period прогнозы; это ровно тот прогон, который породил числа статьи. Воспроизводимость RMSE проверяется (§3.1), но не переобучение.
3. **Direct, не bottom-up** (§4).
4. **DM-конвенция отличается от архивной.** В `Diebold-Mariano.R` авторов в `dm.test` подаются уже **квадраты** ошибок, а `dm.test` по умолчанию возводит их в квадрат ещё раз (`power=2`), то есть их p-value — тест на четвёртых степенях. Мы воспроизводим их числа как кросс-проверку архива (ожидаемые 0.032952 / 0.005115 / 0.005355 / 0.132256), но **наш** тест — стандартный DM-HLN на квадратах ошибок; сравнивать p-value напрямую нельзя, и отчёт это оговаривает.
5. **Public archive урезан:** 16 из 88 компонентных групп без BSU, 87 кодов ОКВЭД2, сырые МП не включены. На агрегатное сравнение это не влияет, на «полное воспроизведение статьи» — влияет.
6. **Винтажи не учитываются** — общий ограничитель и для нас, и для авторов.
7. **Наш nowcast — parity-адаптация v2, не продакшн-модель.** Продакшн v2 прогнозирует м/м ИПЦ walk-forward; здесь — накопленный SA-таргет на фиксированном сплите.
8. **h4/h5** есть в архиве (`catboostVCB_IBK.xlsx`) и считаются как дополнительные; в таблице статьи их нет.
