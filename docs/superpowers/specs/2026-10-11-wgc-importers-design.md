# Пакет `wgc/`: импортёры WGC ETF Flows и золотых резервов ЦБ — design

Дата: 2026-10-11. Пункт: `docs/GOLD_THESIS_DATA_ROADMAP.md` §2, новый follow-up фазы 3 — «Фаза 3 — follow-up: WGC-импортёры (ETF Flows и резервы ЦБ)».
Ветка: `feat/wgc-importers`. Следующий пункт роадмапа (не в этом PR): национальные ЦБ напрямую (NBP/CNB/CBRT/ЦБ РФ/НБК/ЦБУ).

Приёмка пункта: `make import STAT=wgc_etf_flows` наполняет 20 рядов историей с 2003-02; `v_gold_etf_flows` за сент-2026 показывает 9 952,2 млн $ / 4 255,67 т / 574,23 млрд $; `v_cb_gold_dynamics` отдаёт POL/CZE/TUR/RUS/KAZ/UZB/CHN с MoM/YTD и сверкой с блогом WGC 10.2026; `make all` зелёный; `make mcp-check` — ПРОВЕРКА ПРОЙДЕНА.

## 1. Пробел

1. **ETF-потоки WGC** (фаза 3, 11.10.2026) заведены 20 структурными рядами `etf_<метрика>_<регион>` с `source='webbridge'`, но живут полуавтоматом: после месячного отчёта сессия вручную переписывает ~20 чисел в `POST /v1/manual_series`. Источник (Excel-выгрузка goldhub) уже доступен как файл — ручной перенос не нужен.
2. **Золотые резервы ЦБ вне IMF**: `v_imf_macro` заполнен только Китаем; по POL/CZE/TUR/RUS/KAZ/UZB IRFCL через datasource даёт нули/пропуски (фаза 1). Тезисы 3–4 («Польша +98 т YTD») не закрываются. WGC публикует по этим странам месячные изменения в тоннах с 01.2002 (IMF IFS + правки WGC).

## 2. Источник и механизм получения файлов

- Страницы: `gold.org/goldhub/data/gold-etfs-holdings-and-flows` (ETF) и `gold.org/goldhub/data/gold-reserves-by-country` (ЦБ). HTML страниц содержит прямые ссылки `/download/file/<id>/<имя>`.
- **Скачивание — только браузером** (у пользователя google-вход): проверено 2026-10-11 — curl/urllib получают сброс/`403` даже с cookie `__cf_bm`. Поэтому импортёры читают **локальную папку** (прецедент — `polyus/data/`, `polyus/datapack.go`).
- Папка `wgc/data/` (относительно CWD; в `.gitignore`). Runbook: скачать файл в браузере → положить в `wgc/data/` → дождаться weekly-джобы или `make import STAT=…`.
- Частота: Excel-выгрузки — **только месячные** (ETF: «Downloadable data in excel is available on a monthly basis»; данные ЦБ: месячный релиз с лагом ~2 мес — файл «Updated October 2026» несёт данные до 31.08.2026). Недельные апдейты существуют только на сайте; PDF-комментарии (например, `CB_Blog_Post_Oct26.pdf`) — не ETL (сессионное чтение через WebBridge, как раньше). Вне объёма.
- Фикстуры тестов — реальные файлы в `wgc/testdata/` (ETF 1,5 МБ; Changes 466 КБ; Holdings 42 КБ; всего ~2 МБ, коммитятся).

## 3. Форматы файлов (layout снят с винтажа 2026-10, проверен вручную)

### 3.1 `ETF_Flows_*.xlsx`

| Лист | Раскладка | Использование |
|---|---|---|
| `Fund flows by month` | кол. A — дата (Excel-serial, конец месяца); B..E — справочные итоги (цена, унции, тонны, стоимость USD); фонды — колонки F.. (239 шт.); стр. 2 — Active/Inactive, стр. 4 — регион фонда, стр. 6 — имя фонда; данные 2003-02-28…2026-09-30 (284 мес.) | источник `etf_flow_usd_mln_<регион>`: месячная сумма фондов по региону (млн USD) |
| `Demand by month` | та же раскладка, тонны | источник `etf_flow_tonnes_<регион>` (тоннажный поток = WGC «Demand») |
| `Holdings by month` | та же раскладка, тонны (сток) | источник `etf_holdings_tonnes_<регион>` |
| `Charts Data` | 8 блоков; для импорта — «Area chart - monthly holdings in US$»: Date + 4 региона, 284 мес., значения в абсолютных USD | источник `etf_aum_usd_bn_<регион>` (значение / 1e9); блоки A/J (месячные потоки, только 16 мес.) и AI (запасы т) — сверочные для тестов |

Правила разбора:

- Регионы — строго `North America | Europe | Asia | Other` (строка 4) → `north_america | europe | asia | other`; непустое значение вне словаря — **ошибка** (не молчаливая потеря). Колонки фондов определяются динамически: F.. до конца строки 4.
- `world` — сумма четырёх регионов; пишется только если значения есть у **всех четырёх** (иначе занижение).
- Пустая ячейка фонда → вклад не учитывается; если у всех фондов региона пусто, точка региона **не пишется** (отсутствие данных ≠ 0).
- Даты: serial → `excelize.ExcelDateToTime`; значения читать raw (без number format), float с проверкой `err`.
- Сверки (закрепляются тестами на фикстуре): сент-2026 world = **9 952,215641** млн $ (flow), **4 255,669814** т (holdings), **574,233914** млрд $ (AUM); регионы сентября совпадают с «Key Tables by fund»; суммы фондов за 16 перекрывающихся месяцев совпадают с блоками A/J/AI «Charts Data»; `D` (тонны) листов = сумма фондов (warn при расхождении в рантайме, не ошибка).

### 3.2 `Changes_latest_as_of_*.xlsx` (листы `Main`, `Disclaimer`, `Monthly`, `Annual`)

- `Monthly`: стр. 1–7 служебные; **строка 8 — дата-заголовок (serial) на каждую колонку**; данные со строки 9: A — полное имя, B — короткое имя, C — комментарий (не импортируем), колонки **D..KM = 296 месяцев, 2002-01…2026-08**. Значения — месячные **изменения в тоннах** со знаком. Пусто = нет данных (пропуск), `0` = ноль изменения — пишется как есть.
- Словарь стран (по колонке B, короткое имя, ровно одна строка на страну): `Poland, Rep. of`→POL, `Czech Rep.`→CZE, `Turkey`→TUR (**строго равенство** — `Turkey*` (gross, включая банки) пропускается), `Russian Federation`→RUS, `Kazakhstan, Rep. of`→KAZ, `Uzbekistan, Rep. of`→UZB, `China, P.R.: Mainland`→CHN. Страна не найдена/дубль — ошибка.
- Дата точки: конец отчётного месяца заголовка (конвенция проекта). Ряд: `cb_gold_change_tonnes_<iso3>`.
- `Annual` — сверка в тестах (сходимость с суммой месяцев проверяется при реализации; источником истины остаётся `Monthly`).
- Известные особенности (оговорки в каталоге, не «дорисовываем»): RUS — в 2026 только 5 непустых месяцев, сумма файла −34,21 т (блог WGC говорит −56 т — расхождение фиксируется тестом/каталогом); UZB — данные с 01.2018; Turkey — две строки (берём net `Turkey`, сверка YTD-2026: POL +97,772, CHN +80,246, CZE +14,153, KAZ +36,063, UZB +48,210, TUR −81,607 — совпадает с блогом WGC 10.2026).

### 3.3 `World_official_gold_holdings_as_of_*.xlsx` (один лист `PDF`)

- Таблица топ-100 из блоков по 5 колонок (rank, страна, тонны, `% of reserves`, `Holdings as of`); блоки находятся по заголовку `Tonnes` в строке заголовков. Сноски в именах (`Turkey5)`, `Belarus, Rep. of4)`) — чистятся регэкспом перед словарём.
- Ряд: `cb_gold_holdings_tonnes_<iso3>` — уровень на per-country дату `Holdings as of` (serial; нормализуется к концу месяца; у части стран дата старше — храним как есть). `% of reserves` не импортируем.
- На 2026-10: POL 647,984 / CHN 2 386,551 / RUS 2 270,536 / TUR 532,093 / UZB 438,556 / KAZ 377,107 / CZE 85,760 т, все as of 31.08.2026. Отсутствие страны в топ-100 — `log.Warn`, не ошибка.

## 4. Дизайн кода (пакет `wgc/`)

Прецедент — `eia/`: пакет-импортёр пишет в `macro_series` своим `Name()`; слепой импорт в `main.go`.

- `wgc/files.go` — `dataDir = "wgc/data"`; `findLatestFile(mask)` — `filepath.Glob`, выбор самого свежего по **mtime** (имена содержат месяцы, лексикографика неверна: `Oct2026` > `Nov2026` как строки), тай-брейк по имени. Нет файла — вызывающий решает (warn + 0 rows).
- `wgc/parse.go` — общие `seriesPoint{Series string, Date time.Time, Value float64}`, `monthEnd(t)`, `cellFloat`/`cellDate` (raw-чтение, проверка err).
- `wgc/etf.go` — импортёр `wgc_etf_flows`: разбор §3.1 → 20 рядов (`source='wgc'`) → один батч `PrepareBatch → Append (err checked) → Send` → `util.UpsertSeriesCatalog` (20 записей) после успешного Send.
- `wgc/cb.go` — импортёр `wgc_cb_reserves`: разбор §3.2+§3.3 → ряды дельт и уровней (7 стран × 2 ряда) тем же батчем; нет changes-файла → нет дельт (warn), нет holdings → нет уровней (warn); нет ни одного — 0 rows; каталог — 14 записей с оговорками (RUS-пропуски, Turkey net, UZB с 2018).
- `wgc/series_meta.go` — 20 + 14 описаний (title/unit=`тонны` или `млн USD`/`млрд USD`/`frequency='M'`/origin — имя листа + файла/description).
- Ошибки: битый/нечитаемый файл, неизвестный регион, пропавшая страна из словаря — ошибка импорта (fail-fast, урок `eia`). Отсутствие файлов — warn + 0 rows (урок `dcf_engine`, чтобы dagu не краснел до первого скачивания).
- Логи: `Imported N rows of macro_series (wgc, ETF flows: X точек / 20 рядов)` и аналогично для CB (с разбивкой changes/holdings).
- Тесты офлайн (без БД/сети) на фикстурах `wgc/testdata/`: сверки §3; сериализация даты (serial 46295 → 2026-09-30); пустая папка → 0 rows; неизвестный регион → ошибка; словарь стран — обе сверки (YTD/уровни).

## 5. Витрины и правило 11

- `v_gold_etf_flows` (`views/gold_etf_flows.go`) — приоритет источников становится **`wgc > webbridge > manual`** (`coalesce(maxIfOrNull(value, source='wgc'), …webbridge…, …manual…)`; `maxIf` по-прежнему запрещён), `source IN ('wgc','webbridge','manual')`; комментарий витрины дополняется описанием импортёра. Сид `sql/wgc_etf_flows_catalog.sql` **не трогаем** — он описывает webbridge-фолбэк.
- Новая `v_cb_gold_dynamics` (плановая из роадмапа §3) в `views/` (импортёр `gold_views`): строка на страну — `iso3`, `country`, `last_change_date`, `mom_change_tonnes` (последняя дельта), `ytd_change_tonnes` (сумма дельт с 01.01 года последней точки), `holdings_tonnes`, `holdings_date` (последний уровень и его дата). Эскиз: агрегаты по `macro_series FINAL WHERE source='wgc' AND series LIKE 'cb_gold_change_tonnes_%' / 'cb_gold_holdings_tonnes_%'`, `iso3 = substring(series, длина_префикса+1)`, ограничение списка — 14 имён рядов из Go (как `wgcEtfSeriesNamesSQL`); словарь `iso3→country` — массив в Go. Числа сверки: YTD POL 97,772 / CHN 80,246 / TUR −81,607 (на 31.08.2026); уровни — из holdings-файла (§3.3).
- Комментарии таблицы и каждой колонки (`ALTER TABLE … MODIFY COMMENT` / `COMMENT COLUMN`), `GRANT SELECT` для `kimi_reader` в `sql/mcp_kimi_reader.sql`.
- `scripts/mcp_check.py`: + витрина `v_cb_gold_dynamics` читается; + каталог `source='wgc'` полон (34 записи); существующие проверки `v_gold_etf_flows`/`webbridge` остаются.

## 6. Расписание и документация

- `dagu/wgc.yaml`: `type: chain`, два шага (`wgc_etf_flows`, `wgc_cb_reserves`), еженедельно (понедельник 20:17 МСК, не пересекается с `forecast.yaml` 20:23), `overlap_policy: skip`, retry 3 × 300 с; без файлов — no-op.
- ARCHITECTURE.md: §2 — пакет `wgc/`; §6.1 — импортёры `wgc_etf_flows`/`wgc_cb_reserves`; §6.2 — комментарий `source` дополняется активным `wgc`; §6.3 — приоритет `v_gold_etf_flows`, новая `v_cb_gold_dynamics`; README — импортёры, расписание, ручной шаг скачивания файлов.
- `docs/GOLD_THESIS_DATA_ROADMAP.md`: статус нового пункта (+ отметка приёмки после прогонов) и следующий пункт «национальные ЦБ напрямую» (⏳).

## 7. Не делаем (границы)

- Национальные ЦБ напрямую — следующий пункт роадмапа.
- Недельная гранулярность и PDF-комментарии — не ETL.
- Fund-level таблица/дашборд (идея python-наброска), `CBGA_sales`, `Quarterly_gold_and_FX_Reserves`, `% of reserves` — не импортируем.
- `etf_flows_month`, `v_gold_dashboard`, `v_imf_macro` не трогаем; схема `macro_series` не меняется; Python+pandas в ETL не вводим (обоснование — план 2026-10-11, §6: единый CI/dagu/деплой и правило 11; Python остаётся для ML-трека и ручных скриптов).

## 8. Риски

- Пропуски/расхождения CB-данных (RUS −34,2 т против блоговых −56; Turkey gross/net; UZB с 2018) — пишем как в файле, оговорки в каталоге, блог — только сверка в тестах.
- Дрейф формы файлов (фонды/страны/имена листов меняются) — динамический разбор словарями, фикстуры фиксируют винтаж 2026-10; неизвестный регион/страна из списка-цели → ошибка.
- staging: файлы кладутся на хост вручную (как сиды) — отметить в «Осталось» роадмапа.
