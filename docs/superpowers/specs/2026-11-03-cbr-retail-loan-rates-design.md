**Дата:** 3 ноября 2026 г.
**Пункт роадмапа:** [ROADMAP_KEY_RATE.md](ROADMAP_KEY_RATE.md) §4.2 №8, фаза 2 («ставки по

**План:** [2026-11-03-cbr-retail-loan-rates.md](../superpowers/plans/2026-11-03-cbr-retail-loan-rates.md).

## 1. Зачем

Канал «жёсткость ДКУ»/трансмиссия контура прогноза ключевой ставки закрыт со стороны
юрлиц (`cbr_int_rate_loans`, 2026-10-15) и пассивов (`cbr_bank_int_rate`), но не розничных
кредитов. Пробел №8 роадмапа фиксирует остаток: «ставки по кредитам физлицам (в т.ч.
ипотека по ПСК) — иные источники и остаются открытыми». Пункт закрывает остаток тремя
импортёрами: средневзвешенные ставки по кредитам физлицам по срокам (источник A),
средневзвешенная ставка по ипотечным жилищным кредитам РФ (источник B) и квартальный
корпус среднерыночных значений ПСК по категориям для кредитных организаций (источник C).

**Решение владельца (2026-11-03):** весь остаток, включая корпус ПСК, — в рамках #119;
реализация диспатчем coder-субагентов `deepseek/deepseek-flash`.

### Разметка листа `ставки_руб`

- Строки 1–3: заголовок «Средневзвешенные процентные ставки…», «(в целом по Российской
  Федерации)», «% годовых».
- Строка 4: два group header'а: колонки B–I — «Всего», колонки J–Q — «в том числе
  автокредиты».
- Строка 5: 16 названий колонок — 8 сроков × 2 группы; наборы сроков идентичны.
  Особенности группы «Всего»: колонка B — «до 30 дней, включая ''до востребова-ния**''»
  (перенос + двойная сноска `**`), колонка C — «от 31 до 90 дней**`. Группа «автокредиты»
  — без `**`.
- Строки 6+: данные «Январь 2014» … «Декабрь 2025».
- После данных: сноска, начинающаяся с «*».
- Пропуски: пустая ячейка, литеральный `-` (например, у `Автокредиты: до 30 дней, включая
  «до востребования»` 33 точки из 144, то есть 111 пропусков; у автокредитов `от 31 до 90
  дней` — 86 точек, `от 91 до 180 дней` — 105; ряды «Всего» заполнены полностью) и
  литеральный ноль — по §6.7 все три означают «данных не имеется», точкой ряда не становятся.

### 2.3 Источник C — среднерыночные значения ПСК (квартальный корпус)

| Свойство | Значение |
|---|---|
| Лента | страница `https://www.cbr.ru/statistics/bank_sector/psk/` (обновление 14.08.2026): блоки по пяти типам кредиторов (`ko` — кредитные организации, `mfo`, `kpk`, `skpk`, `lomb`); актуальный выпуск + версионный список (`data-versions-item`) + легаси-листинг PDF |
| Файлы `ko` | `/Collection/Collection/File/<id>/<DDMMYYYY>_ko.<ext>`; на снимке **48 выпусков без разрывов**: 23 PDF (публикации 14.11.2014 … 15.05.2020), 13 XLS (14.08.2020 … 16.11.2023), 12 XLSX (16.11.2023 … 14.08.2026) |
| Содержание | Среднерыночные значения полной стоимости потребительских кредитов (займов) и предельные значения (среднерыночное × 4/3, кап по ч. 11 ст. 6 353-ФЗ), % годовых, по категориям кредитов |
| Периодичность | квартальная; дата точки — **конец периода расчёта** («за период с 1 июля по 30 сентября 2018 г.» → 2018-09-30); дата применения (следующий квартал) — в каталоге, не в ключе |

**Три эры формата (разбор — §3.4):**

1. **PDF-эра** (2014–2020-05): `pdftotext -layout` (прецедент `cbr_mt_forecast`,
   зависимость в CI уже есть). Заголовок: «за период с 1 июля по 30 сентября 2018 г.»
   (без ««»», родительный падеж). Таблица: `код  категория  среднерыночное  предельное`,
   десятичная запятая. Таксономия: 2014–2018 (Указание 3249-У) — категории 1–4
   (авто / лимит кредитования / POS / нецелевые), **ипотечных категорий нет**; с 2019
   (Указание 5112-У) — добавлена категория 5 (регулярные выплаты на счёт).
2. **XLS-эра** (2020-08 … 2023-11): BIFF, лист `AVG`, те же колонки, точка-десятичный
   разделитель; таксономия 1–5; парсер — `github.com/shakinm/xlsReader` (уже в `go.mod`,
   прецедент `fedstat/excel.go`: `xls.OpenReader` → `GetSheets()` → `GetRows()`).
3. **XLSX-эра** (2023-11 … ): лист `AVG`, excelize, точка-десятичный разделитель;
   **новая таксономия** (Указание 881-П, категории 1–8): 1 авто, 2 электронные средства
   платежа, 3 POS-перечисление, 4 иные без залога, 5 регулярные выплаты,
   **6 залог жилого помещения в МКД (6.1.1/6.1.2 — приобретение, «ипотека по ПСК»)**,
   7 залог жилого дома/участка, 8 иные с залогом. ~20 листьев с числами.

**Семантика рядов:** код категории НЕ стабилен между эрами (2018: 2 = лимит
кредитования; 2026: 2 = электронные средства платежа). Идентичность ряда — по
(код + наименование категории как опубликовано); расхождение наименований у одного кода
между винтажами — норма исторического ряда, а не ошибка разбора.

## 3. Решения по дизайну

### 3.1 Таблицы и имена импортёров (стандарт §7)

| Импортёр | Таблица | Имя рядов |
|---|---|---|
| `cbr_int_rate_loans_ind` | `cbr_int_rate_loans_ind` | 16: `Всего (кредиты физлицам): <срок>`, `Автокредиты: <срок>` |
| `cbr_mortgage_rate` | `cbr_mortgage_rate` | 1: `Средневзвешенная ставка по жилищным кредитам, РФ` |
| `cbr_psk` | `cbr_psk` | по категориям (§3.5) |

`Name() == TableName` для всех трёх. Восемь сроков (нормализованные подписи, идентичны
у `cbr_int_rate_loans`): `до 30 дней, включая «до востребования»`; `от 31 до 90 дней`;
`от 91 до 180 дней`; `от 181 дня до 1 года`; `до 1 года, включая «до востребования»`;
`от 1 года до 3 лет`; `свыше 3 лет`; `свыше 1 года`. Префиксы групп:
`Всего (кредиты физлицам): ` и `Автокредиты: ` (в данных и каталоге — «Автокредиты», а не
дословная «в том числе…»). Совокупность в префиксе первой группы обязательна:
`series_catalog` ключуется по `(source='cbr', series)`, и имена `Всего: <срок>` уже заняты
рядами `cbr_int_rate_loans` (кредиты юрлицам) — точное совпадение вытеснило бы описания
одного импортёра другим, а в `v_cbr_macro` две разные совокупности стали бы неразличимы
под одним `series`.

### 3.2 DDL

```sql
CREATE TABLE IF NOT EXISTS cbr_int_rate_loans_ind (
      name LowCardinality(String)
    , date Date
    , rate Float64
) ENGINE = ReplacingMergeTree ORDER BY (name, date);

CREATE TABLE IF NOT EXISTS cbr_mortgage_rate (
      name LowCardinality(String)
    , date Date
    , rate Float64
) ENGINE = ReplacingMergeTree ORDER BY (name, date);

CREATE TABLE IF NOT EXISTS cbr_psk (
      date Date
    , category_code String
    , category LowCardinality(String)
    , psk_avg Float64
    , psk_max Nullable(Float64)
    , source_file LowCardinality(String)
) ENGINE = ReplacingMergeTree ORDER BY (category_code, date);
```

A и B — та же форма, что `cbr_int_rate_loans` (сравнимость рядов во времённой оси).
C — широкая форма: обе величины одной строкой (среднерыночное и предельное — одна
публикация, читаются вместе); `source_file` — имя выпуска (винтажный след, по образцу
`cbr_form101`/`cbr_dip_bulletin`); ключ `(category_code, date)` — пересмотры категорий
заменяются, как у всех ReplacingMergeTree. `psk_max` — `Nullable(Float64)`: в ранних
выпусках (PDF-эра 2014) предельное значение ещё не публиковалось, и `NULL` значит «в
выпуске его не было», а не ноль (живой выпуск 14112014_ko.pdf печатает только
среднерыночное). Уже созданная таблица с `psk_max Float64` мигрируется идемпотентным
`ALTER TABLE cbr_psk MODIFY COLUMN psk_max Nullable(Float64)` в начале прогона
(`CreateTable` импортёра): 746 строк первого живого прогона сохраняются, гейт по
`source_publications` не сбрасывается.

### 3.3 Парсеры A и B (стандарт §6, по образцу §3.4 спеки `cbr_int_rate_loans`)

- Значения сырые (`RawCellValue`); якоря, а не индексы; база колонок — позиция подписи
  первой группы; нормализация переносов «до востребова-ния» и снятие `**`; сверка
  заголовков с ожидаемым набором — fail-fast (стандарт §6.4); `util.MonthsToNum` для
  меток периодов; строка с «*» — конец данных; пусто/`-`/ноль → пропуск точки (§6.7);
  дата — предпоследний день месяца: `time.Date(year, month+1, -1, …)` — единая конвенция
  контура (как у вкладов `cbr_bank_int_rate` и кредитов юрлицам `cbr_int_rate_loans`),
  поэтому сопоставление по `toStartOfMonth(date)`.
- B — широкий формат: месяцы из строки 3 по колонкам, строка региона ищется по колонке A
  по точному значению `РОССИЙСКАЯ ФЕДЕРАЦИЯ` (не индекс 4); строка не найдена — fail-fast.
- Fail-fast с именем таблицы в ошибке; индексация слайсов с проверкой (§6.5); без `panic`.

### 3.4 Парсер C — три эры одного корпуса

- Лента выпусков: парсинг страницы `/statistics/bank_sector/psk/` (HTML-ссылки
  `href="/Collection/Collection/File/<id>/<date>_ko.<ext>"`), тип `ko` только. Гейт
  идемпотентности — по `source_publications` с `PublicationSource = "cbr_psk"` и ключом
  версии = имя файла `<DDMMYYYY>_ko.<ext>` (дата+ext; `<id>` остаётся в URL): известное
  имя → пропуск без скачивания; новое → скачивание, разбор, запись, строка версии.
  Страница качается каждый прогон (дешёвый GET листинга — прецедент `minec_urals_price`).
- Разбор по расширению: `.xlsx` → excelize; `.xls` → `xls.OpenReader`; `.pdf` →
  `BodyFunc` + `pdftotext -layout`. Точка входа разбора — нормализованная таблица
  «код | категория | avg | max | период(конец квартала) | имя файла»; три адаптера
  приводят эры к ней.
- PDF-эра 2014: таблица печатает **одно** значение (среднерыночное), предельного ещё
  нет. Одно значение → `psk_avg = <значение>`, `psk_max = NULL`; `NULL` означает «в
  выпуске не публиковалось», а не ноль. Две величины — `avg` и `max` одной строкой.
- Повреждённый текстовый слой PDF (живой 13022015_ko.pdf: потерянные буквы/цифры,
  управляющие байты на месте значений, месяцы в чужой кодировке; ни `-raw`, ни
  `-enc UTF-8/Latin1`, ни `-nopgbrk` не восстанавливают): разбор возвращает
  типизированный признак `errCbrPskUnreadablePDF` (управляющие байты или межбуквенные
  `**`-разделители, либо ноль точек после разбора). `Import` пропускает такой выпуск с
  предупреждением и сохраняет строку версии с `Points: 0`, чтобы гейт не скачивал файл
  каждый прогон; прогон при этом успешен. Плата названа: исправленный файл под тем же
  именем гейтом не отслеживается (лечение — удалить строку версии и повторить прогон).
- XLS-эра: лист данных выбирается **по содержимому**, а не по имени: перебираются листы
  книги и берётся первый, где есть строка периода «за период с … по …» И хотя бы одна
  точка с числом. Служебные листы без периода или без чисел пропускаются (живые выпуски
  2022: `AVG` — шаблон с названиями категорий, числа в «Лист2»; выпуски 2023: лист
  «Лист1»). Ни одного листа-кандидата — ошибка. `X`/`х`/`X X` (в том числе в двух
  колонках), пусто и `-` в числовых колонках — «данных нет», не ошибка; произвольный
  нечисловой текст — ошибка. NUL-байты и управляющие символы (`< 0x20`) в ячейках XLS
  снимаются: живой 16112022_ko.xls хранит коды категорий с хвостом `\x00`.
- Период из заголовка выпуска: PDF-эра — «за период с 1 июля по 30 сентября 2018 г.»
  (парсинг русских родительных месяцев); XLS/XLSX-эра — строка 2 листа. Дата точки —
  последний день периода; fallback по дате публикации из имени файла запрещён (сдвиг
  на квартал) — непарсящийся заголовок это fail-fast.
- Секции таксономии (строки с кодом без чисел) в точки не идут; лист без `avg` в точке
  пропускается с предупреждением в лог; `max` без `avg` — ошибка (сдвиг колонок).
- Ноль строк по новому выпуску — ошибка (§6.4), кроме нечитаемого PDF: там версия
  сохраняется с 0 точек и прогон продолжается. Ноль новых выпусков в прогоне — no-op
  «новых выпусков нет (в ленте N, в таблице M)».

### 3.5 Точки контроля публикации и производные (стандарт §9/§10)

- A и B: `PublicationCountPoints` — `SELECT count() FROM <table> FINAL` (файлы
  помесячные, шаг ежедневный; §9.1/§9.2); артефакт — шаблонным путём, архив общим
  механизмом.
- C: гейт по ленте (свой `Import()` поверх частей шаблона — по образцу `cbr_mt_forecast`,
  у которого гейт по своей таблице; `PublicationCountPoints` не объявляется, префлайт
  шаблона не подменяет ленту).
- Каталог:
  - A: 16 записей (`cbrIntRateLoansIndSeriesMeta`), unit «% годовых», F=M, origin —
    файл/лист/группа/срок; description — что измеряет (средневзвешенная ставка по новым
    кредитам физлицам в рублях за месяц, взвешена объёмом размещений; «Всего (кредиты
    физлицам)» — все кредиты физлицам, «Автокредиты» — подгруппа), привязка даты (предпоследний день месяца:
    `time.Date(year, month+1, -1, …)` — единая конвенция контура, сопоставлять по
    `toStartOfMonth(date)`) и **зафиксированное отставание публикации**:
    на снимке 2026-11-03 ряды кончаются 2025-12 (юрлицовый файл того же листинга
    обновлён до 2026-08) — ряд актуален с лагом источника;
  - B: 1 запись, unit «% годовых», F=M, origin — файл/лист/РФ; description — ставка по
    новым ипотечным жилищным кредитам физлицам-резидентам в рублях (средневзвешенная по
    объёму выдач), привязка даты — предпоследний день месяца (единая конвенция контура);
  - C: одна запись на каждую категорию каждой эры-доступности: XLSX-эра — 20 категорий
    (1.1, 1.2, 2.1.1, 2.1.2, 2.2.1, 2.2.2, 3, 4.1, 4.2, 5.1, 5.2, 6.1.1, 6.1.2, 6.2,
    7.1.1, 7.1.2, 7.2, 8.1, 8.2, 8.3); XLS/PDF-эры — категории эпохи (авто 1.1/1.2,
    лимит/ЭСП 2.x, POS 3.x, нецелевые 4.x, регулярные выплаты 5; в XLS-выпусках 2023 года
    ипотека уже присутствует укрупнёнными кодами 6–8). Имя ряда:
    `ПСК <код>: <краткое наименование>`, unit «% годовых», F=Q; description — что это
    среднерыночное значение-кап (не фактическая ставка; применяется в следующем
    квартале), код категории менял смысл между эрами — читать по наименованию;
    «ипотека по ПСК» — коды 6.1.1/6.1.2 с 2023-11. Каталог динамический: коды и
    наименования читаются из таблицы (`argMax(category, date)`), а не объявляются
    статическим списком.
- Витрины:
  - A и B — общая `v_cbr_macro` (кредитные ставки того же контура и единиц): `Tables` +
    `UNION ALL SELECT 'cbr', toString(name), date, toFloat64(rate) FROM … FINAL`;
    комментарии дополняются («ставки по кредитам физлицам и ипотека»). Отдельный
    `GRANT` не нужен; сырые таблицы закрыты (§10.4).
  - C — своя витрина `v_cbr_psk` (квартальные «кап»-ряды иной семантики, в общей
    макровитрине не место): `SELECT date, category_code, category, psk_avg, psk_max,
    source_file FROM cbr_psk FINAL ORDER BY (category_code, date)` с комментариями
    таблицы и колонок; `psk_max` — Nullable, комментарий колонки фиксирует «NULL =
    предельное значение в выпуске не публиковалось»; публикуется в `AfterImport`
    вместе с каталогом; `GRANT SELECT` в `sql/mcp_kimi_reader.sql`; проверка
    `make mcp-check`.
- Публикуют `AfterImport: afterCbrMacro(...)` (A, B) и `AfterImport` с каталогом + витриной
  C (стандарт §10.2).
