# Календарь раскрытия топ-5 банков и форвардная витрина кредитного портфеля

**Дата:** 17 октября 2026 г.
**Пункт роадмапа:** [ROADMAP_KEY_RATE.md](../../ROADMAP_KEY_RATE.md) §4.2 №20, шаг фазы 2.
**Issue:** [#86](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/86).

## 1. Зачем

Кредитный канал M2 в контуре прогноза ключевой ставки читается по агрегату ЦБ «Кредит экономике» (`cbr_credit_m2x`), который публикуется с лагом около месяца: на 2026-10-17 в dev-БД есть данные до 2026-09-01. Помесячный кредитный портфель крупнейших банков с быстрой скоростью раскрытия даёт **опережающий срез**: состав портфеля (корпоративный/розничный), темп месяца и раннюю ревизию тренда до публикации агрегата ЦБ. Даты раскрытия — триггеры для модели и MCP-агента: когда появляется новая точка и когда пересчитывать тренд кредитного канала.

## 2. Решения

1. **Набор банков** — топ-5 по объёму кредитного портфеля **среди тех, у кого высокая скорость публичного раскрытия** (помесячные данные). Кандидаты: Сбер, ВТБ, Т-Банк, Совкомбанк, МКБ. Фактический состав подтверждается разведкой; если быстрых банков меньше пяти, фиксируется фактическое число — список формально не «добивается».
2. **Календарь** — новая категория `bank_results` в существующей `events_calendar`; схема не меняется, структурированные поля — в `threshold` JSON.
3. **Витрина** — `v_bank_loan_portfolio_forward` в пакете `views/`: помесячный портфель банков, MoM/YoY, сравнение с «Кредитом экономике» ЦБ, дата публикации из календаря.
4. **Первый срез** — на уже собранных `SBER` (РСБУ, до 2026-06) и `VTBR` (МСФО, до 2026-08); новые тикеры попадут в витрину автоматически, когда появятся их импортёры.

## 3. Календарь `bank_results`

### 3.1 Формат строки

- `category = 'bank_results'`;
- `title = '<Банк>: результаты за <месяц> <год> — кредитный портфель (<подтверждённая|ожидаемая> дата)'`;
- `event_time = NULL`;
- `threshold`:
  - подтверждённая дата: `{"bank":"VTBR","report_month":"2026-09","metric":"customer_loans","date_status":"confirmed","source":"https://www.vtb.ru/ir/calendar/"}`;
  - ожидаемая дата: `{"bank":"SBER","report_month":"2026-09","metric":"customer_loans","date_status":"expected","rule":"…","basis":"2026-07-07, 2026-08-07, 2026-09-07"}`;
- `status` — `pending` для будущих, `done` для состоявшихся подтверждённых публикаций.

`event_date` — **дата публикации**, `report_month` — отчётный месяц. Это разные поля, и подменять одно другим нельзя.

### 3.2 Правила дат

1. Сначала ищется опубликованная будущая дата в IR-календаре банка. Если есть — `date_status=confirmed`, `source` — URL.
2. Если будущей даты нет — собираются не менее шести последних фактических дат публикаций; берётся медиана дня публикации, в `basis` перечисляются использованные даты, в `rule` — правило. `date_status=expected`.
3. Если нет ни будущей даты, ни ряда фактических дат — строка не создаётся; банк остаётся кандидатом в issue.
4. Даты не «округляются» до красивых; выходные/праздники — ближайший рабочий день по фактическому календарю публикаций банка.

### 3.3 Идемпотентность

Сид `sql/events_calendar_bank_results_q4_2026.sql` — обычный `INSERT` в `ReplacingMergeTree(event_date, category, title)`. Повторный прогон с теми же значениями — no-op. Если ожидаемая дата уточнилась, добавляется строка с новым `title`; старая остаётся историей. Витрина выбирает строку по `argMax(event_date, (status IN ('done','verified'), event_date))`, то есть подтверждённую/позднюю.

## 4. Витрина `v_bank_loan_portfolio_forward`

**Где:** `views/company.go`, в `companyViewsDDLViews()` после `v_company_financials`. Это секторная витрина, а не персональная `v_<эмитент>_*`.

**Источники (`Tables`):** `company_financials`, `events_calendar`, `cbr_credit_m2x`. `util.CreateView` пропускает витрину, пока нет любой из таблиц.

**Гранулярность:** одна строка на `(bank, report_month, metric)` для `metric IN ('customer_loans','loans_corporations','loans_individuals')`, `period_type='M'`.

**Колонки:** `bank`, `report_month`, `metric`, `source_kind`, `value_bln_rub`, `mom_pct`, `yoy_pct`, `publish_date`, `date_status`, `event_status`, `cbr_credit_total_bln_rub`, `cbr_mom_pct`, `cbr_yoy_pct`, `bank_share_of_cbr_pct`.

**Расчёт:**
- `report_month = toDate(concat(substring(period,1,4), '-', substring(period,6,2), '-01'))`;
- MoM/YoY — `lagInFrame(value, 1|12) OVER (PARTITION BY bank, metric ORDER BY report_month)`;
- календарь — `JSONExtractString(threshold, 'bank'|'report_month'|'date_status')`, `argMax` как в §3.3;
- ЦБ — `cbr_credit_m2x FINAL WHERE series = 'Кредит экономике'`, те же окна.

**Ловушка LEFT JOIN:** ClickHouse не отдаёт `NULL` для не-Nullable `Date`/`String` при отсутствии совпадения. В финальном `SELECT` — `if(...='', NULL, ...)` / `if(...='', 'missing', ...)`; для ЦБ — `toNullable` или проверка на `toDate(0)`.

## 6. Критерии приёмки

1. `make all` зелёный.
2. `make ch-sql FILE=sql/events_calendar_bank_results_q4_2026.sql` — сид применяется, повтор идемпотентен.
3. `make import STAT=events_calendar` не затрагивает строки сида; `bank_results` на месте.
4. `make import STAT=company_views` создаёт витрину; запрос к ней отдаёт SBER/VTBR `customer_loans` с MoM/YoY и сравнением с ЦБ.
5. `make mcp-user`, `make mcp-check` — новая проверка OK.
6. `ARCHITECTURE.md`/`README.md`/`KEY_RATE_CHANNELS.md` синхронизированы; статус пункта в роадмапе — ✅ с числами приёмки.
7. В PR — протокол приёмки и список банков, оставшихся кандидатами.

## 8. Риски

| Риск | Митигация |
|---|---|
| Источник дат не подтверждён у 3–4 банков | В календарь идут только подтверждённые/обоснованные строки; остальные — кандидаты в issue |
| JS/антибот у Сбера, Т-Банка, Совкомбанка | Сид ручной; автопарсер — только ВТБ; ограничение в README |
| `publish_date` пуст для исторических месяцев | Явно в комментарии витрины; заполнение истории — отдельный пункт |
| Смешение баз РСБУ/МСФО | Колонка `source_kind` + оговорка; темпы считать внутри ряда |
| Ожидаемая дата воспринимается как факт | `date_status=expected` + `rule`/`basis`; title содержит «ожидаемая дата» |
