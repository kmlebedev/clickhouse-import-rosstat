## 2. Цели и гипотезы

**Таргеты (три, фиксированы):**

| Код | Таргет | Источник | Единица |
|---|---|---|---|
| `T_NSA` | официальный ИПЦ, накопленный m/m за `O+1…O+h`, NSA | `rosstat_ipc_mes` | п.п. |
| `T_SA` | SA ИПЦ без КУ (`TARGET_FULL`-прокси: [cb_comp_proxy](../../research/2026-10-18-cb-comp-proxy.md)), накопленный | `cbr_indicators_cpd` «Все товары и услуги» + допущения cb_comp_proxy | п.п. |
| `T_CORE` | «Базовый ИПЦ» SA, накопленный m/m | `cbr_indicators_cpd` («Базовый ИПЦ», 2002-02+) | п.п. |

**Горизонты:** h ∈ {1, 3, 6}; конвенция origin — live3 (`O` — последний месяц с `cutoff_for(O) ≤ d`, цель — накопленная `O+1…O+h`). Дополнительно h0 — диагностика «nowcast месяца `O`», в gate не входит.

**Гипотезы:**

- **H1 (инфраструктура).** Единая сетка 3 таргета × 3 горизонта на фиксированных фолдах с MCS даёт воспроизводимое ранжирование; без неё выводы «iterate» из §«Состояние» не различимы по причине (мощность vs модель).
- **H2 (недельный агрегат 2009+).** Признаки из агрегата недельной оценки (накопленный индекс месяца `O` к cutoff, доля покрытия, последняя неделя, 4-нед. накопленный, тарифная неделя) **снижают RMSE** на h1 и h3 против v2-базы (и против v3 `weekly`-признаков) за счёт роста выборки с ~57 до ~200 месяцев и прямого сигнала о только что завершившемся месяце. Ожидание: эффект на h1 ≥ 10 % RMSE; на h6 — не ожидается (проверяется как отрицательный контроль).
- **H3 (core с обученными весами).** Core-прокси из недельных товарных групп с **неотрицательными весами, обученными as-of** (NNLS/ridge на таргет `T_CORE`), превосходит (а) официальный агрегат B0 и (б) M1 `core_raw` с фиксированными весами CB_COMP из [weekly-core-components](../../research/2026-10-22-weekly-core-components.md) (покрытие весов 14,5–18,2 %). Побочная проверка: прямая модель на `T_CORE` (ElasticNet/CatBoost на лагах, ожиданиях и агрегатных признаках H2).

H3 не повторяет #364: там веса фиксированные, окно 2021+, только 1-step; здесь — обученные веса, длинная история агрегата (H2) как контроль и горизонты 1/3/6.

## 3. Данные и as-of

- Календарь публикаций — `scripts/lib/publication_calendar.py` (месячный ИПЦ, недельный — среда, CBR SA — 15–22 `M+1`); при отсутствии строки — fallback-правила модуля, помечаются в паспорте. Прежний `cutoff_for` (8-е `M+1`) сохраняется как консервативный для сравнимости с v2/v3, а календарный as-of — как robustness (R3).
- Недельная точка доступна к `date + 2` (как в v3). Недели, пересекающие границу месяцев, распределяются **по дням**; индекс месяца `O` к cutoff — геометрическое произведение недельных индексов, приведённых к дням в месяце.
- Агрегатные признаки (имена фиксируются до результата):

| Признак | Определение |
|---|---|
| `wkagg_mtd` | накопленное изменение (п.п.) в месяце `O` по доступным к cutoff дням |
| `wkagg_cov` | доля дней месяца `O`, покрытых доступными неделями (0…1) |
| `wkagg_mtd_scaled` | `wkagg_mtd / wkagg_cov` при `cov ≥ 0,5`, иначе NaN |
| `wkagg_last` | последняя доступная недельная точка, п.п. |
| `wkagg_4w` | накопленное за последние 28 дней |
| `tariff_week` | календарный флаг недели индексации (график: июль 2022–2025, октябрь 2026; Jan-1 неделя) |

- Пропуски недель до 2016 (24–51 дата/год): признаки считаются по фактически покрытым дням, `wkagg_cov` честно отражает дыру; **интерполяции на 7-дневную сетку нет** (в отличие от [weekly-core-proxy §5.7](../../research/2026-10-22-weekly-core-proxy.md)).
- NaN ≠ 0; импутация — медиана train внутри фолда; `wkagg_*` на неделях без покрытия — NaN, не 0.
- Выборки (фиксируются):
  - `S_W22` — 2022-01…2026-08, как `weekly` v3 (воспроизведение прежних чисел);
  - `S_L13` — 2013-10…2026-08, как `long` v3 (все признаки v2, включая `usd_mm`, `key_rate`);
  - `S_L09` — 2009-06…2026-08, **без** `usd_mm` и `key_rate` у **всех** моделей этой выборки (стартуют 2013); набор фиксируется заранее, чтобы не менять информацию между челленджером и бейзлайном.
- Таргет и признаки читаются «последней редакцией»; винтажей нет (ограничение, §9).

## 4. Фолды и протокол

- Expanding walk-forward; random split запрещён.
- **Purge/embargo:** train-строка `O'` допустима, если `O' ≤ O − h − 1` (правило live3), т.е. её цель `O'+1…O'+h` опубликована к cutoff `O`.
- **Min train:** 60 месяцев для `S_L09`/`S_L13` (первый тестовый origin `S_L09` — 2014-06; `S_L13` — 2018-10), 24 для `S_W22` (как v3 `DEFAULT_START`). Min-train не подбирается по ошибке.
- **Primary test-окно для лидерборда:** origins 2016-01…2026-08 для `S_L09`; **общие фолды** для всех сравниваемых моделей — пересечение допустимых фолдов; пары сравниваются только на нём (правило gate).
- **Срезы-отчёты (не gate):** 2016–2019, 2022–2023, 2024–2026; без шоковых окон 2014-12…2015-03, 2020-03…2020-04, 2022-03…2022-06 (R2). Шок остаётся в primary (правило 8).
- Seeds и версии: `SEED = cm.SEED`, CatBoost дефолты внутри фолда (без тюнинга по тесту); любые гиперпараметры — только CV внутри train.

### 5.1. Поправка 2026-10-28: состав моделей эксперимента 1 (внесена до первого прогона сетки)

Состав «5 бенчмарков + 4 кандидата» не раскладывается на все девять ячеек: у `T_SA` и `T_CORE` нет компонентных рядов (bottom-up не определён), а `v4c`/`v4d` зависят от Task 3 (ещё не выполнен). Поэтому **эксперимент 1** оценивает на каждой ячейке по **7 моделей** (≥ 3 — достаточно для MCS), набор фиксируется здесь, до результатов:

| ячейки | модели |
|---|---|
| `T_NSA` × h1/h3/h6 | `B1`, `B2`, `B3`, `v2_bottomup`, `v3_bottomup`, `v4a_bottomup`, `v4b_bottomup` |
| `T_SA`, `T_CORE` × h1/h3/h6 | `B1`, `B2`, `B3`, `v2_baseline` (direct CatBoost v2), `v3_direct`, `v4a_direct`, `v4b_direct` |

`v4a_*` — признаки v2 + `wkagg_*`; `v4b_*` — v3 + `wkagg_*`; обучение — CatBoost с дефолтами v3 (`fit_catboost`: `RMSE`, seed `SEED`, `month` категориальный), для `*_bottomup` — по трём компонентам с NNLS-весами. `v4c_core_nnls`/`v4d_core_direct` войдут в эксперимент 3 после Task 3 и в лидерборд эксперимента 1 не входят; «9 моделей» из §5 читать как итог после Task 3.

Дополнения протокола (не меняют §4):

1. **Накопленная цель** для всех таргетов — сложный процент за `O+1…O+h`; признаки строки origin `O` — на `cutoff_for(O)`.
2. **B1 для h-горизонта** — накопленный рост за последние h опубликованных месяцев `O−h…O−1` (как в live3).
3. **Лаги `y_lag1`/`y_lag2`** у `T_SA` и `T_CORE` — значения самого таргета за `O−1`/`O−2` (публикация ЦБ — 15–22-е `O`, раньше cutoff `O+1`); у `T_NSA` — прежние.
4. **`S_L09`:** модели v2/v3 запускаются прежним кодом при подмене `cpi_monthly.feature_names` (убираются `usd_mm`, `key_rate`), чтобы набор признаков был единым для всех моделей выборки; подмена снимается после прогона.
5. **Сравнения:** каждая модель против `v2_bottomup` (`T_NSA`) или `v2_baseline` (`T_SA`, `T_CORE`) и против `B3`; MCS 90 % — по всем 7 моделям ячейки на общих фолдах.
6. **Окна:** основная выборка — `S_L09` (min train 60, primary-окно origins 2016-01 и позже); `S_L13` (min train 60, с 2018-10) и `S_W22` (min train 24) — robustness, отдельными прогонами.
7. **Паспорт:** `ML_LOG=1`, эксперимент `cpi_v4`, окно `<таргет>:h<h>`, `target_date` — месяц origin; `unit="pp"`.

**Признак `core_nnls(O)`** (месячный, as-of, не зависит от фолда):

1. Обучение — месяцы `m ≤ O−1`, у которых известны `Базовый ИПЦ` m/m (CBR SA публикует месяц `m` в 15–22-е `m+1`, т.е. значение `O−1` известно к cutoff `O`) и вектор корзин.
2. Колонки — корзины, присутствующие в месяце `O` и не менее чем в `MIN_TRAIN_MONTHS = 24` месяцах обучения; строки — месяцы, где присутствуют все выбранные колонки (complete-case, импутаций нет).
   Если колонок меньше `MIN_BUCKETS = 8` — `NaN` (см. поправку ниже).
3. Если строк < 24 — `core_nnls = NaN` (в моделях импутация медианой train внутри фолда, CatBoost принимает NaN).
4. Веса — `scipy.optimize.nnls` по `y = core_mm` **без свободного члена и без нормировки суммы к 1** (веса неотрицательны; сумма — диагностика, в отчёт). Значение = `w · x_O`.

Известное ограничение (не обход): таргет — SA, корзины — NSA `m/m`; сезонность корзин не вычитается. Панель до 2021 содержит 5–19 рядов в месяц и месяцы с пропусками.

**Уточнение 2026-10-29 (после диагностики покрытия, до любых результатов моделей).** Первоначальная оценка «определён с 2023» была неверной: без порога по числу корзин `core_nnls` формально определяется с 2013-01, но по 2–4 корзинам (2013–2020), 5 корзин в 2021 и 13–14 с 2022-07 — это три разных прокси, а не один ряд. Вводится `MIN_BUCKETS = 8` (по смыслу: меньше половины групп — не core-прокси): до порога `core_nnls = NaN`. Следствие: признак определён с 2022-07, общие фолды `v4c` в эксперименте 3 — примерно 2022-07…2026-08 (~50 origin'ов, вблизи `MIN_COMMON_FOLDS = 12` с запасом, но мощность низкая); в `S_L09` до 2022-07 `core_nnls` — NaN (медианная импутация), что обязательно указывается в отчёте. Значение 8 выбрано по диагностике покрытия, а не по ошибке моделей.

**Модели эксперимента 3** (таргет `T_CORE`, накопленная цель, лаги `y_lag1/2` — самого core):

- `v4c_core_nnls` — CatBoost (`fit_catboost_names`) на признаках `v4a` + `core_nnls`.
- `v4d_core_direct` — ElasticNetCV (конфигурация B3, §3.4 v2-спеки: alphas `logspace(−4, 1, 20)`, `l1_ratio [0.1, 0.5, 0.9]`, `TimeSeriesSplit(3)`, медианная импутация и `StandardScaler` только по train) на признаках `v4a` (включая лаги core, ожидания и `wkagg_*`), без `core_nnls`.

Спецификаций ровно две; добавление новых — отдельный пункт.

## 6. Метрики

- Primary: **RMSE** на каждой из 9 ячеек (таргет × h) отдельно; MAE — сопутствующая; для `T_NSA` дополнительно RMSE с исключением тарифных месяцев.
- DM-HLN (`lib.eval_utils.diebold_mariano`) с поправкой на перекрытие окон (h-1 лагов для h=3, 6) + блочный бутстрап 95 % CI разницы RMSE (блок 3, n=2000, `BOOTSTRAP_*` v3).
- **MCS 90 %** по всем 9 моделям в каждой ячейке — решающий инструмент для многих спецификаций; парные DM — вспомогательный.
- **MDE:** `_mde_ratio` из v3 считается и печатается для каждой пары; ожидаемое при n≈120 — порядка 8–10 % по RMSE (оценка, не гарантия): эффекты ниже MDE называются «не обнаруженными», а не «отсутствующими».
- Множественность: 9 ячеек × 4 кандидата → порог для «значимо» в отчёте Bonferroni 0,05/36 = 0,0014 справочно; gate использует правило §7 (primary-ячейки, без поправки), остальное — разведочное, помечается как таковое.

## 7. Предрегистрированный gate

**Эксперимент 1 (инфраструктура, H1) — обязательный, не имеет gate по качеству.** Критерии готовности: сетка 9 ячеек воспроизводится побайтово (sha256 `predictions.csv`), регрессионный гейт v2/v3 на `S_W22` (эталон Task 4, §7.1) пройден, MCS и DM/CI считаются, паспорт `ML_LOG=1`. Gate для разных имён моделей реализуется in-script (расширение `ml-gate` `--champion-model/--challenger-model` — отдельный follow-up #184, не блокирует).

Сравнения экспериментов 2–3 по-прежнему идут на общих фолдах с бенчмарками `v2_bottomup`/`v3_bottomup` текущих данных; кросс-временные сравнения со Stage 1 в отчётах не делаются.

**Эксперимент 2 (H2).** Primary-ячейки: `T_NSA` h1 и h3 на `S_L09`. Challenger `v4a_agg` (или `v4b_agg_div`) — `promote` в смысле «кандидат для ансамбля/следующего пункта» только если одновременно:
1. RMSE ниже `v2_bottomup` на **общих** фолдах в обеих primary-ячейках;
2. DM-HLN p < 0,05 **и** 95 % бутстрап-CI ΔRMSE исключает 0 хотя бы в h1;
3. robustness: знак эффекта сохраняется на `S_L13` и на срезе 2022–2026 (`S_W22`) — без этого `iterate`;
4. модель входит в MCS-90 % ячейки;
5. нет значимой деградации (p<0,05 в худшую сторону) на h6.

Иначе — `iterate`/`reject` по причине, записанной в gate-артефакте. Отрицательный контроль: h6 не используется как критерий успеха.

**Эксперимент 3 (H3).** Primary — `T_CORE` h1 на `S_L09` (общие фолды 2016+). `v4c_core_nnls`/`v4d_core_direct` — кандидат, только если RMSE ниже **и** официального агрегата-прокси B0 (4-нед. средняя), **и** M1 `core_raw`-аналога (где определено; на 2022+ — прямое сравнение в `S_W22`), DM p < 0,05 и CI исключает 0; на h3/h6 — «не хуже B3» (+5 % допуска, DM не значимо хуже). Coverage-gate #76 (≥50 % весов) **не** переопределяется: пока веса группируются из панели с покрытием 39,3 %, вывод формулируется как «hybrid/proxy», не «core выделен».

Общие: gate-артефакт `build/ml-gate/<run>.json` с решением и причиной; `promote` ≠ deployment; `forecast_log` не пишется; для CPI registry — явный `make mlflow-promote` только после отдельного решения владельца.

## 8. Риски и стоп-условия

| Риск | Реакция |
|---|---|
| Стыки источников агрегата (бюллетени/BI/XLSX) дают скачки или дубли | шаг 1 плана: аудит стыков; при расхождении > 0,05 п.п. на пересечении — признак строится из одного источника на сегмент, решение — в отчёт |
| Пропуски недель 2009–2015 (24–33 даты/год) превращают `wkagg_mtd_scaled` в шум | `cov`-гейт 0,5; robustness «только 2016+» (R1) |
| Структурные сдвиги (2014–15, 2020, 2022) доминируют в RMSE | срезы и R2 без шоковых окон; шок в primary остаётся |
| Утечка через склейку недель по границе месяца | юнит-тест: признак месяца `O` не использует точки `date + 2 > cutoff`; тест на синтетической недельной сетке |
| H3: покрытие весов 39,3 % — прокси, не core | формулировка вывода; coverage-gate #76 сохраняется |
| MDE выше эффекта | выводы «не обнаружено»; не расширяем спецификации post hoc |
| Quick-прогон смешан с full | `quick=true` в паспорте; в отчёт только full |

**Стоп:** если регрессионный гейт v2/v3 на `S_W22` (эталон Task 4, §7.1) не воспроизводится — дальше не идём, чиним расхождение.
