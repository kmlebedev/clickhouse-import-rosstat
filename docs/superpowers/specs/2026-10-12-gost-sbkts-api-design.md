# gost_vehicle_safety_certificate (СБКТС Росстандарта) — API-импортёр — design

Дата: 2026-10-12. Пункт: `docs/GOLD_THESIS_DATA_ROADMAP.md`, «Фаза 4 — follow-up 6: СБКТС Росстандарта —
прокси импорта авто (торговый баланс → курс рубля)»; канал №7 в `docs/ROADMAP_DCF_POLYUS.md` §10.1.

## Пробел

Реестр СБКТС (свидетельств о безопасности конструкции ТС) — публичный прокси объёма импорта автомобилей:
каждой ввезённой машине соответствует запись реестра, и число выданных СБКТС в день читается как поток
импорта (тезис статьи: импорт авто ↔ ослабление рубля; курс рубля — вход рублёвой оценки PLZL и рублёвой
выручки от продажи золота за валюту). Сегодня источник в контуре есть только формально:

- `craw/gost.go` пишет **построчным `conn.Exec` в цикле** (нарушение правила 2), ошибки в `OnHTML`
  проглатываются, `context.TODO()`, токен `gtn.access.appid` вписан в комментарии файла (нарушение правила 1),
  второй DDL `gost_vehicle_safety_certificate_type` мёртв, `dagu/craw.yaml` — 1-е число месяца 11:31;
- «исторический» обход (рекурсивный `e.Request.Visit` по ссылке «Вперёд») умирает на глубине нескольких
  недель: **стена пагинации** измерена (ниже) — данные старше ~2 месяцев через портал недостижимы;
- колонок для аналитики торгового баланса нет вовсе (год выпуска, эко-класс, двигатель, производитель).

## Цель и объём

Импортёр `gost_vehicle_safety_certificate` (пакет `craw/`, `Name()` — имя таблицы) переписывается на
API-транспорт с тремя режимами (`GOST_MODE`), расширенной схемой и витринами для агента; расписание —
раз в час. Критерий приёмки пункта: «история СБКТС достижима целиком, хвост обновляется ежечасно,
агент читает дневной поток импорта авто через витрины».

**Вне объёма** (follow-up): `tnved` (в API пуст), миграция дашбордов, сверка потока СБКТС с курсом
(аналитический слой — отдельный пункт), возврат портального канала как основного (остаётся методом
сверки в приёмке).

## Три режима (env `GOST_MODE`; пусто → `since`; неизвестное значение → ошибка до сети и БД)

### `since` — «доходим до уже загруженного» (этим режимом работает dagu)

Окно `[anchor − GOST_SETTLE_DAYS, сегодня МСК]`, где
`anchor = GREATEST(max(date) в таблице, maxIf(publication_date, publication_date > '2016-01-01'))`.
Дни читаются **целиком** и идемпотентно перезаписываются (ключ `ReplacingMergeTree`), поэтому «стоп»
наступает на уже имеющихся днях, а лаг публикации (~2 суток) не теряет опоздавшие документы: хвост
`GOST_SETTLE_DAYS` (по умолчанию 3) перечитывается каждый час. Пустая таблица → предупреждение
«история не загружена, запустите `GOST_MODE=full`» + последние 7 дней (dag не падает впустую).
Обычная нагрузка — 4–12 запросов в час.

### `full` — «вся история» (ручной прогон)

Обход дней диапазона `[GOST_FROM, GOST_TO]` (по умолчанию `2016-01-01` … вчера МСК; публикации реестра
начинаются в 2016–2017: 2015-06-15 — 0, 2017-06-15 — 316). Резюмируемость: повтор любого диапазона —
идемпотентный upsert; неудачные дни перечисляются в ошибке. Ожидаемая длительность всей истории —
часы (5–10 тыс. запросов), запуск чанками по годам.

### `check` — «полнота» (read-only)

По каждому дню окна `count` API против `uniqExact(certificate_number)` в таблице по `publication_date`;
печатается сводка и список дней с расхождением, расхождение — ошибка прогона (exit ≠ 0). Строк не пишет,
витрины не трогает. Легаси-строки с `publication_date = 1970-01-01` (таблица до бэкфилла) в сверке
дня не участвуют и отдельно считаются в сводке «не бэкфилено».

## Транспорт и разбор

- `GET https://www.gost.ru/standards/rest-api/libraries/search?query=<DD.MM.YYYY>&page=N&size=900&tmsp=<мс>`
  с заголовками `gtn.access.appid: $GOST_APP_ID`, `Accept: application/json`, `User-Agent: util.HttpUA`;
  транспорт — `util.HttpClient` (нац. сертификаты); пер-запросный дедлайн 120 с; ретраи
  `cenkalti/backoff/v5` (RetryAfter на таймаут/5xx), пауза ~200 мс между запросами (щадим источник).
  Токен читается **только из env** (правило 1; без значения — ошибка с подсказкой, где взять:
  JS-конфиг страницы реестра `standarts.adminsHeaders`).
- **Дневной срез**: `page=1` → `count`; страницы до `ceil(count/900)`; строки фильтруются клиентски
  по точной дате публикации (текстовый запрос может совпасть и в другом поле); собрано меньше `count`
  или `count > 10000` (окно API; исторический максимум дня ~2.3 тыс.) — ошибка дня.
- Маппинг: `dateofissueofcertificate` (epoch мс → дата МСК; фиксированный офсет +3), `product` → `mark`,
  `type` → `type`, `numberofcertificate` → `certificate_number`, `ecoclass`, `enginetrademark`,
  `yearofmanufacturing` (4 цифры, иначе 0), `nameofmanufacturer`, `uniqueidentifierofdocument` → `uid`,
  дата среза → `publication_date`. Значения `-`/пусто сохраняются как есть.
- Запись — **одним батчем на день** (`PrepareBatch → Append (err checked) → Send`); пустой день (count=0)
  — один запрос, без записи. Итог: `Imported N rows of gost_vehicle_safety_certificate`; при ошибках —
  `errors.Join` по дням и exit ≠ 0 (dag краснеет → retry).

## Схема и миграция

Канонический DDL (ARCHITECTURE.md §6.2; существующая таблица сохраняет тот же ORDER BY, поэтому
не пересоздаётся) + идемпотентные `ALTER TABLE … ADD COLUMN IF NOT EXISTS` при каждом прогоне:

```sql
CREATE TABLE IF NOT EXISTS gost_vehicle_safety_certificate (
    mark LowCardinality(String),                 -- марка ТС (product)
    type LowCardinality(String),                 -- тип/модель ТС (type)
    date Date,                                   -- дата выдачи СБКТС (МСК)
    certificate_number String,                   -- номер СБКТС («ТС RU …»)
    ecoclass LowCardinality(String),             -- экологический класс; '-' — не применимо
    enginetrademark String,                      -- двигатель: модель, топливо (дизель/бензин/электро)
    yearofmanufacturing UInt16,                  -- год выпуска; 0 — не указан / строка до бэкфилла
    nameofmanufacturer LowCardinality(String),   -- производитель
    uid String,                                  -- uniqueidentifierofdocument (провенанс)
    publication_date Date                        -- дата батча публикации (провенанс/резюмируемость)
) ENGINE = ReplacingMergeTree ORDER BY (mark, type, date, certificate_number);
```

Мёртвый DDL `gost_vehicle_safety_certificate_type` удаляется. Старые строки получают дефолты новых
колонок; `full` перезаписывает их по тому же ключу (число строк в таблице не удваивается). Импортёр
предупреждает, если видит строки с `publication_date = 1970-01-01` («не бэкфилено»).

## Витрины (правило 11)

- `v_gost_vehicle_safety_certificate` — строки (`date, publication_date, mark, type, certificate_number,
  ecoclass, enginetrademark, yearofmanufacturing, nameofmanufacturer`; `uid` не выводится), `FINAL`.
- `v_gost_vehicle_safety_daily` — `date, mark, certificates = uniqExact(certificate_number)` (день × марка;
  разбивка по моделям — GROUP BY по строковой витрине).
- Создаются импортёром (`CREATE OR REPLACE VIEW … DEFINER = default SQL SECURITY DEFINER`), комментарии
  таблицы и каждой колонки — `ALTER TABLE … MODIFY COMMENT` / `COMMENT COLUMN` (образец — `news/schema.go`).
- `GRANT SELECT` обеих витрин — `sql/mcp_kimi_reader.sql`; сырая таблица агенту не выдаётся; проверки —
  `scripts/mcp_check.py` (обе витрины читаются запросом, `SELECT count() FROM
  gost_vehicle_safety_certificate` → ACCESS_DENIED).
- `series_catalog` не пополняется — прецедент `news_events`/`bold_fund_snapshot` (не ряд `macro_series`).

## Расписание

`dagu/craw.yaml`: один шаг `gost_vehicle_safety_certificate`, `schedule: "17 * * * *"` (раз в час,
`overlap_policy: skip`, минута :17 свободна между `news` :07/:37), retry 3 × 300 с, `env: GOST_MODE=since`
и `GOST_APP_ID` из окружения хоста. Комментарий DAG фиксирует: стену портала (почему не HTTP-листинг),
лаг публикации (почему хвост 3 дня), щадящую нагрузку (4–12 запросов в час) и ручные режимы
(`full`/`check`) вне расписания.

## Ограничения и риски

- Расхождение счётчиков портала (3.569 млн) и API (3.44 млн) — 3.6 % не объяснено; на проверенном окне
  наборы совпали. Митигация: сверка портал↔API на 2–3 других окнах; при системной дыре — вернуть
  портальную ветку как хвостовой канал (дизайн это допускает).
- Ротация `GOST_APP_ID`: 401/403 → понятная ошибка с подсказкой.
- Окно API 10 800: день с >10k документов — жёсткая ошибка (исторически максимум ~2.3 тыс.).
- Изменения (amendments) сертификата с новой датой выдачи дают вторую строку при том же номере —
  оговорка в комментарии витрин (в метрике дня считать `uniqExact(certificate_number)`, что витрина
  и делает).
- Полный прогон длится часы и запускается вручную; незавершённый прогон не портит данные (идемпотентность).
