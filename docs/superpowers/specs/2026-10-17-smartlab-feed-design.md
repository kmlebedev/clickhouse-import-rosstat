# smartlab-feed — design

Дата: 2026-10-17. Пункт: `docs/ROADMAP_KEY_RATE.md` §6, фаза 1.4 — «Лента smart-lab в `news_watch`
(`source='smartlab'`) — полный текст поста уже приходит в `description`; фильтр витрины расширить
стемами ставки». Этим пунктом закрывается строка контракта данных `docs/KEY_RATE_PUBLICATIONS.md`
§6 «Посты-образцы и рыночный разбор» (❌ фаза 1.4).

## Пробел

`news_watch` собирает пять лент РФ-канала (Интерфакс, РБК, ЦБ РФ ×2, TASS) — в `v_news_events` нет
ни постов-образцов, ни рыночного разбора: публикационный контур
(`KEY_RATE_PUBLICATIONS.md` §4) опирается на «недельные посты, которые берутся за образец»,
но источник образцов в контуре не собран. Раздел «Посты-образцы и рыночный разбор» держит
❌, а подготовка регулярной публикации упирается в отсутствие внешнего взгляда рынка
с явными порогами (`KEY_RATE_CHANNELS.md` §6).

## Цель и объём

Две ленты smart-lab в `news_watch` под общим `source='smartlab'` + сохранение полного текста
поста (новая колонка `description` в `news_events`) + расширение фильтра витрины стемами
ставки + документы. Критерий приёмки пункта (роадмап): посты видны агенту; повторный прогон
идемпотентен.

**Вне объёма**: сам публикационный прогон (`KEY_RATE_PUBLICATIONS.md` §7), бэкфилл старых окон
лент, скрапинг страниц постов, изменения дашборда (панель «Событийный фон (лента)» читает
`v_news_events` и подхватит посты сама), заполнение `sentiment` (follow-up news-watch).

## Схема и миграция

- Канон `ARCHITECTURE.md` §6.2 — `news_events` получает колонку `description String` после `url`
  (правило 8: канон правится первым; копия в `news/schema.go` обязана совпадать).
- Существующая таблица расширяется идемпотентно — паттерн `gostSchemaStatements`
  (`craw/gost.go`): `ALTER TABLE news_events ADD COLUMN IF NOT EXISTS description String AFTER url`
  выполняется в каждом прогоне после `CREATE TABLE IF NOT EXISTS` и до чтения лент, во всех
  режимах (в `check` — как сейчас DDL).
- Запись: `newsInsert` переходит на явный список колонок
  `(date, source, title, url, description, sentiment)` — порядок `Append` — контракт с ним
  (образец — `gostInsert`).
- Строки, записанные до миграции, получают пустой `description`; позиции, выпавшие из окна
  ленты, задним числом не перечитываются (дефолт-свойство миграции `ADD COLUMN`).

```sql
CREATE TABLE IF NOT EXISTS news_events (
    date DateTime,
    source LowCardinality(String),
    title String,
    url String,
    description String,              -- текст позиции из ленты: у smart-lab — полный текст поста (HTML
                                     -- после разбора XML-сущностей); у новостных лент — краткое
                                     -- описание позиции; '' — описания нет
    sentiment Nullable(Float32)      -- -1..1, заполняет LLM-сессия
) ENGINE = ReplacingMergeTree ORDER BY (date, source, title);
```

## Парсинг

- `rssItem`/`newsItem` получают `Description` (`xml:"description"`); значение — `strings.TrimSpace`
  (внутренние переводы строк и разметка сохраняются как есть: это текст поста). Отсутствующее
  или пустое — `''`: не ошибка и не повод пропустить позицию.
- Колонка заполняется для всех лент: у новостных в `description` краткое описание; спецкейсов
  «только для smartlab» в коде нет.

## Витрина

- `v_news_events` получает колонку `description` (+ комментарий: «текст позиции из ленты: полный
  текст поста smart-lab (HTML) или краткое описание новости; '' — описания нет; при цитировании —
  атрибуция автора и smart-lab»).
- `newsViewStatements`: 8 → 9 стейтментов (VIEW + комментарий таблицы + 7 комментариев колонок);
  тест-пин обновляется.
- Фильтр `newsFilter` расширяется стемами ставки/денежного рынка:
  `|вклад|депозит|наличн|кредит|ОФЗ|RGBI|RUONIA|RUSFAR`. Проверено на живых заголовках обеих
  лент 2026-10-17: добавление включает «Наличные бьют рекорд в России, вклады населения не растут»
  и не даёт ложных включений среди остальных 39 заголовков. Позитивные и негативные кейсы —
  в `TestNewsFilterMatchesThesisStems`.
- Комментарий таблицы витрины дополняется smart-lab.

## Расписание и режимы

`dagu/news.yaml` — без изменений расписания (каждые 30 минут, `since`, окна 20–100 позиций);
комментарий дополняется smart-lab. Окно smart-lab — 20 постов на ленту; история копится
с первого прогона; простой дольше окна теряет позиции ленты безвозвратно (ограничение класса
`news_watch`, уже документировано).

## Приёмка (живая)

1. `make all` — зелёный.
2. `make import STAT=news_watch` (режим `all`): в логе обе ленты smartlab со счётчиками позиций;
   запись N строк; повторный `NEWS_WATCH_MODE=since make import STAT=news_watch` → 0 строк;
   `NEWS_WATCH_MODE=check` — покрытие, дыр нет.
3. MCP (`kimi_reader`): `SELECT … FROM v_news_events WHERE source='smartlab' ORDER BY date DESC`
   — посты видны; пост-пример (`url` содержит `1363355`) — с непустым `description`;
   `SELECT count() FROM news_events` → ACCESS_DENIED.
4. `make mcp-check` — зелёный.
5. Статус пункта в роадмапе обновлён тем же PR; протокол приёмки — комментарием в PR.

## Ограничения

- Окно лент — 20 постов; образцы, выпавшие из окна, в БД не перечитываются (канонические
  примеры фиксируются ссылками в документе).
- `description` — HTML после разбора XML-сущностей; витрина отдаёт как есть (без стриппинга
  разметки).
- Расширение фильтра — общий `v_news_events` (затронет и золотой контур): шум допустим
  по дизайну фильтра, лишнее снимает запрос сессии.
