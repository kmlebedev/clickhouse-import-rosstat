## 1. Контекст и цель

Публикация [smart-lab.ru/blog/1370053.php](https://smart-lab.ru/blog/1370053.php) показывает цену нефти Urals в **постоянных рублях сентября 2026** и сравнивает её с **сезонной нормой 2018–2022**; отдельно в тексте разобрано бюджетное правило. Ключевые числа публикации (октябрь-2026 — оценка): `$101.46 × 82.97 = 8 418 ₽/барр.`, `+93.8%` г/г номинально и `+83.1%` г/г реально, `+7.4%` м/м; среднее января–сентября 2026 — `5 523 ₽/барр.`; сезонная норма 2018–2022 — `6 812 ₽/барр.`; нефтегазовые доходы января–сентября 2026 — `5 471 млрд ₽` (`−17.2%` г/г).

Цель пункта — воспроизвести график публикации **кодом** (дашборд как код, ARCHITECTURE.md §6.7) и добавить к нему ECharts-панель бюджетного правила (`$59 → ФНБ`), которой в публикации нет. Итог: дашборд `urals-budget-rule` из 7 панелей в 2 рядах на четырёх уже существующих витринах.

## 4. Контракт

### 4.1. Общие правила таргетов

- Каждый таргет — `CHQuery` (`NewCHQuery`), `editorType "sql"`, `pluginVersion "4.3.2"`; ECharts/stat/barchart — `tableQuery` (формат 1, `queryType "table"`).
- Только витрины `v_*`; сырые таблицы запрещены (проверяется `Validate` и тестами `grafana/`).
- Фильтр диапазона — `$__dateFilter(date)` **на сырой колонке `date`** в графиках и срезах по месяцам (П1, П2, П7). Stat-панели П3–П6 — снимок последнего опубликованного месяца и `$__dateFilter` не используют: диапазон дашборда не должен менять «октябрь 2026» (так же устроены snapshot-таблицы `finance-polyus`).
- `LIMIT` на графиках нет; агрегация — в ClickHouse; алиасы колонок русские.
- `$__dateFilter` на `Date32` (`v_minec_macro.date`) и `Date` (`v_cbr_macro.date`, `v_fedstat_ipc.date`) допустим: макрос подставляет литералы дат, сравнение типов ClickHouse выполняет сам.

### 4.2. П1 — Urals в постоянных рублях (база — сентябрь 2026)

**Смысл.** Ось X — календарные месяцы (1–12). Ряды: сезонная норма 2018–2022 (синяя), линии годов 2023–2026, октябрь-2026 — полый маркер-оценка. Дефлятор — накопленный уровень ИПЦ (`ipc31074/Все товары и услуги`), база — **последний опубликованный** месяц ИПЦ (сейчас сентябрь 2026): `real_rub = urals × usd_avg × level(последний опубликованный ИПЦ) / level(мес)`.

**Таргет (дословно; `SETTINGS join_use_nulls = 1` обязателен — иначе `LEFT JOIN` подставляет 0 вместо NULL, и оконный `anyLast` уносит нулевой дефлятор в октябрь):**

```sql
WITH
    ipc AS (
        SELECT toDate32(date) AS date,
               exp(sum(log(value / 100)) OVER (ORDER BY date)) AS level
        FROM v_fedstat_ipc
        WHERE series = 'ipc31074/Все товары и услуги'
          AND (region = 'Российская Федерация' OR date >= '2023-01-01')
    ),
    base AS (SELECT argMax(level, date) AS level FROM ipc),
    usd AS (
        SELECT toDate32(toStartOfMonth(date)) AS month, avg(value) AS usd_avg
        FROM v_cbr_macro
        WHERE series = 'cbr_currency_usd'
        GROUP BY month
    ),
    monthly AS (
        SELECT u.date AS date, u.value AS urals, d.usd_avg AS usd_avg, i.level AS ipc_level
        FROM v_minec_macro AS u
        INNER JOIN usd AS d ON d.month = u.date
        LEFT JOIN ipc AS i ON i.date = u.date
        WHERE u.series = 'urals_avg_price'
    ),
    filled AS (
        SELECT date, urals, usd_avg,
               anyLast(ipc_level) OVER (ORDER BY date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS level_used,
               toUInt8(ipc_level IS NULL) AS is_estimate
        FROM monthly
    ),
    seasonal AS (
        SELECT toMonth(date) AS month,
               round(avg(urals * usd_avg * (SELECT level FROM base) / level_used), 0) AS seasonal_norm
        FROM filled
        WHERE toYear(date) BETWEEN 2018 AND 2022
        GROUP BY month
    )
SELECT
    f.date AS "Месяц",
    toYear(f.date) AS "Год",
    toMonth(f.date) AS "Месяц года",
    round(f.urals * f.usd_avg * (SELECT level FROM base) / f.level_used, 0) AS "Реальная цена, ₽/барр.",
    s.seasonal_norm AS "Сезонная норма 2018–2022, ₽/барр.",
    f.is_estimate AS "Оценка"
FROM filled AS f
INNER JOIN seasonal AS s ON s.month = toMonth(f.date)
WHERE $__dateFilter(f.date)
ORDER BY f.date
SETTINGS join_use_nulls = 1
```

**Почему так.**

- `ipc.level` — накопленный ИПЦ от начала ряда (`exp(sum(log(value/100)) OVER (ORDER BY date))`); база отношения сокращается, поэтому важен только уровень, а не точка отсчёта.
- `base` — последний опубликованный уровень ИПЦ (сейчас `2026-09-01`). Это и есть «постоянные рубли сентября 2026»; база фиксируется данными, а не литералом.
- `anyLast(...) OVER (... ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)` переносит последний опубликованный уровень ИПЦ на месяцы без публикации — октябрь-2026 считается по дефлятору сентября (как в публикации).
- `is_estimate = toUInt8(ipc_level IS NULL)` — полый маркер-оценка ровно там, где ИПЦ ещё не опубликован.
- `seasonal` считается по **полному** ряду до применения `$__dateFilter` (окно дашборда не должно менять норму 2018–2022): `WHERE` стоит в финальном `SELECT`, а не внутри `filled`.
- Пропуски 2018-06/2018-07 (их нет в источнике) не заполняются: строк нет — точек нет (практика «пропуск ≠ ноль»).

**Живая проверка (2026-11-03, ClickHouse 26.10.1, `kimi_reader`; `$__dateFilter` заменён явными границами):** 104 строки, `2018-01-01 … 2026-10-01`; октябрь-2026: `real_rub = 8 418`, `Оценка = 1`; сентябрь-2026: `7 837`; сезонная норма: янв `7 186`, мар `7 410`, апр `6 345`, июл `6 588`, сен `6 840`, октябрь `6 984`; общее среднее 2018–2022 — `6 812`; 2018: номинал `4 336`, реально `7 582`; среднее янв–сен 2026 — `5 523`.

**JS-контракт (форма; тело — в коде, без литеральных данных):**

```js
const s = context.panel.data.series[0];
// поля — по именам из таргета: "Год", "Месяц года", "Реальная цена, ₽/барр.",
// "Сезонная норма 2018–2022, ₽/барр.", "Оценка"; значения — только из s.fields.
// 1) категории X — 12 календарных месяцев (подписи месяцев — массив Presentational, не данные);
// 2) сезонная норма — одна точка на месяц из колонки seasonal (дедуп по месяцу);
// 3) линии 2023, 2024, 2025, 2026 — пивот (Год, Месяц года) → [месяц, значение];
//    строки с "Оценка" === 1 (октябрь-2026) в линии годов НЕ входят;
// 4) строки с "Оценка" === 1 — только отдельная scatter-серия: symbol 'emptyCircle', label со значением;
// 5) tooltip: год, месяц, значение; линии не соединяют пропуски (connectNulls: false).
return { ... };
```

Инварианты: нет массивов данных, вписанных в JS; нет сырых таблиц (только `v_*` в таргете); timezone не конвертируется (отображение — `Timezone(browser)`); цифры публикации (`101.46`, `8418`, `6812` и т. п.) в JS не вписываются — они приходят из SQL; строки с `Оценка = 1` из линий годов исключаются и рисуются только полым маркером-оценкой.

### 4.3. П2 — Бюджетное правило: цена отсечения $59

**Смысл.** Urals `$/барр.` по месяцам с 2018; горизонтальный `markLine` на `$59`; stacked area «≤ $59 — в бюджет» / «> $59 — в ФНБ»; подпись последней точки. `$59` — **параметр бюджетного правила Минфина** (цена отсечения Urals, действует до 2027; снижение до $50 обсуждается только с 2027), **не ряд из витрины**. В SQL и JS константа допускается только с комментарием-источником.

**Таргет (дословно):**

```sql
-- $59 — цена отсечения бюджетного правила Минфина для Urals (действует до 2027;
-- The Bell, mn.ru; снижение до $50 обсуждается только с 2027). Это параметр правила,
-- а не ряд витрины: в v_series_catalog его нет.
SELECT
    date AS "Месяц",
    value AS "Urals, $/барр.",
    least(value, 59) AS "В бюджет (≤ $59)",
    greatest(value - 59, 0) AS "В ФНБ (> $59)"
FROM v_minec_macro
WHERE series = 'urals_avg_price'
  AND $__dateFilter(date)
ORDER BY date
```

**JS-контракт (форма):**

```js
const s = context.panel.data.series[0];
// поля: time "Месяц", number "Urals, $/барр.", "В бюджет (≤ $59)", "В ФНБ (> $59)";
// данные — только из context.panel.data.
// 1) xAxis type 'time'; основная линия — Urals;
// 2) два area-ряда "В бюджет"/"В ФНБ" с stack: 'rule' (стопка = цена Urals);
// 3) markLine на значение BUDGET_RULE_CUTOFF (= 59) с подписью «Бюджетное правило: $59»;
//    константа — с комментарием-источником (параметр Минфина, не ряд витрины);
// 4) endLabel основной линии — подпись последней точки (значение $/барр.);
// 5) tooltip: месяц, цена, «в бюджет», «в ФНБ».
return { ... };
```

Инварианты: `markLine` — единственное место JS, где появляется `59` (с комментарием-источником); литеральных рядов данных нет; `connectNulls: false`.

### 4.4. П3 — Urals, $/барр. (октябрь 2026)

```sql
SELECT round(argMax(value, date), 2) AS "Urals, $/барр."
FROM v_minec_macro
WHERE series = 'urals_avg_price'
```

`argMax` вместо `ORDER BY … LIMIT 1`: снимок последнего месяца, без `LIMIT` (конвенция «без LIMIT на панелях-снимках» — как `fpModelRunSQL`). Живая проверка: `101.46`.

### 4.5. П4 — Курс ЦБ, ₽/$ (октябрь 2026)

```sql
SELECT round(avg(value), 2) AS "Курс, ₽/$"
FROM v_cbr_macro
WHERE series = 'cbr_currency_usd'
  AND toStartOfMonth(date) = (SELECT max(toDate(date)) FROM v_minec_macro WHERE series = 'urals_avg_price')
```

Месячное среднее дневного ряда (`avg()` + `toStartOfMonth`) за тот же месяц, что и последний Urals; `количество дней октября — 23` (полный месяц). Живая проверка: `82.97` (точное среднее `82.971357`).

### 4.6. П5 — Urals в рублях, ₽/барр. (октябрь 2026)

Одна строка, три поля: значение `8 418 ₽/барр.` и два г/г темпа. Дефлятор — тот же, что в П1 (октябрь считается по уровню сентября).

```sql
WITH
    ipc AS (
        SELECT toDate32(date) AS date,
               exp(sum(log(value / 100)) OVER (ORDER BY date)) AS level
        FROM v_fedstat_ipc
        WHERE series = 'ipc31074/Все товары и услуги'
          AND (region = 'Российская Федерация' OR date >= '2023-01-01')
    ),
    base AS (SELECT argMax(level, date) AS level FROM ipc),
    usd AS (
        SELECT toDate32(toStartOfMonth(date)) AS month, avg(value) AS usd_avg
        FROM v_cbr_macro
        WHERE series = 'cbr_currency_usd'
        GROUP BY month
    ),
    monthly AS (
        SELECT u.date AS date, u.value AS urals, d.usd_avg AS usd_avg, i.level AS ipc_level
        FROM v_minec_macro AS u
        INNER JOIN usd AS d ON d.month = u.date
        LEFT JOIN ipc AS i ON i.date = u.date
        WHERE u.series = 'urals_avg_price'
    ),
    filled AS (
        SELECT date, urals, usd_avg,
               anyLast(ipc_level) OVER (ORDER BY date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS level_used
        FROM monthly
    ),
    cur AS (SELECT max(date) AS date FROM filled)
SELECT
    round(anyIf(urals * usd_avg, date = (SELECT date FROM cur)), 0) AS "₽/барр.",
    round(100 * (anyIf(urals * usd_avg, date = (SELECT date FROM cur)) /
                 anyIf(urals * usd_avg, date = addYears((SELECT date FROM cur), -1)) - 1), 1) AS "г/г номинально, %",
    round(100 * (anyIf(urals * usd_avg * (SELECT level FROM base) / level_used, date = (SELECT date FROM cur)) /
                 anyIf(urals * usd_avg * (SELECT level FROM base) / level_used, date = addYears((SELECT date FROM cur), -1)) - 1), 1) AS "г/г реально, %"
FROM filled
SETTINGS join_use_nulls = 1
```

Живая проверка: `8 418`, `+93.8`, `+83.1` (окт-2025 номинал `53.68 × 80.9214 = 4 343.86`; реально `4 596.59`).

### 4.7. П6 — Нефтегазовые доходы, млрд ₽ (янв–сен 2026)

```sql
SELECT
    round(sumIf(value, toYear(date) = 2026), 0) AS "Янв–сен 2026, млрд ₽",
    round(100 * (sumIf(value, toYear(date) = 2026) / sumIf(value, toYear(date) = 2025) - 1), 1) AS "г/г, %"
FROM v_minfin_budget
WHERE source = 'minfin_oil_gas'
  AND series = 'Нефтегазовые доходы, всего'
  AND toMonth(date) <= 9
  AND toYear(date) IN (2025, 2026)
```

Живая проверка: `5 471` и `−17.2` (2025 янв–сен: `6 609.6`).

### 4.8. П7 — Нефтегазовые доходы федерального бюджета по месяцам, млрд ₽

2025 vs 2026, `source = 'minfin_oil_gas'`, `series = 'Нефтегазовые доходы, всего'`. Пивот по годам делает SQL: месяцы 1–12 по X, две числовые колонки-серии. У 2026 после сентября строк нет — `NULL`, а не `0` (иначе пустые месяцы рисовались бы нулевыми барами); честный ноль дохода отличить от пропуска в публикации нельзя, и это оговорено в описании панели.

```sql
SELECT
    toMonth(date) AS "Месяц",
    round(sumIf(value, toYear(date) = 2025), 1) AS "2025",
    nullIf(round(sumIf(value, toYear(date) = 2026), 1), 0) AS "2026"
FROM v_minfin_budget
WHERE source = 'minfin_oil_gas'
  AND series = 'Нефтегазовые доходы, всего'
  AND toYear(date) IN (2025, 2026)
  AND $__dateFilter(date)
GROUP BY "Месяц"
ORDER BY "Месяц"
```

Панель: `barchart`, `XField("Месяц")`, единица `units.Rubles`, `span 24`. Живая проверка: 2025 — `789.1, 771.3, 1081.3, 1085.6, 512.7, 494.8, 787.3, 505.0, 582.5, 888.6, 530.9, 447.8`; 2026 — `393.3, 432.3, 617.0, 855.6, 678.9, 683.6, 934.0, 424.0, 452.4, null, null, null`.

### 4.9. Панельные настройки и описания

- П3–П6 — `stat.NewPanelBuilder()`, `ReduceOptions(common.NewReduceDataOptionsBuilder().Calcs([]string{"lastNotNull"}).Values(false))`, `TextMode` auto; П5 показывает три поля одной строки (значение и два темпа), подписи полей приходят из SQL.

- Описание каждой панели — источник, зерно ряда, единицы и оговорки: П1 — «постоянные рубли сентября 2026, дефлятор ИПЦ, октябрь — оценка по дефлятору сентября; 2018-06/07 в источнике отсутствуют»; П2 — «$59 — цена отсечения бюджетного правила Минфина (до 2027), не ряд витрины»; П7 — «значения за месяц, не накопленным итогом; NULL после сентября 2026 — публикация ещё не вышла».

## 6. Ловушки данных

- Регион в `v_fedstat_ipc` после 2023 — новое определение РФ; литерал нового региона не сравнивается (нормализация юникода). Рабочий фильтр: `region = 'Российская Федерация' OR date >= '2023-01-01'` (старый регион кончается 2022-12).
- ИПЦ за октябрь-2026 не опубликован → октябрь считается по дефлятору сентября (перенос последнего уровня ИПЦ), как в блоге.
- `v_minec_macro.date` — `Date32` (1-е число месяца); курс — дневной `v_cbr_macro`, месячная средняя через `avg()` + `toStartOfMonth`.
- Дополнительно (следствия, проверено живыми запросами): в `v_minec_macro` **нет 2018-06 и 2018-07** — это разрыв, а не нули (строки не рисуются, `connectNulls: false`); `v_fedstat_ipc` за октябрь 2026 отсутствует; `v_minfin_budget` за октябрь–декабрь 2026 ещё пуст (`nullIf` в П7 превращает пустой `sumIf` в `NULL`, а не в `0`); `LEFT JOIN` в ClickHouse по умолчанию подставляет `0`, а не `NULL` — поэтому П1/П5 требуют `SETTINGS join_use_nulls = 1`.

## 8. Риски

- **Зависимость от `infra/5.14`.** Helper и пин версии плагина живут в 5.14; при обновлении плагина формат `options` сверяется по живому экспорту (конвенция Makefile), тест типа панели ловит смену ID плагина.
- **База дефлятора подвижна.** Когда Росстат опубликует ИПЦ за октябрь 2026, `base` сдвинется на октябрь, октябрьский маркер перестанет быть оценкой, а весь ряд пересчитается в «рубли октября». Это ожидаемое поведение определения (`level(последний опубликованный ИПЦ)`), но приёмочные числа §4 зафиксированы на базе сентября 2026 — в протоколе указывается дата базы. Если нужна несдвигаемая база — отдельный пункт (литерал базы в SQL) и правка спеки.
- **Константа `$59`.** Бюджетное правило действует до 2027; при смене параметра меняется одна константа с комментарием-источником + тест. Снижение до $50 с 2027 — не этот пункт.
- **Демпфер Минфина.** Ряда нет в витринах; публикационная метрика «2/3 доходов» на дашборде не воспроизводится — это осознанный гэп (следствие-импортёр), а не забытая панель.
- **Пропуски источника.** 2018-06/07 и октябрь–декабрь 2026 в бюджетном ряду: панели не подставляют нули; описание панели это оговаривает.
- **`SETTINGS join_use_nulls = 1`.** Меняет семантику `LEFT JOIN` только в этом запросе; без него октябрь получил бы нулевой дефлятор (проверено живым прогоном). При рефакторинге SQL настройку нельзя терять — на это есть тест `is_estimate = 1` для октября.
- **Дневной курс.** Месячное среднее считается по опубликованным дням; для октября 2026 — 23 дня (полный месяц). При неполном месяце средняя будет по факту вышедших дней — так же считает публикация.

## 9. Следствия и что не входит

- **Следствие 1 (отдельный пункт):** ряд демпфера Минфина (сумма демпфера за месяц, млрд ₽) в витринах отсутствует — нужен импортёр/ряд каталога, чтобы воспроизвести утверждение «демпфер ≈ 2/3 нефтегазовых доходов». В этот дашборд не входит.
- **Следствие 2:** если понадобится несдвигаемая база дефлятора (фиксированный сентябрь 2026) — параметр базы в SQL и тест; сейчас определение — «последний опубликованный ИПЦ».
- **Не входит:** изменения `grafana/echarts.go`, Makefile, CI, SQL импортёров, DDL, витрин и грантов; другие дашборды; staging-установка плагина (действие владельца).
