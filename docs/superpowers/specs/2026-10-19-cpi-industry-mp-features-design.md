# Отраслевые МП-признаки для компонентного nowcast ИПЦ: дизайн (2026-10-19)

**Пункт:** `key-rate/phase-4-ml-components`, Task 2 (issue [#235](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/235), родитель [#76](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/76)).
**Роль:** ML-инженер. Go-код, DDL, витрины, гранты и запись данных в ClickHouse не входят.
**Предшественник:** Task 1 — аудит публичной панели (issue [#234](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/234), PR [#244](https://github.com/kmlebedev/clickhouse-import-rosstat/pull/244)).
**Статус:** дизайн до реализации.

---

## 1. Задача

Проверить, дают ли 16 публичных отраслевых листов `mp_survey_data.xlsx` (IBK, ценовые ожидания, издержки) больше для компонентного nowcast ИПЦ, чем агрегатные признаки `cbr_survey`. Сравнение — на одних и тех же фолдах, с DM-HLN, блочным бутстрапом и MDE; незначимый результат публикуется как результат.

## 2. Входы

| Вход | Где | Объём / период |
|---|---|---|
| Отраслевой МП | публичный `https://www.cbr.ru/Content/Document/File/135603/mp_survey_data.xlsx` | 31 лист, 16 отраслевых × 297 месяцев, 2002-01…2026-09; IBK/ценовые ожидания/издержки raw+SA без пропусков |
| Агрегатный МП | `macro_series`, `source='cbr_survey'` через `cpi_monthly.load_survey` | 7 признаков v2 |
| Таргеты | `rosstat_ipc_mes` через `cpi_monthly.load_targets` | 4 ряда: общий ИПЦ, продовольствие, непродовольствие, услуги |
| Макро-контроли и недельные ряды | `cpi_monthly` / `cpi_monthly_v3` | база v2 + 4 недельных признака Stage 1 |

Отраслевые листы — **невесовые признаки**: публичного mapping «отрасль → код ИПЦ/вес» нет; публичный кроссворд 87 стандартных кодов ОКВЭД2 → 11 листов построен (Task 7 #248), но он отраслевой, а код-уровневых значений публичная книга не содержит. Весовое покрытие по листам не начисляется.

## 3. Признаки

- SA-блок (сезонно скорректированные данные) — сопоставим с `_sa`-признаками агрегатного МП; raw в этом пункте не используется.
- Три индикатора: IBK (headline, без «факт»/«ожид»), ценовые ожидания предприятий, издержки производства.
- На каждый лист и индикатор — уровень `M−1` и изменение `M−1 − M−2`.
- Итого 16 × 3 × 2 = **96 признаков**; имена `ind_<slug>_<ibk|price_exp|costs>_sa` и `…_sa_chg`.
- Отсутствующая точка/лист → NaN, не 0; строка выборки из-за industry-признака не выбрасывается.
- CatBoost обрабатывает NaN нативно; ElasticNet — импутация медианой train внутри фолда (колонка без наблюдений → 0.0 после стандартизации).

## 4. As-of / PIT

- cutoff месяца `M` — 8-е число `M+1`;
- доступность отраслевой точки `P` — конец `P+1` (`cpi_monthly.available_from_survey`), та же граница, что у агрегатного МП;
- на cutoff(M) доступны `M−1` и раньше; точка `M` не участвует;
- проверка: точка `M` не попадает в признаки даже при `date + 2 ≤ cutoff`; точка с `available_from > cutoff` игнорируется.

Винтажного архива нет: as-of — правило, а не фактические даты публикации. Это ограничение называется в отчёте.

## 5. Mapping отрасль → компонент

Публичного mapping нет, поэтому фиксируется **prior** (допущение о канале переноса), а не веса:

| Группа | Листы |
|---|---|
| `food` | Сельское хозяйство; Обработка_потребительские; Торговля розничная (47) |
| `nonfood` | Промышленность; Добыча; Обработка; Обработка_инвестиционные; Обработка_промежуточные; Строительство; Торговля авто (45) |
| `services` | ЭЭГП; Водоснабжение; Транспортировка и хранение; Услуги |
| `general` (во все компоненты и в direct) | Торговля (45+46+47); Торговля оптовая (46) |

Robustness-вариант `all` использует все 16 листов для каждого компонента и проверяет, не держится ли вывод на этом prior.

## 6. Выборки и фолды

| Выборка | Окно | Start | Фолды | Роль |
|---|---|---:|---:|---|
| `long` | 2013-10…2026-08 | 48 | 107 | primary: отраслевая панель полна, разреженности недельных рядов нет |
| `weekly` | 2022-01…2026-08 | 24 | 32 | secondary: сопоставимость со Stage 1 и свежий режим |

Строки и фолды общие для всех моделей: `build_sample_industry` вызывает `cpi_monthly_v3.build_sample_v3` и добавляет industry-признаки. Walk-forward только расширяющимся окном; random split запрещён.

Для `long` официальный прогон использует сокращённый набор (`v2_bottomup`, `v3_bottomup`, `ind_only_bottomup`, `v3_ind_bottomup`, `B1`): direct-модели, `ind_bottomup` и `v3_ind_all_bottomup` дороги и уже проверены на `weekly`; это робастность primary-контраста, а не полный перебор.

## 7. Модели

| Имя | Признаки | Роль |
|---|---|---|
| `v2_baseline` / `v2_bottomup` | база v2 + 7 агрегатных МП | baseline, регрессионный гейт |
| `v3_direct` / `v3_bottomup` | v2 + 4 недельных | Stage 1, регрессионный гейт |
| `ind_direct` | v2 + все 96 industry | direct-эффект industry |
| `ind_bottomup` | v2 + mapped industry | инкремент над агрегатным МП |
| `ind_only_bottomup` | база без агрегатного МП + mapped industry | aggregate vs industry |
| `v3_ind_direct` | v3 + все 96 industry | direct + weekly + industry |
| `v3_ind_bottomup` | v3 + mapped industry | главный кандидат |
| `v3_ind_all_bottomup` | v3 + все 96 для каждого компонента | robustness mapping |
| `B1`, `B2`, `B3`, `B3_weekly` | как в `cpi_monthly` / `cpi_monthly_v3` | бенчмарки |
| `B3_ind` | база без агрегатного МП + mapped industry, ElasticNetCV | линейная проверка |

CatBoost — дефолты, `random_seed=20261018`, `month` категориальным, без тюнинга по тесту. NNLS-веса — по обучающему окну фолда, нормированы к 1.

## 8. Метрики и решение

- RMSE/MAE (п.п. м/м, h1), DM-HLN (`eval_utils.diebold_mariano`), парный блочный бутстрап разницы RMSE (блок 3, n=2000, seed 20261018), MDE при 80 % мощности.
- Primary-семейство из 2 контрастов (Holm): `v3_ind_bottomup` vs `v3_bottomup`; `ind_only_bottomup` vs `v2_bottomup`.
- Secondary: direct-контрасты, `v3_ind_all_bottomup` vs `v3_ind_bottomup`, `weekly`, `B3_ind` vs `B3`; p-values показываются, но вердикт по ним не выносится.
- `promote`: оба primary-контраста не хуже, хотя бы один значим (DM p < 0.05 или 95 % CI Δ исключает 0), значимой деградации нет, `all`-вариант согласен по знаку.
- `iterate`: направление положительное, но значимости/мощности нет, либо значим только один контраст.
- `reject`: улучшения нет или значимая деградация.
- Регрессионный гейт: `v2_bottomup`/`v3_bottomup` воспроизводят Stage 1 (`weekly` 0.362300 / 0.311487; `long` start 48 0.688869 / 0.642997) с допуском 1e-6; расхождение — разбор. Артефакты пишутся до проверки гейта, чтобы расхождение не уничтожало посчитанные результаты. Если паспорт Stage 1 `git_dirty=1` или его SHA отличается, baseline пересчитывается текущим кодом, а абсолютные числа Stage 1 используются только как исторические; это называется в отчёте. Гейт применим только к официальному окну Stage 1 (`start` по умолчанию для выборки, `embargo=0`); на сокращённом/отладочном окне он помечается `skipped`, а не сравнивает чужие числа.
