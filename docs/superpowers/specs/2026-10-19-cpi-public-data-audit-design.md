# Аудит публичной панели ИПЦ: дизайн (2026-10-19)

**Пункт:** `key-rate/phase-4-ml-components`, Task 1 (issue [#234](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/234), родитель [#76](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/76)).
**Роль:** ML-инженер (аудит данных; прод-код и схема не меняются).
**Статус:** дизайн до реализации.

---

## 1. Задача

До моделирования зафиксировать публичную панель ИПЦ и её mapping на компоненты/группы: какие ряды есть, что они измеряют, какова глубина и покрытие весов, какие PIT/as-of ограничения. Решение — достаточно ли покрытия для полного bottom-up (≥50 % весов) или только для hybrid «4 официальных компонента + признаки».

Сырые `rosstat_ipc_mes`, `v_rosstat_macro` и каталог — только чтение. Внутренняя панель ЦБ (87 кодов ОКВЭД2, `model.xlsx`, BSU, `panel.csv`) не используется.

## 3. Нормализатор и mapping

Сопоставление — с **именами весов** (они несут код и вес), а не с именами словаря.

1. `raw` — точное совпадение строк.
2. `basic` — lower, `ё → е`, пунктуация/пробелы схлопываются.
3. `extended` — плюс снятие скобочных уточнений и единиц: `шт|кг|л|мл|г|м3|м2|пара|пачка|рулон|день|сутки|поездка|услуга|человека|таблеток|таблетки|драже`.

Основной результат — `extended`: 118 совпавших рядов/кодов, 30 несопоставленных. Сырых точных — 111, `basic` — 113. Число «112 точных» из Stage 1 текущим алгоритмом не воспроизводится; отчёт фиксирует все три числа и не подгоняет результат.

Покрытие = сумма весов совпавших листовых кодов (`уровень=7`, `окато_код=643`) / сумма всех листовых весов года; агрегат `1` в знаменатель не входит. Считается для 2016–2024 и по компонентам `уровень_2`: `6` — продовольствие, `7` — непродовольствие, `9000` — услуги.

## 4. Отраслевой МП

16 отраслевых листов × 3 индикатора (IBK, ценовые ожидания, издержки) × raw/SA. Публичного mapping «отрасль → код ИПЦ» без 87 кодов ОКВЭД2 нет, поэтому весовое покрытие по МП-листам **не начисляется**: в таблице `weight = "—"`, `basis = "feature, not weighted"`, компонентный prior — только допущение Task 2.

## 5. PIT/as-of

- cutoff месяца `M` — 8-е число `M+1`;
- недельная точка доступна с `date + 2`; в признаки попадают только точки с `date + 2 ≤ cutoff`;
- месячная метка `M` доступна не раньше конца `M+1`; на cutoff 8-го `M+1` она не участвует;
- проверка: 0 нарушений на 2013-10…2026-08; официальные значения используются только ex post для сверки, не как признаки.

Винтажного архива `rosstat_ipc_mes`/weekly нет; PIT проверяется на уровне правила cutoff, а не фактических дат публикации. Это ограничение называется явно.

## 6. Компаундирование недель

`monthly_index = Π(value_i/100)`, `m/m = monthly_index − 1`. Проверка — по агрегатному недельному ряду 2009-04…2021-12 против официального месячного m/m: MAE/RMSE/max. С 2022 г. агрегатного недельного ряда нет; для 2022+ допускается только coverage-limited диагностика по 118 совпавшим товарным рядам, не bottom-up.

## 7. Решение

Гейт полного bottom-up — покрытие ≥50 % весов. При 39,3 % (услуги 29,0 %) полный 88-групповой bottom-up не заявляется; режим — **hybrid** «4 официальных компонента + признаки». Частичный bottom-up — только robustness-проверка с названным покрытием.
