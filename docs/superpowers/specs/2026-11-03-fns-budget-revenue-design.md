## 1. Контекст и критерий

Критерий пункта: `fns_budget_revenue` + витрина — поступления **по видам налогов, РФ и субъекты, месячно**; перекрёстный контроль с доходами консолидированного бюджета в `v_minfin_budget`, расхождение объяснено в описании ряда; `series_catalog`, `GRANT`.

Сейчас фискальный контур в базе — одна строка: `v_minfin_budget`, `source = 'minfin_mesyats'`, `series = 'Доходы, всего'` (188 точек, 2011-01 … 2026-08, млрд руб. за месяц). Налоговой структуры нет ни в одной таблице, данных ФНС — ни в одной.

### 2.3. Содержимое `…reg.zip` и разбираемый файл

Внутри 8–9 файлов с cp866-именами: `11О Поступление налогов по территориям.xlsx` (с 2023 — `11О ЕНС Поступление налогов по территориям…xlsx`), `12О Начислено…`, `21О/22О/31О`, `SP1/SP2`, `Раздел4/Раздел5`. Разбирается **только `11О`** — поступления по территориям.

| Свойство | Наблюдение |
|---|---|
| Листы | имена — диапазоны кодов строк (`1000`, `1010-1020`, `1130-1151`, `1610-1626`, …); в 2020-книге есть служебные `hidden1…hidden6` и `Фед-Рег`, `Мест-Спец` |
| Шапка листа | строки заголовков, затем **строка-якорь:第一 колонка = `А`**, в ней — коды колонок `<код>` или `<код>.<n>`; заголовки уровней — в строках выше того же столбца |
| Уровни бюджета | `Всего` (= федеральный + консолидированный субъекта) / `в федеральный бюджет` / `в консолидированный бюджет субъекта РФ` / `из него — в доходы местных бюджетов` (последний — часть третьего, не аддитивен) |
| Строки | `РОССИЙСКАЯ ФЕДЕРАЦИЯ`, служебная `в том числе:`, 8 федеральных округов, 85 субъектов = 94 территории (в 2020 и 2026 совпадает) |
| Единицы | тыс. рублей |
| Семантика | **накопленным итогом с начала года** (не за месяц). Проверено: as-of 01.09.2026, код 1010, РФ: всего 31 696 941 451 = федеральный 18 129 843 421 + консолидированный 13 567 098 030; годовой as-of 01.01.2026 за код 1000: всего 46 326 666 317 тыс. руб. |
| Перекрёсток с `1nm<as-of>.xlsx` | Раздел I федеральной книги даёт те же федеральный/консолидированный значения тех же кодов — `11О` согласован с ней |
| Особые значения | отрицательные (уточнения/возвраты) — нормальны; литеральные `X` и `-` — «нет данных», не точка |

### 2.4. Покрытие и дрейф

* **70 artifacts в окне 2020-01 … 2026-08**, отсутствие источника: 2023-01…07, 2023-09, 2024-01, 2024-02 (2026-09 на 2026-11-03 ещё не опубликован). Месяцы не фабрикуются; в помесячной витрине месяц после разрыва отдаёт `NULL`, а не ноль и не сумму за два месяца.
* **Ревизии** (`ut`) замечены для 2021-01…04 (`ut_1nm01022021reg.zip`), 2023-12, 2024-06 и 2024-07 (`1nm010724ut_reg.zip`): источник перепубликует отчёт, подменяя файл на странице. Оригинала и ревизии одного месяца одновременно на странице не наблюдалось, поэтому предпочтение ревизии — защита, а не рабочая необходимость.
* **Формат внутренних файлов**: 2018–2019 — legacy `.xls` (BIFF), с 2020 — `.xlsx`. По решению владельца бэкфилл начинается с **2020-01**, читается только `.xlsx`; 2018–2019 через `shakinm/xlsReader` (прецедент `minfin/debt_stock_parse.go`) — отдельный пункт.
* **Названия территорий дрейфуют**: 7 написаний разошлись между 2020 и 2026 (`г. Москва` ↔ `город Москва`, `Чукотский автономный округ` ↔ `Чукотский АО`, `Ненецкий АО`, `Ханты-Мансийский АО - Югра`, `Ямало-Hенецкий АО` — с латинской `H`). Лечатся каноническим списком и таблицей написаний (§3.5); таблицы строятся из точных написаний источника одной функцией нормализации, чтобы опечатка в ключе не могла остаться живучей (тест `TestFnsTerritoryTablesAreNormalized`).
* **Состав строк листа тоже дрейфует** (скан всех 70 архивов, 2026-11-03): в ревизии декабря 2023 года к 94 стандартным строкам добавлены четыре новых субъекта (Донецкая Народная Республика, Луганская Народная Республика, Запорожская область, Херсонская область — все со значением `х`, то есть без данных) и две не-территориальные строки: «Юго-Западные субъекты» (группировка со значениями по 4 рядам группы `1200`) и «МИ ФНС РОССИИ ПО УПРАВЛЕНИЮ ДОЛГОМ» (администратор поступлений со значениями по всем 47 рядам — 32,46 млрд тыс. руб. по строке 1000). Четыре субъекта добавлены в канонический список, две строки объявлены исключениями: иначе прогон падал на неизвестной территории, а наивный приём добавил бы 51 точку группировки и администратора в региональный разрез.
* **Маркер «нет данных» пишется двумя начертаниями**: латинская `X` и кириллическая `х` (U+0445, ревизия 2023-12) — без сравнения по обоим разбор падал на `х` как на нечисле.
* **Уровни колонок нестабильны у мелких кодов**: у `1610` (налог на игорный бизнес) в 2026 колонка подписана `1610.2` с заголовком «в федеральный бюджет», а в 2020 — `1610.3` «в консолидированный бюджет субъекта». Такие коды в набор не входят (§3.4).

## 3. Решение

### 3.1. Адресация

```text
пакет:        fns/                    (ФНС; будущие 1.8 → fns_tax_burden, 1.9 → fns_tax_arrears — сюда же)
импортёр:     fns_budget_revenue      (Name(), TableName, CLICKHOUSE_IMPORT_STAT, id шага dagu)
таблица:      fns_budget_revenue      (Name() == TableName)
source:       'fns_budget_revenue'    (в series_catalog и в витрине — как у импортёров собственных таблиц)
витрины:      v_fns_budget_revenue          (как опубликовано, накопленное с начала года)
              v_fns_budget_revenue_monthly  (за месяц — разность накопленных)
env:          FNS_1NM_FROM=YYYY-MM — ремонт/бэкфилл с отчётного месяца включительно (по умолчанию 2020-01)
```

Имя пакета и таблицы фиксируются этой спекой до ветки (go-engineer §5.1).

### 3.2. Схема

Новая таблица, канонический DDL (§6.2 `ARCHITECTURE.md`, правка до кода):

```sql
CREATE TABLE IF NOT EXISTS %s (
    date Date,                       -- 1-е число отчётного месяца = as-of минус месяц
    region LowCardinality(String),   -- каноническое название территории из декларированного списка
    region_kind LowCardinality(String), -- rf | federal_district | subject
    series LowCardinality(String),   -- стабильный идентификатор: вид налога + уровень бюджета
    value Float64                    -- тыс. руб., накопленным итогом с начала года (как опубликовано)
) ENGINE = ReplacingMergeTree ORDER BY (series, region, date);
```

Хранится **только то, что публикует источник** (накопленное). Помесячное значение — производное, его считает витрина (§3.6): парсер не читает базу и остаётся офлайн-тестируемым (стандарт §6.1), а пропуск месяца не превращается в фантомную точку. Ревизия (`ut`) пишет те же ключи и перекрывает оригинал после мержа (`FINAL`).

### 3.3. Импортёр: цикл и инкремент

`fns/budget_revenue.go`, `fnsBudgetRevenue{util.ClickHouseImport}` с собственным `Import()` (артефактов много — прецедент `minfin_ofz_auction`, `cbr/cbr_dip_bulletin`):

1. DDL (цикл `CreateTable`).
2. `util.GetPage(fnsFormsURL)` → `fnsYearLinks(page)`: строки блока `#t1`, ячейка с `1-НМ`, относительные ссылки годов. Ни одной ссылки — ошибка (стандарт §4.4).
3. Для каждого года, чей отчётный период пересекается с окном `[start; ∞)`, — `util.GetPage` годовой страницы → `fnsMonthlies(page)`: все `href` с `reg.zip`, нормализация `\` → `/`, абсолютный адрес от хоста страницы (тот же `www.nalog.gov.ru`, который отдаёт и файлы — `data.nalog.ru` дублирует тот же контент, но перебивка хоста лишила бы тест возможности подменить источник локальным сервером), разбор as-of-даты из имени, отчётный месяц = as-of − 1 месяц, выбор ревизии. Имя без распознаваемой даты — предупреждение и пропуск (не ошибка: источник добавляет артефакты других форм), распознаваемая дата `as-of ≠ 1-е число` или дата дальше двух месяцев вперёд — пропуск (артефакт с годом из будущего отсёк бы все настоящие месяцы стартом `max(date)+1`). **Пустая страница завершившегося года (от `fnsFirstYear` до прошлого) — ошибка прогона**: если источник переименует архивы, молчаливый ноль держал бы dagu зелёным при остановленном контуре; для текущего года пустая страница легитимна.
4. **Гейт по множеству месяцев**: `SELECT DISTINCT date FROM fns_budget_revenue FINAL ORDER BY date` (один запрос; FINAL — иначе несмёрженные части ревизии дали бы «известный» месяц дважды). Обычный прогон не качает месяцы, которые уже лежат в таблице. `FNS_1NM_FROM` задан → `start` = этот месяц включительно **и** известные месяцы окна перечитываются (режим ремонта: без перечитывания ревизия уже импортированного месяца была бы не видна, а «путь ремонта» остался бы обещанием); неразобранное значение — ошибка прогона. Иначе пустая таблица → `start = 2020-01`, непустая → `max(date) + 1 месяц`. Режим `ARCHIVE_ACTION=restore` отвергается в начале `Import()` явной ошибкой: точек контроля публикации нет, значит нет и версий в архиве (§9.6) — иначе команда сначала обошла бы источник и упала бы на внутреннем шаблоне.
5. Каждый новый месяц — внутренний `util.ClickHouseImport{TableName, CreateTable, DataUrl, BodyFunc}` (прецедент `ofz_auction`): шаблон качает байты зипа, отдаёт их разбору, ведёт батч и `AfterImport`.
6. `AfterImport` публикует каталог и обе витрины один раз на прогон: у внутренних шаблонов `AfterImport` nil, публикация — в конце внешнего `Import()`, чтобы не пересоздавать витрину 70 раз при бэкфилле. При нуле новых месяцев производные всё равно публикуются — по прецеденту `rosstat_ipc_weeks_bulletins`, иначе первая пустая база не получит витрину.
7. Логи — logrus: `Imported %d rows of fns_budget_revenue`.

Точка контроля публикации **не объявляется**: артефактов много, HEAD одного URL не отвечает на вопрос «что уже разобрано» (стандарт §9.3; прецеденты `minec_urals_price`, `cbr_mp_summary`). no-op доказывают гейтом (§3.3.4) и повторным прогоном. Винтажного архива нет (§9.6 требует объявленной точки контроля) — **названное отступление**: `make archive-restore STAT=fns_budget_revenue` для импортёра не поддерживается.

### 3.4. Набор рядов (курируемый, по решению владельца)

Ряд = пара (код строки, уровень). Объявлены пары, подтверждённые **в обоих опорных годах** (2020-02 и 2026-09) и смыслово согласованные с подписями колонок: 13 кодов, 47 рядов.

| Код | Название источника | series-стаб | уровни |
|---|---|---|---|
| 1000 | Доходы, администрируемые налоговыми органами | `admin_revenues` | total, federal, regional, local |
| 1010 | Налоговые и неналоговые доходы | `tax_nontax_revenues` | total, federal, regional, local |
| 1020 | Налоговые доходы | `tax_revenues` | total, federal, regional, local |
| 1030 | Налоги на прибыль, доходы | `profit_income_taxes` | total, federal, regional, local |
| 1040 | Налог на прибыль организаций | `profit_tax` | total, federal, regional, local |
| 1130 | Налог на доходы физических лиц | `ndfl` | regional, local |
| 1200 | Налоги на товары (работы, услуги), реализуемые на территории РФ | `goods_taxes` | total, federal, regional, local |
| 1210 | НДС на товары (работы, услуги), реализуемые на территории РФ | `vat_domestic` | federal |
| 1220 | Акцизы по подакцизным товарам, производимым на территории РФ | `excise_domestic` | total, federal, regional, local |
| 1720 | Налоги, сборы и регулярные платежи за пользование природными ресурсами | `resource_taxes` | total, federal, regional, local |
| 1730 | Налог на добычу полезных ископаемых | `ndpi` | total, federal, regional, local |
| 1970 | Задолженность и перерасчёты по отменённым налогам, сборам и иным обязательным платежам | `abolished_taxes` | total, federal, regional, local |
| 2370 | Неналоговые доходы, администрируемые налоговыми органами | `nontax_revenues` | total, federal, regional, local |

`series` = `<стаб>_<уровень>` (`ndfl_regional`, `vat_domestic_federal`, `admin_revenues_total`). Уровни: `total` = всего (федеральный + консолидированный субъекта), `federal` = в федеральный бюджет, `regional` = в консолидированный бюджет субъекта РФ, `local` = из графы «региональный» в доходы местных бюджетов (не аддитивен к `total`).

Пары, не входящие в набор (в т. ч. `1130_total`/`1130_federal`, `1610`, `1230`–`1250`, `1845`, `2000`, мелкие КБК и строки-подстроки), **игнорируются разборкой** — это осознанное ограничение, чтобы каталог оставался читаемым (правило 11), а не «забыли». Полный матрикс кодов источника — отдельный пункт роадмапа.

### 3.5. Разбор (`fns/budget_revenue_parse.go`, без сети)

`fnsParseBudgetRevenue(body []byte, batch driver.Batch) error`:

1. `zip.NewReader(bytes.NewReader(body))`; выбор внутреннего файла по признаку: имя содержит `11` + `Поступлен` + `территори` и оканчивается на `.xlsx` (регистронезависимо, с декодированием cp866-имён и снятием числовой приставки `79732178_`). Ни одного — ошибка с именем таблицы; несколько — ошибка (неоднозначность).
2. `excelize.OpenReader`; обход листов: пропускаются скрытые (`GetSheetVisible`) и листы без строки-якоря.
3. Строка-якорь — первая в пределах шапки (первые 20 строк), у которой `cells[0] == "А"`. В ней собираются `(код, суффикс)` по регулярке `^(\d{3,4})(?:\.([1-4]))?$` (суффикс без указания = `1`).
4. Уровень — по **суффиксу** (это собственная нумерация колонок источника: 1 = всего, 2 = федеральный, 3 = консолидированный субъекта, 4 = местные). Подпись колонки (ближайшая непустая ячейка того же столбца выше якоря) проверяется по ключевым словам (`всего`/`федеральн`/`консолидирован`/`местн`); при конфликте — **warn и импорт** (прецедент подписи-артефакта у `1610` §2.4), потому что идентификатором столбца в файле остаётся суффикс.
5. Территория: строки после якоря, `cells[0]` ≠ пусто. Служебные (`в том числе:`, пустые) — пропуск; объявленные не-территориальные строки (`fnsTerritoryExcludedSpellings`: «Юго-Западные субъекты», «МИ ФНС РОССИИ ПО УПРАВЛЕНИЮ ДОЛГОМ» — обе только в ревизии 2023-12) — пропуск с debug-логом, потому что их значения задвоили бы региональный разрез. Название проходит канонизацию: `fnsNormalizeTerritory` (нижний регистр, `ё`→`е`, без пунктуации и пробелов), затем канон `fnsTerritoryNames` (1 РФ + 8 ФО + 85 субъектов + 4 новых субъекта ревизии 2023-12), затем `fnsTerritoryAliasSpellings` (8 написаний других лет, включая «Ямало-Hенецкий АО» с латинской `H`). Обе таблицы строятся из точных написаний источника одной функцией нормализации — ключей, набранных вручную, в коде нет. Класс `region_kind`: `РОССИЙСКАЯ ФЕДЕРАЦИЯ` → rf, суффикс «федеральный округ» → federal_district, остальное → subject. **Неизвестное название — ошибка прогона** с текстом названия: молча потерять целый субъект в фискальной таблице хуже, чем упавший шаг изолированного DAG, а правка — одна строка в таблице написаний (спека §2.4 показывает, что такие строки у источника бывают: именно так были объявлены четыре новых субъекта и две не-территориальные строки).
6. Значение: `excelize.Options{RawCellValue: true}` (стандарт §6.2); пустая ячейка, `-`, `—`, латинская `X`/`x` и кириллические `Х`/`х` — не точка (§6.7; кириллический маркер найден живым прогоном на ревизии 2023-12); неразобранное число там, где ожидалось число — ошибка с названием территории, листа и колонки (§6.4); `strconv.ParseFloat` с проверкой, разделители разрядов (обычный, NBSP, узкий пробел) снимаются, десятичная запятая поддерживается.
7. Контроль структуры листа по классам: ровно одна строка rf, ровно 8 федеральных округов, не меньше 85 субъектов. Верхняя граница не проверяется: ревизия 2023-12 добавляет четыре новых субъекта (без значений). Меньше — ошибка прогона с фактическими счётчиками.
8. Точка: `Append(date, region, regionKind, series, value)`; один `PrepareBatch` на артефакт, `Abort` на пути ошибки; `panic` нет, индексы проверяются.

## 4. Перекрёстный контроль с Минфином (часть приёмки, текст идёт в `description`)

Окно сравнения — 2020-01 … 2026-08 (данные Минфина с 2011-01, ФНС с 2020-01). Сопоставляются: год ФНС = **декабрьское накопленное** строки РФ «всего» из `v_fns_budget_revenue` (за 2026 — августовское; сумма помесячных разностей была бы меньше на пропущенные публикации) против годовой суммы `v_minfin_budget` (`source = 'minfin_mesyats'`, `series = 'Доходы, всего'`), единицы приводятся: тыс. руб. / 1e9 = трлн руб. против млрд руб. / 1000.

Разложение ожидаемого расхождения (фиксируется числами в протоколе и в `description`):

1. Минфин считает консолидированный бюджет Российской Федерации **с государственными внебюджетными фондами**, ФНС — только доходы, администрируемые налоговыми органами.
2. Таможенные доходы (пошлины, НДС на ввозимые товары, администрируемые ФТС) в 1-НМ не входят.
3. Неналоговые и иные доходы бюджетов, администрируемые не ФНС.
4. Ревизии (`ut`) и уточнения прошлых периодов: ФНС перепубликует отчёт, Минфин — файл месяца.

Наблюдение 2025: Минфин 75,574 трлн руб. против ФНС 46,33 трлн руб. (федеральный 26,62 + консолидированный субъекта 19,70) — расхождение ≈ 29 трлн руб. объясняется п. 1–3.

Сверка по всем годам окна (живая приёмка 2026-11-03, трлн руб.; ФНС — строка РФ «всего» за год, то есть **декабрьское накопленное**: в 2023 и 2024 у источника пропуски помесячных публикаций, и сумма доступных разностей (6,98 и 33,40) была бы меньше года на пропущенные месяцы; «месяцы» — сколько помесячных значений отдаёт витрина):

## 7. Ограничения и отступления

* Курируемый набор (47 рядов из ~716 колонок-кодов листа `11О`) — решение владельца 2026-11-03; остальное не импортируется и в каталоге не числится.
* Бэкфилл с 2020-01: 2018–2019 требуют чтения legacy `.xls` — отдельный пункт.
* Страховые взносы (Раздел IV 1-НМ, `Раздел4…xlsx` в том же зипе) — вне пункта; критерий говорит о налогах, и смешение уровней исказило бы сверку с Минфином.
* Точки контроля публикации нет (§9.3), винтажного архива нет (§9.6) — названное отступление; no-op доказывается гейтом по месяцам.
* PIT не заявляется: дата публикации артефакта не хранится, `date` — отчётный месяц; пересборка ревизий (`ut`) перекрывает предыдущее значение того же ключа.
* Обход зависит от строки-якоря `А` и подписей колонок: смена вёрстки — ошибка прогона, а не «0 строк»; дрейф 2020↔2026 закреплён двумя фикстурами.
* Неизвестное название территории — ошибка (обоснование в §3.5.5), а не warn.

## 8. Вне объёма

* `1.8` (налоговая нагрузка) и `1.9` (задолженность, формы 4-НМ/4-НОМ) — отдельные пункты; пакет `fns/` для них общий.
* Годовые открытые данные ФНС (`nmpn`, `poved`, `nacm`, `nacp`) — не импортируются; `nmpn` остаётся доступной кросс-проверкой годовых сумм.
* Региональные страницы `rn<код>` (отчёты отдельных УФНС) — не краулятся: тот же разрез даёт один федеральный `reg.zip`.
* Дашборд по новому источнику — вне пункта (по необходимости — пункт `infra`/`dashboard-migration`).
