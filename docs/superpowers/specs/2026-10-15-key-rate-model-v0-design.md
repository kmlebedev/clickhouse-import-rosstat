## 1. Зачем

Контур ключевой ставки после фаз 1–2 собрал входы: ставку, инфляцию и её SA-версии, ожидания, рынок труда, кредит, бюджет, курс, рыночную вменённую траекторию KEYRATE, резюме ЦБ. 2. **обязательную лестницу бенчмарков** (порядок фиксируется до результатов);
3. **метод №2** — имплицитное инерционное правило Тейлора;
4. **метод №3** — упорядоченную логит-модель решения (MLE);

## 2. Предусловие: календарь заседаний 2014–2019 (Go, `calendar/`)

### 2.1 Что нашли

Страница `cbr.ru/dkp/cal_mp/` (и фикстура `calendar/testdata/cal_mp.html`, снята 2026-10-14) содержит **вкладки лет 2014–2027**. Разметка трёх эпох:

- **2014–2018** — таблицы `<table class="data">` в панелях вкладок: дата вида `14 февраля` (без года) с `rowspan` на строки события;
- **2019** — карточки `div.main-events_day` с датой без года (`8 февраля`);
- **2020+** — карточки с полной датой (`13 февраля 2026 года`) — их и читает текущий `parseCalMP`.

Год виден в лейбле вкладки: `a.tab[href="#<key>"]` с `data-text="YYYY год"`; содержимое — панель `[data-tabs-content="<key>"]` (`id="tab_content_<key>"`). Текущее поведение (2020+) обязано сохраниться бит-в-бит; расширение — аддитивное.

### 2.2 Правила разбора

| Правило | Формулировка |
|---|---|
| Год | из вкладки; панель без вкладки (или вкладка без года) — содержимое пропускается (не ошибка) |
| Карточки без года (2019) | дата `D месяца` + год панели |
| Таблицы (2014–2018) | дата из первой колонки (`D месяца`, в т.ч. с `rowspan` — действует до следующей даты), событие из второй колонки |
| Предикат заседания старой эры | «заседание совета директоров» ∧ («по вопросам денежно-кредитной политики» ∨ «ключевой ставке»), регистронезависимо; «Внеочередное заседание …» входит |
| Дедуп | по дате; пересечение эпох (если год выложен дважды) схлопывается |
| Fail-fast | как сейчас: 0 дат по странице — ошибка |

## 3. Выборка решений

Единица наблюдения — заседание. Источники: `events_calendar` (канонические строки: `category='cbr'` ∧ `title='СД ЦБ РФ: заседание по ключевой ставке'` — ручные строки-триггеры отсекаются по `title`), `cbr_key_rate` (дневной ряд действующих ставок).

**Исход заседания на дату `d`:**

- `rate_before` = ставка, действующая на `d − 1` (решение публикуется в 13:30 и вступает в силу со следующего дня; у внеочередных 2014-03-03 и 2014-12-16 — в тот же день, и `d − 1` защищает и этот случай);
- `rate_after` = ставка, действующая на `min(d + 7, next_meeting − 1)`, где `next_meeting` — следующее заседание выборки (защита от двух решений в одном окне: 2014-12-11/16, 2014-12-16/2015-01-30 и т.п.);
- `step_bp` = `round((rate_after − rate_before) × 100)`; класс `y3` ∈ {−1 снижение, 0 сохранение, +1 повышение}.

**Сверка ярлыков:** для заседаний, присутствующих в `cbr_mp_summary` (22 резюме с февраля 2024), при непустом `decision_delta_bp` шаг обязан совпасть; расхождение — ошибка прогона (fail-fast), а не строка отчёта.

Ожидаемый размер выборки: 108 прошедших заседаний (2014-02-14 … 2026-09-11), из них цикл 2024–2026 — 24.

## 4. Признаки и as-of слой (v0)

**Гипотеза модели** — инерционная форма: `i_t = c + ρ·i_{t−1} + a·π_t + b·gap_t`. Три признака, набор фиксирован до результатов, тюнинга по тесту нет ([KEY_RATE_MODEL.md](../../KEY_RATE_MODEL.md) §6.1: «только простые модели (2–3 признака)»):

| Признак | Ряд | Период | Правило доступности (v0) |
|---|---|---|---|
| `rate_before` | `cbr_key_rate` | день | доступен в день действия (лага нет) |
| `pi_saar` | `cbr_indicators_cpd`, серия **«Базовый ИПЦ»** (SA м/м, %); приводится к годовому: `((1 + x/100)^12 − 1)×100` | конец месяца M | конец месяца **M+1** (консервативно; фактическая публикация — во второй декаде M+1) |
| `gap` | `macro_series(source='cbr_survey', series='business_climate_sa')` — ИБК ЦБ SA, пункты (прокси разрыва выпуска) | 1-е число отчётного месяца M | конец месяца **M+1** |

- As-of выбирает **последнюю точку** с `available_from(period) ≤ дата заседания`; если ряда нет вовсе (нет точки раньше) — заседание **исключается** из выборки и перечисляется в отчёте (счётчик «пропущено»).
- Правила доступности — константы кода с комментариями; тесты пинуют: (а) значение, опубликованное позже даты заседания, не используется (синтетические точки); (б) границы (точка ровно на дату заседания / ровно в конце M+1).
- **Это приближение, а не point-in-time слой.** Ревизии объясняющих рядов и точные даты публикаций здесь не учтены; полноценный PIT-слой — следующий пункт фазы 4 (после `cbr_dip_bulletin`). В отчёт — раздел «что не проверено».
- 2024+ дополнительно несут `cbr_infl_exp`, Брент и прочие каналы — вне v0 (см. §11).

## 5. Обязательные бенчмарки (порядок фиксируется заранее)

| # | Бенчмарк | Прогноз шага |
|---|---|---|
| B1 | «ставка не изменится» | 0 б.п. |
| B2 | «повтор последнего решения» | шаг предыдущего заседания выборки |
| B3 | AR(1) на уровне ставки: `i_t = c + φ·i_{t−1}` (OLS, HAC), обучение на окне | `pred_level − rate_before` |

Распределений B1–B3 не дают (вырожденные) → в вероятностных метриках не участвуют; в классификационных — участвуют (`sign(step)`).

## 6. Методы №2–3

**Метод №2 — инерционное правило Тейлора.** OLS `i_t` на `[1, rate_before, pi_saar, gap]`, ковариация HAC (Newey–West, `maxlags=4` заседания ≈ полугодие, small-sample correction включена). Прогноз уровня → шаг `pred_level − rate_before`. Свободные коэффициенты — форма свободной оценки; долгосрочные импликации (r*, α, β) докладываются в отчёте, но не ограничиваются.

**Метод №3 — упорядоченная логит-модель решения.** statsmodels `OrderedModel` (`distr='logit'`) на тех же трёх регрессорах, классы упорядочены {−1, 0, +1}. Выход — `P(снижение)`, `P(сохранение)`, `P(повышение)`. Точечный шаг для сведения к общему ряду метрик: `E[step] = Σ_c P(c)·μ_c`, где `μ_c` — средний шаг класса на обучающем окне (`μ_0 = 0`). Вырожденное окно (в обучающей части меньше двух классов) — метод на этом шаге пропускается с записью в отчёт.

Байесовская версия приоритетов (pymc/bambi) и «inflated»-версия — отдельные подпункты роадмапа (решение владельца 2026-10-15).

## 7. Walk-forward, метрики, тесты значимости

- **Walk-forward, единый train/test split запрещён.** Два прогона: расширяющееся окно (минимум 24 заседания в обучении) и скользящее (окно 40 заседаний); обе схемы докладываются как проверка робастности, выбор окна по ошибке не делается. Каждый шаг — переобучение только на прошлом, прогноз h=1.
- **Режимный блок 2024–2026** (24 заседания) — отдельной строкой отчёта; гиперпараметры на нём не подбираются.
- **Метрики §6.2:** RMSE и MAE по шагу (б.п., основная; MAPE не применяется), hit rate по направлению, матрица ошибок 3×3, QWK, Brier (multiclass) и log loss для вероятностных прогнозов (№3; базлайн — безусловные частоты классов на обучающем окне), надёжностная таблица (5 бинов).
- **Тесты §6.3:** Diebold–Mariano с поправкой HLN против каждого бенчмарка (statsmodels ≥ 0.15; если фактический API иной — реализовать DM+HLN по формуле из источника и назвать путь в отчёте); Mincer–Zarnowitz (регрессия «факт на прогноз», HAC; гипотеза a=0 ∧ b=1); Pesaran–Timmermann для направления; блочный бутстрап (блок из 4 заседаний, 2000 ресэмплов, фиксированный сид) — интервал для разницы RMSE с бенчмарками.
- Порядок бенчмарков и спецификации фиксируются этой спекой **до** первого прогона.
