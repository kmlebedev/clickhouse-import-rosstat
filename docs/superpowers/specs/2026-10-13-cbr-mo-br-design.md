# Макроэкономический опрос ЦБ (mo_br): импортёр консенсуса — дизайн (пункт 1.5 контура ключевой ставки)

> **Дата:** 2026-10-13 · **Ветка:** `feat/cbr-mo-br` · **Пункт:** `docs/ROADMAP_KEY_RATE.md` §6 фаза 1.5 — «Макроэкономический опрос ЦБ (8 раз в год) → медианы и интервалы прогнозов».
> **Критерий приёмки (роадмап):** «консенсус-бенчмарк доступен агенту; глубина истории зафиксирована».

## 1. Цель

Дать контуру прогноза ключевой ставки **консенсус-бенчмарк** — медианы и интервалы прогнозов профессиональных аналитиков:

- **модель** (`docs/KEY_RATE_MODEL.md` §6, бенчмарк №4): «побить профессионалов»; сравнение только по опросам, опубликованным строго до заседания, на горизонте, который опрос покрывает;
- **публикации** (`docs/KEY_RATE_PUBLICATIONS.md` §6): строка «Консенсус аналитиков (обязательный референс) — макроопрос ЦБ — ❌ фаза 1.5» становится ✅ и подкрепляется витриной.

Соблюдается конвенция фазы 3: **все источники `www.cbr.ru` живут в пакете `cbr/`**; новый импортёр — 14-я запись реестра `cbr/importers.go`.

- **Дата волны в файле** — 1-е число месяца волны (напр. `2026-09-01` для сентябрьской); публикация наступает через 2–6 дней после полевого периода. Для point-in-time это фиксируется явно (см. §3.4).

## 3. Решения

### 3.1 Транспорт

Паттерн link-finder фазы 3 (как `cbr/Infl_exp.go`): `Import()` → `getPage(страница mo_br)` → `findLink(page, 'a[href$="full.xlsx"]')` → абсолютный `https://www.cbr.ru` + href → `util.GetXlsx`. Константный URL файла (`File/144490/full.xlsx`) **не** хардкодим: id может смениться между волнами; ссылка со страницы устойчива к этому, а смена имени файла даст fail-fast («ссылка не найдена»). Страница и файл скачиваются каждым прогоном (≈560 КБ), прогон ежедневный и идемпотентный.

### 3.2 Разбор

`parseMoBr(xlsx *excelize.File) ([]moBrPoint, []util.SeriesMeta, error)` — чистая функция (без сети), в `cbr/mo_br_parse.go`:

- находит строку шапки волн (строка с ≥3 датами) и колонки-волны; находит блоки статистик по меткам колонки B; для «годовых» листов читает годы из даты колонки D;
- `moBrPoint{ Series string; Date time.Time /* волна */; Value float64 }`;
- **реестр дескрипторов 17 показателей** (номер листа → базовое имя, заголовок, единица; генерируется в `cbr/mo_br_meta.go`): незнакомый лист-показатель → **ошибка** (структура источника изменилась — нужно дополнить реестр кодом);
- fail-fast (конвенция Review Focus фазы 3): не найден хоть один из 17 известных листов-показателей / не найдена шапка волн / нет ни одного блока из 6 статистик на листе / **0 точек после разбора** → ошибка до `Send`;
- пустые значения («-») пропускаются, соседние не страдают.

### 3.3 Хранение и имена рядов

`macro_series`, `source='cbr_mo_br'` (единый long-формат контура `source, series, date, value`; отдельная таблица отвергнута — разорвала бы общий механизм витрин/каталога). Запись — одним батчем `PrepareBatch → Append(err!) → Send`; каждый прогон — **полный upsert всей истории файла** (43 волны), идемпотентно по ключу `(source, series, date)`.

Имена рядов — самодокументируемые: `<base>_<year>_<stat>` для годовых показателей, `<base>_<stat>` для листов 16–17:

- базовые имена (17): `cpi_dec`, `cpi_avg`, `key_rate_avg`, `gdp_yoy`, `unemp_avg`, `unemp_dec_nsa`, `wage_nominal`, `budget_balance`, `exports`, `imports`, `usd_rub`, `oil_tax`, `brent`, `urals`, `cds_5y`, `neutral_rate`, `gdp_long_term`;
- суффиксы статистик (6): `median`, `p10`, `p90`, `min`, `max`, `answers`;
- примеры: `key_rate_avg_2027_median`, `cpi_dec_2026_p10`, `usd_rub_2028_max`, `neutral_rate_median`, `gdp_long_term_p10`.

**Семантика даты.** `date` = дата волны из файла (1-е число месяца волны; `KEY_RATE_MODEL.md` §6 требует «опросы, опубликованные строго до заседания» — из витрины/каталога читается, что фактическая публикация наступает через 2–6 дней). Это приближение; точная привязка — §3.4.

### 3.4 Точка контроля публикации (`cbr_mo_br_vintage`)

Новая мини-таблица:

```sql
CREATE TABLE IF NOT EXISTS cbr_mo_br_vintage (
    vintage Date,               -- дата волны из файла (1-е число месяца)
    first_seen Nullable(Date)   -- дата первого наблюдения волны конвейером (≈ дата публикации); NULL — волна существовала до внедрения конвейера
) ENGINE = ReplacingMergeTree ORDER BY vintage;
```

Логика прогона: прочитать существующие `vintage` (`SELECT vintage FROM cbr_mo_br_vintage FINAL`) → вставить только отсутствующие. Если известных волн ещё нет (первый прогон после внедрения) — все волны из файла вставляются с `first_seen = NULL` (честная метка «предыстория»: конвейер их не наблюдал). Каждая волна, впервые появившаяся в файле на последующих прогонах, получает `first_seen` = дата прогона — точная нижняя граница «когда волна стала доступна» для бэктеста фазы 4. Полевые даты со страницы («Даты проведения опроса: …») **не** парсятся — вне объёма (см. §7).

DDL фиксируется в `ARCHITECTURE.md` §6.2 (канонический) — правило AGENTS.md №8.

### 3.5 Витрина и MCP-доступ

`v_cbr_mo_br` (паттерн `v_cbr_survey`): `SELECT source, series, date, value FROM macro_series FINAL WHERE source = 'cbr_mo_br'`, `util.View` через `CreateView`; комментарий таблицы и каждой колонки:

- дата = волна опроса, публикация +2–6 дней; `first_seen` — `cbr_mo_br_vintage`;
- значения — прогнозы аналитиков (медиана/квартильный интервал/диапазон/число ответов), а не факты — читать `v_series_catalog` по `(source='cbr_mo_br', series)`;
- `answers` — число ответов по показателю и году в данной волне (не значение прогноза).

Грант `kimi_reader` — в `sql/mcp_kimi_reader.sql`; `scripts/mcp_check.py` — новые строки: витрина читается (число строк > 0), каталог `source='cbr_mo_br'` непуст; сырая `macro_series` уже проверяется как закрытая.

### 3.6 Каталог (`series_catalog`)

Описания **генерируются из разбора**: 17 дескрипторов (заголовок, единица, «что измеряет и как читать») × присутствующие годы × присутствующие статистики; описания статистик шаблонные («медиана прогнозов аналитиков», «10-й процентиль — нижняя граница центральной тенденции», …, «число ответов участников»). Ряды этого source **не** добавляются в `cbrAllSeriesMeta()` (`TestSeriesMetaWellFormed` строг к `source='cbr'`); у каталога свой тест полноты и корректности полей (образец — `cbr/mp_survey_series_meta_test.go`).

### 3.7 Интеграция

- **Пакет `cbr/`**: `cbr/mo_br.go` (импортёр: кастомный `Import()` — `findLink` → `GetXlsx` → `parseMoBr` → DDL vintage → батч в `macro_series` → upsert `cbr_mo_br_vintage` → `util.UpsertSeriesCatalog` → `util.CreateView(v_cbr_mo_br)`; `Name()` = `cbr_mo_br`, `TableName` = `macro_series` — как `cbr_mp_survey`), `cbr/mo_br_parse.go`, `cbr/mo_br_meta.go`.
- **Реестр**: 14-я запись `{moBrImporter, "macro_series"}`; в `cbr/importers_test.go` allowlist `macro_series` расширяется до `{cbr_mp_survey, cbr_mo_br}` (проверка (б) перестаёт быть «только один»).
- **Dagu**: шаг `cbr_mo_br` последним в `dagu/cbr.yaml` (цепочка 09:17, ежедневно; файл обновляется 8 раз в год — будничный прогон no-op).
- **Фикстура**: zip-хирургия `full.xlsx` до трёх листов — «1» (ИПЦ дек/дек, годовая разметка), «3» (ключевая ставка, годовая), «16» (нейтральная ставка, спецформа). Ожидаемо 114 рядов / 2 058 точек на фикстуре; тесты офлайн.
- **Тесты**: `cbr/mo_br_test.go` (импортёр: Name, DDL, идемпотентность vintage-логики на фейке), `cbr/mo_br_parse_test.go` (фикстура: двусторонность точек ⇄ каталога, споты сентябрьской волны, fail-fast: нет листа / нет шапки / нет блоков / 0 точек / незнакомый показатель), `cbr/mo_br_series_meta_test.go` (полнота и корректность каталога).
- **Живая проверка** (scratch-тест, не коммитится): полный файл → число рядов/точек ≥ текущих 642/9 348, максимальная волна ≥ 2026-09-01.

## 4. Приёмка (роадмап §6, шаг 1.5)

1. `make all` — зелёный.
2. `make import STAT=cbr_mo_br` → `Imported N rows`; повторный прогон идемпотентен (витрина и каталог не растут).
3. Витрина читается агентом через MCP: число рядов = фактическому (на 2026-10-13 — **642**), число точек — **9 348**, глубина **2021-05-01 … 2026-09-01 (43 волны)** — «глубина истории зафиксирована».
4. `cbr_mo_br_vintage`: 43 волны предыстории seeded с `first_seen = NULL` (конвейер их не наблюдал); логика «новая волна → `first_seen` = дата прогона» покрыта офлайн-тестом (первый прогон — NULL, добавленная волна — дата, повтор — идемпотентно).
5. `make mcp-user` → грант `v_cbr_mo_br`; `make mcp-check` → ПРОВЕРКА ПРОЙДЕНА (включая новые строки); `dagu validate dagu/cbr.yaml` → exit 0.
6. Статус 1.5 в `docs/ROADMAP_KEY_RATE.md` — ✅ + блок живой приёмки с числами; доки синхронизированы тем же PR (см. §5).

## 7. Риски

| Риск | Митигация |
|---|---|
| Сменится id/имя XLSX или разметка листов | Ссылка берётся со страницы (`findLink`); адаптивный парсер; fail-fast на структуру и 0 точек; живой ежедневный прогон заметит в первый же день |
| ЦБ добавит новый показатель (лист) | Незнакомый лист → ошибка импортёра; добавление дескриптора — одна запись в реестре |
| ЦБ расширит горизонт (2030+) | Имена рядов с годом подхватятся автоматически (год из колонки D); каталог генерируется из разбора |
| Дата волны ≠ дата публикации (лаговое окно 2–6 дней) | Семантика задокументирована; `first_seen` фиксирует фактическую доступность волн, впервые появившихся после внедрения; допровадные 43 волны — `NULL` («предыстория») |
| Число ответов `answers` — не прогноз | Явная оговорка в каталоге и комментарии витрины |
