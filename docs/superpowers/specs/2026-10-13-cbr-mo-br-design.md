# Макроэкономический опрос ЦБ (mo_br): импортёр консенсуса — дизайн (пункт 1.5 контура ключевой ставки)

> **Дата:** 2026-10-13 · **Ветка:** `feat/cbr-mo-br` · **Пункт:** `docs/ROADMAP_KEY_RATE.md` §6 фаза 1.5 — «Макроэкономический опрос ЦБ (8 раз в год) → медианы и интервалы прогнозов».
> **Критерий приёмки (роадмап):** «консенсус-бенчмарк доступен агенту; глубина истории зафиксирована».

## 1. Цель

Дать контуру прогноза ключевой ставки **консенсус-бенчмарк** — медианы и интервалы прогнозов профессиональных аналитиков:

- **модель** (`docs/KEY_RATE_MODEL.md` §6, бенчмарк №4): «побить профессионалов»; сравнение только по опросам, опубликованным строго до заседания, на горизонте, который опрос покрывает;
- **публикации** (`docs/KEY_RATE_PUBLICATIONS.md` §6): строка «Консенсус аналитиков (обязательный референс) — макроопрос ЦБ — ❌ фаза 1.5» становится ✅ и подкрепляется витриной.

Соблюдается конвенция фазы 3: **все источники `www.cbr.ru` живут в пакете `cbr/`**; новый импортёр — 14-я запись реестра `cbr/importers.go`.

## 3. Решения

### 3.1 Транспорт и префлайт

Паттерн link-finder фазы 3 (как `cbr/Infl_exp.go`), плюс дешёвая проверка версии файла:

1. `Import()` → `getPage(страница mo_br)` → `findLink(page, 'a[href$="full.xlsx"]')` → абсолютный URL, `name` = basename (`full.xlsx`). Константный URL файла (`File/144490/full.xlsx`) **не** хардкодим: id может смениться между волнами; ссылка со страницы устойчива к этому, смена имени файла даст fail-fast («ссылка не найдена»).
2. **Лёгкий HEAD** по URL файла → `fingerprint` версии (§3.4). Сегодняшний прогон, если версия уже импортирована и количественный чек сошёлся, **не скачивает файл и не пишет в БД** — это главное назначение шага (файл обновляется 8 раз в год, а dagu ходит ежедневно).
3. Только при новой версии (или провале чека, или недоступности HEAD) — `util.GetXlsx` и полный импорт.

Стоимость будничного no-op прогона: страница (~260 КБ) + HEAD; полный путь (~560 КБ, парсинг, батч-запись всей истории) — только при смене версии.

### 3.2 Разбор

`parseMoBr(xlsx *excelize.File) ([]moBrPoint, []util.SeriesMeta, error)` — чистая функция (без сети), в `cbr/mo_br_parse.go`:

- находит строку шапки волн (строка с ≥3 датами) и колонки-волны; находит блоки статистик по меткам колонки B; для «годовых» листов читает годы из даты колонки D;
- `moBrPoint{ Series string; Date time.Time /* волна */; Value float64 }`;
- **реестр дескрипторов 17 показателей** (номер листа → базовое имя, заголовок, единица; в `cbr/mo_br_meta.go`): незнакомый лист-показатель → **ошибка** (структура источника изменилась — нужно дополнить реестр кодом);
- fail-fast (конвенция Review Focus фазы 3): не найден хоть один из 17 известных листов-показателей / не найдена шапка волн / нет ни одного блока из 6 статистик на листе / **0 точек после разбора** → ошибка до `Send`;
- пустые значения («-») пропускаются, соседние не страдают.

### 3.3 Хранение и имена рядов

`macro_series`, `source='cbr_mo_br'` (единый long-формат контура `source, series, date, value`; отдельная таблица отвергнута — разорвала бы общий механизм витрин/каталога). Запись — одним батчем `PrepareBatch → Append(err!) → Send`; импорт — **полный upsert всей истории файла** (43 волны), идемпотентно по ключу `(source, series, date)`; выполняется только при новой версии файла (§3.4).

Имена рядов — самодокументируемые: `<base>_<year>_<stat>` для годовых показателей, `<base>_<stat>` для листов 16–17:

- базовые имена (17): `cpi_dec`, `cpi_avg`, `key_rate_avg`, `gdp_yoy`, `unemp_avg`, `unemp_dec_nsa`, `wage_nominal`, `budget_balance`, `exports`, `imports`, `usd_rub`, `oil_tax`, `brent`, `urals`, `cds_5y`, `neutral_rate`, `gdp_long_term`;
- суффиксы статистик (6): `median`, `p10`, `p90`, `min`, `max`, `answers`;
- примеры: `key_rate_avg_2027_median`, `cpi_dec_2026_p10`, `usd_rub_2028_max`, `neutral_rate_median`, `gdp_long_term_p10`.

**Семантика даты.** `date` = дата волны из файла (1-е число месяца волны; `KEY_RATE_MODEL.md` §6 требует «опросы, опубликованные строго до заседания» — из витрины/каталога читается, что фактическая публикация наступает через 2–6 дней; дата фактической доступности версии файла — `source_publications`, §3.4).

### 3.4 Точки контроля публикаций — общая таблица `source_publications` + HEAD-префлайт

Общий механизм для **всех** источников, чьи файлы обновляются реже прогонов (первый потребитель — `cbr_mo_br`; пер-источниковых таблиц не заводим; миграция существующих импортёров — вне объёма, §6). Две части: общая таблица версий и лёгкий префлайт.

**Таблица (канонический DDL — `ARCHITECTURE.md` §6.2):**

```sql
CREATE TABLE IF NOT EXISTS source_publications (
    source LowCardinality(String),  -- источник-потребитель: 'cbr_mo_br'
    name LowCardinality(String),    -- имя артефакта: 'full.xlsx'
    fingerprint String,             -- md5 от (имя|ETag|Last-Modified|Content-Length) — отпечаток версии контента
    first_seen DateTime,            -- когда конвейер впервые увидел эту версию
    points UInt64,                  -- число точек (строк series,date), записанных этой версией
    url String                      -- URL артефакта (аудит)
) ENGINE = ReplacingMergeTree ORDER BY (source, name, fingerprint);
```

Одна строка = одна увиденная версия артефакта; история версий накапливается (новая волна → новая строка). `first_seen` — **наблюдение конвейером**, не публикация: для версии, существовавшей на момент внедрения, это дата первого прогона (для `mo_br` — 2026-10; семантика документируется). Таблица внутренняя — агенту (`kimi_reader`) не выдаётся.

**Отпечаток версии (`util/publications.go`):** `HeadFingerprint(url)` — HEAD через `util.HttpClient`; `fingerprint = md5(name + "|" + ETag + "|" + Last-Modified + "|" + Content-Length)`. У CBR честного `Content-MD5` нет (проверено), но композит заголовков меняется ровно при смене файла; отсутствие ETag не ломает (тогда композит из Last-Modified + Content-Length). Не-200 или сеть — ошибка.

**Логика прогона `mo_br`:**

1. `findLink` → URL, `name` → `HeadFingerprint` → к `source_publications` (`SELECT … FINAL WHERE source/name/fingerprint`).
2. **Версия известна** → количественный чек: `SELECT count() FROM macro_series FINAL WHERE source='cbr_mo_br'` = сохранённому `points`? Да → лог `no-op: версия <fingerprint> уже импортирована, N точек на месте`, импорт не делается; возвращается проверенное N. Нет → полный импорт (self-heal).
3. **Версия неизвестна** (или HEAD недоступен — fallback: полный импорт без записи версии, документируется) → `GetXlsx` → `parseMoBr` → DDL `macro_series` → батч → **`SavePublication`** (только после успешного `Send`) → `UpsertSeriesCatalog` → `CreateView` → в лог уже реальный `Imported N rows`.

Так «точка контроля публикации» становится единой для контура: имя + md5-отпечаток + дата первого наблюдения + число точек.

### 3.5 Витрина и MCP-доступ

`v_cbr_mo_br` (паттерн `v_cbr_survey`): `SELECT source, series, date, value FROM macro_series FINAL WHERE source = 'cbr_mo_br'`, `util.View` через `CreateView`; комментарий таблицы и каждой колонки:

- дата = волна опроса, публикация +2–6 дней; даты фактической доступности версий файла — `source_publications` (внутренняя, агенту не выдана);
- значения — прогнозы аналитиков (медиана/квартильный интервал/диапазон/число ответов), а не факты — читать `v_series_catalog` по `(source='cbr_mo_br', series)`;
- `answers` — число ответов по показателю и году в данной волне (не значение прогноза).

Грант `kimi_reader` — в `sql/mcp_kimi_reader.sql`; `scripts/mcp_check.py` — новые строки: витрина читается (число строк > 0), каталог `source='cbr_mo_br'` непуст; сырая `macro_series` уже проверяется как закрытая.

### 3.6 Каталог (`series_catalog`)

Описания **генерируются из разбора**: 17 дескрипторов (заголовок, единица, «что измеряет и как читать») × присутствующие годы × присутствующие статистики; описания статистик шаблонные («медиана прогнозов аналитиков», «10-й процентиль — нижняя граница центральной тенденции», …, «число ответов участников»). Ряды этого source **не** добавляются в `cbrAllSeriesMeta()` (`TestSeriesMetaWellFormed` строг к `source='cbr'`); у каталога свой тест полноты и корректности полей (образец — `cbr/mp_survey_series_meta_test.go`).

- **Пакет `cbr/`**: `cbr/mo_br.go` (импортёр: кастомный `Import()` — префлайт §3.4 → при новой версии `GetXlsx` → `parseMoBr` → DDL `macro_series` → батч → `util.SavePublication` → `util.UpsertSeriesCatalog` → `util.CreateView(v_cbr_mo_br)`; `Name()` = `cbr_mo_br`, `TableName` = `macro_series` — как `cbr_mp_survey`), `cbr/mo_br_parse.go`, `cbr/mo_br_meta.go`.

Тесты — `util/publications_test.go` (композит отпечатка на httptest-HEAD, смена каждого компонента меняет md5, ошибки non-200/сети). ## 4. Приёмка (роадмап §6, шаг 1.5)

1. `make all` — зелёный.
2. Первый `make import STAT=cbr_mo_br` — полный импорт: `Imported 9348 rows` (число фиксируется фактическое); в `source_publications` появилась строка `(cbr_mo_br, full.xlsx, <fingerprint>, first_seen=<день приёмки>, points=9348, url)` — «точка контроля публикации».
3. Повторный прогон — **лёгкий префлайт**: в логе `no-op: версия <fingerprint> уже импортирована, 9348 точек на месте`; полного импорта (скачивания XLSX, парсинга, записи) нет; новых строк в `source_publications` нет; счётчики витрины не выросли.
4. Витрина читается агентом через MCP: число рядов = фактическому (на 2026-10-13 — **642**), число точек — **9 348**, глубина **2021-05-01 … 2026-09-01 (43 волны)** — «глубина истории зафиксирована».
5. `make mcp-user` → грант `v_cbr_mo_br`; `make mcp-check` → ПРОВЕРКА ПРОЙДЕНА (включая новые строки); `dagu validate dagu/cbr.yaml` → exit 0.
6. Статус 1.5 в `docs/ROADMAP_KEY_RATE.md` — ✅ + блок живой приёмки с числами; доки синхронизированы тем же PR (см. §5).

## 7. Риски

| Риск | Митигация |
|---|---|
| Сменится id/имя XLSX или разметка листов | Ссылка берётся со страницы (`findLink`); адаптивный парсер; fail-fast на структуру и 0 точек; ежедневный прогон заметит в первый же день |
| Отпечаток версии: CBR отдаёт только ETag+Last-Modified+Content-Length (без Content-MD5) | Композит из всех доступных заголовков; пропажа ETag не ломает (композит из остальных); недоступность HEAD → обычный полный импорт (без записи версии) |
| Гонка HEAD→GET: файл сменился между префлайтом и скачиванием | Окно секунд; записанная версия окажется на волну позже — следующий прогон увидит новый отпечаток и доимпортирует |
| Переименование файла ЦБ (не `full.xlsx`) | `name` из ссылки; смена имени = новая версия (импорт выполнится, в таблице появится строка нового имени) |
| Дата волны ≠ дата публикации (лаговое окно 2–6 дней) | Семантика задокументирована; `source_publications.first_seen` фиксирует фактическую доступность версий файла с момента внедрения |
| Число ответов `answers` — не прогноз | Явная оговорка в каталоге и комментарии витрины |
