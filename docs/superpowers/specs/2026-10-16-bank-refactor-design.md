# Спека: рефакторинг пакета `bank/` по стандарту импортёров

**Дата:** 16 октября 2026 г.
**Статус:** спека пункта [ROADMAP_KEY_RATE.md](../../ROADMAP_KEY_RATE.md) §6 «Фаза 3.1 — рефакторинг пакета `bank/` по стандарту».
**Стандарт:** [IMPORTER_PACKAGE_STANDARD.md](../../IMPORTER_PACKAGE_STANDARD.md) — ссылки вида «стандарт §N» ниже указывают на него.
**Основание:** §9 спеки [2026-10-15-sber-spending-importers-design.md](2026-10-15-sber-spending-importers-design.md) — остаток «рефакторинг пакета `bank/` целиком (реестр `importers.go`, `colly`, каталог и витрины остальных четырёх импортёров, развязка `rus_vtb_group_ifrs`/`tbank_group_ifrs`) — отдельный будущий пункт».
**Прецеденты:** рефакторинги [`cbr/` (фаза 3, 2026-10-13)](2026-10-13-cbr-refactor-design.md) и [`rosstat/` (фаза 2, шаг 1, 2026-10-14)](2026-10-14-rosstat-refactor-design.md); также [публикационный префлайт](2026-10-14-publication-preflight-design.md) и [`cbr_dip_bulletin`](2026-10-15-cbr-dip-bulletin-design.md) (гейт пофайловых версий).
**Ветка:** `feat/bank-refactor`.

## 1. Цель и объём

### 1.1. Цель
Привести пакет `bank/` (шесть импортёров) к стандарту целиком: реестр с тестом-энфорсером, транспорт только через `util`, запись только батчами, каталог рядов и витрины, развязка общей таблицы `rus_vtb_group_ifrs`, живой источник `domrf_mortgage`. Отдельный эффект — восстановление понедельной цепочки `dagu/bank.yaml`, которая сегодня падает на первом шаге и не доходит ни до одного Sber-шага.

### 1.2. Объём
1. `bank/importers.go` + `bank/importers_test.go` — реестр и тест-энфорсер (стандарт §8), проверки адаптированы под утверждённый набор имён (§1.4, О1).
2. `domrf_mortgage`: живая ссылка со страницы (JSON → `/api/v2/content/download/…`), пересмотр разбора под лист «13 Ставки предложения», точка контроля публикации, каталог и витрина.
3. `rus_vtb_group_ifrs`: вывод `colly` (страница — `util.GetPage` + goquery), сортировка файлов по дате отчёта, пофайловые версии с гейтом (прецедент `cbr_dip_bulletin`), каталог и витрина.
4. `sber_finansovie_rezultaty`: `CrawFunc` → `DataUrl` + `ImportFunc` (включает винтажный архив, стандарт §9.6), сырые значения, каталог и витрина.
5. `tbank_group_ifrs`: развязка таблицы и констант; перевод на шаблон; вывод из расписания до починки источника.
6. `bank/series_meta.go` и `bank/views.go`: каталог рядов всех источников пакета и витрина `v_bank_macro` (пять таблиц); `v_bank_sber_spending` сохраняется.
7. Проводка: `dagu/bank.yaml`, `sql/mcp_kimi_reader.sql`, `scripts/mcp_check.py`, `ARCHITECTURE.md`, `README.md`, стандарт (§18 и примеры §9.3/§9.6), `ROADMAP_KEY_RATE.md` (пункт, техдолг, статус), комментарий в `util/clickhouse_import.go`.

### 1.3. Вне объёма (названо явно)
- Смена legacy-типа `Float32` шести таблиц — по `ARCHITECTURE.md` §6.2 «legacy — Float32, не трогать»; остаётся отдельным остатком §9.
- Починка источника Т-Банка (живой XLSX) и его каталог/витрина — отдельный пункт: [префлайт-спека](2026-10-14-publication-preflight-design.md) фиксирует это осознанным исключением («починка источника (XLSX вместо PDF) и развязка таблиц — отдельный пункт работ»); развязка берётся сюда, починка — нет.
- Точки контроля публикации двух наборов Сбера — не пересматриваются (решение §4.2 [спеки Sber-расходов](2026-10-15-sber-spending-importers-design.md)).
- Правовой вопрос условий использования `sberindex.ru` ([KEY_RATE_MODEL.md](../../KEY_RATE_MODEL.md) §4) — не инженерная задача.
- Остальные пакеты с долгом по стандарту §18 (`customs/`, `fao/`, `minfin/`, `moex/`, `bold/`, `wgc/`, `craw/`, `news/`, `financial/` и прочие) — не этот пункт.
- Восстановление из архива (`ARCHIVE_ACTION=restore`): для `rus_vtb_group_ifrs` — не поддержано (набор файлов; `Import` падает с понятной ошибкой до сети, как CrawFunc-случай шаблона); для `domrf_mortgage` — ограничение общих импортёров с вычисляемой ссылкой (`BeforeImport` в режиме restore не вызывается, статического `DataUrl` у импортёра нет).

### 2.3. Живой дефект расписания
`dagu/bank.yaml` — `type: chain`; первый шаг `domrf_mortgage` падает на 404, а упавший шаг останавливает цепочку: **Sber-шаги, ВТБ и Т-Банк по понедельникам не выполняются**. ## 3. Решения

### 3.1. Реестр и тест-энфорсер (стандарт §8)
- `bank/importers.go` — по образцу `cbr/importers.go`: `bankImporter{chimport.ImportStat; table string; countPoints string}`; шесть записей-литералов в порядке `dagu/bank.yaml` (Т-Банк — последним, вне расписания); единственный `init()`.
- Утверждённый набор имён — литеральный: `{domrf_mortgage, rus_vtb_group_ifrs, tbank_group_ifrs, sber_finansovie_rezultaty, sber_consumper_spending_index, sber_izmenenie_trat}`.
- `bank/importers_test.go` — энфорсер `TestBankImportersNamedAndRegistered`:
  - (а′) `Name()` ∈ утверждённого набора;
  - (б) `table` ∈ набора и `table == Name()`;
  - (в) имена уникальны и все зарегистрированы в `chimport.Stats`;
  - (г) `dagu/bank.yaml` в обе стороны, **плюс явная проверка «шага `tbank_group_ifrs` в расписании нет»** (О2);
  - (д) набор объявлений точки контроля — литерал: `domrf_mortgage → "SELECT count() FROM domrf_mortgage FINAL"`, `rus_vtb_group_ifrs → "SELECT count() FROM rus_vtb_group_ifrs FINAL"`, `sber_finansovie_rezultaty → "SELECT count() FROM sber_finansovie_rezultaty FINAL"`; сверка с `Publication()` (запрос и `Source == Name()`), у остальных объявления нет;
  - (¬) число импортёров пакета в `chimport.Stats` (по утверждённому набору имён) равно `len(реестр)`.

### 3.2. `domrf_mortgage` — живой источник, точка контроля, каталог и витрина
- **Транспорт**: `util.GetPage` + goquery — из JSON страницы берётся XLSX-ссылка блока «Топ ипотечных банков» (категория «Ипотечный рейтинг», поле `file2.src`); `DataUrl = "https://xn--d1aqf.xn--p1ai" + src`; вычисление в `BeforeImport` (стандарт §5.4, §4.3). Разбор страницы — **чистая функция над байтами** (тест на HTML-фикстуре, §11.3); ссылка не найдена — ошибка (§6.4).
- **Разбор**: лист «13 Ставки предложения»; поиск по признаку (§6.3), **сырые значения** (§6.2), fail-fast; имя ряда — банк из источника (односторонний контракт §11.4); привязка даты — месяц. Точная разметка фиксируется живой фикстурой (разведка файла — первая задача плана).
- **Точка контроля публикации**: объявляется (§9.1: файл месячный, шаг недельный); запрос — литерал выше; отпечаток — `URL|имя|Content-Length` (ETag/Last-Modified у источника нет; URL меняется с версией файла). Страница запрашивается каждый прогон (лёгкая), no-op — после HEAD и сверки числа точек.
- Убрать `fmt.Printf` и проглоченную ошибку; DDL — `%s`-форма, колонка `rate Float32` остаётся (legacy, §6.2).
- Фикстуры: HTML страницы + урезанная книга (хирургия zip, §11.2); тесты: разбор страницы (успех / блок отсутствует), разбор книги, spot-значения, fail-fast, односторонний контракт каталога.

### 3.3. `rus_vtb_group_ifrs` — транспорт, порядок, пофайловые версии с гейтом (О3)
- **Транспорт**: `colly` убирается; список ссылок — `util.GetPage` + goquery по константному селектору (`a[href*="rus-vtb-group-ifrs-as-of"]`, только `.xlsx`, dedupe, **сортировка по дате отчёта по возрастанию** — свежие вставляются последними и выигрывают у пересекающихся периодов); разбор страницы — чистая функция над байтами (тест на HTML-фикстуре); пусто — ошибка.
- **Гейт и пофайловые версии** (прецедент `cbr_dip_bulletin`, стандарт §8 п. 13): на каждый файл — `util.HeadFingerprint(link)` (ETag/Last-Modified у источника есть) и `util.PublicationKnown(ctx, conn, Name(), basename(link), fp)`; известный — пропуск; новый — `DataUrl = link` и вызов встроенного `util.ClickHouseImport.Import` (шаблон в цикле, по файлу: DDL → разбор батчем → архив версии → строка `source_publications` на файл). Сбой HEAD — как у префлайта: полный импорт файла без записи версии.
- **Производные**: шаблон публикует `AfterImport` на каждом файле; собственный `Import()` дополнительно зовёт производные после цикла — пустая дельта не должна оставлять каталог/витрину неопубликованными (урок `rosstat_ipc_weeks_bulletins`).
- Ряды — строки баланса из листа до «Итого собственные средства»: имя ряда даёт источник, контракт каталога — односторонний (§11.4); единицы и привязка даты снимаются с фикстуры.
- **Ограничения, названные в докблоке и README**: самолечение архива на no-op-пути гейта не работает — как у `cbr_dip_bulletin` (лечится ручным прогоном после чистки); `restore` не поддержан (ошибка до сети).
- Фикстуры: HTML страницы + один живой XLSX; тесты: отбор/фильтр PDF/дедуп/сортировка, разбор, spot-значения, fail-fast, контракт каталога.

### 3.4. `sber_finansovie_rezultaty` — конвертация на `DataUrl` + `ImportFunc`
- `CrawFunc` → `DataUrl` (статичный URL) + `ImportFunc`: шаблон качает байты, тот же срез уходит в разбор и в **винтажный архив** (стандарт §9.6) — сегодня это документированное исключение «CrawFunc не архивируется»; точка контроля сохраняется (`bank/sber_fin_rez.go:36,128`), повторный прогон — no-op с проверкой наличия версии в архиве.
- Разбор: лист «Баланс», сырые значения (§6.2), fail-fast, батч; структура переименовывается (`LoansToCorporationsStat` → `SberFinRezStat`); DDL — `%s`-форма (сохраняется).
- Фикстура: живая книга (56 947 Б, коммитится как есть); тесты: разбор, spot-значения, fail-fast, контракт каталога.

### 3.5. `tbank_group_ifrs` — развязка (О2, О4)
- Своя таблица `tbank_group_ifrs` и свои `%s`-DDL/константы вместо `vtbIfrsTableDdl`/`vtbIfrsDataInsert` (`bank/tbank_fin_rez.go:82,94`); колонка значения — **`Float64`** (правило 5 AGENTS.md: таблица новая; legacy-таблицы пакета остаются `Float32`).
- Перевод на шаблон (`DataUrl` — текущий PDF + `ImportFunc`): падение на открытии книги до разбора и вставки; текст ошибки шаблона дополняется именем таблицы (мелкое улучшение `util/clickhouse_import.go` в духе §6.4). Разбор переводится на батч механически и **не верифицируется** (О4).
- Из `dagu/bank.yaml` шаг убирается (О2); каталог/витрина не заводятся (ряды неизвестны); `v_bank_macro` таблицу не включает (на свежей БД она может не существовать — `CreateView` ждёт все `Tables`, §10.3).

### 3.6. Каталог рядов и витрины (стандарт §10)
- `bank/series_meta.go`: добавляются `domrfSeriesMeta`, `vtbSeriesMeta`, `sberFinSeriesMeta` (source — имена таблиц; `origin` — файл/лист источника; `description` — что измеряет, как читать, привязка даты); существующие 51 описание Сбера сохраняются; `afterBankMacro(meta)` заменяет `afterSberMacro` — публикует каталог (`bankSeriesMeta` целиком: сходится независимо от того, какой импортёр отработал) и обе витрины.
- Витрина `v_bank_macro`: long-форма (`source, series, date, value`) по **пяти** таблицам (`domrf_mortgage`, `rus_vtb_group_ifrs`, `sber_finansovie_rezultaty`, `sber_consumper_spending_index`, `sber_izmenenie_trat`), значения — `toFloat64`; комментарии таблицы и каждой колонки; `Tables` — константами пакета, `Select` — литералами (образец `v_rosstat_macro` в `rosstat/series_meta.go`).
- `v_bank_sber_spending` сохраняется без изменений состава (контракт дашборда `key-rate-publications` и `scripts/mcp_check.py`), публикуется тем же хелпером.
- Грант `SELECT ON default.v_bank_macro` в `sql/mcp_kimi_reader.sql` (стандарт §10.4); сырые таблицы (включая новую `tbank_group_ifrs`) агенту не выдаются.
- `scripts/mcp_check.py`: непустота и число рядов `v_bank_macro` по каждому новому `source`, полнота каталога по новым source, закрытость новых сырых таблиц (497) — по образцу существующих проверок пакета (§10.5).
- Контракты каталога — односторонние на фикстурах (§11.4); числа рядов и точек фиксирует приёмка.

### 3.7. Расписание

## 5. Риски и митигации

| Риск | Митигация |
|---|---|
| Страница ДОМ.РФ вернёт JS-challenge или сменит разметку JSON | Разбор — чистая функция с fail-fast и понятным текстом; HTML-фикстура; при возврате challenge прогон падает ошибкой, а не «0 строк» |
| Разметка листа «13 Ставки предложения» отличается от ожиданий | Разведка живого файла — первая задача плана; фикстура фиксирует разметку; смена — fail-fast |
| Переразбор на сырые значения уточнит точки ДОМ.РФ | Заявленное исправление: расхождения назвать в протоколе приёмки поимённо (§15.2) |
| Порядок файлов ВТБ меняет, какие значения «свежее» | Сортировка по дате отчёта (возрастание); изменение данных (если есть) — назвать в протоколе |
| Сбой HEAD у файла ВТБ | Полный импорт файла без записи версии (как у префлайта); идемпотентно |
| Ограничение самолечения архива на no-op-пути гейта ВТБ | Документировано (как у `cbr_dip_bulletin`); лечение — ручной прогон после удаления строк |
| Шаг Т-Банка забудут вернуть после починки источника | Энфорсер проверяет отсутствие явно; тексты в dagu/README/ARCHITECTURE называют условие возврата |
| Заметный объём: три переписанных импортёра + реестр + витрины | Задачи — по импортёру, независимы; ревью задач и финальное — по AGENTS.md |
