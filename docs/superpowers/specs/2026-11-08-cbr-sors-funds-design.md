## 1. Зачем

Контур ключевой ставки собирает активную сторону банковской системы (кредиты юрлицам и
физлицам, ипотека, ПСК) и балансы домохозяйств (`cbr_households_b_mes`), но **пассивной
стороны по РФ в нём нет**: сколько денег лежит на счетах организаций, в депозитах юрлиц и во
вкладах физлиц (с эскроу и без), в счетах эскроу и у ИП. Без этого тезис «деньги перетекают в
активы» (из депозитов — в недвижимость, ОФЗ, акции) не проверяется числом: нет знаменателя.

Пункт добавляет 21 ряд: 7 строк источника × 3 листа («итого», «в рублях», «в инвалюте»).

## 2. Источник (проверен живьём 2026-11-08)

| Свойство | Значение |
|---|---|
| Страница | `https://www.cbr.ru/statistics/bank_sector/sors/` — «Сведения о размещенных и привлеченных средствах», обновление 30.10.2026 |
| Файл | `https://www.cbr.ru/vfs/statistics/BankSector/Borrowings/02_01_Funds_all.xlsx` — **прямая стабильная ссылка**; HEAD `200`, `Content-Length: 42 817`, `Last-Modified: Fri, 30 Oct 2026 13:52:34 GMT` |
| Заголовок | «Средства на счетах организаций, банковские депозиты (вклады) и другие привлеченные средства юридических лиц, физических лиц и индивидуальных предпринимателей (в целом по Российской Федерации), млн руб.» |
| Листы | `итого`, `в рублях`, `в инвалюте` — разметка одинаковая, строки-подписи совпадают |
| Шапка | строка 1 — заголовок (merged A1:S1), строка 2 — даты `01.02.2012` … `01.10.2026` (177 месяцев, текстом, первое число месяца) |
| Данные | строки 3–9: подпись в колонке A (отступ пробелами, сноска `*`/`**` в конце), далее 177 значений |
| Значения | целые числа (числовой формат `#,##0`), `-` — «данных нет» |
| Точки | **3 177** = 3 × 1 059 (177 × 4 + 93 × 2 + 165) |
| Пропуски | `без эскроу` и `эскроу` — до 2019-02 (`-`, 84 месяца), ИП — до 2013-02 (`-`, 12 месяцев) |
| Ноль | значение, а не пропуск: лист «в инвалюте», строка эскроу — 93 нуля (счета эскроу рублёвые) |
| Единицы | млн руб. на всех трёх листах; лист «в инвалюте» — рублёвый эквивалент иностранной валюты и драгоценных металлов |

Подписи строк (как в файле, с отступом и сноской) и стабильные коды:

| Подпись источника | Код ряда |
|---|---|
| `Средства клиентов, всего` | `clients_total` |
| `средства на счетах организаций` | `org_accounts` |
| `депозиты юридических лиц*` | `corp_deposits` |
| `вклады (депозиты) и другие привлеченные средства физических лиц (с учетом счетов эскроу)` | `households_deposits_escrow` |
| `вклады (депозиты) и другие привлеченные средства физических лиц**` | `households_deposits` |
| `средства на счетах эскроу` | `escrow_accounts` |
| `средства индивидуальных предпринимателей` | `ip_accounts` |

Суффикс валютного разреза: лист «итого» — без суффикса, «в рублях» — `_rub`, «в инвалюте» — `_fx`.
Итого 21 имя: `clients_total`, `clients_total_rub`, `clients_total_fx`, `org_accounts`, … ,
`ip_accounts_fx`.

**Смысловые факты, которые обязан зафиксировать каталог** (проверены на файле):

- `clients_total` — итог источника, **не равен** сумме опубликованных строк: на 2026-10 разница
  ≈ 7,5 трлн руб. (нераскрытые компоненты). Складывать строки и называть это «всего» нельзя.
- `households_deposits_escrow` ≈ `households_deposits` + `escrow_accounts`: на 2019-06 … 2020-01
  совпадает до единицы, на 2026-10 расхождение 64 млн руб. (0,00009 %) — округление/пересчёт
  источника; за тождество не выдавать.
- Сноска источника к строке `**`: «Показатель не включает средства на счетах эскроу с
  01.07.2019». Ряд `households_deposits` публикуется с 2019-02; до этой даты — `-`.
- `escrow_accounts_fx` — нули по всей истории; это значение («валютных эскроу нет»), не пропуск.

## 3. Решения по дизайну

### 3.1 Таблица и имя импортёра (стандарт §7)

`Name() = TableName = cbr_sors_funds`; префикс `cbr_` — пространство имён пакета. Имя выбрано по
слагу страницы источника (`sors` — «Сведения о размещенных и привлеченных средствах») плюс
предмет (`funds` — средства клиентов).

```sql
CREATE TABLE IF NOT EXISTS cbr_sors_funds (
      name LowCardinality(String)
    , date Date
    , balance Float64
) ENGINE = ReplacingMergeTree ORDER BY (name, date);
```

`Float64` — правило 5 AGENTS (деньги/цены в новых таблицах); `balance` — остаток на дату, как у
`cbr_m2` и `cbr_households_b_mes` (не поток). Ключ `(name, date)`: пересмотр точки источником
заменяет строку.

### 3.2 Транспорт и разбор (стандарт §4, §6)

- `DataUrl` — статический URL файла (ссылка неизменна; вычисляемой ссылки нет), сеть — только
  внутри `Import()`, в `init()` её нет.
- Книга читается шаблонным путём (`ImportFunc`): так файл попадает в винтажный архив версий
  общим механизмом (§9.6), отступлений не требуется.
- Значения — **сырые** (`excelize.Options{RawCellValue: true}`): в файле формат `#,##0`,
  форматированное чтение вернуло бы `25,865,164` и потребовало бы склейки разрядов.
- Строка дат ищется **по признаку**, а не по индексу: первая строка, где не менее 12 ячеек
  (начиная со второй колонки) разбираются как `02.01.2006`. Нет такой строки — ошибка.
- Подписи строк нормализуются (`strings.TrimSpace`, затем снятие хвостовых `*` и повторный
  `TrimSpace`) и сверяются с картой «подпись → код», объявленной в коде (стандарт §6.8:
  заголовок источника может измениться, имя ряда — нет). Пропала любая из 7 подписей — ошибка
  со списком пропавших (источник сломан или подменён, §6.4). Незнакомые строки (сноска, пустые)
  пропускаются; лишние листы книги, кроме трёх ожидаемых, — `log.Warnf` и импорт продолжается
  (§6.6).
- `""` и `-` — не точка (§6.7); ноль пишется значением; нечисловая ячейка — ошибка с листом,
  подписью строки, датой и значением; 0 точек — ошибка (§6.4).
- `panic` нет; индексация проверяется; ошибки оборачиваются именем таблицы.

### 3.3 Точка контроля публикации и производные (стандарт §9, §10)

- Файл обновляется раз в месяц, шаг расписания — ежедневный: объявляется
  `PublicationCountPoints: "SELECT count() FROM cbr_sors_funds FINAL"`. Будничный прогон —
  HEAD-отпечаток + количественный чек → no-op без скачивания. Строка версии пишется последней,
  после точек и производных; винтажный архив работает по §9.6.
- Каталог — `cbrSorsFundsSeriesMeta` (21 запись): `source='cbr'`, `unit` «млн руб.», `frequency`
  «M», `origin` — файл + лист + подпись строки, `title` — русское название с валютным разрезом,
  `description` — что измеряет, привязка даты, оговорки §2.
- Витрина — общая `v_cbr_macro` (`afterCbrMacro`): семантика ряда та же «ряд → дата → значение»,
  отдельная витрина не нужна. Ветка `UNION ALL SELECT 'cbr', toString(name), date,
  toFloat64(balance) FROM cbr_sors_funds FINAL`; комментарий витрины и колонки `series`
  дополняются. Новый `GRANT` не нужен: `v_cbr_macro` уже выдана `kimi_reader`, сырая
  `cbr_sors_funds` агенту не выдаётся (§10.4).

### 3.4 Расписание и MCP-проверки

- `dagu/cbr.yaml`: шаг `cbr_sors_funds` в **хвосте** цепочки (падение нового шага не лишает
  данных проверенные шаги), `retry_policy` 3 × 300 с; реестр `cbr/importers.go` — та же позиция.
- `scripts/mcp_check.py`: (а) каталог — 21 запись по `origin LIKE '%/Borrowings/02\_01\_Funds\_all.xlsx%'`;
  (б) витрина — `uniqExact(series)` по явному списку 21 кода = 21 и непустота; (в) сырая
  `cbr_sors_funds` — отказ ClickHouse 497.
- `sql/key_rate_coverage.sql` — строка покрытия по таблице.

## 5. Отступления от стандарта

Нет. Отдельная витрина не заводится осознанно: ряд укладывается в штатную long-форму
`(source, series, date, value)` общей витрины пакета (§10.3), а `afterCbrMacro` — штатный
хелпер производных (§10.2).
