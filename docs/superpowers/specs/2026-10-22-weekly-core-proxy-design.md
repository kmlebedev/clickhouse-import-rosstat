# Недельный прокси базовой инфляции: сезонное сглаживание 4-нед. средней — design

**Дата:** 2026-10-22. **Пункт:** `key-rate/phase-4-weekly-core-proxy` ([issue #348](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/348), `role:research`). **Зависимость:** #347 (панель 36) — смержена PR [#349](https://github.com/kmlebedev/clickhouse-import-rosstat/pull/349), база ветки — `origin/main` `262f4d9`. **Ветка:** `research/348-weekly-core-proxy` (worktree `.worktrees/weekly-core-proxy`).
**Приёмка (кратко):** отчёт `docs/research/2026-10-22-weekly-core-proxy.md` + JSON; MAE/RMSE и DM против baseline на месячной сетке 2022-01 … 2026-09; отдельный прогон без тарифных месяцев; в ClickHouse не пишет; `make docs-check` и `make all` зелёные.

## 1. Пробел

Панель 36 даёт 4-недельную среднюю недельного индекса (геометрическое среднее четырёх недель, степень 52) по двум базам — невзвешенной товарной средней и официальному агрегату. Это **не** оценка базовой инфляции: товарная средняя перегружена волатильными позициями (картофель, помидоры), не имеет весов, а недельный ряд нерегулярен (≈51 дата в году, пропуски 4–21 день, тарифные недели). При этом панель 36 читается как «годовой темп», и неизвестно, можно ли вообще привести недельную среднюю к месячной базовой инфляции ЦБ и какая корректировка это делает лучше.

Панель 36 — вход, а не объект изменения: исследование отвечает на вопрос «какой способ сезонной/календарной корректировки даёт наименьшую ошибку на месячной сетке» и формулирует go/no-go для производного ряда.

Тарифная неделя 2026-10-05 (индекс 100,96) раздувает 4-нед. среднюю агрегата до **+16,21 %** — это и есть предмет корректировки.

## 3. Предрегистрация

Правила фиксируются до прогона; менять их после просмотра MAE нельзя.

### 3.1. Вход и цель

- `goods` — невзвешенное среднее по доступным на дату товарным рядам (агрегат исключён).
- `agg` — официальный агрегат «Индекс потребительских цен (недельная оценка)».
- Период входа: 2022-01-10 … 2026-10-19.
- Цель: `Базовый ИПЦ` м/м → `pow(1 + v/100, 12) − 1`, 2022-01 … 2026-09 (57 месяцев).
- Диагностический второй таргет: headline ИПЦ (`v_rosstat_macro`, `value − 100` м/м) → та же формула.
- Baseline B0 — дословно формула панели 36: `pow(exp(avg(ln(idx/100)) по 4 неделям), 52) − 1`; окно только при `n = 4`.

### 3.2. Выравнивание

Primary: значение месяца M — последнее значение с датой ≤ конца M (окно целиком внутри M, без данных M+1).
Robustness: среднее значений внутри M; первая неделя M+1 (обе публикуются до месячного ИПЦ и проверяют чувствительность к краю месяца).

### 3.3. Методы

1. **B0** — baseline без корректировки, обе базы.
2. **CAL** — календарная регрессия недельного лог-прироста `g_t = ln(idx_t/100)`:
   `g_t = β0 + β1·days_t + β2·holidays_t + β3·tariff_t + β4·jan_first_t + β5·may_t + ε_t`,
   где `days_t` — длина интервала, `holidays_t` — федеральные праздники в интервале (пакет `holidays`), `tariff_t` — тарифная неделя, `jan_first_t` — первая публикация января, `may_t` — интервал 1–9 мая. As-of: для каждого конца месяца OLS только по данным ≤ cutoff, минимум 26 недель; колонки с нулевой вариацией в окне отбрасываются. Скорректированный прирост `g_adj = g_t − (X_t − X̄_cutoff)β` (среднее прироста сохраняется), далее 4-нед. средняя и степень 52.
   In-sample вариант на полном окне — только диагностика, в приёмку не входит.
3. **STL** — регулярная 7-дневная сетка от 2022-01-10 до последней даты; недостающие недели заполняются равномерным лог-приростом по дням (накопленный уровень сохраняется). Вход — лог-уровень, `STL(period=52, robust=True)`; as-of пересчёт на каждом cutoff, минимум 104 недели (2 периода); `L_sa = L − seasonal`, 7-дневный лог-прирост, 4-нед. средняя.
4. **X13** — та же сетка и уровень, `Rscript` + `seasonal` 1.11: `seats_log_cal` (`transform.function="log"`, `regression.aictest="td"`, `outlier=""`), as-of по cutoff. **Gate 0** до кода: проба `ts(x, frequency=52)`; если X-13/`seasonal` отвергает недельную частоту — статус `infeasible` с точным текстом ошибки, числа не выдумываются. Если R/пакета нет — `unavailable`.

### 3.4. Тарифные месяцы

Основной список — по графику индексации: **2022-07, 2023-07, 2024-07, 2025-07, 2026-10**. Наблюдаемые скачки агрегата: 2022-07-01 = 100,23; 2023-07-03 = 100,13; 2024-07-01 = 100,66; 2025-07-07 = 100,79; 2026-07-06 = 100,31; 2026-10-05 = 100,96. Июль 2026 в основной список не входит (перенос основной индексации на октябрь), но входит в sensitivity-прогон `+2026-07`, потому что скачок 0,31 п.п. выше соседних недель.

### 3.5. Оценка и критерий

- MAE, RMSE (п.п. годовых), bias, corr; n — общее окно метода и цели.
- Diebold–Mariano (HLN, `h=1`) против baseline **на общем окне месяцев**; для базы `agg` — против `B0-agg`, для `goods` — против `B0-goods`.
- Отдельный прогон без тарифных месяцев (основной список) для каждого метода.
- Метод принимается, если MAE ниже baseline **и** DM p < 0,05 (двусторонний, как возвращает `eval_utils.diebold_mariano`). Иначе — вывод «недельная 4-нед. средняя остаётся индикативной, сезонную корректировку не заявляем».
- Для STL/X-13 окно короче истории; сравнение — на общем окне, ограничение мощности (MDE) публикуется.

### 3.6. Post-hoc дополнение: X-13 на месячной сетке (по запросу владельца)

Недельная частота 52 X-13 недоступна, поэтому дополнительно проверяется 4-нед. накопленный индекс (`Π idx/100 × 100`) на конце месяца — 57 точек 2022-01 … 2026-09, `frequency=12` (`frequency=13`, неперекрывающиеся 4-нед. блоки, X-13 тоже отвергает), `seats_log_cal` (log, `aictest="td"`, авто-выбросы), годовое выражение `(SA/100)^13 − 1`. Full-sample — in-sample; as-of — расширяющееся окно, минимум 36 месяцев. Это **post-hoc** проверка, вне критерия §3.5: она не меняет формальное решение, а показывает, есть ли у метода сигнал на месячной сетке.

**Расширение 2009+.** Тот же метод на всём официальном агрегате: `v_rosstat_macro` (бюллетени 2009–2018 + BI 2019+), 760 точек 2009-04-06 … 2026-10-12, регулярная 7-дневная сетка, 4-нед. индекс = `exp(L_t − L_{t−4})` (ровно 28 дней), месячная сетка 2009-05 … 2026-09 (209 точек). Товарная база не расширяется: до 2022 состав 26→111 рядов, уровни несопоставимы. Full-sample и as-of (≥36 месяцев) считаются на всех 209 месяцах, на 2019+ и на 2022+; grid-базис сверяется с сырой 4-точечной панелью на 2022+. Это тоже post-hoc.

## 4. Почему так

- **Baseline дословно как панель 36** — иначе сравнение было бы с другой величиной; расхождение с задеплоенным SQL проверяется перед PR.
- **Календарная регрессия на лог-приросте**, а не на уровне: прирост аддитивен по неделям, календарные эффекты (праздники, длина интервала, тариф) входят линейно; расширяющееся окно исключает look-ahead.
- **STL/X-13 на лог-уровне** — стандартная декомпозиция индекса; сезонная компонента в лог-пунктах, SA-прирост — разность. Период 52 на 7-дневной сетке даёт дрейф фазы ≈1,25 дня в год за 4,8 года — ограничение, а не ошибка.
- **Две базы и два таргета** — товарная средняя отвечает на вопрос issue, агрегат показывает цену отказа от невзвешенной средней, headline — контроль того, что провал (если будет) связан с базовой, а не с любым месячным рядом.
- **X-13 Gate 0** — не тратим цикл на метод, который может быть неприменим к частоте 52; отрицательный результат фиксируется как evidence.

## 7. Что не проверяется

- Ревизии и винтажи недельных/месячных рядов: в витринах одна версия, PIT-слоя нет.
- Веса ИПЦ: публично недоступны (покрытие архива CB_COMP 39,3 %), взвешенная товарная средняя не строится.
- Влияние состава товарной панели (107–111 рядов) на уровень средней — только публикуется, не корректируется.
- X-13 при `infeasible`/`unavailable` — метод не измерен; вывод формулируется по фактически прогнанным.
