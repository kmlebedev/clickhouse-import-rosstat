# Спека: `infra/5.11` — скил `rosstat-sql` в плагине `rosstat-mcp`

**Дата:** 2026-11-01
**Пункт:** `infra/5.11` (issue [#503](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/503)); зависит от `infra/5.10` (#474, смержен)
**Роль:** Go-инженер (манифесты, CI, docs)

## 1. Цель

Плагин `rosstat-mcp` 0.3.0 даёт агенту только инструмент `run_query` сервера `rosstat-staging`. Как правильно читать витрины, агент не знает: правила живут в ролевых скилах этого репо — памятка «Time-series SQL: практики ClickHouse» в `dashboard-migration` и матрица проверок в `editor-in-chief`. Без них внешний агент берёт смысл ряда из названия, считает по дублям, теряет индекс функцией над колонкой и путает дату периода с датой публикации.

Решение владельца (2026-11-01): перенести общие правила чтения витрин в плагин одним скилом, отдельным пунктом, версия **0.4.0**. Это пересмотр требования 5.10 «без скилов»: теперь — **только MCP плюс один скил о том, как им пользоваться**. Агентов, команд и хуков в плагине по-прежнему нет.

## 2. Решение

### 2.1 Скил

Файл `skills/rosstat-sql/SKILL.md` в корне `kmlebedev/rosstat-mcp`.

**Язык и расход токенов** (решение владельца 2026-11-01). Скил читает только агент, поэтому он пишется **по-английски** — так он короче в токенах. Отвечать пользователю агент должен **по-русски**; это первое правило в теле скила. Названия рядов, `title` и `description` из каталога цитируются как есть.

**Бюджет:**
- `description` во frontmatter — ≤ 300 символов. Он грузится в контекст каждой сессии, даже когда скил не нужен.
- Тело — ≤ 6 КБ (порядка 1,5 тыс. токенов). Стиль — императивные пункты без вступлений и пересказа документации. Шаблоны запросов — минимальные, без комментариев внутри SQL.
- Ссылок на внешние документы для чтения нет: всё нужное — в самом скиле.
- **Пересмотр 2026-11-01 (skill-creator):** ядро `SKILL.md` (≤ 6 КБ) — порядок работы, доступ, правила запросов, ловушки; шаблоны запросов и point-in-time вынесены в `references/templates.md` и `references/point-in-time.md`, агент читает их только по ссылке из ядра. Весь скил ≤ 10 КБ. В порядок работы добавлен поиск витрины по `source` через `system.tables.create_table_query`: имена витрин не совпадают с источниками (`domrf_mortgage` — в `v_bank_macro`).

Frontmatter: `name: rosstat-sql`; `description` — когда применять: любой SQL к `rosstat-staging` (поиск ряда, последнее значение, динамика, г/г, срез «что было известно на дату»).

Разделы:

1. **Доступ.** Только витрины `v_*` (база `default`); сырые таблицы и `forecast_log` отвечают `ACCESS_DENIED` (497) — это не ошибка запроса, а граница доступа. Пользователь `readonly = 2`: запись и DDL запрещены, настройки сессии (`max_execution_time`) менять можно.
2. **Как найти данные.** `v_series_catalog` (`source`, `series`, `title`, `unit`, `frequency`, `origin`, `description`) → `DESCRIBE` нужной витрины и её комментарии (`system.tables.comment`, `system.columns.comment`, если доступны) → фильтр по `series`. Смысл ряда — из `description`/`unit`, не из названия; единицы у пакетов разные (проценты vs доли).
3. **Как писать запрос** (общие правила из памятки `dashboard-migration` без Grafana-макросов):
   - фильтр по сырой колонке даты в `WHERE`, без функций над колонкой;
   - агрегация в ClickHouse, а не в клиенте; `LIMIT` — для разведки и top-N, не для временных рядов;
   - последнее значение — `max(date)` + `argMax(value, date)`, а не `ORDER BY date DESC LIMIT 1` по всей витрине;
   - бакеты — `toStartOfInterval(col, INTERVAL 1 DAY|WEEK|MONTH)` (unit-форма); ловушка секундной формы (`INTERVAL 86400 SECOND` выравнивается по UTC);
   - пропуск ≠ ноль: `WITH FILL` только когда отсутствие строки и правда ноль или последнее значение;
   - г/г и производные — оконными функциями по полному ряду, а не по обрезанному окну;
   - перед тяжёлым запросом — `EXPLAIN ESTIMATE`; явный `SETTINGS max_execution_time = …`.
4. **Ловушки данных** (из матрицы `editor-in-chief`, без редакционной части): дубли строк в витринах — `SELECT DISTINCT` / `GROUP BY`; квартальная дата — 1-е число квартала, следующего за отчётным; дата периода ≠ дата публикации; свежесть — `max(date)` на момент ответа, а не по памяти; единицы и знаки.
5. **Point-in-time.** `v_point_in_time` (все версии, смысл колонок), `v_point_in_time_asof(as_of='YYYY-MM-DD')` — срез строго до даты (`published_at < as_of`), `v_point_in_time_version` — версия набора. У параметризованной витрины нет `DESCRIBE` без аргумента.
6. **Шаблоны запросов.** Четыре готовых запроса: поиск ряда в каталоге; последнее значение и свежесть; месячная динамика с г/г; срез `as_of` с ревизией (`unemployment_sa`, 2023-11-30: 2.885274 на `as_of='2024-02-07'`, 2.916127 на `as_of='2026-09-02'`).

Каждый SQL-пример скила прогоняется живьём через MCP `rosstat-staging` до мержа (§4); пример, который не прошёл, в скил не попадает.

### 2.3 Тесты нового репо

- `test_no_component_fields` → `test_components`: `agents`, `commands`, `hooks` запрещены везде; `skills` — только `"./skills/"` и только в Codex и Kimi.
- Новый `test_skill`: в `skills/` ровно один каталог `rosstat-sql` с `SKILL.md`; frontmatter разбирается, `name == "rosstat-sql"`, `description` непустой и ≤ 300 символов; размер `SKILL.md` ≤ 6144 байт, всего скила с `references/` ≤ 10240; `SKILL.md` ссылается на каждый файл `references/`; проверки SQL и секретов — по всем файлам скила; в теле есть правило отвечать по-русски (`Russian`); в SQL-блоках скила все таблицы после `FROM`/`JOIN` — `v_*`, `system.*` или табличная функция `v_point_in_time_asof(...)`; секретов нет (литеральные `Bearer`, `password=`).
- Allowlist — плюс `skills/rosstat-sql/SKILL.md` и два файла `references/`; общий бюджет размера репозитория остаётся 64 КБ.

### 2.4 Этот репозиторий

- `dashboard-migration`: памятка остаётся (её правила проверяют тесты `grafana/`), в начало — ссылка на скил `rosstat-sql` как источник общих правил; Grafana-специфика без изменений.
- `editor-in-chief`: в шаги 3–4 — ссылка на скил `rosstat-sql` (дедупликация, даты периодов, каталог); матрица проверок остаётся (редакционная).
- `ARCHITECTURE.md` §6.5, `README.md` (раздел плагина), `AGENTS.md` (абзац «Плагин:»): «MCP плюс скил `rosstat-sql`».
- `docs/ROADMAP_INFRA.md`: строка 5.10 — ✅ Done (смержен 2026-11-01); новая строка 5.11; «Границы фазы».

## 3. Вне объёма

- Перенос ролевых скилов в плагин.
- Новые витрины, гранты, изменение MCP-сервера.
- Автоматическая синхронизация текста скила с памятками ролевых скилов (ссылка вместо копии).

## 4. Проверки и приёмка

1. CI нового репо зелёный; `claude plugin validate .` без ошибок и warnings.
2. Каждый SQL-пример скила выполнен через MCP `rosstat-staging` (токен из env через `make`, значение не печатается); результаты — в протоколе приёмки.
3. Claude Code в изолированном `CLAUDE_CONFIG_DIR`: установка по README, скил `rosstat-mcp:rosstat-sql` виден в списке скилов, `claude mcp list` → ✔ Connected, размер установки — десятки КБ; на вопрос по-русски агент со скилом отвечает по-русски.
4. Codex, Kimi, Qwen, Cursor — если клиент установлен; иначе «не проверено».
5. Этот репо: `make all` зелёный.

## 5. Риски

- **Дрейф правил.** Скил и памятка `dashboard-migration` пересекаются; источник общих правил — скил, памятка ссылается на него и держит только то, что проверяют тесты `grafana/`.
- **Сжатие против полноты.** 6 КБ не вместят все правила памятки и матрицы; в скил идут только правила, которые меняют результат или стоимость запроса. Остальное остаётся в ролевых скилах репо.
- **Язык ответа.** Английский текст скила может тянуть агента отвечать по-английски; правило «answer in Russian» стоит первым и проверяется в живой приёмке (п. 3 §4).
- **Срок жизни чисел.** Пример ревизии ПИТ опирается на винтажи 24-01/26-06 — они неизменны; примеры «последнего значения» не фиксируют чисел.
- **Kimi/Qwen/Cursor** — подхват `skills/` без живой проверки остаётся «не проверено».
