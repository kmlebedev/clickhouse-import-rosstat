## 1. Гипотеза и решение

Калиброванное правило ДДКП ЦБ

```
i_t = γ1·i_{t−1} + (1−γ1)·(r* + E3π_MP + γ2·(E3π_MP − 4) + γ3·gap_t)
```

с параметрами `γ1 = 0.75`, `γ2 = 1.5` (жёсткий сценарий — 1.9), `γ3 = 0.5`, целью 4 % и MP-индикатором `E3π_MP = 0.75·E3(core) + 0.25·E3(headline)` — **устойчивее и интерпретируемее** свободного OLS-Тейлора, коэффициенты которого на нашей выборке плохо идентифицированы (`a = −0.0064`, `r* = 7.69`).

Гипотеза: `cbr_rule` на walk-forward как минимум не хуже текущего `taylor` и `ordered_logit` по RMSE шага в б.п., а по вероятностям классов (Brier/log loss) даёт сопоставимую или лучшую калибровку. **Гипотеза может быть отвергнута** — это допустимый результат: пункт измеряет правило, а не доказывает его превосходство.

Решение по итогу: `promote` / `iterate` / `reject` (определение — §10). «Promote» здесь означает «трек можно добавить в публикационный контур», а не «модель в проде»; alias `champion` в MLflow — не deployment (до #184).

## 2. Что именно прогнозируется

- Единица — **заседание Совета директоров ЦБ**; прогноз — шаг ставки в базисных пунктах на заседание `t` и вероятности классов `{cut, hold, hike}`.
- `rate_before` — фактическая ставка накануне заседания (известна на дату прогноза). Поэтому правило применяется как **одношаговое инерционное правило от фактической ставки**:
  - `target_level = 0.75·rate_before + 0.25·(r* + E3π_MP + γ2·(E3π_MP − 4) + 0.5·gap)`;
  - `step_bp = (target_level − rate_before)·100`.
- Это **не** симуляция многоквартальной траектории и не воспроизведение официального прогноза ЦБ. Модельный путь с рекурсивным `i_{t−1}` — вне объёма (см. #272, сценарный веер).
- Решение оценивается на данных, доступных **строго до** заседания; исход — фактическое решение после него.

## 3. Данные и as-of

| Признак | Источник | Правило доступности |
|---|---|---|
| `rate_before` | `cbr_key_rate` | ставка на `d − 1` (конвенция `key_rate_model.build_decisions`) |
| `E3_core` (адаптивный) | `cbr_indicators_cpd`, серия «Базовый ИПЦ», SA м/м, % | точка месяца M доступна в конце M+1 (`available_from_cpd`) |
| `E3_headline` (адаптивный) | `cbr_indicators_cpd`, серия «Все товары и услуги», SA м/м, % | то же |
| `E3_headline` (консенсус) | `v_cbr_mo_br`, `cpi_dec_<Y>_median`; fallback `cpi_avg_<Y>_median` | волна + 6 дней (`CONSENSUS_PUBLICATION_LAG_DAYS`); `Y` — год точки `t + 3 квартала` |
| `gap_gdp` | `rosstat_vvp_kvartal`, серия `10 Валовой внутренний продукт` (SA, цены 2021, млрд руб.) | конец квартала + 3 месяца |
| `gap_ibk` | `macro_series` (`source='cbr_survey'`), `business_climate_sa`, пункты | конец месяца M+1 (`available_from_survey`) |
| `r*` | константы 2/3/4 %; вариант-тренд | только прошлые заседания, min 8, clip [0; 6] |

### 3.1. Адаптивные ожидания

Для трёх последних доступных SA м/м значений `r_1, r_2, r_3`:

```
G = Π_{j=1..3}(1 + r_j/100)
E3 = (G^(12/3) − 1)·100 = (G^4 − 1)·100
```

— годовое геометрическое среднее трёх месячных темпов. Для `n` доступных значений показатель степени — `12/n` (минимум 1, максимум 3; при `n < 1` признак отсутствует). Это **прокси** ожиданий «через 3 квартала», а не модельный прогноз; Филлипс/nowcast-путь — пункт #269.

`E3π_MP = 0.75·E3_core + 0.25·E3_headline`.

### 3.2. Консенсус-вариант

`E3_headline` берётся из медианы макроопроса ЦБ на календарный год `Y = year(t + 3 квартала)`:
сначала `cpi_dec_<Y>_median` (ожидаемый декабрьский г/г), при отсутствии — `cpi_avg_<Y>_median`.
`E3_core` остаётся адаптивным: core-прогноза в опросе нет. Это осознанно **не** «чистые рациональные ожидания», а гибрид; в отчёте он называется `cbr_rule_consensus`.
Доступность волны — `wave_date + 6 дней`; если волны на год `Y` нет — фолд пропускается (`DegenerateWindowError`), счётчик пропусков публикуется.

### 3.3. Разрыв выпуска

```
gap_gdp_t = (level_t / HP_trend_t − 1)·100, λ = 1600
```

HP-фильтр — **односторонний по доступности**: на дату заседания берутся только кварталы, опубликованные по правилу «конец квартала + 3 месяца»; минимум 8 кварталов, иначе `None`. Для `cbr_rule_ibk` — HP по месячному ИБК (`λ = 14400`), разрыв в пунктах трактуется как процентный (единицы — допущение, фиксируется в отчёте).

### 3.4. `r*`

- База: `r* = 3.0` (середина диапазона 2–4 %, фиксируется до прогона).
- Чувствительность: `r* ∈ {2, 3, 4}` × `γ2 ∈ {1.5, 1.9}` (таблица, без отдельных DM-треков).
- Вариант `cbr_rule_rtrend`: среднее `(rate_before − headline_yoy)` по последним 20 заседаниям (минимум 8), clip [0; 6]; `headline_yoy` — 12-месячное компаундирование SA м/м headline.

## 4. Варианты

| Имя | Отличие от базы |
|---|---|
| `cbr_rule` | γ2 = 1.5, `r* = 3.0`, адаптивные E3, `gap_gdp` |
| `cbr_rule_hard` | γ2 = 1.9 |
| `cbr_rule_ibk` | `gap_ibk` вместо `gap_gdp` |
| `cbr_rule_consensus` | `E3_headline` из `cbr_mo_br`, `E3_core` адаптивный; подвыборка с первой доступной волны |
| `cbr_rule_rtrend` | `r*` = тренд реальной ставки |

Все варианты используют одни и те же строки выборки; пропуски фолдов считаются отдельно. Гиперпараметры **не выбираются по тесту**: база и список вариантов зафиксированы этим документом до первого прогона.

## 5. Вероятности классов

- `σ_train` — RMS остатков правила на обучающем окне: для каждой прошлой строки правило применяется с её `rate_before` и признаками, остаток = `actual_step_bp − rule_step_bp`.
- Требуется `n ≥ 8` остатков и `σ_train > 0`; иначе `DegenerateWindowError`.
- `σ = max(σ_train, 25 б.п.)`.
- `step_hat ~ N(step_bp, σ)`; границы классов — `±12.5` б.п. (полушаг между 0 и 25):
  - `P(cut) = Φ((−12.5 − step_bp)/σ)`;
  - `P(hike) = 1 − Φ((12.5 − step_bp)/σ)`;
  - `P(hold) = 1 − P(cut) − P(hike)`.
- Вероятности клипуются в `[1e-6, 1−1e-6]` и нормируются; это **соглашение о дискретизации** непрерывного шага в три класса, а не структурное распределение.
- Точечный прогноз для RMSE/MAE — `step_bp` правила, а не `E[step]` из вероятностей (это важно для сопоставимости с B1–B3).

## 6. Бэктест

- Выборка: `build_decisions` + `build_rows` `key_rate_model` — 108 заседаний `2014-02-14 … 2026-09-11` (живой снимок; число перепроверяется).
- Walk-forward: расширяющееся окно, `min_train = 24` (основное, 84 фолда); скользящее `rolling40` (робастность, 68 фолдов). Оба окна в отчёте; выбор окна по ошибке запрещён.
- Бенчмарки: B1 `hold`, B2 `repeat`, B3 `AR(1)`, `ordered_logit`, `climatology` — те же функции и те же фолды, что у `key_rate_model`.
- Primary metric: **RMSE шага в б.п.** на расширяющемся окне. Дополнительно: MAE, hit rate, матрица ошибок классов.
- Значимость: DM-HLN против B1, B3 и `ordered_logit` (B2 — справочно), p-value и знак; блочный бутстрап 95 % CI разницы RMSE (`block=4`, `n=2000`, `seed=20261015`).
- Вероятности: Brier (multiclass), log loss, reliability bins; сравнение с `ordered_logit` и `climatology`.
- Калибровка уровня/направления: Mincer–Zarnowitz, Pesaran–Timmermann.
- Режимы: 2014–2021, 2022–2023, 2024–2026; отдельный разрез 2018+ для `gap_gdp` (HP на коротком окне).
- Остаток правила `actual − cbr_rule`: среднее/σ, top-10 отклонений, доля совпадения направления — диагностика экспертного суждения (research §5.3).
- MDE: при 84 фолдах ожидаемый MDE разницы RMSE — порядка 10–15 % (оценивается бутстрапом post hoc); точное значение публикуется в отчёте.
- Бюджет экспериментов: один предзарегистрированный прогон, один повтор для проверки детерминизма, без тюнинга по тесту.

## 7. Что не проверяется

1. **Нет PIT/винтажей по ВВП и CPD**: ревизии не учтены; as-of — консервативный лаг публикации, а не снимок первого релиза.
2. **HP в реальном времени** и короткая ранняя выборка (2014–2017: 8–20 кварталов); односторонний фильтр не равен винтажному.
3. **E3 — прокси**, а не структурная ожидаемая инфляция; консенсус-вариант — гибрид и подвыборка с 2021.
4. **Правило одношаговое** от фактической ставки, не рекурсивный путь.
5. **Вероятности** — соглашение `N(step, σ_train)` с границей ±12.5 б.п.
6. **Вне объёма**: Филлипс/nowcast-путь (#269), term/credit-признаки (#270), сценарный веер (#272), бюджетный импульс (#274).
7. **Не пишем в `forecast_log`** и не публикуем; текущий прогноз — только информационный артефакт.

- Выборка 108 заседаний; walk-forward на обоих окнах (84/68 фолдов), пропуски названы.

## 10. Правило решения

| Вердикт | Условие |
|---|---|
| `promote` | `cbr_rule` значимо лучше `ordered_logit` **и** хотя бы одного из B1/B3 по RMSE (DM p < 0.05, бутстрап-CI разницы не содержит 0), Brier/log loss не хуже; рекомендация — добавить трек в публикационный контур (решение владельца) |
| `iterate` | направление в пользу правила, но значимости нет; или точечная точность лучше, а вероятности хуже |
| `reject` | правило значимо хуже `ordered_logit` или B1/B3 по RMSE; либо вероятности значимо хуже |

«Значимо» — это DM/CI, а не «число меньше». Незначимый результат публикуется как результат, а не прячется. `promote` не означает запись в `forecast_log`: это отдельное решение владельца после отчёта.
