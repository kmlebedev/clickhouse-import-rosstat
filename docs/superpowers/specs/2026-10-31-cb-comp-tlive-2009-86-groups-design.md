# Task 15 (#465): `T_LIVE@2009` — 86 групп — протокол

> **Пункт:** `key-rate/phase-4-cb-comp-88-groups-live`, зонтик [#419](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/419), Task 15 [#465](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/465), `role:ml`. Продолжение Task 14 ([#454](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/454), PR [#458](https://github.com/kmlebedev/clickhouse-import-rosstat/pull/458)).
> **Статус:** протокол до прогона. `@2010` не меняется.

## 1. Зачем

`T_LIVE@2009` (Task 14) начинается 2009-01, но содержит 84 группы: `1710`/`1730` не восстановлены, потому что листовой резерв был запрещён до 2010 (нет словаря/весов 2009). Это сужение корзины на 2,8 п.п. ИПЦ. Цель Task 15 — восстановить `1710`/`1730` в 2009 по публичным весам Росстата и получить 86 групп, как у `@2010`.

## 2. Данные

- Публичный файл `CPR_tov_RF_2004-2026.xlsx` (Росстат, [страница цен](https://rosstat.gov.ru/statistics/price), `https://rosstat.gov.ru/storage/mediabank/CPR_tov_RF_2004-2026.xlsx`), листы 2008/2009; sha256 файла `188e7455…`.
- Snapshot `docs/research/2026-10-31-cb-comp-tlive-2009-early-weights.json`: веса 10 листьев `1710` (`1707`, `1711`, `1712`, `1714`, `1717`, `1718`) и `1730` (`1701`, `1702`, `1715`, `1716`) за 2008/2009, URL и sha256. Сумма листьев 2009 — 2,211, совпадает с публичной группой «Кондитерские изделия»; 2008 — 2,230.
- Листья и их 31074-ряды берутся из словаря 2010 (состав `1710`/`1730` не менялся); все 10 рядов имеют 24 точки за 2008–2009.
- Group weights для агрегата `T_LIVE` остаются архивными 2016 (как для 2010–2015); публичные групповые веса 2008/2009 — отдельный follow-up. Это ограничение называется явно.

## 3. Метод

- `VERSION_PRESETS["2009"]` получает `leaf_fallback_start=2008-12`; `@2010` остаётся `2010-01`.
- `leaf_weights` дополняется таблицами 2008/2009 из snapshot; `year_key` для 2008/2009 берёт их, для 2010+ — прежний 2016.
- `group_nsa` для `@2009` разрешает листовой резерв с 2008-12; `aggregated_mm` для `1710`/`1730` использует листья словаря 2010 и веса 2008/2009. Для `@2010` ничего не меняется.
- X-13 для `1710`/`1730` в `@2009` фитится с 2008-12 (первый SA м/м — 2009-01); их SA 2010+ меняется, поэтому модели `@2009` перепрогоняются.
- T_LIVE — та же формула; train-окна не меняются (2010-03…2018-12, BS 2016+).

1. `panel.csv @2009`: 2009-01, `groups_with_sa_first_month=86`, нет `8310`/`9218`; покрытие 0,937 от ИПЦ 2016.
2. `T_LIVE[1]` — 2009-01, `T_LIVE[6]` — 2009-06; `1710`/`1730` есть в 2009.
3. `@2010` регрессия: первый SA 2010-02, 86 групп, числа на 2019+ не меняются.
4. Повтор панели побайтно.
5. Task 2/3/9 на новой панели: R0/R9/R10; пины `@2009` обновляются по фактическим Task 3/9; сравнение с 84-групповой версией и `@2010`.
6. `make all`, `make docs-check`.

Гейт: 86 групп и покрытие 0,937; иначе — отрицательный результат, `@2009` остаётся 84-групповой research-серией.
