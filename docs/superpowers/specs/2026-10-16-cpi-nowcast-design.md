# Спека: ML-трек — nowcast месячного ИПЦ до публикации Росстата

**Дата:** 16 октября 2026 г.
**Пункт роадмапа:** [docs/ROADMAP_KEY_RATE.md](../../ROADMAP_KEY_RATE.md) §6, фаза 4, подпункт «ML-трек (nowcast ИПЦ, CatBoost + бенчмарки elastic net/AR(1))» — реализация [KEY_RATE_MODEL.md](../../KEY_RATE_MODEL.md) §4 («ML-трек: CatBoost на компонентах») и метода №4 («Nowcast устойчивой инфляции»).
**Решения владельца (2026-10-16):** объём — только ML-трек (метод №1 и ансамбль — отдельными подпунктами); агрегация — **direct + bottom-up** (оба, со сравнением); walk-forward — **старт 24** (основной) + **старт 48** (робастность, как в докладе).
**Статус:** спека дизайна; нормативные правила импортёров не пересказываются — ссылки вида «стандарт §N» ([IMPORTER_PACKAGE_STANDARD.md](../../IMPORTER_PACKAGE_STANDARD.md)).

---

## 1. Зачем

Контур ключевой ставки умеет оценивать устойчивую инфляцию только из месячных публикаций (в v0 — `cbr_indicators_cpd`, публикуется после Росстата). Между релизами есть **недельные** данные Росстата (131 позиция с 2022-01) — они позволяют выдать прогноз месячного ИПЦ **до официальной публикации**. Это и есть задача ML-трека: покомпонентный nowcast (CatBoost) с обязательными бенчмарками, честной схемой валидации (purging/embargo) и выводом «входит ли трек в ансамбль» ([KEY_RATE_MODEL.md](../../KEY_RATE_MODEL.md) §4: «без значимого выигрыша над бенчмарками ML-трек в ансамбль не входит»).

Границы применимости зафиксированы докладом и здесь не пересматриваются: бустинг — только на **компонентах** данных, никогда на решении по ставке; обучение локальное, артефакты модели (набор признаков, окно) — рядом с прогнозом.

## 2. Данные, таргет, признаки

### 2.1 Таргет

`rosstat_ipc_mes` (колонки `name`, `date`, `percent`): 4 ряда (имена закреплены кодом дословно):

| Код | Ряд (полное имя в БД) |
|---|---|
| `cpi_all` | «Индексы потребительских цен на товары и услуги по Российской Федерации» |
| `cpi_food` | «Индексы потребительских цен на продовольственные товары по Российской Федерации» |
| `cpi_nonfood` | «Индексы потребительских цен на непродовольственные товары по Российской Федерации» |
| `cpi_services` | «Индексы потребительских цен на услуги по Российской Федерации» |

Значение — индекс «к концу предыдущего месяца» (100 = без изменения). Таргет: **y = percent − 100 (п.п., м/м, несглаженный ряд)**; дата точки — последний день месяца. Доступный диапазон таргета: 1991-01 … 2026-09; **выборка ML-трека — с 2022-01** (глубже нет недельных признаков), ≈57 месяцев.

### 2.2 Дата прогноза (cutoff)

Для месяца `M` прогноз делается на **8-е число месяца M+1** — до публикации Росстата (выпуски месячного ИПЦ выходят 10–16-го; сентябрь-2026 — 14.10.2026). В признаки месяца `M` попадает **только опубликованное к cutoff**: всё, что опубликовано позже, не участвует (правила §2.4).

### 2.3 Признаковый набор (фиксированный; 9 числовых + 1 категориальный)

Никакого тюнинга и отбора признаков по результатам. `month` передаётся CatBoost категориальным признаком.

| # | Признак | Определение |
|---|---|---|
| 1 | `share_rising_wk` | доля позиций недельного ИПЦ с `percent > 100` на последней неделе, опубликованной к cutoff (на 2026-10-05 — 111 «живых» позиций из 131) |
| 2 | `median_wk` | медиана `(percent − 100)` на той же неделе |
| 3 | `median_wk4` | среднее недельных медиан за 4 последние недели |
| 4 | `gasoline_4w` | сумма `(percent − 100)` позиции «Бензин автомобильный» за 4 недели |
| 5 | `usd_20d` | 100 × ln(USD_t / USD_{t−20}) по `cbr_currency_usd` (`price`, руб./USD); `t` — последняя точка ≤ cutoff |
| 6 | `key_rate` | ключевая ставка, действующая на cutoff (`cbr_key_rate`; без лага — точка в день вступления в силу) |
| 7 | `ofz_1y` | доходность ОФЗ, тенор `1y` (`ofz_curve`), последняя точка ≤ cutoff |
| 8 | `fao_mm` | % м/м по «Food Price Index» (`fao_food_price_Indices_monthly`), последняя доступная точка |
| 9 | `y_lag1` | таргет месяца `M−1` (опубликован к cutoff по правилу §2.4) |
| 10 | `month` | категориальный месяц 1–12 (CatBoost `cat_features`) |

Агрегат недельного ИПЦ отсутствует в источнике (проверено: 131 позиция — только товары/услуги-позиции, агрегатов нет), поэтому недельные признаки считаются по позициям (§2.3 пп. 1–4).

**`ofz_1y` при отсутствии точки:** источник (`ofz_curve`, тенор `1y`) хранит только текущий снимок G-кривой МосБиржи — истории нет, копится с 2026-10 (импортёр ходит ежедневно); до накопления признак в бэктест-окне равен `NaN` и ошибки не даёт (CatBoost — NaN-бакет, enet-бенчмарк — импутация). Это осознанное исключение из правила «нет данных → месяц пропускается»: выбрасывать месяцы из-за систематически отсутствующего ряда нельзя; as-of при этом не нарушается — точка позже cutoff не используется.

### 2.4 Правила доступности (as-of v0; консервативные)

| Ряд | Точка | `available_from` |
|---|---|---|
| `rosstat_ipc_weeks` | регистрация (понедельник) | `date + 2 дня` (публикация Росстата по средам) |
| `rosstat_ipc_mes` | конец месяца M | конец месяца M+1 (публикация 10–16-го; запас до cutoff) |
| `cbr_currency_usd` | день | `date + 1` |
| `cbr_key_rate` | день вступления в силу | `date` |
| `ofz_curve` | биржевой день | `date + 1` |
| `fao_food_price_Indices_monthly` | 1-е число месяца **публикации** (значение — индекс за предыдущий месяц; так его хранит импортёр, `mes.AddDate(0,1,0)`) | `date + 6 дней` (FAO публикует в первые дни месяца) |

Отсутствие доступной точки `ofz_1y` — единственное исключение из правила «нет данных → месяц пропускается»: признак равен `NaN`, месяц остаётся в выборке (обоснование — §2.3; источник хранит только снимок кривой).

**Защита от утечек (обязательно, тестами):**

1. мутант-тест: подмена признака на «будущее» значение меняет прогноз (признак реально читается) и наоборот — запись, опубликованная после cutoff, в признаки не попадает;
2. purge-проверка: для каждого фолда интервал времени признаков тестового месяца не пересекается со временем меток обучающих месяцев (структурно пересечений нет — assert-тест фиксирует это);
3. embargo — параметр `--embargo-months` (по умолчанию 0; прогон с 1 — робастность).

Это приближение, а не point-in-time слой: точные даты публикаций и ревизии не учтены (Отдельный пункт фазы 4, после `cbr_dip_bulletin`). В отчёт — раздел «что не проверено».

## 3. Модели

### 3.1 Модель месяца (CatBoost)

- `CatBoostRegressor(loss_function='RMSE', random_seed=SEED, verbose=False)`, **дефолтные гиперпараметры** (доклад: дефолты фиксируются в метаданных модели — фиксируются здесь и в JSON прогона).
- `allow_writing_files=False` — **ратифицировано контроллером (Task 4, применяется в Task 5)**: это не гиперпараметр и не отступление от дефолтов библиотеки, а запрет побочного эффекта — без него CatBoost создаёт каталог `catboost_info/` в рабочем каталоге прогона. Каталог не создаётся; флаг — часть код-конфигурации (`catboost_params`), пинован тестом `get_params()` собранной модели и в метаданные модели (`catboost_metadata`, JSON прогона) как «дефолт библиотеки» не входит.
- `monotone_constraints` — только там, где направление априорно: `share_rising_wk` +1, `median_wk4` +1, `gasoline_4w` +1, `usd_20d` +1 (ослабление рубля и рост цен → рост ИПЦ); остальные без ограничений. Порядок признаков и знаки пинованы тестом.
- `cat_features=['month']`.

### 3.2 Два способа агрегации (решение владельца)

- **direct** — CatBoost на таргет `cpi_all`.
- **bottom-up** — CatBoost на три компоненты (`cpi_food`, `cpi_nonfood`, `cpi_services`); агрегат = `Σ w_j · ŷ_j`, веса `w` — из **неотрицательной регрессии** (NNLS) общего ИПЦ на компоненты **по обучающему окну фолда** (без утечки), нормированные к сумме 1; веса докладываются в отчёте (проверка: сумма ≈ 1, компоненты ≈ [0.36–0.40, 0.35–0.40, 0.25–0.30]).
- Обе схемы оцениваются на одних фолдах; сравнение direct vs bottom-up — самостоятельный результат (доклад §4: direct лучше в спокойные периоды, bottom-up — в турбулентные).

### 3.3 Обязательные бенчмарки (фиксируются до результатов)

| # | Бенчмарк | Прогноз |
|---|---|---|
| B1 | «прошлый месяц» (last value) | `y_{M−1}` |
| B2 | AR(1) с сезонными дамми | OLS `y_M` на `y_{M−1}` + 11 дамми месяца (HAC, maxlags=3) |
| B3 | ElasticNetCV | `ElasticNetCV(alphas=logspace(−4, 1, 20), l1_ratio=[0.1, 0.5, 0.9], cv=TimeSeriesSplit(3))` на стандартизованных признаках §2.3 (кроме `month`), обучение только на тренировочном окне фолда |

Бенчмарки — на том же признаковом пространстве и тех же фолдах, что модели. Медиана макроопроса ЦБ как бенчмарк не берётся: горизонт выпусков — годовой, месячного сопоставления нет (названо в §7).

**Минимальные обучающие окна (фиксируются здесь, реализация — `DegenerateWindowError`, walk-forward пропускает фолд со счётчиком):** B2 — не менее 14 строк (const + `y_{M−1}` + 11 дамми + хотя бы одна остаточная степень свободы); B3 — не менее 12 строк (иначе признаки не оцениваются). У B3 «NaN-колонки» (NaN более половины значений окна), которых больше половины, — тоже вырожденное окно; недосход координатного спуска (`ConvergenceWarning`) вырождением НЕ считается: фолд оценивается, а число недосошедших фолдов выводится в отчёт по каждому окну.

## 4. Валидация, метрики, тесты значимости

- **Walk-forward, расширяющееся окно**: старт 24 месяца (основной, ≈33 фолда), старт 48 (робастность, ≈9 фолдов); переобучение на каждом фолде; embargo 0 (прогон с 1 — робастность). Единичный train/test split запрещён.
- **Метрики:** RMSE и MAE в п.п. (м/м); отдельным блоком «последние 12 фолдов».
- **Тесты:** Diebold–Mariano с поправкой HLN — `catboost_direct` и `catboost_bottomup` против каждого бенчмарка, и `bottomup` против `direct`; блочный бутстрап разницы RMSE (блок 3 месяца, 2000 ресэмплов, `seed=SEED`).
- **Вердикт «в ансамбль»:** формулируется по значимости выигрыша над бенчмарками; ансамбль — отдельный подпункт роадмапа.
- Общие оценочные функции (`rmse`/`mae`, DM с конвенцией нулевой дисперсии, блочный бутстрап) **выносятся в `scripts/eval_utils.py`** и переиспользуются `scripts/key_rate_model.py` (тонкие обёртки с прежними именами; 169 тестов остаются зелёными) — без дублирования логики.

Зависимости: `catboost>=1.2` (проверено на arm64 macOS: 1.2.10), `scikit-learn`, `pandas`, `statsmodels>=0.15`, `scipy`, `numpy` — только через `uv run --with`. В ClickHouse скрипт **не пишет**.

**Текущий nowcast** (`cpi_nowcast_forecast.json`): месяц — последний, чей месячный ИПЦ ещё не опубликован на дату прогона, **включая незакрытый текущий**. Наличие метки общего ИПЦ в `rosstat_ipc_mes` и есть публикация (импортёр пишет её только после релиза Росстата), поэтому цель — месяц за последним опубликованным; если же метка месяца-цели по консервативному расписанию §2.4 (`available_from_mes` — конец M+1) уже должна была выйти, а её нет, это дыра импорта, а не неопубликованный месяц, — цели нет (внятное сообщение, JSON не пишется). На 2026-10-16: сентябрь-2026 опубликован 14.10 → цель = **октябрь 2026**.

Признаки — as-of даты прогона (не канонического cutoff); недельное окно — 1…4 последних недели, опубликованные к дате прогона после конца `M−1` (минимум одна). Неполное окно (`N < 4`) — пометка «частичное окно: N из 4 недель» в `note` JSON и в разделе «Текущий nowcast» отчёта плюс оговорка, что режим генерации признаков отличается от бэктеста (там окно строго четыре недели; бэктест не меняется). `y_lag1` — опубликованная (есть в данных) метка `M−1`: консервативное `available_from_mes` в живом режиме исключило бы уже вышедший лаг. Модели и бенчмарки обучаются на полной выборке, `bottomup_weights` — веса NNLS по ней же; `catboost_direct`/`catboost_bottomup` в JSON — объекты `{"forecast", "metadata"}` (метаданные модели §3.1), `benchmarks` — прогнозы B1–B3 (`null` — метод не посчитан, причина в `note`).

Ветка «нет цели живого nowcast'а» (нет неопубликованного месяца, нет недельного окна или ни один метод не посчитан) бэктест НЕ отменяет: отчёт и CSV пишутся как обычно (walk-forward валиден и без живого прогноза), причину называют раздел отчёта и консоль, а подчищается только устаревший `cpi_nowcast_forecast.json` (`write_nowcast_artifact`): дат в именах нет, и оставленный `forecast.json` читался бы как текущий прогноз. Если же у прогона нет НИ ОДНОГО прогноза вовсе (пустая выборка или выборка короче старта walk-forward), не пишется ничего, а все три артефакта прошлого прогона удаляются (`clear_stale_artifacts`, образец — Task 6 ветки v0). Прогон не падает ни в одной из веток.

## 6. Приёмка

1. `make all` — зелёный; тесты обоих скриптов зелёные (в т.ч. 169 прежних после выноса `eval_utils`).

3. Живой прогон `make cpi-nowcast`: фолды (24/48), RMSE/MAE по всем моделям и бенчмаркам, DM p-value, веса bottom-up, текущий nowcast октября-2026 — числа в протокол PR.
4. README/ARCHITECTURE/ROADMAP синхронизированы тем же PR; статус подпункта — ✅ (после приёмки).
5. Один PR в конце; протокол живой приёмки — комментарием (стандарт §16.1 п. 8).

## 7. Границы (явно вне пункта)

- **Метод №1 (рыночные вероятности KEYRATE) и ансамбль** — отдельные подпункты; ML-трек входит в ансамбль только со значимым выигрышем (§4).
- **Данные СберИндекса не используются**: условия использования `sberindex.ru` не подтверждены (KEY_RATE_MODEL.md §4) — трек строится на недельных данных Росстата; включение Сбера — отдельным пунктом после юридического выяснения.
- **Point-in-time слой** (точные даты публикаций, винтажи) — отдельный пункт; здесь — консервативные правила §2.4.
- Конкретные продпозиции (яйца/куры/плодоовощи) как отдельные признаки, инфляционные ожидания, ставки по вкладам, квартальные ВВП-каналы, текстовый канал — не входят (набор признаков фиксирован).
- Публикационный контур (посты, журнал), бенчмарк «медиана макроопроса ЦБ» (годовой горизонт), витрины MCP, графики — отдельные пункты.
- 2022-01 — нижняя граница выборки (недельные данные глубже не отдаются источником).
