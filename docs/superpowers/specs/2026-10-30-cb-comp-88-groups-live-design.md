## 1. Зачем

Live bottom-up требует четырёх вещей, которых сейчас нет на живых данных: (1) соответствия 88 групп CB_COMP рядам публичного источника; (2) месячных индексов групп (NSA); (3) SA групп нашим X-13; (4) весов СПР на текущий год. Пока цели групп берутся из архива авторов (срез 2024-09), модель не может работать после 2024 и не может быть production. Task 1 отвечает, можно ли собрать эти четыре слоя из публичных данных с точностью, достаточной для Task 2.

## 4. Данные и as-of

- Только чтение: `v_fedstat_ipc` через `lib.clickhouse.ch_query` (`kimi_reader`), архив CB_COMP — локально (`.worktrees/cb-comp-archive/build/cb-comp/extracted`, md5 `797f00518c3a0fe6d4cd2c2ad22aa70a`), в репозиторий не добавляется.
- Единицы: м/м в п.п. (`value − 100`); уровни — накопленное произведение `value/100`.
- As-of: месяц `M` 31074 считается доступным с 9-го числа `M+1` (конвенция W0 `publication`); X-13 as-of — перефит на каждом origin по данным `≤ M−1`. Режим «вся выборка» — только для сверки с архивом (у авторов SA тоже по всей выборке на 2024-09).
- Винтажей 31074 нет (ЕМИСС ревизии не хранит): «последняя редакция», сказано явно.
- Веса: лаг один год (`weight_for_month`), как у CB_COMP и в #190.

## 5. Методы

1. **Маппинг (Q1).** Ключ — код группы `model.xlsx` → состав группы по `dictionary_cpi.xlsx` соответствующего года → названия позиций → нормализованные названия рядов 31074 (`normalize` из Task 3: регистр, пробелы, кавычки, единицы измерения в хвосте). Сначала ищется готовый ряд группы по названию; если нет — группа собирается из позиций. Каждой группе присваивается метод `direct | aggregated | missing` и доля веса, покрытая найденными позициями. Ручные соответствия — только списком в коде с причиной, не fuzzy-подбором.
2. **Агрегация (Q2).** Для `aggregated`: м/м группы = взвешенное среднее м/м позиций весами СПР года (лаг год), нормированными на покрытую долю; позиция без данных в месяце — исключается с перенормировкой, число позиций пишется.
3. **SA (Q3).** X-13 `seas(transform.function="log")`, авто-модель и автовыбросы, без подбора, на уровне индекса группы; SA м/м — отношение соседних SA-уровней. Ряд короче 36 месяцев или с неудачным фитом — `sa_failed` (NaN), не заменяется NSA. Режимы: вся выборка (сверка с архивом) и as-of (для Task 2).
4. **Сборка (Q4).** SA ИПЦ без КУ = `Σ w_g·sa_g / Σ w_g` по группам с данными, ЖКУ `9470` вне компонент, как в #190; накопленный прирост за h по формуле архива `exp(Σ log(1+x/100))·100 − 100`. Источник SA групп в сборке — наш X-13 (вся выборка) и, отдельной строкой, as-of.
5. **Веса (Q5).** Поиск публичных таблиц весов ИПЦ (структура потребительских расходов для расчёта ИПЦ): сайт Росстата, ЕМИСС, методологические положения; проба доступа и формата; сверка найденных весов 2016–2024 с `cpi_weights_tovar.xlsx`. Решение go/no-go и handoff Go-импортёру.
6. **Швы (Q6).** Для 2023+ — сравнение агрегата и нескольких групп «РФ без новых субъектов» с архивом 2023-01…2024-09; для рождений/снятий — список групп, у которых состав позиций меняется внутри 2016–2024.

## 6. Метрики

RMSE, MAE, bias (ours − reference), корреляция; по каждой группе и взвешенно по весам 2024; окна 2016-01…2024-07 (основное для SA), 2010-01…2024-09 (NSA), 2019-01…2024-07 и normal-54 (сборка); n указан везде.

## 12. Решение владельца 2026-10-30: цель Task 2 — наш live SA ИПЦ без КУ

**Основание.** Главный гейт Task 1 не пройден ни в основном прогоне (сборка h1 0,106), ни с поправкой §11 (0,1048). Разведка показала, что разрыв с `TARGET_FULL` создают 55 групп без эталона авторов и отличие их SA-панели `fst` от архивного `mom_sa`; подбор спецификаций по группам этого не закроет ([отчёт](../../research/2026-10-30-cb-comp-88-groups-panel.md) §6a). Решение владельца в [#421](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/421): вариант 3 — Task 2 учится и оценивается на **нашей** цели. Гейт §7 при этом не пересматривается и в отчёте остаётся «не пройден».

**Цель `T_LIVE`.** Накопленный за h месяцев прирост SA ИПЦ без КУ, собранный из 88 групп:
- SA групп — наш X-13 на всей выборке со спецификациями §11 (9950 — C4, остальные — C0), источник — `v_fedstat_ipc`;
- веса — СПР Росстата с лагом в год; ЖКУ `9470` вне компонент; нормировка на группы, у которых в месяце есть SA (9218 — NaN, 9260 — с 2024-11 NaN);
- накопление — как у `TARGET_FULL`: `exp(Σ log(1 + x/100))·100 − 100` за h месяцев, заканчивающихся в M.

Ряд `T_LIVE[1]` за 2010-01…2026-09 — производный артефакт Task 1 (`build/cb-comp-groups/`), в репозиторий не коммитится; его sha256 пишется в паспорт Task 2.

**Как сравнивать с CB_COMP** (детали — протокол Task 2, до его результатов):
1. **Основная метрика Task 2** — RMSE нашей модели против `T_LIVE` на окне и origin статьи (2019-01…2024-07, normal-54, origin `M−(h−1)`).
2. **Сравнение с CB_COMP «каждый на своей цели»**: DM-HLN и бутстрап по разности потерь `(ŷ − T_LIVE)² − (ŷ_CB − TARGET_FULL)²`. Формулировка вывода — «точность на собственной цели», а не «точнее по одной истине».
3. **Справочно — на одной истине**: наша модель против `TARGET_FULL`. Сюда входит компонента расхождения целей (h1 0,105 / 0,082 на 67 / 54 месяцах; h2/h3/h6 — §6a), она называется явно.
4. В отчёте Task 2 обязательно выписываются RMSE `T_LIVE` против `TARGET_FULL` на тех же месяцах, чтобы читатель видел, сколько разницы создаёт сама цель.

**Что не доказывается.** «Лучше CB_COMP» по пункту 2 не означает «лучше прогнозирует SA-инфляцию ЦБ». Это сравнение двух систем, каждая из которых прогнозирует свою SA-цель. Для live-публикаций это и есть рабочая постановка: `TARGET_FULL` после 2024-07 не существует.

## 13. Протокол Task 2 (#422): `per_sheet` bottom-up на нашей панели, цель `T_LIVE`

- SA групп — артефакт Task 1, перегенерируется на коде `main`: `make cb-comp-groups-panel ARGS="--asof --jobs 8"` → `build/cb-comp-groups/panel_amended.csv` (спецификации §11; колонки `sa_full_mm` — вся выборка, `sa_asof_mm` — as-of с 2019-01). Его sha256 пишется в паспорт.
- МП — публичная книга ЦБ по листам: `make cb-comp-public-export` → `build/cb-comp-parity/{public_panel,sheet_map}.csv` (`v_cbr_mp_public_panel`, `v_cbr_mp_bsu_map`), режим `per_sheet` как в #252.
- Макро-признаки (`usd_mm`, `key_rate`, `fao_mm`) — `cb_comp_parity.load_feature_rows()` (as-of правила v2), как в #190/#222/#252.
- CB_COMP и `TARGET_FULL` — архив авторов; RMSE CB_COMP на normal-54 пинуются (0,158805 / 0,296655 / 0,443623 / 0,971459).

**Цели.**
- Цель группы g на горизонте h — накопленный прирост её SA (`sa_full_mm`) за h месяцев, заканчивающихся в M (`cb_comp_bottomup.component_targets` от `log(1 + x/100)`).
- `T_LIVE[h](M)` — §12: м/м SA ИПЦ без КУ = `Σ w_g·sa_g / Σ w_g` по группам с SA в месяце (веса СПР года `M.year − 1`, без ЖКУ `9470`), затем накопление за h месяцев.

**Модели** (как в #252, без подбора):
- `live_per_sheet` (основная) — 88 компонентных CatBoost на дефолтах (`random_seed = 20261018`). 72 группы с BSU-кодами получают `per_sheet`-признаки МП, 16 групп без BSU — без МП. Базовые признаки — `y_lag1`, `y_lag2` (лаги SA группы), `usd_mm`, `key_rate`, `fao_mm`, `month`. Агрегат — `cb_comp_bottomup.aggregate` (веса с лагом год, нормировка на группы с прогнозом).
- `live_nomp` — то же без МП у всех групп (справочно).
- `live_per_sheet_asof` (robustness) — тестовые лаги `y_lag1/2` берутся из `sa_asof_mm`, обучение не меняется.

**Окна.** Train — целевые месяцы 2010-03…2018-12 без 2014-12…2015-03; test — 2019-01…2024-07 (67); основное окно оценки — normal-54 (без 2020-04 и 2022); origin `M−(h−1)`; горизонты 1/2/3/6, primary — h1/h3/h6, h2 справочно.

**Гейты и сравнения** (до результатов):

| id | что | условие |
|---|---|---|
| **R0** регрессия | тем же кодом `per_sheet` на **архивных** целях (`cb_comp_bottomup.run_bottomup`, `feature_mode = "per_sheet"`) | RMSE против `TARGET_FULL` = 0,191215 / 0,308390 / 0,463865 / 0,971324 (допуск 1e-6). Не совпало — стоп, разбор |
| **G2** основной гейт Task 2 | `ratio_live[h] = RMSE(live_per_sheet − T_LIVE) / RMSE(CB_COMP − TARGET_FULL)` на normal-54 | `ratio_live[h] ≤ 1,05 × ratio_per_sheet[h]`, то есть ≤ **1,264 / 1,098 / 1,050** на h1/h3/h6 (h2 справочно ≤ 1,092) |
| **E2** «каждый на своей цели» | классификация W5b (`cpi_two_stage_cb_comp.compare_to_cb`): ошибки `ŷ − T_LIVE` против `ŷ_CB − TARGET_FULL` | DM-HLN p < 0,0167 (Бонферрони), 95 % CI ΔRMSE без 0; паритет — 90 % CI отношения ∈ [0,90; 1,10] и p ≥ 0,05 |
| **E3** на одной истине (справочно) | та же классификация с ошибками `ŷ − TARGET_FULL` | — |
| **E4** расхождение целей | RMSE `T_LIVE` против `TARGET_FULL` по h на 67 и 54 месяцах | — |

Все 67 месяцев — справочно. Порог G2 — пересчёт пункта «не хуже `per_sheet` на 5 %» из #422 на отношение к CB_COMP, потому что абсолютные RMSE на разных целях несравнимы.

**Детерминизм и паспорт.** Повторный прогон обязан дать побайтно те же предсказания и `result.json`. Паспорт в JSON: git SHA, sha256 входов (панель групп, публичная панель, карта листов, архивные файлы), хэш конфигурации и выборки. `ML_LOG` и MLflow не используются: Task 2 — сравнительный эксперимент без промоушена; паспорт для gate появится в Task 7.

**Что не доказывается.** E2 — сравнение двух систем, каждая на своей SA-цели, а не «точнее по SA ЦБ». Признаки МП — листовые, а не 87 кодов. Винтажей нет. Лаги в основной модели — SA всей выборки, как у CB_COMP; честный live — robustness `live_per_sheet_asof`.

**Решение владельца** ([#422](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/422), 2026-10-30): обучение — на целях групп из нашей панели, как в Task 2 (их сборка — `T_LIVE`). Основная истина сравнения с CB_COMP — `TARGET_FULL`. Протокол записан до любых результатов Task 3.

Пороги ниже выбраны с этим знанием; они не подогнаны под `live_per_sheet`: G3 — это тот же критерий «не хуже `per_sheet` #252 на 5 %», что и в G2.

**Данные, окна, цели групп, признаки МП и макро** — без изменений относительно §13 (те же входы и sha256, что в Task 2; train 2010-03…2018-12 без выбросов статьи; test 2019-01…2024-07; normal-54; origin `M−(h−1)`; горизонты 1/2/3/6; primary — h1/h3/h6).
