## 1. Зачем

В Task 3 elastic net проиграл CatBoost на длинном горизонте: `live_en` на окне 2010–2018 дал h6 1,922 к CB_COMP против 1,062 у `live_cb`. Отчёт Task 3 объясняет это переносом уровня 2010–2018 на 2019–2024. В статье Кошкина–Крылова (2025) EN_COMP — лучшая модель на h2/h3 (табл. 2–3), а h3 — главный незакрытый горизонт `combo3` (1,010 при пороге G3 1,098, но и при пороге паритета 1,10 это лишь точка без значимости).

Гипотеза: для elastic net работают те же два приёма, что сработали для BS в Task 9 — короткое окно **2016+** и **переобучение на каждом тестовом месяце**. Тогда `live_en16` перестанет переносить уровень 2010–2018, а `combo4` = среднее `combo3` и `live_en16` улучшит h3, не испортив h1/h6.

## 3. Данные и окна

- **`live_en16`** — тот же вход, что у `live_en` Task 3: C0-панель `build/cb-comp-groups/panel.csv` (sha256 `aec91f99…`), публичная книга МП `build/cb-comp-parity/public_panel.csv` (`47176baa…`), `sheet_map.csv` (`0d8a6ab5…`); признаки `per_sheet`, `month` исключён.
- **Цель групп** — SA ИПЦ без КУ из нашей панели (как Task 2/3); оценка — `TARGET_FULL` из архива CB_COMP, normal-54.
- **Выбросы статьи** — `cp.TRAIN_OUTLIER_MONTHS | cp.OUTLIER_MONTHS` (17 месяцев), исключаются по месяцу цели `t`, как в Task 9.

## 4. Модели

Для каждого h ∈ {1, 2, 3, 6} и тестового месяца M (origin `M−(h−1)`):

**`live_en16`** — `StandardScaler → ElasticNetCV` в конфигурации B3 репозитория (`cb_comp_live_en.make_enet`: `alphas = ENET_ALPHAS`, `l1_ratio = (0,1; 0,5; 0,9)`, `cv = TimeSeriesSplit(3)`, `random_state = 20261018`), признаки без `month`, NaN — медианой train, колонка без наблюдений — 0 (`cb_comp_live_en.enet_fit_predict`).

- строки обучения — цели `t` из `[2016-01 + h, M − h]`, `t ∉` выбросов статьи, таргет не NaN; признаковая строка — origin `t−(h−1)`, как в `cb_comp_bottomup.model_rows`;
- правило `t ≤ M − h`: накопленный таргет строки `t` требует ИПЦ до `t`, а к origin `M−(h−1)` известен ИПЦ только до `M−h` (та же логика, что у BS в Task 9);
- модель переобучается на каждом M (расширяющееся окно); строка M и всё позже `M−h` в обучение не входят;
- минимум строк — `max(MIN_TRAIN_ROWS, ENET_MIN_TRAIN)` = 20; иначе у группы/горизонта/месяца нет прогноза.

**Кандидаты:**

| id | прогноз |
|---|---|
| `live_cb` | Task 3, без изменений (бенчмарк) |
| `live_en16` | EN по группам, окно 2016+, помесячное переобучение |
| `combo3` | `(live_cb + bs_econ16 + bs_rozn16) / 3` — код Task 9 на `T_LIVE` |
| `combo4` | `(combo3 + live_en16) / 2`, веса равные, не подбираются |

Справочно (в решении не участвуют): `bs_econ16`, `bs_rozn16` (Task 9), `combo3_tf` (BS на `TARGET_FULL`).

Агрегат — веса СПР с лагом год, нормировка на группы с прогнозом (`cb_comp_live_bottomup.aggregate`).

## 5. Проверки до гейта (R11)

- **R11a — `combo3` = Task 9.** Отношения к CB_COMP на `TARGET_FULL`, normal-54: 1,034768 / 0,957109 / 1,010198 / 0,894035 (h1/h2/h3/h6), допуск 1e-3; `live_cb` — 1,192851 / 1,012704 / 1,075820 / 1,061691, допуск 1e-3.
- **R11b — границы окна и отсутствие будущего.** В коде: для каждой обучающей строки `2016-01 + h ≤ t ≤ M − h`; в офлайн-тестах: порча таргетов после `M − h` и признаков после origin не меняет прогноз для M.

Любая R11 не пройдена — прогон останавливается, гейт не считается.

## 6. Оценка

Истина `TARGET_FULL`, normal-54 (как §15):

1. **Против CB_COMP** — `cpi_two_stage_cb_comp.compare_to_cb` (класс W5b, отношение, 90 % CI, DM-HLN) для `live_en16` и `combo4` на всех h.
2. **Попарно против `combo3`** — `cpi_v4_leaderboard.compare_pair` (DM-HLN с поправкой на h, 95 % блочный бутстрап-CI ΔRMSE); для h3 дополнительно направление ΔRMSE.
3. **MCS 90 %** по `live_cb`, `combo3`, `live_en16`, `combo4` и CB_COMP для h1/h3/h6 (`cpi_v4_leaderboard.mcs_included`).
4. Справочно — RMSE против `T_LIVE`, на всех 67 месяцах, по подпериодам 2019–2021 / 2023–2024; `combo3_tf`.

## 7. Гейт G11 (предрегистрирован)

**G11 пройден**, если одновременно:

1. **h3, `combo4` лучше `combo3`:** ΔRMSE = RMSE(`combo4`) − RMSE(`combo3`) < 0 **и** DM-HLN p < **0,10** (формулировка issue #439). 95 % CI ΔRMSE приводится; если он включает 0, результат помечается «слабая значимость» — гейт по CI не режется, но в выводе это оговорено.
2. **h1 и h6, `combo4` не хуже `combo3`:** отношение `combo4` к CB_COMP не выше отношения `combo3` более чем на **0,02** (маржинал Task 9, `NOHARM_MARGIN`).
3. **MCS 90 %:** `combo4` входит в набор на h1, h3 и h6 вместе с CB_COMP.

G11 не пройден — отрицательный результат публикуется, `combo3` остаётся базой Task 4/5; замена базы — только решение владельца.
