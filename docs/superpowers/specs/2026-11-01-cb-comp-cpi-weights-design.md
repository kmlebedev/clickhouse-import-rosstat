> **Связанные:** стандарт [IMPORTER_PACKAGE_STANDARD.md](../../IMPORTER_PACKAGE_STANDARD.md) §14; [ARCHITECTURE.md](../../../ARCHITECTURE.md) §6.1–§6.3; отчёт [2026-11-01-cb-comp-cpi-weights.md](../../research/2026-11-01-cb-comp-cpi-weights.md).
> **ML-часть вынесена.** Потребитель весов (live `load_weights`, сверка с архивом, покрытие) живёт в [`kmlebedev/bi-ml-models`](https://github.com/kmlebedev/bi-ml-models) — отдельная задача со ссылкой на эту витрину. Здесь — только публикация данных: таблица, каталог, витрина, грант.

## 1. Гипотеза

Публичные книги Росстата «Структура потребительских расходов населения для расчёта ИПЦ по РФ» — машиночитаемый источник годовых весов ИПЦ: после импорта витрина `v_rosstat_cpi_weights` отдаёт вес каждой позиции по годам без архива CB_COMP 2024 и без ручных выгрузок.

Проверяемые следствия (Go-часть):

1. обе книги разбираются обоими макетами, которые публикует Росстат, без ручных правок;
2. годы идут непрерывно, суммы листов проходят валидацию, повторный прогон — no-op;
3. каталог `cpi-weight:<код>:<items|groups>` и витрина публикуются и на полном, и на no-op-пути;
4. агент читает витрину через `kimi_reader`, сырая таблица закрыта.

## 2. Данные

| Файл | Что | Годы | Листы |
|---|---|---|---|
| `CPR_Tov_RF_2004-2026.xlsx` | товары (услуги)-представители, СПР | 2004–2026 | лист = год; 2022 — один лист |
| `CPR_Gr-tov-RF_2001-2026.xlsx` | группы и товары, СПР группы | 2001–2026 | лист = год; 2022 — два листа («до 01.04» и «с 01.04») |

- URL берутся со страницы `https://rosstat.gov.ru/statistics/price` **регистронезависимыми** селекторами `a[href*="cpr_tov_rf_2004-" i]` и `a[href*="cpr_gr-tov-rf_2001-" i]`. Росстат меняет регистр имён между релизами: в снимке 2026 — `CPR_tov_RF_2004-2026.xlsx` / `CPR_Gr-Tov-RF_2001-2026.xlsx`, в живой странице 2026-11-13 — `CPR_Tov_RF_2004-2026.xlsx` / `CPR_Gr-tov-RF_2001-2026.xlsx`. Без флага `i` селектор регистрозависим (прецедент — `labourForceLinkSelector`).
- Начало горизонта (2004/2001) в селекторе отделяет полную книгу групп от годовой `CPR_Gr-tov-RF_2026.xlsx` — её ссылка стоит на странице раньше.
- **Макет (probe 2026-11-01 по Wayback-копиям).**
  - товарный файл 2025-винтажа: `код | название | СПР` (проценты, 3 колонки); 2024-винтажа: `N п/п | код | название | вес` (доли, 4 колонки, у веса нет подписи); 2016 — составная ячейка `код  название`;
  - групповой файл: 2016–2024 — только `название | СПР` (**без кодов**), 2025–2026 — `локальный код | название | СПР`; 2022 — два листа.
- **Единицы.** Публичный файл — проценты (сумма товарного листа ≈ 100); доли-винтаж (сумма ≈ 1) приводятся к процентам по сумме листа.
- **2022.** Оба групповых листа сохраняются как `variant` (`''`, `before-2022-04-01`, `from-2022-04-01`): без варианта в ключе публикации затирали бы друг друга.
- **Объединённая группа.** «Воздушный и железнодорожный транспорт» публикуется **одной** строкой (0,859 % в 2024, 0,843 % в 2025) — отдельными кодами 9260/9290 она не разбита. Поэтому сумма товарного листа штатно не дотягивает до 100 на её вес.

## 3. Go-импортёр `rosstat_cpi_weights`

**Пакет `rosstat/`, файлы** `cpi_weights.go` (импортёр, DDL, витрина, каталог), `cpi_weights_parse.go` (разбор), `cpi_weights_test.go`, `testdata/cpi_weights_{items,groups}.xlsx` (реальные урезанные книги), `testdata/price_page_cpr_case.html`.

**Собственный `Import()`** (прецедент `rosstat_ipc_weeks_bulletins`): внешний `Import()` один раз берёт страницу и обе ссылки, затем запускает два шаблонных `util.ClickHouseImport` — по одному на файл. Каждый получает DDL, HEAD-префлайт, скачивание, архив версии и публикацию каталога/витрины; разбор конкретной книги — свой `ImportFunc`. Внешний `Import()` после обоих файлов публикует каталог и витрину ещё раз — self-heal для случая, когда оба файла в no-op. DDL — до сети. Режим restore отклоняется явно: URL вычисляется со страницы.

**Таблица** (`%s`-шаблон в коде; канон — `ARCHITECTURE.md` §6.2):

```sql
CREATE TABLE IF NOT EXISTS rosstat_cpi_weights (
    year        UInt16,
    variant     LowCardinality(String),
    source_file LowCardinality(String),
    level       UInt8,
    code        LowCardinality(String),
    name        LowCardinality(String),
    weight      Float64
) ENGINE = ReplacingMergeTree
ORDER BY (year, variant, source_file, code);
```

`source_file` — `CPR_tov_RF` | `CPR_Gr-Tov-RF`; `level` — уровень иерархии из файла (0, если файл его не даёт); вес — проценты. У группового файла 2016–2024 кода в источнике нет: строка получает синтетический `code='name:<нормализованное название>'`, каталог такие строки пропускает.

**Витрина** `v_rosstat_cpi_weights` — широкая: `year, variant, source_file, level, code, name, weight` с комментариями таблицы и каждой колонки. Широкая, а не long: вес — свойство `(год, код)`, а не датированный ряд. `AfterImport` шаблона публикует каталог и витрину на полном пути; внешний `Import()` вызывает его ещё раз после обоих файлов — self-heal для случая, когда оба файла в no-op (no-op-путь шаблона `AfterImport` не вызывает).

**Каталог.** Одна запись на `(code, source_file)`: `cpi-weight:<code>:<items|groups>`; title — `argMax(name, year)`; unit `% (доля в структуре потребительских расходов ИПЦ)`; frequency `A`; origin — файл, лист, код; description — годы, сумма, правило 2022.

**Идемпотентность.** HEAD-отпечаток каждого файла (`util.HeadFingerprint`) + `util.PublicationKnown`/`SavePublication` (source `rosstat_cpi_weights`, name — имя файла): оба известны и `count()` совпал → no-op без скачивания; иначе качаются оба, пишутся все точки, обе версии сохраняются. Число точек версии — по файлу (`WHERE source_file = …`), иначе после записи второго файла первая версия всегда выглядела бы неполной.

**Регистрация/обвязка:** `rosstat/importers.go` (12-я запись + энфорсер в `importers_test.go`), 12-й шаг в хвосте `dagu/rosstat.yaml`, `GRANT SELECT ON default.v_rosstat_cpi_weights TO kimi_reader`, проверка в `scripts/mcp_check.py`, `docs/IMPORTERS.md`, `ARCHITECTURE.md` §2/§6.1/§6.2/§6.3/§7, `README.md`, `docs/LIMITATIONS.md`.

## 4. Валидация импортёра (fail-fast, до записи)

1. Годы: товары 2004–2026 без пропусков, группы 2001–2026; 2025 и 2026 присутствуют, горизонт не ниже 2024.
2. Строк на лист: товары ≥ 400, группы ≥ 50; коды уникальны в `(year, variant, source_file)`.
3. Вес — число > 0; дубль с другим весом — ошибка; `-`/`…`/`—`/пустая ячейка — пропуск, нечисловой текст — ошибка.
4. Сумма товарного листа после нормировки масштаба — 90…100,5 (публикация не дотягивает до 100 на объединённую группу транспорта); для группового файла сумма не нормируется (в файле все уровни), нижняя граница 90 — защита от пустого листа.
5. Ссылки: оба селектора находят ровно ту книгу, которая нужна (проверяется на двух фикстурах страницы — с обоими написаниями).

## 5. ML-часть — вне этого репозитория

Потребитель весов, сверка 2016–2024 с архивом CB_COMP, политика пропусков `803`/`930.АГ`/`9260`/`9290`/`9218` и покрытие ≥ 0,85 — задача репозитория моделей: `load_weights(source="live"|"archive")`, `cb_comp_weights_check`, матрица live/archive по скриптам. Вход — витрина `v_rosstat_cpi_weights` из этого PR. Здесь фиксируется только контракт данных: проценты, год-ключ, `variant` 2022, `code='name:…'` у групповых строк без кода.

## 6. Гейт (Go)

| Условие | Как проверяется |
|---|---|
| Обе книги разбираются, годы непрерывны | 13 офлайн-тестов на реальных фикстурах + синтетике (оба макета, 2022, дубли, сумма, пустой лист) |
| Ссылки находятся при обоих написаниях | `TestCPIWeightsFindLink` на `price_page.html` и `price_page_cpr_case.html` |
| Повтор — no-op | HEAD-префлайт по каждому файлу + `source_publications` + `count()` по файлу |
| Каталог и витрина опубликованы | `AfterImport` шаблона + повторный вызов из внешнего `Import()` (self-heal при no-op обоих файлов); `mcp-check` (витрина непуста, ≥400 кодов, год ≥2026; каталог ≥500 рядов) |
| Агент читает только витрину | `GRANT SELECT` на `v_rosstat_cpi_weights`, сырая таблица — отказ 497 |
| Сборка | `make all`, `make docs-check`, `dagu validate dagu/rosstat.yaml` |

Живой импорт — часть приёмки, но не блокирующая для кода: на 2026-11-13 страница цен отдаёт 200, а файлы `CPR_*` — 404 (см. §8).

## 7. Stop-rules

- Сумма товарного листа вне 90…100,5 → импорт падает, данные не пишутся.
- В книге нет 2025 или 2026 → падение (горизонт старше 2024 не считается актуальным).
- Ссылка не найдена ни одним из двух написаний → падение до записи, а не «0 rows».
- Источник недоступен (404 на файлах) → код и офлайн-тесты готовы, живая приёмка «не проверено», статус не `Done`, PR не мержится как завершённый.

## 8. Границы

- В ClickHouse пишет только Go-импортёр; модели читают витрину.
- Иерархия групп (`dictionary_cpi.xlsx`, `model.xlsx`) остаётся входом модели — P0.4 даёт веса, а не структуру.
- Текущий 2026-винтаж книг не проверен: файлы 404, макет сверен по Wayback-копиям 2025/2026. Первый живой импорт обязан подтвердить макет; расхождение — падение валидации, а не тихая запись.
