## 1. Гипотеза

Публичные файлы Росстата «Структура потребительских расходов населения по товарам (услугам)-представителям для расчёта ИПЦ по РФ» — достаточный live-источник весов: после импорта `load_weights` читает их из ClickHouse, и live-модель перестаёт зависеть от архива весов 2024 (для месяцев 2026 берётся вес 2025, а не фолбэк 2024).

Проверяемое следствие: веса 2016–2024 совпадают с архивом CB_COMP (`max |Δ| = 0`), 2025–26 проходят проверку суммы, повторный прогон Task 9 даёт те же числа на 2019–2024, покрытие весов ≥ 0,85.

- **Пропуски и объединённые группы.** `803` — вес с 2023, `930.АГ` — с 2022; до первого года веса нет, назад не бэккастим. Публичный файл публикует «Воздушный и железнодорожный транспорт» **одной** группой (0,859 % в 2024), а модель — двумя кодами `9260`/`9290`; для 2016–2024 их веса берутся из архива (именованное исключение `LIVE_ARCHIVE_FALLBACK`, перечисляется в отчёте), для 2025–2026 веса нет — коды выпадают из агрегата (покрытие −0,0086), импутации нет. `9260` после 2024-10 вообще без ряда. `9218` — SA не сходится, вне сборки (вес 0,0025).

## 3. Go-импортёр `rosstat_cpi_weights`

**Пакет `rosstat/`, файлы** `cpi_weights.go` (импортёр, DDL, витрина, каталог), `cpi_weights_parse.go` (разбор), `cpi_weights_test.go`, `testdata/cpi_weights_*.xlsx`.

**Собственный `Import()`** (прецедент `rosstat_ipc_weeks_bulletins`): внешний `Import()` один раз берёт страницу и обе ссылки, затем запускает два шаблонных `util.ClickHouseImport` — по одному на файл. Каждый получает DDL, HEAD-префлайт, скачивание, архив версии и публикацию каталога/витрины; разбор конкретной книги — свой `ImportFunc`. Внешний `Import()` после обоих файлов публикует каталог и витрину ещё раз — это self-heal для случая, когда оба файла в no-op. Режим restore отклоняется явно: URL вычисляется со страницы.

**Таблица** (`%s`-шаблон в коде; канон — `ARCHITECTURE.md` §6.2):

```sql
CREATE TABLE IF NOT EXISTS rosstat_cpi_weights (
    year        UInt16,
    variant     LowCardinality(String),
    source_file LowCardinality(String),
    level       UInt8,
    code        LowCardinality(String),
    name        LowCardinality(String),
    weight      Float64
) ENGINE = ReplacingMergeTree
ORDER BY (year, variant, source_file, code);
```

`source_file` — `CPR_tov_RF` | `CPR_Gr-Tov-RF`; `level` — уровень иерархии из файла (0, если файл его не даёт). Вес — проценты (доли-винтажи умножаются на 100 при разборе). У группового файла 2016–2024 кода в источнике нет: строка получает синтетический `code='name:<нормализованное название>'`, каталог такие строки пропускает.

**Витрина** `v_rosstat_cpi_weights` — широкая: `year, variant, source_file, level, code, name, weight` с комментариями таблицы и каждой колонки. Широкая, а не long: вес — свойство `(year, code)`, а не датированный ряд; long-форма заставила бы ML-загрузчик парсить код из имени ряда. `AfterImport` публикует каталог и витрину на полном и no-op-пути.

**Каталог.** Одна запись на `(code, source_file)`: `cpi-weight:<code>:<items|groups>`; title — `argMax(name, year)`; unit `% (доля в структуре потребительских расходов ИПЦ)`; frequency `A`; origin — файл, лист, код; description — годы, сумма 100, группа/товар, правило 2022.

**Идемпотентность.** HEAD-отпечаток каждого файла (`util.HeadFingerprint`) + `util.PublicationKnown`/`SavePublication` (source `rosstat_cpi_weights`, name — имя файла): оба известны и `count()` совпал → no-op без скачивания; иначе качаются оба, пишутся все точки, обе версии сохраняются. Публикация каталога/витрины — после `Send`.

**Регистрация/обвязка:** `rosstat/importers.go` (12-я запись), 12-й шаг в хвосте `dagu/rosstat.yaml`, `GRANT SELECT ON default.v_rosstat_cpi_weights TO kimi_reader`, проверка в `scripts/mcp_check.py`, `docs/IMPORTERS.md`, `ARCHITECTURE.md` §6.1/§6.2/§6.3/§7, `README.md`, `docs/LIMITATIONS.md`.

## 4. Валидация импортёра (fail-fast, до записи)

1. Годы: товары 2004–2026 без пропусков, группы 2001–2026; 2025 и 2026 присутствуют.
2. Строк на лист: товары ≥ 400, группы ≥ 50; коды уникальны в `(year, variant, source_file)`.
3. Вес — число > 0; дубль с другим весом — ошибка; `-`/`…`/`—`/пустая ячейка — пропуск, нечисловой текст — ошибка.
4. Сумма товарного листа после нормировки масштаба — 90…100,5 (публикация может не дотягивать до 100 на объединённую группу «Воздушный и железнодорожный транспорт» 0,859 %); для групп сумма не нормируется (в файле все уровни), нижняя граница 90 — защита от пустого листа.
5. Страховка от смены макета — структурная: число позиций и сумма; наличие `803`, `930.АГ`, `9260` в 2024–2026 проверяет ML-скрипт `cb-comp-weights-check`, а не Go-импортёр (импортёр не должен знать про 88 групп модели).

## 5. ML: переключение

Загрузчик живёт рядом с архивным путём — в `cb_comp_bottomup.py` (`load_archive_weights`, `load_live_weights`, `load_weights`), чтобы не тянуть `normalize_code`/`weights_path`/`GroupSpec` в отдельный модуль и не ломать импорт-граф; сверка и покрытие — отдельный `scripts/models/cb_comp/cb_comp_weights_check.py`. **Live-путь использует товарный файл** (у него есть коды во все годы) и словарь архива: веса групп считаются из листьев той же арифметикой, что архив; групповой файл — сверка по названиям. Для 2025–2026 берётся словарь 2024; новые коды вне словаря выпадают. Состав:

- `load_archive_weights(archive, years, specs)` — текущая логика (`окато_код=643`, листья уровня 7, сумма по уровню группы); отсутствующий лист года пропускается.
- `load_live_weights(archive, years, specs, query=ch_query)` — читает **товарные** строки витрины (`source_file='CPR_tov_RF'`, проценты/100), агрегирует листья по словарю года (для 2025–2026 — словарь 2024) ровно как архив; `9260`/`9290` для 2016–2024 — именованный архивный фолбэк, для 2025–2026 отсутствуют; возвращает `{год: {код: доля}}`.
- `compare_weights(live, archive)` и `coverage_report(...)` — для гейта и отчёта.

`cb_comp_bottomup.load_weights(archive, years, specs, source="archive", query=None)`: default — прежний архивный путь (исторические прогоны и пины воспроизводятся без ClickHouse), `source="live"` — витрина; переключение делается явным аргументом в перечисленных скриптах. `_year_weights` терпит отсутствующие листы, поэтому `WEIGHT_YEARS = 2016…2026` работает в обоих режимах: архив отдаёт 2016–2024 (фолбэки не меняются), live — 2016–2026. Для тестовых месяцев 2019–2024 год весов ≤ 2023, числа Task 9 не меняются; меняются только месяцы 2026 (2024 → 2025).

**Матрица источников (решение владельца 2026-11-01):**

| Скрипт | Источник весов | Почему |
|---|---|---|
| `cb_comp_h1_bs_combo.py` (Task 9), `cb_comp_88_live_gate.py` | `live` (default), `--weights archive` для регрессии | базовая модель; P0.4 |
| `cb_comp_live_bottomup.py`, `cb_comp_live_en.py`, Task 5/10/11/12 | `live` (default) | окна оценки ≤ 2024, числа не меняются |

## 7. Гейт

1. **Веса 2016–2024 = архив** по 88 группам + `9470`: `max |Δ| <= 1e-12` на пересечении кодов, как Q5; отсутствующие в live коды перечисляются. **2022 — вариант-исключение:** товарный файл 2025-винтажа содержит один лист 2022, групповой — два; если live-2022 расходится с архивом (на Wayback-копии — до 0,0043), это строка отчёта и решение владельца, а не молчаливый выбор варианта.
2. **2025–26:** товарный лист 100 ± 0,5; годы непрерывны; 550/552 позиции; год-к-году изменения по коду — отчёт (не жёсткий порог).
3. **Task 9:** `--weights archive` воспроизводит 1,035 / 0,957 / 1,010 / 0,894 (R9a/R9b/R9c, G9); `--weights live` — те же числа, `predictions.csv` побайтно, `result.json` — max |Δ| = 0.
4. **Покрытие** 2025–26 ≥ 0,85 (ожидается ≈ 0,921).

## 8. Stop-rules

- Веса 2016–2024 не совпали (`max |Δ| > 1e-12`), кроме 2022-варианта и имён объединённых групп → `load_weights` не переключается, отрицательный результат в отчёт и PR, решение за владельцем.
- В live нет кода группы, который есть в архиве (кроме известных `803`/`930.АГ` до их года) → гейт не закрывается, список публикуется.
- Сумма 2025/2026 вне 100 ± 0,5 → импорт падает (fail-fast), данные не пишутся.
- Источник недоступен → импортёр и офлайн-тесты готовы, live-приёмка «не проверено»; статус не `Done`, PR не мержится как завершённый.

## 9. Границы

- P0.6 shadow и панель/T_LIVE остаются на архивных весах до конца окна shadow или отдельного решения о перепиновке; их пины не переписываются.

## 10. Что фиксирует probe (до кода парсера)

- Имена листов и точный заголовок/макет каждого файла (оба макета Q5 или один).
- Есть ли колонка уровня/иерархии и как в файле отличить группу от товара.
- Форма листов 2022 (два листа: подписи и порядок).
- Число строк по годам 2016–2026, суммы, наличие `803`/`930.АГ`/`9260`.
- Результат записывается в этот раздел; фикстуры — урезанные реальные листы (когда источник доступен).

**Probe 2026-11-01 (Wayback-копии, живой rosstat отдаёт 502):**
- `CPR_Gr-Tov-RF_2001-2026.xlsx` (снимок 2026): 28 листов — «Содержание» + 2001–2026 + два 2022; 2016–2024 без кодов, 2025–2026 с локальными кодами; 2024 «Мясопродукты» 9,072, 2026 код 10 — 8,821; 86/88 групп совпали с архивом по названию (`max |Δ| <= 1e-9`), 9260/9290 — объединённая группа 0,859 %; фикстура `rosstat/testdata/cpi_weights_groups.xlsx`.
- `CPR_Tov_RF_2004-2025.xlsx` (снимок 2025): 23 листа 2004–2025; 2024 — 3 колонки, проценты, 559 товаров, сумма 99,141 % (нет объединённой группы 0,859 %); 2016 — составная ячейка `код  название`; фикстура `rosstat/testdata/cpi_weights_items.xlsx`.
- 2024-винтаж товарного файла — 4 колонки и доли (0,00648); парсер поддерживает и его (вес — колонка после названия, масштаб — по сумме).
- Live-арифметика (товарные листья + словарь) на реальном файле 2025-винтажа воспроизводит архив для 2016, 2017–2021, 2023, 2024 с `max |Δ| <= 7e-18`; 2022 — до 0,0043 (вариант-исключение).
- Живой probe повторяется при восстановлении источника; текущий 2026-винтаж может отличаться от Wayback-копий, поэтому первый импорт — с проверкой макета.
