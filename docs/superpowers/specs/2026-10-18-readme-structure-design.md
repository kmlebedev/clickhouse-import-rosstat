## 1. Цель

Сделать README **понятной точкой входа** (ориентир — до ~250 строк): что это, быстрый старт, компактная карта данных, ключевые команды и карта документации. Полные спецификации импортёров и эксплуатационные детали вынести в отдельные файлы `docs/`, не потеряв ни одного факта, команды, URL или числа.

## 2. Не цели

- Менять поведение кода, схемы ClickHouse, расписания Dagu.
- Переписывать содержание: перенос **дословный**, без сокращений и «улучшений».
- Публиковать спеки/планы `docs/superpowers/**` на docs-портале.
- Менять Docs-портал кроме манифеста `docs/site-pages.json` (новые страницы должны быть в навигации).

## 4. Правила переноса

1. **Дословно.** Ни один факт, URL, число, имя таблицы, команда или предупреждение не теряется и не пересказывается. Заголовки адаптируются под новый уровень; текст — нет.
2. **Заголовки.** Каждый новый файл начинается с `# <название>` и строки `> Часть документации проекта; входная точка — [README.md](../README.md).` Перенесённые заголовки понижаются/повышаются до логичного уровня (`##` для разделов, `###` для подразделов).
3. **Ссылки.** Внутренние ссылки на README/ARCHITECTURE/другие новые docs сохраняются; относительные пути корректируются под новое расположение файла (все новые файлы лежат в `docs/`, поэтому пути вида `docs/...` из README становятся `../...` или `...` в зависимости от цели).
4. **Без дублей.** Детальная таблица импортёров живёт только в `docs/IMPORTERS.md`; в README — компактная. Полная таблица команд — только в `docs/DEVELOPMENT.md`; в README — ключевые. Полный список env — только в `docs/CONFIGURATION.md`; в README — обязательные.
5. **Проверка полноты.** Для каждого перенесённого блока сверить начало/конец исходных строк и число пунктов списка; суммарное число строк новых файлов + README должно быть не меньше исходного (с поправкой на заголовки/ссылки).
6. **Docs-портал.** Новые страницы добавить в `docs/site-pages.json`; `--check` генератора должен пройти, `mkdocs build --strict` — без предупреждений.

## 5. Критерий приёмки

1. README ≤ ~300 строк; содержит быстрый старт, карту документации, компактную таблицу доменов, ключевые env и команды; открывается как осмысленная landing page.
2. Созданы 7 файлов: `docs/IMPORTERS.md`, `docs/CONFIGURATION.md`, `docs/OPERATIONS.md`, `docs/DEVELOPMENT.md`, `docs/GOLD_CONTOUR.md`, `docs/LIMITATIONS.md`, `docs/GRAFANA.md`; каждый начинается с заголовка и ссылки на README.
3. Перенесённый текст дословный: выборочная сверка 10 контрольных строк (команды, числа, URL) совпадает с исходным README; ни один раздел не потерян.
4. `python3 scripts/docs_build.py --check` — 0; `make docs-check` — 0; `make docs-build` — 0 без WARNING; в `build/site` есть новые страницы.
5. Внутренние ссылки сайта — 0 битых (кроме служебной `404.html`); ссылки README на новые docs ведут на существующие файлы.
6. `make all` — зелёный.
7. `docs/ROADMAP_INFRA.md` — строка `3.4` со статусом `✅ сделан этим PR`; `docs/ROADMAP_INDEX.md` — `3.1`–`3.4`; `ARCHITECTURE.md` — карта документации; issue `[infra/3.4]` закрыт PR; протокол — комментарием в PR.

## 6. Риски

| Риск | Мера |
|---|---|
| Потеря факта при переносе | дословная экстракция по диапазонам строк; контрольные сверки; ревью диффа |
| Битые ссылки после смены расположения | `--check` генератора + `mkdocs --strict` + ручная проверка README |
| Дублирование деталей в README и docs | README содержит только компактные таблицы; подробности — одна точка |
| Docs-портал публикует лишнее | в манифест добавляются только 7 новых страниц; `superpowers/**`, `plans/**`, `archive/**` не трогаются |
| Слишком длинные новые файлы | это допустимо: спецификации — не landing page; навигация MkDocs даёт поиск и оглавление |
