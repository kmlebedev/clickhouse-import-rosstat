# Винтажная база: архив версий файлов источников — дизайн

> **Дата:** 2026-10-14 · **Ветка:** `source-file-archive` · **Пункт:** новый `docs/ROADMAP_INFRA.md`, фаза 1 «Надёжность данных», шаг 1.1 «Винтажная база: архив версий файлов источников» (файл инфраструктурного роадмапа, не привязанного к трекам прогнозирования, заводится этим же PR).
> **Критерий приёмки:** живой прогон на dev-ClickHouse — версия файла сохранена в архиве, запись о ней есть в `registry.jsonl`, повторный прогон — no-op (в т.ч. с проверкой «версия в архиве»); self-heal-ветка «версия известна, но не в архиве → полный импорт» проверена на local-бэкенде и на Яндекс.Диске; `make archive-registry` обновляет git-зеркало реестра; `make env-check` показывает новый ключ; `make all` и `make mcp-check` зелёные; документация обновлена, статус шага 1.1 — ✅ с командой и результатом.

## 1. Цель и объём

### 1.1 Цель

Импортёры репозитория скачивают файлы источников в память и нигде не сохраняют: `util.GetFile` (`util/xls.go`) читает тело целиком и отдаёт ридером, на диск не пишет. Версия артефакта фиксируется только отпечатком в `source_publications` (md5 от `имя|ETag|Last-Modified|Content-Length`) — без содержимого. Отсюда два класса потерь:

1. **«Урезанное» обновление файла.** ЦБ перезаписывает выгрузку по тому же URL (у страниц `mo_br`, `credit_m2x`, `aipd` архива волн нет вовсе — `ARCHITECTURE.md` §6.1). Новая волна может нести меньше истории, чем старая; прежние точки в ClickHouse остаются (`ReplacingMergeTree`, DELETE нигде нет), но перезалить/сверить их нечем — сам файл утрачен. Количественный чек `PublicationCountPoints` этого не ловит: он считает строки в БД, а не точки в артефакте.
2. **Пустая база.** ClickHouse может быть развёрнут с нуля; наполнять его предполагается в том числе из архива — значит реестр архива обязан читаться **без ClickHouse**.

Цель пункта: сохранять каждую увиденную конвейером версию файла источника в объектном хранилище и вести реестр версий, самодостаточный (файл + реестр) — сегодня на бесплатном личном Яндекс.Диске (~5 ГБ), через Go-интерфейс `Store`, заменяемый на S3-совместимое хранилище без правок вызывающего кода (правило владельца: «максимально бюджетно, через go-интерфейс»).

### 1.2 Объём

- **Пакет `archive/`**: интерфейс `Store` (Put/Get/Exists), бэкенды `LocalStore` (dev/тесты) и `YandexDisk` (REST API), реестр `Registry`, конструктор `FromEnv`. Без новых зависимостей (stdlib).
- **Интеграция в общий шаблон** `util.ClickHouseImport`: архивация версии после успешного импорта; проверка «версия известна, но не в архиве» на no-op-пути. Пакеты импортёров **своего кода не меняют**.
- **Охват**: 14 импортёров с точкой контроля публикации, чей XLSX скачивает сам шаблон, — десять в `cbr/` (`cbr_mp_survey`, `cbr_mo_br`, `cbr_households_b_mes`, `cbr_m2`, `cbr_credit_m2x`, `cbr_loans_to_corporations`, `cbr_loans_to_individuals`, `cbr_bank_int_rate`, `cbr_indicators_cpd`, `cbr_infl_exp`) и четыре в `rosstat/` (`rosstat_ipc_mes`, `rosstat_salaries_mes`, `rosstat_vvp_kvartal`, `rosstat_labour_force_mes` — последний влит в `main` PR #61 до начала этой ветки и попадает под механизм без правок).
- **Реестр**: `registry.jsonl` в самом хранилище (истина) + git-зеркало `docs/archive/registry.jsonl` (цель `make archive-registry`).
- **Нормативные документы**: новый `docs/ROADMAP_INFRA.md`; требование 9.6 в `docs/IMPORTER_PACKAGE_STANDARD.md` (винтажная база — для всех будущих пакетов); ссылка в `AGENTS.md`; `ARCHITECTURE.md`, `README.md`.

### 1.3 Вне объёма (названо явно)

## 2. Источник (проверено 2026-10-14)

**Yandex Disk REST API** (официальная документация; проверялся как основной кандидат — «максимально бюджетно, личная учётка»):

| Что | Как |
|---|---|
| Авторизация | OAuth-токен своего приложения (scope `cloud_api:disk.write`/`read`), заголовок `Authorization: OAuth <token>`; implicit-flow: `oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>` ([quickstart](https://yandex.ru/dev/disk/api/concepts/quickstart.html)) |
| Загрузка | `GET cloud-api.yandex.net/v1/disk/resources/upload?path=…&overwrite=true` → `href` + `method`; затем `PUT` тела на `href` (токен не нужен), успех `201`/`202`; `href` живёт 30 минут ([upload](https://yandex.ru/dev/disk/api/reference/upload.html)) |
| Скачивание | `GET …/resources/download?path=…` → `href` → `GET` |
| Папки | `PUT …/resources?path=…`; повтор — `409`, штатный признак «папка есть» (нужна: загрузка падает, если родительской папки нет) |
| Метаданные/существование | `GET …/resources?path=…` (200 / 404) |
| Ошибки | `401` (токен), `403`/`413`/`423`/`507` (квота, лимит загрузок, размер файла, нет места), `429`, `503`; имя файла ≤255 символов, путь ≤32 760 |

**Объём артефактов** (живые HEAD-замеры — спека `2026-10-14-publication-preflight-design.md` §2): `mp_survey_data.xlsx` 2,18 МБ, `monetary_agg_SA.xlsx` 584 КБ, `households_bm.xlsx` 285 КБ, `02_04_New_loans_ind.xlsx` 163 КБ, `01_01_A_New_loans_corp_by_activity.xlsx` 62 КБ, `regulatory_rates.xlsx` 20 КБ; остальные — того же порядка. Версии дедуплицируются (пишется только смена версии) → оценка **150–250 МБ/год**; бесплатных 5 ГБ хватает на годы.

**Готовых зависимостей нет**: Go-клиенты Яндекс.Диска заброшены (2019–2022), официального SDK нет. API в две ручки реализуется на stdlib — новых зависимостей ноль (`govulncheck` в CI не затрагивается). Интерфейс `Store` (Put/Get/Exists) без изменений ложится на S3 (`PutObject`/`GetObject`/`HeadObject`).

## 3. Решения

### 3.1 Пакет `archive/`

```go
// Store — объектное хранилище версий файлов. Ключи относительные, с «/»-разделителями;
// корень навешивает бэкенд (смена корня/бэкенда не меняет ключи).
type Store interface {
    Name() string                                          // 'local' | 'yandex' — для логов и реестра
    Put(ctx context.Context, key string, body []byte) error
    Get(ctx context.Context, key string) ([]byte, error)   // реестр, тесты, будущее восстановление
    Exists(ctx context.Context, key string) (bool, error)
}
```

- `archive/key.go` — `Key(source, basename, fingerprint string, sum [32]byte) string`: `fingerprint != ""` → `<source>/<fingerprint[:16]>_<basename>`; иначе (недоступный HEAD) → `<source>/sha-<hex(sum)[:16]>_<basename>`. Basename санитизируется (`/ \ : * ? " < > |` и управляющие символы → `_`, обрезка до 200 байт по границе руны) — имена у источников бывают кириллические, имя файла на Диске ≤255 символов.
- `archive/local.go` — `LocalStore{Dir}`: `Put` = `MkdirAll` + `os.WriteFile`, `Get` = `os.ReadFile`, `Exists` = `os.Stat`. Dev-бэкенд и харнесс тестов.
- `archive/yandex.go` — `NewYandex(token, root, baseURL string, hc *http.Client)`: `root` — каталог на Диске (`disk:/rosstat-archive`), `baseURL` — переопределяемый для тестов (`httptest`).
  - `Put`: подготовить каталоги пути (`PUT resources`, `201`/`409` ok) → `resources/upload?overwrite=true` → `PUT` тела на `href`; принимаются `201` и `202`.
  - `Get`: `resources/download` → `GET href`; `Exists`: `GET resources` (`200`/`404`).
  - Повторы: до 3 попыток с нарастающей паузой (1с, 2с) на `429` и `503`; типизированные ошибки `ErrAuth` (`401`) и `ErrQuota` (`403`/`413`/`423`/`507`) — для разного текста в логе; остальные коды — обычная ошибка со статусом.
  - Дедлайн операции — 2 минуты (как `util.fileTimeout`; `HttpClient` создан без `Timeout`).
  - **Секреты не логируются**: `href` (подписанная ссылка) и токен в логи не попадают — логируется путь на Диске.
  - HTTP-клиент инъектируется: прод передаёт `util.HttpClient` (правило 4 AGENTS.md), тесты — `httptest.Server`.
- `archive/fromenv.go` — `FromEnv(hc *http.Client) (Store, error)`: `ARCHIVE_BACKEND` (`local`|`yandex`|пусто = выключено), `ARCHIVE_YANDEX_TOKEN`, `ARCHIVE_YANDEX_DIR` (default `disk:/rosstat-archive`), `ARCHIVE_LOCAL_DIR`. Ошибка конфигурации → вызывающий (имя `util`) пишет `log.Errorf` и работает **без архива**: недоступный/неправильный архив не должен останавливать импорт данных.

### 3.2 Ключ объекта и проверка «версия в архиве»

Ключ выводится из данных префлайта (`source`, `name`, `fingerprint`) **без содержимого файла** — поэтому проверка «версия уже в архиве?» на no-op-пути — это один `Store.Exists(key)`, без чтения реестра и без ClickHouse. Это же свойство даёт самолечение: не найдя версию в архиве, префлайт уходит в полный импорт и дописывает архив (в т.ч. разово — при первом включении архива, когда все текущие версии уже импортированы, и при смене бэкенда).

Асимметрия принята сознательно: `source_publications` идентифицирует версию по тому же отпечатку, и архив обязан говорить на том же языке; `sha256` фактического содержимого пишется в реестр рядом (§3.4) — при неизменных заголовках и изменённом содержимом архивируется последняя версия отпечатка (как и в `source_publications`), но реестр фиксирует, что содержимое менялось.

### 3.3 Интеграция в шаблон `util.ClickHouseImport` (пакеты импортёров не меняются)

Механизм включается парой «хранилище настроено (`ARCHIVE_BACKEND`) + объявлена точка контроля (`PublicationCountPoints`)». Архивация **не объявляется** отдельным полем импортёра: множество «файл обновляется реже прогонов» уже очерчено точкой контроля, и второй декларации не заводится.

**Порядок полного пути:** DDL → `BeforeImport` → префлайт → **точки** → **архив** → `AfterImport` → версия.

- Хелпер `util.GetFileBytes(url) ([]byte, error)` (`GetFile` + `ReadAll`); путь `ImportFunc` в шаблоне качает байты сам и разбирает из памяти (`excelize.OpenReader(bytes.NewReader(body))`); лог скачивания сохраняется. `ImportXls` **удалён**: его место занял приватный `importXlsBody(ctx, body, conn)` (разбор книги из памяти → `PrepareBatch` → `ImportFunc` → `Send`); потребителей вне `util` у метода не было, а непотребляемый экспорт — мёртвый код (стандарт §3.3).
- Архив пишется **после успешного разбора и `Send`** — HTML-заглушка WAF и битый файл в архив не попадают. Пишет `util`: `sha256` → ключ (§3.2) → `Exists` (есть — не перезагружаем) → `Put` → `Registry.Ensure` (§3.4).
- **Сбой архива — не сбой прогона, но блокирует запись версии:** лог `log.Errorf` с причиной (`ErrAuth`/`ErrQuota` — различимые тексты подсказывают действие), импорт данных и производные выполняются штатно, строка версии в `source_publications` **не пишется**. Тогда следующий прогон повторит полный импорт и допишет архив — дыры «версия считается импортированной, а в архиве её нет» не остаётся. Конвейер данных при недоступном Диске не встаёт.
- **Префлайт + проверка архива:** когда префлайт вернул `noop` и архивация включена — `Store.Exists(key)`; нет или ошибка → `warn` «версия известна, но не в архиве — полный импорт» и полный импорт. Архив выключен → поведение ровно прежнее (ни одного лишнего вызова).
- Состояние — ленивый синглтон `util` (env читается на первом обращении; тесты подставляют `Store` по образцу `fileTimeout`). `CrawFunc`-путь не трогается (файл качает сам импортёр — винтаж не обеспечивается, стандарт §9.6).

### 3.4 Реестр: `registry.jsonl` на Диске + git-зеркало

Реестр — **файл в самом хранилище**, в корне: `registry.jsonl`, одна строка JSON = одна сохранённая версия. Идентичность строки — `key`; upsert: та же версия с тем же `sha256` — строка не меняется, иначе заменяется (last-wins, как `ReplacingMergeTree`); новые строки — в порядке `first_seen`. Чтение — один `Get`, лениво на процесс; запись — после `Put` объекта; сбой чтения/записи реестра — сбой архивации (§3.3). Штатный писатель один (последовательная цепочка dagu); потерянная при конкурентном ручном прогоне строка самолечится — `Exists` вернёт «нет», полный импорт допишет.

```json
{"source":"cbr_m2","name":"monetary_agg_SA.xlsx","fingerprint":"8f3c…","sha256":"b7d1…","size":583746,"url":"https://www.cbr.ru/vfs/…","key":"cbr_m2/8f3c…_monetary_agg_SA.xlsx","first_seen":"2026-10-14T09:20:11+03:00"}
```

Реестр читается без ClickHouse — по нему будущий пункт восстановления найдёт версии (`source`, `key`, `sha256`, `url`) и проверит целостность. **Git-зеркало** (`docs/archive/registry.jsonl`, тот же формат) обновляется целью `make archive-registry` → бинарник в режиме `ARCHIVE_ACTION=registry` (до подключения к ClickHouse) скачивает `registry.jsonl` из хранилища и пишет в репозиторий; рядом `docs/archive/README.md` (происхождение файла, как обновлять, коммит — периодический/ручной; автокоммит с staging невозможен). Таблица в ClickHouse для реестра **не заводится**: реестр обязан быть доступен при пустой БД, а SQL-доступ — потребность будущего пункта.

## 5. Риски и митигации

| Риск | Митигация |
|---|---|
| Токен истёк/отозван, квота, `429`/`503`/`423` | Различимые `ErrAuth`/`ErrQuota` в логе; warn + self-heal (версия не пишется, следующий прогон дописывает архив); данные не зависят от Диска |
| Лимиты бесплатного тарифа (объём загрузок, размер одного файла) | 150–250 МБ/год и файлы ≤ нескольких МБ — запас на порядки; проверяется живой приёмкой |
| Смена семантики префлайта («версия известна» ⇒ «версия в архиве») | Только при включённом архиве; выключение `ARCHIVE_BACKEND` возвращает прежнее поведение; названо в ARCHITECTURE §8 и стандарте §9.6 |
| Первый прогон после включения — полный ре-импорт 14 артефактов | Ожидаемая разовая цена (так текущие версии попадают в архив); названо в README |
| Read-modify-write `registry.jsonl` при конкурентных ручных прогонах | Штатный писатель один; строка самолечится префлайтом (см. §3.4) |
| Заголовки не изменились, содержимое — да (слабость отпечатка) | Унаследована от `source_publications`; `sha256` в реестре фиксирует факт смены содержимого (§3.2) |
| Утечка токена или подписанной `href` в логи | Только `os.Getenv`; логируется путь на Диске, не `href`/токен |
| `archive/registry.jsonl` разошёлся с Диском (зеркало устарело) | Зеркало — снимок на дату; в `docs/archive/README.md` порядок обновления; истина — файл на Диске |

## 6. Приёмка

1. `make all` — зелёный (gofmt, golangci-lint, `go vet`, `go test -race ./...`, обе сборки).
2. **Local-бэкенд, машинный цикл:** `make import STAT=cbr_m2 ARCHIVE_BACKEND=local ARCHIVE_LOCAL_DIR=build/archive-dev` → объект `cbr_m2/<fp16>_monetary_agg_SA.xlsx` и `registry.jsonl` в `build/archive-dev/`, строка версии в `source_publications`; повтор → `no-op, версия … уже импортирована`, без скачивания; удалить объект из local-каталога → прогон → `warn` «версия известна, но не в архиве», полный импорт, объект восстановлен.
3. **Yandex-бэкенд, живой:** `make import STAT=cbr_m2 ARCHIVE_BACKEND=yandex ARCHIVE_YANDEX_DIR=disk:/rosstat-archive` (токен из env; смена бэкенда даёт полный импорт) → файл виден в веб-интерфейсе Диска, размер совпадает с `size` в реестре (подтверждает владелец); повтор → no-op.
4. `make archive-registry ARCHIVE_BACKEND=yandex` → `docs/archive/registry.jsonl` содержит запись версии.
5. `make env-check` — строка `ARCHIVE_YANDEX_TOKEN` отображается.
6. `make mcp-check` — ПРОВЕРКА ПРОЙДЕНА (схема и гранты не менялись — контроль неизменности).
7. Документация и статус шага 1.1 в `docs/ROADMAP_INFRA.md` — ✅ с командами и результатами, тем же PR.
