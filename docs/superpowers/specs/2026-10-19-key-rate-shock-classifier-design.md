# Спека: классификатор шоков по каналам прогноза ключевой ставки

**Дата:** 19 октября 2026 г.
**Пункт роадмапа:** `key-rate/phase-4-shock-classifier` — [ROADMAP_KEY_RATE.md](../../ROADMAP_KEY_RATE.md) §6, фаза 4.
**Issue:** [#200](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/200).
**Зависит от:** `key-rate/phase-4-forecast-log` (#127, `forecast_log`/резолвер), `key-rate/phase-4-ml-v2` (каналы мониторинга предприятий), `infra/1.x` (календарь заседаний).
**Статус:** спека дизайна; план — [2026-10-19-key-rate-shock-classifier.md](../plans/2026-10-19-key-rate-shock-classifier.md).

## 1. Зачем

Контур прогноза ставки учится на решениях ЦБ, но часть решений — **шоки**: внеочередные заседания, на которых ставка меняется вне регулярного цикла. Такие наблюдения не являются «ошибкой измерения» и не должны ни молча исключаться, ни получать тот же вес, что обычные заседания. Issue #200 формулирует правило:

> «Явный шок — внеочередное собрание и изменение ставки ЦБ, естественное понижение веса у выбросов.»

Спека переводит это в измеримый компонент:

1. **явная метка** шока берётся из первоисточника (календарь ЦБ + ряд ставки), а не назначается вручную;
2. **аномальный скор** по каналам прогноза даёт причинный вес каждому заседанию, поэтому «естественные» выбросы — не только явные шоки — мягко понижаются;
3. **модели ставки** (правило Тейлора и упорядоченный логит) умеют применять эти веса; сравнение «с весами / без» измеряется walk-forward.

Компонент не заменяет модель и не меняет её официальные артефакты без явного флага. Он отвечает на вопрос «какие наблюдения модель должна слушать тише и почему», а не «какой будет ставка».

## 2. Решения

| Вопрос | Решение |
|---|---|
| Потребитель | веса наблюдений для `key_rate_model` (Тейлор + ordered logit); отдельный скрипт `shock_classifier.py` |
| Метка | явные шоки из источника служат **валидацией**; веса даёт неконтролируемый аномальный скор |
| Признаки | все доступные каналы прогноза с as-of и явной маской пропусков; `core` — проверка робастности |
| Хранение | локальные артефакты + `ML_LOG` (`ml_runs`/`ml_predictions`); новых таблиц/витрин ClickHouse нет |
| Модель классификатора | логистическая регрессия (описательный слой); **не** CatBoost — 6 положительных меток |
| Аномальный скор | расстояние Махаланобиса с Ledoit–Wolf сжатием, walk-forward, только прошлое |

## 3. Метка шока

### 3.1 Признак «внеочередное» в `events_calendar`

Сейчас `calendar/events.go` пишет все канонические заседания с одним `title` (`calMPTitle`), и признак внеочередного заседания, который парсер видит в тексте страницы ЦБ, в БД теряется. Спека добавляет колонку:

```sql
emergency UInt8 DEFAULT 0
```

- в `CREATE TABLE IF NOT EXISTS` (`eventsDdl`);
- идемпотентным `ALTER TABLE events_calendar ADD COLUMN IF NOT EXISTS emergency UInt8 DEFAULT 0` сразу после DDL — таблица уже существует в dev/проде;
- в `INSERT` (`calMPInsert`) и в батч;
- в `eventsView.Columns` — описание; `v_events_calendar` (`SELECT *`) получает колонку автоматически, отдельный `GRANT SELECT` не нужен.

Парсер `parseCalMP` возвращает не только дату, но и флаг: `[]calMPMeeting{Date time.Time; Emergency bool}`. Флаг — регистронезависимая подстрока `внеочередн` в нормализованном тексте карточки/строки таблицы (`calMPText`). Даты не хардкодятся.

`ReplacingMergeTree ORDER BY (event_date, category, title)` не меняется: повторный импорт заменяет строку того же ключа, `FINAL` отдаёт новую версию. Требуется однократный `make import STAT=events_calendar` после миграции.

### 3.2 Правило метки

```
emergency_meeting = events_calendar.emergency == 1
explicit_shock    = emergency_meeting AND step_bp != 0
```

`step_bp` — шаг решения на этом заседании из `cbr_key_rate` (правило `rate_before`/`rate_after` модели v0). Внеочередное заседание без изменения ставки — `emergency_meeting=1`, `explicit_shock=0`; отчёт печатает такие отдельно (в истории таких нет, но правило не должно молча ломаться).

Ожидаемые положительные метки на фикстуре: `2014-03-03`, `2014-12-15`, `2022-02-28`, `2022-04-08`, `2022-05-26`, `2023-08-15` — 6 событий, все с изменением ставки.

## 4. Панель заседаний и каналы

### 4.1 Единица наблюдения

Строка панели — заседание:

- `Decision` из `key_rate_model`: `meeting_date`, `rate_before`, `rate_after`, `step_bp`, `y3`;
- `emergency`, `explicit_shock`;
- вектор каналов, снятых **as-of даты заседания**;
- `missing_count` — число отсутствующих каналов в строке.

Для заседания `d` точка месячного ряда за отчётный месяц `M` доступна, если `end_of_month(M+1) <= d` (та же консервативная конвенция, что в `key_rate_model.asof`: публикация во второй декаде `M+1`). Дневные ряды доступны в день `d`. Точка, опубликованная после `d`, не участвует — это проверяется тестом.

### 4.2 Признаки

| Признак | Источник | Преобразование | Покрытие |
|---|---|---|---|
| `rate_before` | `cbr_key_rate` | уровень, % | 2013+ |
| `pi_saar` | `cbr_indicators_cpd`, `Базовый ИПЦ` | SA м/м → годовой темп `((1+x/100)^12−1)×100` | 2002+ |
| `cpi_saar` | `cbr_indicators_cpd`, `Все товары и услуги` | то же | 2002+ |
| `infl_exp_expected` | `cbr_infl_exp`, `ожидаемая инфляция` | уровень, % | 2023+ |
| `infl_exp_observed` | `cbr_infl_exp`, `наблюдаемая инфляция` | уровень, % | 2023+ |
| `unemployment` | `rosstat_labour_force_mes`, `Уровень безработицы` | уровень, % | 2017+ |
| `wage_yoy` | `rosstat_salaries_mes` | г/г, % | 1991+ |
| `credit_yoy` | `cbr_credit_m2x`, `Кредит экономике` | г/г, % | 2015+ |
| `m2_yoy` | `cbr_m2`, `М2 SA` | г/г, % | 2001+ |
| `budget_balance` | `minfin_fed_bud_mes` | сальдо за 12 мес. / доходы за 12 мес., % | 2011+ |
| `usdrub_3m` | `cbr_currency_usd` | лог-изменение за 3 мес. | 2013+ |
| `ruania_spread` | `cbr_ruonia` | RUONIA − ключевая ставка, п.п. | 2019+ |
| `price_expectations` | `macro_series`, `source='cbr_survey'`, `price_expectations_sa` | уровень, п. | 2013+ |
| `business_climate` | `macro_series`, `source='cbr_survey'`, `business_climate_sa` | уровень, п. | 2013+ |

**Дельты.** Для `pi_saar`, `cpi_saar`, `infl_exp_*`, `unemployment`, `wage_yoy`, `price_expectations`, `business_climate` добавляется `*_chg` — изменение к предыдущему заседанию (не к предыдущему месяцу): шок — это сдвиг между решениями. Для `m2_yoy`, `credit_yoy` уровень уже является темпом; отдельная дельта не нужна.

**Пропуски.** Отсутствующая точка — `None`, не ноль. Аномальная модель заполняет пропуск медианой обучающего окна; `missing_count` сохраняет информацию о покрытии. Отчёт печатает покрытие по каждому признаку.

**Варианты набора:**

- `all` — все перечисленные признаки (основной);
- `core` — признаки, покрывающие весь период 2014+: `rate_before`, `pi_saar`, `cpi_saar`, `wage_yoy`, `m2_yoy`, `budget_balance`, `usdrub_3m`, `business_climate` (проверка робастности).

**Вне объёма:** `ofz_curve` (история только с 2026), `cbr_mp_summary_channel` (2024+), текстовые каналы, CatBoost, point-in-time слой, новые витрины.

## 5. Аномальный скор и веса

Для каждого заседания `t` в walk-forward (обучение — только заседания строго раньше `t`):

1. стандартизация признаков по медиане/IQR обучающего окна; `IQR=0` → стандартное отклонение, затем 1; пропуск → 0 после стандартизации;
2. `sklearn.covariance.LedoitWolf` на обучающем окне (устойчиво при числе признаков, близком к числу наблюдений);
3. расстояние Махаланобиса `d_t`;
4. `r_t = d_t / median(d_train)`;
5. вес `w_t = 1 / (1 + max(0, r_t − 1)^2)`, клип `[0.05, 1]`.

Свойства:

- вес монотонно убывает с аномальностью, без жёсткого порога — «естественное понижение»;
- первые `MIN_TRAIN = 24` заседания получают `w = 1`: статистик ещё нет;
- веса **причинные**: строка `t` не участвует в оценке своих статистик; CSV содержит только as-of веса;
- для следующего (ещё не состоявшегося) заседания статистики берутся по всем прошлым заседаниям, признаки — as-of даты прогона.

Ограничение: при `all` часть каналов отсутствует на ранних заседаниях; медианная импутация не создаёт «измеренных» значений, а покрытие и `missing_count` публикуются. `core`-вариант показывает, не держится ли результат на импутации.

## 6. Supervised-классификатор (слой валидации)

`LogisticRegression` (L2, `C=1.0`, `class_weight='balanced'`, `max_iter=1000`) на тех же стандартизованных признаках, walk-forward с `MIN_TRAIN=24`.

- фолд без двух классов или без положительных в обучении пропускается со счётчиком;
- метрики: ROC-AUC, PR-AUC, Brier, precision/recall при пороге 0.5, матрица ошибок;
- **веса не из него**: при 6 положительных событиях классификатор описательный и служит проверкой, что явные шоки отделимы каналами. В отчёте — обязательная оговорка о размере выборки.

## 7. Интеграция в `key_rate_model.py`

Новый флаг `--shock-weights PATH` (CSV `meeting_date,weight`):

- загрузчик валидирует даты, уникальность, `0 < w <= 1`; отсутствующая дата — `w=1` и предупреждение со счётчиком;
- `_taylor_fit(train, weights=None)`: при весах — `sm.WLS` с той же `cov_type="HAC"`, `maxlags=4`, `use_correction=True`; без весов — прежний `OLS` (поведение байт-в-байт);
- `_ordered_fit(train, weights=None)`: подкласс `WeightedOrderedModel(OrderedModel)` с `freq_weights`; `loglikeobs` умножает вклад наблюдения на вес; без весов — прежний `OrderedModel`;
- `walk_forward` передаёт вес строки; бенчмарки B1–B3 остаются без весов (эталоны);
- при заданном флаге отчёт получает раздел «Веса шоков»: покрытие, распределение, weighted vs unweighted RMSE/MAE по `taylor` и `ordered_logit`, DM-HLN p-value через `eval_utils.diebold_mariano`, топ-10 пониженных заседаний;
- без флага артефакты и числа не меняются — проверяется тестом на хэш/поля отчёта.

`WeightedOrderedModel` — часть `key_rate_model.py`, а не `shock_classifier.py`: это свойство модели, а не источника весов. Тест: при единичных весах результат совпадает с `OrderedModel` в пределах допуска.

## 8. Артефакты, CLI и `ML_LOG`

`scripts/shock_classifier.py`, цель `make shock-classifier`:

- `shock_classifier_report.md` — выборка, список явных шоков, покрытие, метрики классификатора, распределение весов, weighted/unweighted, топ-10, следующее заседание, ограничения;
- `shock_classifier_weights.csv` — `meeting_date, emergency, explicit_shock, step_bp, y3, anomaly_score, weight, shock_prob, missing_count` + признаки;
- `shock_classifier_forecast.json` — as-of срез на следующее заседание: score, weight, признаки, версия набора;
- CLI: `--features all|core`, `--min-train N` (по умолчанию 24), `--export-fixtures DIR`;
- артефакты — в корне прогона, как у `key_rate_model`; старые артефакты удаляются при раннем выходе;
- `ML_LOG=1` — прогон `key_rate_shock_classifier`, `run_name=shock_classifier__<features>__start<min_train>`, `config`/`sample_meta`/`sample`, метрики и предсказания (`explicit_shock`: `predicted=shock_prob`, `actual=label`, `unit='probability'`; `anomaly_weight`: `predicted=weight`, `actual=1.0`, `unit='weight'`), артефакты. В ClickHouse напрямую не пишет.

Секреты — только из окружения; содержимое `~/.config/rosstat/env` не читается.

## 9. Тесты

Офлайн (`scripts/shock_classifier_test.py`):

1. разметка: 6 внеочередных дат из фикстуры календаря; внеочередное с `step_bp=0` не становится `explicit_shock`;
2. панель/as-of: опубликованная после заседания точка не участвует; дельта — к предыдущему заседанию; пропуск — `None`;
3. аномалия: веса в `[0.05, 1]`, монотонно убывают с `r`, первые 24 = 1, тестовая строка не влияет на статистики обучения, явные шоки в среднем ниже весом;
4. классификатор: на синтетике с разделимыми классами AUC высокий; фолд без положительных пропускается; тестовые метки не участвуют в обучении;
5. веса в моделях: `WLS` с единичными весами = `OLS`; `WeightedOrderedModel` с единичными весами = `OrderedModel`; понижение веса шока меняет коэффициенты в ожидаемую сторону на синтетике;
6. `--shock-weights`: загрузка/валидация CSV, отсутствующая дата → `w=1` + предупреждение; без флага артефакты `key_rate_model` не меняются;
7. артефакты детерминированы; `ML_LOG`-payload содержит метрики/предсказания.

Go-тесты (`calendar/events_test.go`): 6 дат с `emergency=1`, остальные 0; DDL/ALTER идемпотентны; `v_events_calendar` содержит колонку.

## 10. Приёмка

1. `make import STAT=events_calendar` — 118 канонических заседаний, 6 `emergency=1`; повтор идемпотентен.
2. `make shock-classifier` — живой прогон; в отчёте: число заседаний, 6 явных шоков, покрытие каналов, AUC/PR, распределение весов, вес следующего заседания.
3. `make shock-classifier-test` — офлайн-тесты зелёные.
4. `make key-rate-model` без флага — прежние числа/артефакты; `make key-rate-model ARGS="--shock-weights shock_classifier_weights.csv"` — weighted/unweighted RMSE/MAE и DM-HLN.
5. `ML_LOG=1 make shock-classifier` — паспорт в `ml_runs`/`ml_predictions`.
6. `make all`, `make docs-check` — зелёные.
7. Роадмап, issue #200 и Project V2 синхронизированы; PR с `Closes #200`, протокол живой приёмки — комментарием.

## 11. Границы и риски

- **6 положительных меток** — supervised-классификатор описательный; веса даёт аномальный скор. Это главная оговорка отчёта.
- **As-of — приближение**, не point-in-time: ревизии и точные даты публикаций не учтены (наследуется от v0).
- **Пропуски каналов**: покрытие печатается; `core` — проверка робастности; медианная импутация не создаёт «измеренных» значений.
- **Веса не исключают наблюдения**, а мягко понижают вклад.
- **Совместимость**: без `--shock-weights` официальные артефакты/числа `key_rate_model` не меняются; изменение `events_calendar` — идемпотентный `ALTER` + однократный повторный импорт.
- **Вне объёма**: новые таблицы/витрины ClickHouse, гранты, дашборд, публикационный прогон, CatBoost, текстовые каналы ЦБ, point-in-time слой.
