# Пакет `polyus/` — парсеры отчётности Полюса (вынос из legacy `financial/`) — Design

**Дата:** 2026-10-10
**Пункт роадмапа:** самостоятельный пункт перед фазой 3 («DCF-движок»); после завершения — вход для `mine_plans` фазы 3.
**Сопутствующие документы:** [ARCHITECTURE.md](../../../ARCHITECTURE.md) §3 (шаблоны импортёров), §6.2 (DDL); [AGENTS.md](../../../AGENTS.md) правило 7 (пакет `financial/` — legacy).

## 1. Проблема

Отчётность Полюса парсится двумя файлами в пакете `financial/`, куда AGENTS.md запрещает добавлять новый код:

| Файл | Что делает | Состояние |
|---|---|---|
| `financial/gold_polyus.go` (123 строки) | xlsx-датапак: поквартальные операционные результаты по активам с 2007 (`CONSOLIDATED OPERATING RESULTS`, `OLIMPIADA`, `BLAGODATNOYE`, `TITIMUKHTA`, `VERNINSKOYE2`, `ALLUVIALS`, `KURANAKH`, `ZAPADNOYE`, `NATALKA`, `Sukhoi Log`) | Работает; таблица `databook_polyus`; тестов нет |
| `financial/gold_polyus_finance.go` (517 строк) | PDF-отчёты: `pdftotext -layout` по KPI-странице + регулярки; список URL → номер страницы в `init()` | Работает; половина исторических отчётов закомментирована; тестов нет |

Оба используют общий движок `financial/databook.go` (`FinDataBook`): скачивание PDF, `pdftotext`, батч-вставка.

Известные дефекты, которые надо закрыть в этом цикле:

1. **Историю видно только в коде.** Список отчётов и номеров KPI-страниц зашит в `init()` (строки 469–517 `gold_polyus_finance.go`), причём у большинства исторических отчётов строки закомментированы (`// "https://polyus.com/...": 4`). Непонятно, какие периоды реально разобраны, а какие нет.
2. **Свежий отчёт отсутствует.** Последний разобранный период — не 1H2026. Нужен парсинг [отчётности 1H2026 (eng)](https://polyus.com/upload/iblock/889/otchetnost-6m2026_eng.pdf).
3. **Нет тестов.** Ни xlsx-, ни PDF-парсер не покрыт; ошибка регулярки обнаруживается только на живом прогоне.
4. **Прод-код печатает в stderr.** `fmt.Fprintf(os.Stderr, "downloaded %d bytes...")` и `fmt.Printf` в парсерах — нарушение стиля (logrus).
5. **Парсер бросает работу на первой ошибке.** `finDataBookTableImport` возвращает `err` на любом нечисловом значении — одна битая ячейка в датапаке роняет весь импорт.

## 2. Цель

Вынести парсеры Полюса в самостоятельный пакет `polyus/`, привести их к конвенциям проекта (батч-вставка, logrus, проверка ошибок по правилу 6), сделать список разбираемых отчётов данными, добавить 1H2026 и закрыть тестами.

**Критерий приёмки:** `make all` зелёный; `make import STAT=polyus` пишет операционные и финансовые ряды Полюса, включая 1H2026; в `financial/` кода Полюса не осталось; тесты парсеров работают без сети.

## 3. Границы

**Входит:**
- новый пакет `polyus/` с xlsx- и PDF-парсерами, перенесёнными из `financial/`;
- таблица разбираемых отчётов как данные (`pages.go`), с 1H2026;
- тесты обоих парсеров на локальных фикстурах (без сети);
- закрытие дефектов 4 и 5;
- удаление кода Полюса из `financial/`, обновление импортёров/`main.go`, `ARCHITECTURE.md`, `README.md`.

**Не входит (отдельные пункты):**
- вынос остального содержимого `financial/` — пакет остаётся legacy целиком, кроме кода Полюса; см. §4.1 (карта переноса);
- построение `mine_plans` из распарсенных данных — это фаза 3;
- русскоязычные версии отчётов: **парсим только английские** (`_eng`), источник — `https://polyus.com/en/investors/results-and-reports/`;
- рефакторинг общих утилит HTTP/скачивания (`util.HdBase`, `util.GetCSV`) сверх того, что нужно парсерам Полюса.

## 4. Структура пакета

Пакет назван по компании, потому что парсит только её отчётность. Общая на несколько компаний структура появится, когда в контур войдут пиры (`peers_nav`, фаза 3/12) — тогда `polyus/` станет одним из источников наряду с будущим пакетом для ЮГК/Селигдара, а не «общим золотодобывающим» пакетом.

```
polyus/
  polyus.go          типы (Report, MetricDefinition), регистрация импортёров (init(), Name())
  datapack.go        xlsx-парсер операционных результатов   (перенос gold_polyus.go, 123 строки)
  report.go          PDF-парсер финансовых KPI               (перенос gold_polyus_finance.go, 517 строк)
  pages.go           таблица «отчёт → KPI-страницы → парсить да/нет» как данные
  metrics.go         MetricDefinition/MetricRecord и словарь метрик (сейчас часть gold_polyus_finance.go)
  source.go          скачивание PDF + pdftotext (выделено из financial/databook.go)
  datapack_test.go   тесты xlsx-парсера на локальной фикстуре
  report_test.go     тесты PDF-парсера на сохранённом текстовом слепке
  testdata/          фикстуры (xlsx + текстовый слепок pdftotext)
```

Разделение `report.go` / `metrics.go` — потому что словарь метрик (`metrics`, `Interval`-таблица, `PeriodColumn`) это данные о разметке отчётов, а не логика разбора; он будет расти при подключении новых отчётов, тогда как код разбора — нет.

`source.go` — минимальный вынос нужной части `FinDataBook`: скачивание с проверкой `%PDF-` заголовка и `pdftotext -f N -l N -layout -nopgbrk -enc UTF-8`.

### 4.1 Карта переноса: что уходит из `financial/`, что остаётся

Пакет `financial/` целиком — legacy (AGENTS.md, правило 7). В этот цикл из него уходит **только код Полюса**; остальное остаётся как есть и выносится отдельными пунктами, если понадобится.

| Файл `financial/` | Строк | Что это | Решение |
|---|---|---|---|
| `gold_polyus.go` | 123 | xlsx-датапак Полюса → `databook_polyus` | **переносится** → `polyus/datapack.go` |
| `gold_polyus_finance.go` | 517 | PDF-отчёты Полюса → `polyus_financial_metrics` | **переносится** → `polyus/report.go` + `polyus/metrics.go` + `polyus/pages.go` |
| `databook.go` | 296 | общий движок `FinDataBook` (скачивание, `pdftotext`, батч) | **остаётся** (используется legacy-импортёрами); нужная парсерам Полюса часть копируется в `polyus/source.go` |
| `gold_ugk.go` | 24 | xlsx-датапак ЮГК → `databook_ugk` | **остаётся** в legacy (перенос — отдельный пункт, когда ЮГК понадобится для `peers_nav`) |
| `metal_nlmk.go` | 290 | xlsx НЛМК; в `chimport.Stats` **не зарегистрирован** | **остаётся**; мёртвый код, вне скоупа |
| `metal_chmf.go` | 226 | xlsx Северстали; не зарегистрирован | **остаётся**; мёртвый код |
| `metal_magn.go` | 95 | xlsx ММК; не зарегистрирован | **остаётся**; мёртвый код |
| `yuzd.go`, `bank_vtb.go`, `customs_gov.go`, `investing.go`, `lme.go`, `cbr.go`, `moex.go`, `db.go`, `main.go`, `csv.go` | 1427 | РЖД-новости, банки, таможня, металлы, утилиты БД | **остаются**; к отчётностям отношения не имеют |

Итог по регистрации импортёров: из пакета `financial` в `chimport.Stats` попадают три записи (`databook_polyus`, `polyus_financial_metrics`, `databook_ugk`). После переноса первые две уходят в `polyus`, третья остаётся. `main.go` получает импорт `polyus`; импорт `financial` сохраняется (нужен для `databook_ugk` и остальных legacy-импортёров).


## 5. Модель данных

Схемы таблиц не меняются — переносятся как есть, потому что они уже лежат в ClickHouse:

| Таблица | DDL | Источник |
|---|---|---|
| `databook_polyus` | `(table, name, data, date, value Float32)`, `ReplacingMergeTree ORDER BY (table, name, data, date)` | xlsx-датапак |
| `polyus_financial_metrics` | `(company, metric, period, period_type Enum8('Q','H','FY','LTM'), value Nullable(Float64), unit, source_url, source_page, loaded_at)`, `ReplacingMergeTree(loaded_at)` | PDF-отчёты |

Ставка на существующие таблицы — сознательная: переименование сломало бы уже накопленные ряды и Grafana-дашборд `dashboard/finance-polyus.json`.

## 6. Таблица отчётов как данные (`pages.go`)

Вместо закомментированных строк в `init()` — явный список:

```go
type Report struct {
    URL      string
    Period   string // "FY2025", "1H2026"
    Pages    []int  // KPI-страницы в PDF
    Enabled  bool   // false — отчёт известен, но страницы не выверены
}

var reports = []Report{ ... }
```

Правила:
- у каждого отчёта заполнены `Period` и `Pages`; отчёт, который не парсится, остаётся в списке с `Enabled: false` и комментарием причины — история отчётов видна целиком, «выключенное» не теряется;
- 1H2026 добавляется с `Enabled: true` после выверки страниц на живом PDF (номер KPI-страницы определяется прогоном `pdftotext`, а не угадывается);
- импортёры пропускают `Enabled: false` с логом `log.Infof("skip report %s (%s): disabled", ...)`.

## 7. Обработка ошибок (дефект 5)

xlsx-парсер сейчас падает на первой нечисловой ячейке. Новое поведение:
- ячейки `-`, `N/A`, пустые — пропускаются (как сейчас);
- значение, не поддающееся разбору, — пропуск строки с `log.Warnf` (не `return err`), счётчик пропусков пишется в итоговый лог;
- жёсткая ошибка остаётся для структурных сбоев: лист/таблица не найдены, файл не открылся, `batch.Append`/`Send` не прошли.

Правило 6 AGENTS.md («каждый `batch.Append` с проверкой `err`») сохраняется без исключений.

## 8. Тестирование

**xlsx-парсер** (`datapack_test.go`): фикстура — копия `financial/data/polyus_datapack_fy2025_new.xlsx` в `polyus/testdata/`. Проверяется: число разобранных строк > 0; добыча конкретного актива за конкретный квартал равна ожидаемому числу (значение берётся из файла и фиксируется как эталон); отрицательные значения в скобках разбираются со знаком минус; ячейка `N/A` пропускается, импорт не падает.

**PDF-парсер** (`report_test.go`): фикстура — сохранённый текстовый слепок `pdftotext -layout` KPI-страницы 1H2026 (сеть в тестах не используется). Проверяется: метрика `gold_output` распознана; период и значения совпадают с ожидаемыми.

**Живой прогон (ручная приёмка):** `make import STAT=polyus` — скачивает 1H2026 с сайта, парсит, пишет в ClickHouse; проверка `SELECT period, metric, value FROM polyus_financial_metrics FINAL WHERE period = '1H2026' LIMIT 5`.

## 9. Совместимость и документация

- `main.go`: добавляется blank-импорт `polyus`; существующий импорт `financial` **сохраняется** — в нём остаются `databook_ugk` (ЮГК), мёртвые парсеры металлургов и утилиты, а также используемый ими общий движок `databook.go`. Удаляются только `chimport.Stats`-регистрации `databook_polyus` и `polyus_financial_metrics` вместе с перенесёнными файлами.
- `CLICKHOUSE_IMPORT_STAT` для нового пакета: `polyus` (один импортёр на оба парсера) — уточняется на этапе плана по фактической структуре `Name()`.
- `ARCHITECTURE.md` §6.1 (таблица импортёров) и `README.md` — новый пакет, состав таблиц, команда запуска.
- В `docs/ROADMAP_DCF_POLYUS.md` пункт помечается ✅ со ссылкой на эту спеку после живой приёмки.

## 10. Риски

| Риск | Митигация |
|---|---|
| Разметка PDF 1H2026 отличается от исторических отчётов, регулярки не срабатывают | Страницы выверяются прогоном `pdftotext` на живом файле до включения отчёта; тест на слепке фиксирует разметку |
| Датапак FY2025 не содержит нужных для `mine_plans` строк (в нём есть исторические операционные результаты, но нет LOM-планов и AISC) | Вне этого пункта: фаза 3 строит профиль актива из факта + guidance, что зафиксировано в спеке фазы 3 |
| Перенос ломает legacy-импортёры, использующие `financial/databook.go` | `databook.go` не переписывается, из него выносится только нужная парсерам Полюса часть (`downloadFile`, `extractPage`) в `polyus/source.go` |
| `pdftotext` не установлен в CI | Тест PDF работает на текстовом слепке и не вызывает `pdftotext`; живой прогон требует утилиту и помечен как ручная приёмка |
