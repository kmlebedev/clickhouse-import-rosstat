## 1. Контекст и цель

Контур должен отвечать на вопрос «идёт ли кредит в недвижимость как в инвестиционный актив»: сколько выдачи идёт в первичку (ДДУ), какой ценой кредита это финансируется и как ведёт себя цена актива к инфляции. Сегодня в БД есть только ставка предложения по банкам (`domrf_mortgage`, месячная, доля) — этого мало: нет объёмов, нет ДДУ, нет цены актива и спроса.

Спека объявляет **пакет `domrf/`** с тремя импортёрами, их схему, разбор, идемпотентность и тесты. Пакет `bank/` не трогается: `domrf_mortgage` остаётся там (миграция — отдельный пункт).

## 2. Источник (проверено на живом сайте 2026-10-23)

### 2.1 Антибот и транспорт

Сайт `xn--d1aqf.xn--p1ai` отдаёт на часть запросов HTTP 200 с JS-оболочкой ServicePipe (1,8 КБ, `<js-challenge-loader>`) вместо страницы. Замеры: 1–5 успехов из 8–20 попыток, доля падает при частых запросах; cookie-jar ухудшает результат (1/20). **HEAD и Range — 307 на тот же URL**, GET файла — 200.

Правила транспорта пакета:

1. Страница качается **только** через `domrfGetPage` — до 8 попыток `util.GetPage` с паузой 1 с; ответ считается challenge, если `len < 4096` **и** содержит `servicepipe` или `js-challenge-loader`; после последней попытки — ошибка с числом попыток (не «0 строк»).
2. Файлы (`/api/v2/content/download/...`) качает шаблон `util.ClickHouseImport` (`DataUrl`); WAF на них не распространяется, HEAD не используется.
3. JSON-API раздела `/api/v2/content/analytics/list/?section=…&include=Y` антиботом не закрыт, но **блоки A и B в листингах отсутствуют** — они статические элементы страницы. Листинг годится только для `bank/domrf_mortgage` (там уже есть отдельная ветка `fix/domrf-mortgage-source`), в этом пакете не используется.
4. `robots.txt`: `Crawl-delay: 30`, `/api/` не запрещён, `/upload/` запрещён (PDF не качаем). Прогон — 1–3 запроса в неделю.

## 3. Схема

Пакет `domrf/`, три таблицы (канон ARCHITECTURE.md §6.2): `ReplacingMergeTree`, измерения `LowCardinality(String)`, значения `Float64`.

```sql
CREATE TABLE IF NOT EXISTS domrf_mortgage_market (
      series LowCardinality(String)   -- имя ряда из кода (§5)
    , date Date                       -- первое число отчётного месяца
    , value Float64                   -- единица ряда — в series_catalog
) ENGINE = ReplacingMergeTree ORDER BY (series, date);

CREATE TABLE IF NOT EXISTS domrf_mortgage_weekly (
      product LowCardinality(String)  -- продукт источника как есть
    , date Date                       -- дата недельного среза (пятница)
    , rate Float64                    -- % годовых (18.76), НЕ доля
) ENGINE = ReplacingMergeTree ORDER BY (product, date);

CREATE TABLE IF NOT EXISTS domrf_price_index (
      region LowCardinality(String)    -- имя региона источника
    , room_count LowCardinality(String)-- all | 1 | 2 | 3
    , date Date                        -- первое число месяца
    , index_value Float64              -- 100 = январь 2021
    , index_diff_month Float64         -- % м/м, как в источнике
    , deals UInt32                     -- сделок ДДУ за месяц
) ENGINE = ReplacingMergeTree ORDER BY (region, room_count, date);
```

Единицы наборов несовместимы между рядами и **не пересчитываются**: `млн руб.`, `единиц`, `тыс. руб.`, `доля` (0…1), `% годовых`, `индекс (100 = янв. 2021)`, `сделок`. Совместимость задаёт `v_series_catalog`, а не имя колонки.

**Ставки и унаследованная единица.** `domrf_mortgage` (в `bank/`) хранит **долю** (0.187). Новые таблицы — **проценты** (18.76). Витрины пакета `bank/` новые таблицы не читают; в комментарии `v_domrf_mortgage` сказано, что `domrf_mortgage` — доля и смешивать нельзя.

## 4. Разбор

### 4.1 A: шапка и ряды

1. Лист ищется по единственному имени книги; при нескольких листах — по якорю `общая таблица` (регистр не значим), иначе ошибка.
2. Строка заголовка — первая, где есть ячейка, начинающаяся с `Количество выданных кредитов` (якорь, не номер строки).
3. Merged-диапазоны из `xlsx.GetMergeCells(sheet)` заполняются значением левой верхней ячейки в строках заголовка (три строки, начиная с найденной).
4. Путь колонки — `strings.Join` непустых подписей трёх строк, подряд идущие дубли схлопываются; пробелы (включая неразрывные) нормализуются.
5. Ожидаемые 24 пути объявлены кодом (таблица §5). Каждый путь обязан найти **ровно одну** колонку; дубль или пропуск — ошибка «шапка изменилась», прогон падает.
6. Строки данных: колонка A — `time.Time` (excelize отдаёт серийное число или строку; поддерживаются оба, layout `02.01.2006`), остальные — числа. Строка без даты пропускается; дата приводится к первому числу месяца.
7. Значения `X`/`x`/`-`/пусто — пропуск точки. `NaN`/`Inf` — ошибка.

### 4.2 B: массивы

1. `date[]` парсится layout `02.01.2006`; проверка: длина ≥ 200, строго по убыванию, без дублей.
2. Для каждого продукта: `strings.Split(values[p], ",")`; длина ≤ `len(date)`; при меньшей — берутся первые `n` дат (новые), при большей — ошибка.
3. Пустое значение или нечисло — ошибка (в этом блоке источник не ставит `-`).
4. Продукт, которого нет в `values`, но есть в `titles`, — ошибка (смена состава).

### 4.3 C: JSON

1. Разбор — чистый: `json.Unmarshal` в структуру, затем обход `data.regions` (порядок ключей не значим).
2. Ключ строки — `(region, room_count)`, где `room_count` маппится: `Все классы`/`Комнат` → `all`, `1 комната`/`1.0` → `1`, `2 комнаты`/`2.0` → `2`, `3 комнаты`/`3.0` → `3`; неизвестная подпись — ошибка.
3. `month_dt` — `YYYY-MM-DD`; `index_value`/`index_diff_month` — строки в JSON, парсятся как float; `index_count_deal` — целое (`UInt32`), отрицательное — ошибка.
4. Дубли `(region, room_count, date)` внутри ответа — ошибка (источник не должен отдавать два значения на точку).

## 6. Импорт и идемпотентность

| Импортёр | `Name()` / таблица | Порядок | Гейт |
|---|---|---|---|
| `domrf_mortgage_market` | `domrf_mortgage_market` | `BeforeImport`: страница → `statistical_series` → `DataUrl`; шаблон качает XLSX, `ImportFunc` разбирает | `PublicationCountPoints` объявлен; HEAD источника отдаёт 307 → префлайт fail-open, каждый прогон — полный импорт без записи версии (документировано) |
| `domrf_mortgage_weekly` | `domrf_mortgage_weekly` | свой `Import()`: страница → JSON → батч | нет; полный импорт 1 154 точек, идемпотентен `ReplacingMergeTree` |
| `domrf_price_index` | `domrf_price_index` | свой `Import()`: дешёвый POST (РФ) → решение no-op → полный POST (75×4) | гейт по `max(month_dt)` и числу точек: совпало — no-op без записи в БД |

Все три — батчами `PrepareBatch` → `Append` → `Send`; `AfterImport` публикует каталог и обе витрины (порядок «точки → производные → версия», стандарт §5.2).

`domrf_price_index`: панель — 300 слотов (`regions` × `rooms`); API не принимает больше **120** слотов в одном запросе (400 «Поле Regions не должно превышать 120»), поэтому слоты уходят чанками по 120 (три POST), а не одним телом. Чанк смешивает разрезы — сервер валидирует только число слотов.

## 10. Ограничения

1. Антибот вероятностный: 8 попыток дают высокую, но не 100 % вероятность; полный блок (как у наш.дом.рф) — смена источника решением владельца.
2. Индекс цен — внутренний API без контракта; смена схемы валит разбор.
3. Ревизии истории индексом не хранятся (только последняя версия).
4. `estateClass` не работает — разрез по классу жилья недоступен.
5. `date_from`/`date_to` не работают — история тянется целиком.
6. Аренды и «долевого строительства» (ЕИСЖС) в этом пакете нет — отдельные пункты роадмапа.
