## 1. Задача

Идея владельца: недельные ИПЦ — самый ранний сигнал инфляции. Нужно:

1. **Stage 1.** По недельным сырым ИПЦ получить недельный SA за последние 4 недели (код уже есть — `weekly_cpi_sa`), убрать из него КУ, и по нему прогнозировать **месячный SA ИПЦ без КУ** и **«Базовый ИПЦ» SA** на месяц следующей публикации Росстата. Прогноз — **винтажный**: пересчитывается на каждую дату публикации месячного ИПЦ Росстата, на данных, доступных именно к этому моменту.
2. **Stage 2.** Выход Stage 1 — дополнительный признак к признакам CB_COMP (на наших живых данных из витрин ClickHouse) для прогноза **SA ИПЦ без КУ и «Базового ИПЦ» SA на 1, 3 и 6 месяцев** на **всём окне**: где недельных данных нет, признак — NaN (не 0 и не импутация).
3. **Главная дыра, которую закрывает спека:** история `weekly_cpi_sa` — один полный фит X-13 по всем месяцам (окончательная редакция). Использовать её в бэктесте нельзя: сезонные факторы и выбросы оцениваются по будущим данным. Нужен **as-of перефит недельного X-13** на каждую дату публикации.

4. **Сравнение с CB_COMP (#76).** На **том же отрезке** — тест статьи Кошкина–Крылова 2019-01…2024-07 (67 месяцев, из них 54 «normal»), горизонты 1/3/6 (+2 справочно) — сравнить точность двухэтапной модели с прогнозами CB_COMP из их архива на одних и тех же месяцах и одной истине.
5. **Сверка данных CPI с датасетом CB_COMP.** Перед сравнением сверить наши ряды ИПЦ (SA без КУ, компоненты, КУ, веса) с данными из архива CB_COMP: где совпадают, где расходятся и почему (редакции, определение ряда, покрытие).

Вне объёма: `forecast_log`, production, DDL/витрины/гранты, Stage 3 (ставка), замена `channel_fan_vol`, per-sheet bottom-up CB_COMP. Новые Go-импортёры не пишутся; если as-of перефит должен стать продовым — отдельный Go-пункт после результата.

## 3. Определения

**Дата публикации.** `P_k` — публикация месячного ИПЦ Росстата за месяц `k`: 9-е число `k+1`, 19:00 МСК (правило календаря). **Origin** строки — `P_k`; `M0 = k+1` — месяц, чья публикация следующая. Информационное множество строки `k` — всё, что опубликовано **строго до** `P_k` включительно моментом 19:00 (признаки на момент публикации; сам релиз `k` в признаки входит, потому что `P_k` — его момент).

**Недельные данные as-of `P_k`.** Недельные точки с `date + 2 дня 19:00 ≤ P_k`; 4-недельный индекс и месячная сетка строятся только из них (по логике `weeklysa/grid.go`: `buildGrid` → `fourWeekIndex` → `monthlyLastInMonth` + `partialMonth`). Неполный месяц `M0` входит как `partial`-точка, как в продовой таблице.

**Таргеты.**

| код | определение | прогнозируемая величина |
|---|---|---|
| `T_SAX` | SA ИПЦ **без КУ**: NSA ИПЦ м/м (`rosstat_ipc_mes`) минус вклад КУ, `(π − w·u)/(1 − w)` с `u` из `ipc31074`, `w = 0,10`, затем X-13 (R `seasonal`, log, автомодель, автовыбросы) | **основной** |
| `T_CORE` | «Базовый ИПЦ» SA ЦБ (`cbr_indicators_cpd`), последняя редакция | **основной** |
| `T_NSA` | официальный ИПЦ м/м | контроль, описательно (связь с #396) |

Горизонт `h ∈ {1, 3, 6}`; накопленный рост `M0 … M0+h−1` по `cumulative_pp` (сложный процент, п.п.) — та же функция, что в #396. **Соответствие конвенциям #396:** строка `k` — это cm-строка с месяцем `O = k+1` (`Row.month` в `cpi_monthly`; в сетке #396 ей соответствует origin `O−1`, поскольку `cumulative_by_origin` берёт окно `origin+1 … origin+h`) с тем же окном таргета `O … O+h−1`, но с признаками на момент `P_k` вместо `cutoff_for(O)` = 8-е число `O+1` (то есть на месяц раньше). *Уточнение терминологии 2026-10-30 (результаты не затрагивает): «origin» в этой спеке — месяц cm-строки `O`, не origin сетки #396.* Сдвиг cutoff — единственное принципиальное отличие; шаг W0 проверяет это тестом и воспроизведением чисел #396 под старым cutoff.

**Истина для оценки.** `T_SAX` — X-13 по всей выборке (окончательная редакция) на момент оценки; `T_CORE` — последняя редакция ЦБ. **Таргеты обучающих строк** — as-of: для origin `P_k` SA-история `T_SAX` берётся из одного X-13-фита на данных `≤ k` (винтажная история), а не из окончательного ряда; `T_CORE` — значения, опубликованные к `P_k` (месяц `m` доступен с 18-го `m+1`, поэтому к `P_k` доступны месяцы `≤ k−1`). Вариант «истина = real-time SA» — в robustness.

**Отрезок сравнения с CB_COMP.** Тест CB_COMP — origin'ы с 2019-01 по 2024-07 (67 месяцев); **normal** — 54 месяца (исключены 2020-04 и 2022-01…2022-12, правило статьи; флаг «Учитывать» из архива). Истина для сравнения — **`TARGET_FULL`** из архива (SA ИПЦ без КУ, накопленный прирост за h месяцев — тот, на который обучен и по которому оценён CB_COMP); `T_SAX` — наш ряд, их различие измеряет W3b. Выравнивание окна и origin CB_COMP (`frollsum(h)` + `shift(h−1)`, origin `M−(h−1)`, см. паритет #190 §2) воспроизводится по архиву до любых выводов: пины RMSE CB_COMP выше (допуск 1e-6) — регрессионный gate W3b.

**Горизонт обучающих строк (purge).** Строка `j` входит в обучение origin `P_k`, только если её таргет-окно `M0(j) … M0(j)+h−1` полностью опубликовано/посчитано к `P_k`: `M0(j)+h−1 ≤ k−1` для `T_CORE` (ЦБ), `≤ k` для `T_SAX` по данным Росстата; Stage-1-выходы строк обучения — только OOF (§5).

## 4. Этапы работ

Порядок и стоп-условия: W0 → W1 (главная дыра) → W2 → W3 → **W3b (сверка данных CB_COMP)** → W4 → W5 → **W5b (сравнение с CB_COMP)** → W6 → W7. Каждый этап имеет артефакт и условие выхода; если W1 не выполнен — Stage 1/2 на недельном SA **не строятся**. W3b не блокирует Stage 1/2 (кроме регрессионной базы п. 1 для W5b); он может изменить primary `w` только до обучения моделей.

### W0. Конвенция as-of и регрессионная база

- Параметризовать cutoff в коде признаков/лидерборда (`cutoff_for(O)` → `P_k`), не меняя поведения по умолчанию.
- Тест: старый cutoff воспроизводит числа #396 (`S_W22` v2/v3 с эталоном спеки #396 §7.1; допуск 1e-6) — регрессионный gate; новый cutoff не использует данные позже `P_k` (тест на утечку по неделям и месяцам).
- Календарь: фактические даты публикаций Росстата за 2013+ проверить по источнику (пресс-релизы и бюллетень Росстата) для выборки месяцев; расхождение с правилом 9-е ≥ 1 дня — поправка календаря (отдельная запись, не молчаливая).
- **Выход:** конфиг as-of + тесты + таблица проверки дат. **Gate:** регрессия воспроизводится, иначе стоп.

### W1. As-of перефит недельного X-13 (главная дыра)

1. **Порт сетки на Python.** `buildGrid` / `fourWeekIndex` / `monthlyLastInMonth` / `partialMonth` из `weeklysa/grid.go` в Python (чистые функции) + мост R к тому же скрипту `weekly_cpi_sa_x13.R` (тот же spec `weekly-cpi-sa-2026-v1`, тот же SHA-256 скрипта).
2. **Parity на полной выборке.** На всех данных на момент прогона порт должен воспроизвести значения `weekly_cpi_sa` (`sa_index`, `sa_4w`, `saar`) для 209 полных месяцев и 1 `partial` с допуском **1e-6** (`max|diff|`). Не воспроизводится → порт исправляется до любых выводов.
3. **As-of ряд.** Для каждого `P_k` (2013-01…последний) — перефит на данных `≤ P_k`: SA-значение последнего полного месяца, `sa_4w` и `saar` неполного месяца, плюс `revision` = значение as-of минус значение окончательной редакции. Минимум истории для фита — 36 месяцев (как в R-скрипте); origin'ы с меньшей историей — NaN.
4. **Ревизии.** По месяцам 2016+ и по годам: RMSE/bias `as-of − final` для `sa_4w`; дополнительно **сдвиг-стабильность**: изменение `sa_4w` месяца `m`, зафиксированного на `P_{m}`, при последующих перефитах (`P_{m+1}` … `P_{m+12}`).
5. **Качество as-of входа.** Повтор критерия #399 на as-of ряде: RMSE к месячному X-13 (as-of) ≤ 0,20 п.п., \|bias\| ≤ 0,05 п.п., корреляция ≥ 0,95 на 2016+.
6. **Правило.** Окончательная таблица `weekly_cpi_sa` **не используется** ни как признак, ни как таргет в бэктестах; только as-of ряд W1.
- **Gate W1 (выход в W2):** parity (п. 2) выполнен **и** п. 5 выполнен. Если parity не выполнен — стоп, ошибка порта. Если п. 5 не выполнен — недельный SA как вход понижается до сырых `wkagg_*` и сезонных месячных дамми (Stage 1 строится без SA-входа; это фиксируется как поправка, а не молча).
- **Выход:** `scripts/models/cpi/weekly_sa_asof.py` (+ тесты), отчёт `docs/research/<дата>-weekly-sa-asof.md`, артефакт `build/cpi-two-stage/weekly_sa_asof.csv` (не коммитится).

### W2. Коррекция КУ во входе и таргет `T_SAX`

- **Таргет.** Реализовать `T_SAX` (§3) как as-of ряды (винтажная история на `P_k`) и окончательный; тесты на формулу и на отсутствие утечки. Значения `w` — 0,10 (primary), 0,08/0,12 (robustness, W6).
- **КУ во входе Stage 1** — три варианта, выбор **на dev-окне 2016-01…2021-12 по RMSE Stage 1 на `T_SAX` h1** (без обращения к holdout 2022+):
  - `V0` — недельный SA как есть (headline; модель сама учит связь с `T_SAX`);
  - `V1` — недельные приросты в неделях индексации (`tariff_week`, календарь известен заранее) заменяются медианой приростов не тарифных недель того же года до построения индекса (as-of);
  - `V2` — из месячной сетки полных месяцев вычитается реализованный вклад КУ `w·u`; неполный месяц `M0` остаётся сырым (`u(M0)` неизвестен к `P_k`).
- Выбранный вариант фиксируется до holdout и не меняется. Тарифы `M0` (неизвестные к `P_k`) — как признак календаря `tariff_week`/`tariff_month_expected` (расписание: июль, с 2026 — октябрь, январь-1), не как данные.
- **Выход:** функции + тесты, выбор варианта (запись в отчёте с числами dev), `T_SAX` ряды.

**Протокол W2 (уточнение 2026-10-30, до любых результатов W2).** Спека не задавала, чем измеряется «RMSE Stage 1» до построения Stage 1 (W4), и не фиксировала календарь тарифных недель; фиксируется здесь.

1. **`T_SAX`.** Окончательный ряд — X-13 (R `seasonal`, `transform.function="log"`, автомодель и автовыбросы по умолчанию — как в #399) на накопленном уровне ряда `(π − w·u)/(1 − w)`, `π` — `rosstat_ipc_mes` «товары и услуги» м/м, `u` — `ipc31074/Коммунальные услуги` м/м (`v_fedstat_ipc`), `w = 0,10`; SA м/м — отношение соседних SA-уровней, с 2002-01. Винтажная история origin'а `O` — тот же фит на месяцах `≤ O−1`: SA м/м всех месяцев `≤ O−1`. **Допущение A1:** `u(k)` доступно с релизом ИПЦ `k` (в `P_k`); публикация ЕМИСС может опаздывать — не проверено; если `u(k)` недоступно, срез не строится (NaN), а не заполняется.
2. **Календарь тарифных недель для `V1`.** Недельная точка (окно из 7 дней, заканчивающееся её датой) — тарифная, если окно содержит 1 января или 1 июля (стандартные даты индексации) либо 1-е число месяца `m ≤ k` с реализованным `u(m) ≥ 1,5 п.п.` (известно к `P_k`). Данные: месяцы с `u ≥ 0,9` в 2013–2026: июль каждого года (2013–2022, 2024, 2025), январь 2019 (2,59) и январь 2026 (1,55), декабрь 2022 (8,54); июль 2023 — `u = 0,0`. **Находка:** календарь `TARIFF_DATES` в `cpi_weekly_aggregate.py`/`weekly_core_proxy.py` (2022-07, 2023-07, 2024-07, 2025-07, 2026-10) расходится с данными (2023-07 — тарифа нет, 2022-12 пропущен) и здесь не используется; правка — отдельной задачей.
3. **`V2`.** К значению месяца 4-нед. индекса `v` (100 = без изменения) для **полных** месяцев: `v' = 100 + ((v − 100) − w·u_m)/(1 − w)` (без масштабирования: тарифный скачок внутри 28-дневного окна месяца учитывается целиком); неполный месяц `M0` — сырой.
4. **Выбор варианта.** Модель отбора — фиксированная `ElasticNetCV` (конфигурация B3 `cm.ENET_*`, импутация медианой и масштаб только по train), признаки: `sa4w_last` (`sa_4w` последнего полного месяца), `sa4w_partial` (nowcast-значение, NaN → медиана train), `y_lag1` (`T_SAX` месяца `O−1` из винтажной истории), `tariff_expected` (1, если окно `M0` содержит стандартную дату индексации). Цель — `T_SAX(O)` м/м (h1) из винтажной истории тестового origin'а; истина — окончательный `T_SAX(O)`. Walk-forward расширяющимся окном: train — строки с 2016-01 (min 24), purge — строки `O' ≤ O−1`; **тестовые origin'ы dev — 2018-01…2021-12 (48)**; holdout 2022+ не открывается. Метрика — RMSE; справочно — DM-HLN против `V0`, RMSE baseline «только `y_lag1`» и `weekly_naive` (`sa4w_partial` как прогноз). **Правило:** выбирается вариант с минимальным RMSE; `V1`/`V2` выбираются, только если их RMSE ниже `V0` не менее чем на 2 % относительно, иначе — `V0` (простейший). Выбор фиксируется отчётом до W4 и не пересматривается.

## 5. Фолды и протокол

- Walk-forward, расширяющееся окно; один origin в месяц (`P_k`); purge по §3; embargo 0 (purge уже убирает пересечение окон). Seed 20261018 (как #396), блочный бутстрап CI (блок 3, n 2000), DM-HLN, MDE, MCS (только справочно: инструмент в #396 не различал модели).
- Min train: Stage 1 — 24, Stage 2 — 60 (как `S_L09`) для длинной выборки.
- Общие фолды для сравниваемых моделей в ячейке; ячейка = таргет × h × окно.
- **Множественность.** Primary-ячейки Stage 1: `T_SAX` и `T_CORE` (h1); Stage 2: `T_SAX` h1 и `T_CORE` h1. Holm по двум ячейкам внутри каждого этапа (α = 0,05); h3/h6 — не gate, отрицательный контроль (h6) и описание (h3). Сравнение с CB_COMP (W5b) — отдельное семейство: h1/h3/h6 с поправкой Бонферрони (α = 0,05/3 для «лучше»/«хуже»), h2 и все 67 месяцев — справочно.
- Регрессионный gate: прежние числа `v2`/`v3` на `S_W22` под старым cutoff (спека #396 §7.1) должны воспроизводиться до любых выводов.

## 6. Предрегистрированный gate

### 6.1. Gate S1 (Stage 1, holdout 2022+; для каждой цели `T_SAX`, `T_CORE` отдельно)

Кандидат — лучшая из двух моделей Stage 1 по RMSE на dev-окне 2016–2021 (выбор до holdout). Условия на **общих фолдах holdout**:
1. RMSE(кандидат) < RMSE лучшего baseline из {B1, B2, B3, `weekly_naive`, `v3_direct@P_k`};
2. DM-HLN p < 0,05 (после Holm по двум целям) **и** 95 % CI ΔRMSE не содержит 0 против этого baseline;
3. RMSE(кандидат) < RMSE(`weekly_naive`) — недельный SA без модели не должен быть не хуже;
4. знак ΔRMSE отрицателен на 2016–2021 (dev) для тех же пар.

Решение: `pass` — условия 1–4 по обеим целям; `partial` — по одной цели; `fail` — иначе. `fail` Stage 1 останавливает Stage 2 (признак не добавляется).

### 6.2. Gate S2 (Stage 2; primary — `T_SAX` h1 и `T_CORE` h1, общие фолды 2018-01+, для каждой цели отдельно)

`promote` в смысле «кандидат для следующего этапа» (не production, не `forecast_log`), если одновременно:
1. RMSE(`v5_s1`) < RMSE лучшего из {`v3_direct@P_k`, `v4a_direct@P_k`} на общих фолдах, относительное снижение ≥ 5 %;
2. DM-HLN p < 0,05 (Holm по двум целям) и 95 % CI ΔRMSE не содержит 0 против этого baseline;
3. абляция: `v5_s1` лучше `v5_no_s1` (ΔRMSE < 0, DM p < 0,05 без поправки) — улучшение приходит от Stage 1, а не от случайных различий признаков;
4. знак ΔRMSE отрицателен на holdout 2022+ и в R1–R3 (§4 W6);
5. h6 (отрицательный контроль): нет пары «`v5_s1` vs B3» с p < 0,05 и ΔRMSE > 0; h3 — нет значимого ухудшения против `v3_direct`;
6. на полном тестовом окне 2016+ (с NaN-частью) RMSE(`v5_s1`) ≤ 1,02 · RMSE лучшего baseline — признак не ломает период без недельных данных.

Решения: `promote` — 1–6 по **обеим** целям; `iterate` — выполнено ≥ 1 условия по одной цели, но не все; `reject` — условия 1 и 2 не выполнены ни по одной цели; `incomplete` — недосчитаны ячейки/robustness. Формулировка всегда содержит «hybrid/proxy»: `T_SAX` — собственный ряд из реальных тарифов с допущением веса КУ, `T_CORE` — SA ЦБ; покрытие весов панели #364 39,3 % < 50 % (#76).

### 6.3. Сравнение с CB_COMP (W5b; отдельно от S2, не влияет на `promote`)

Для каждого `h ∈ {1, 3, 6}` и каждой нашей модели (`v5_wf`, `v5_frozen`) на 54 normal-месяцах, истина `TARGET_FULL` (при `misaligned` — также target-aligned модель):
- **лучше CB_COMP:** RMSE(наша) < RMSE(CB_COMP), DM-HLN p < 0,0167 (Бонферрони) и 95 % CI ΔRMSE без 0;
- **паритет:** 90 % CI отношения RMSE(наша)/RMSE(CB_COMP) целиком в [0,90; 1,10] (TOST, δ = 10 %, как #190) и DM p ≥ 0,05;
- **хуже:** RMSE(наша) > RMSE(CB_COMP), DM p < 0,0167;
- **не определено** — иначе (в том числе при недосчитанных ячейках).
Дополнительно приводятся ratio и Δ по h2 и по всем 67 месяцам, и строка с #190 (`bottomup_mp`: h1 ratio 1,07, h6 «ours worse») для сравнения с прежней попыткой. Ожидание до запуска: паритет маловероятен (у CB_COMP внутренняя панель МП по 87 кодам; #190 дал «не близок»); результат «не определено» или «хуже» публикуется так же, как «лучше».

## 7. Риски и стоп-условия

- **W1 не проходит parity** → ошибка порта; всё остальное блокируется.
- **Большие ревизии недельного SA** (RMSE `as-of − final` > 0,10 п.п.) → недельный SA в бэктесте всегда as-of; в отчёте — оценка шума; если п. 5 W1 не выполнен — недельный SA исключается как вход.
- **Недельный агрегат до 2016 не пригоден** (bias −0,27) → Stage 1 с 2016; до этого — NaN; не интерполировать.
- **Низкая мощность.** Holdout 2022+ — порядка 55 фолдов; эффекты меньше MDE не различимы; при `fail`/`iterate` это называется «нет доказательств», а не «нет эффекта».
- **Тарифные скачки** (июль 2024/2025, октябрь 2026) смещают оценки; `V1/V2` и R7 это проверяют; `T_SAX` зависит от допущения `w`.
- **Утечка через cutoff.** Единственная конвенция — §3; тесты на неделях и месяцах; regression на #396.
- **Stage 2 из #309 уже не прошёл Gate 2** — ожидание скромное: прошлые попытки ухудшали h1 на 6–10 %; повторение возможно, поэтому gate на улучшение, а не на «не хуже».
- **Несопоставимость с CB_COMP.** Разные редакции данных, разные определения SA (их X-13 ЦБ, наш X-13 по умолчанию), обучение CB_COMP один раз, внутренние МП по 87 кодам; сверка W3b измеряет первые два, `v5_frozen` снимает третье, четвёртое не устраняется — оно вынесено в формулировку «hybrid/proxy».
- **Архив.** 438 МБ, нужен R (`fst`) для `data_panel_bi_sa.fst`; без архива W3b/W5b = `incomplete`, остальные этапы не блокируются.
- **Стоп.** Если W4 `fail` — Stage 2 не строится; если W5 `reject` — отчёт с причиной, пункт закрывается как отрицательный результат.
