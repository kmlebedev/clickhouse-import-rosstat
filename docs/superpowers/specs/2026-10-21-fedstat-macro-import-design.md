## 1. Задача

Расширить существующий пакет `fedstat/` пятью импортёрами, которые забирают публичные макро-ряды ЕМИСС и пишут их в ClickHouse по стандарту пакета:

| Блок | Индикаторы | Таблица (предложение) | Частота |
|---|---|---|---|
| ИПП | `43046` (2000–2016), `57806` (2015–2026) | `fedstat_ipp` | M |
| Розница | `31066` (индекс), `31260` (оборот) | `fedstat_retail` | M |
| Сельхоз | `34128` (Q), `59001` (Y с 2017), `31062` (Y 1991–2016), `43337` (Y стоимость) | `fedstat_agri` | Q/Y |
| Инвестиции | `58089`/`58090` (2017–2026), `34129`/`40562`/`34475` (история) | `fedstat_investment` | Q/Y |
| ИПЦ | `31074` | `fedstat_ipc` | M |

**Почему один импортёр на блок, а не на индикатор.** Индикаторы блока — один домен источника, один транспорт и одна таблица; каждый индикатор получает отдельный `series`/`indicator_id`-ключ. Это осознанное отступление от стандарта §3.2 («один импортёр — один источник»), названное здесь по §1.5; альтернатива — 11 таблиц и 11 импортёров — увеличивает число шагов dagu и не даёт ничего, кроме дробления. Если ревью потребует строгого §3.2, блок делится на таблицы без изменения парсеров.

## 2. Источник и проверенные данные

Полный отчёт — [2026-10-21-fedstat-macro-indicators.md](../research/2026-10-21-fedstat-macro-indicators.md). Кратко:

- Источник: `https://www.fedstat.ru/indicator/<id>`, публичный, без логина.
- Транспорт: GET страницы → CSRF `token` + cookie → POST `https://www.fedstat.ru/indicator/downloadData.do?format=excel` (`application/vnd.ms-excel`, BIFF `.xls`).
- Excel содержит лист «Данные» (шапка: название, год, периоды, тип показателя; строки — измерения, колонки — периоды) и лист «Паспорт» (единица, периодичность, методология, последнее обновление).
- **Зависимость уже есть:** `github.com/shakinm/xlsReader v0.9.12` в `go.mod` (используется в `minfin/debt_stock_parse.go`); новый XLS-парсер не нужен.
- **Определение РФ:** до 2023 — `1688487` («Российская Федерация»), 2023+ — `1849012` («РФ без учёта новых субъектов»). Это разные совокупности, а не география. `58089` за 2023 г. отдаётся под старым кодом — импортёр обязан пробовать оба.
- **Rate limit:** серия POST без паузы → 503; рабочий режим — 10–30 с между запросами, backoff 30/60/120 с, при длительной серии — пауза ≈5 мин. `31074` — один POST на год (2002–2026), ~250–275 КБ XLS/год.
- **Объём research-выгрузки:** 14 индикаторов, 265 362 точки, 0 конфликтов; `31074` — 204 038 точек, 1 105 товаров/услуг, 2002-01…2026-09.

## 4. Модель данных

Все таблицы — `ReplacingMergeTree`, измерения — `LowCardinality(String)`, значения — `Float64`, дата — `Date` (начало периода). DDL — в `%s`-форме шаблона, канонический DDL добавляется в `ARCHITECTURE.md` §6.2 тем же PR, что и первый импортёр.

### 4.1. `fedstat_ipp`

```sql
okved_version LowCardinality(String),  -- 'OKVED1' | 'OKVED2'
okved         LowCardinality(String),  -- имя вида деятельности
indicator_type LowCardinality(String), -- 'м/м' | 'г/г' | 'с начала года'
region        LowCardinality(String),  -- 'Российская Федерация' | 'РФ без новых субъектов'
date          Date,
value         Float64
ENGINE = ReplacingMergeTree ORDER BY (okved_version, okved, indicator_type, region, date)
```

### 4.2. `fedstat_retail`

```sql
series        LowCardinality(String),  -- 'index' | 'turnover'
indicator_type LowCardinality(String), -- 'К предыдущему месяцу' | 'К соответствующему периоду предыдущего года' | 'Оборот розничной торговли'
subject       LowCardinality(String),  -- 'Всего' | 'Розничные рынки и ярмарки' | 'Торгующие организации'
region        LowCardinality(String),
period_type   LowCardinality(String),  -- 'M' | 'CUM'
period        LowCardinality(String),  -- подпись периода источника: 'январь', 'январь-март', …
date          Date,
value         Float64,
unit          LowCardinality(String)   -- 'процент' | 'миллион рублей'
ENGINE = ReplacingMergeTree ORDER BY (series, indicator_type, subject, region, period_type, period, date)
```

`period` — не украшение: у накопительных периодов дата начала одна (1 января), и без подписи `ReplacingMergeTree` схлопнул бы `январь-март`, `январь-июнь`, `январь-сентябрь` и `январь-декабрь` в одну строку. `indicator_type` различает два вида показателя `31066`; у `31260` он постоянный.

### 4.3. `fedstat_agri`

```sql
series        LowCardinality(String),  -- 'index_q' | 'index_y' | 'value_y'
activity      LowCardinality(String),  -- 'Сельское хозяйство' | 'Растениеводство' | 'Животноводство'
category      LowCardinality(String),  -- 'Хозяйства всех категорий' | ...
region        LowCardinality(String),
period_type   LowCardinality(String),  -- 'Q' | 'Y'
date          Date,
value         Float64,
unit          LowCardinality(String)   -- 'процент' | 'миллион рублей'
ENGINE = ReplacingMergeTree ORDER BY (series, activity, category, region, date)
```

### 4.4. `fedstat_investment`

```sql
series        LowCardinality(String),  -- 'index' | 'value'
indicator_id  LowCardinality(String),  -- '58089' | '58090' | '34129' | '40562' | '34475'
summary_type  LowCardinality(String),  -- 'Полный круг' | 'Всего'
region        LowCardinality(String),
period_type   LowCardinality(String),  -- 'Q' | 'CUM' | 'Y'
period        LowCardinality(String),  -- подпись периода источника: 'январь-июнь', 'II квартал', …
date          Date,
value         Float64,
unit          LowCardinality(String)   -- 'процент' | 'тысяча рублей' | 'миллион рублей'
ENGINE = ReplacingMergeTree ORDER BY (series, indicator_id, summary_type, region, period_type, period, date)
```

`period` обязателен по той же причине, что в §4.2: у `58089`/`58090` накопительные периоды одного года имеют одну дату начала, и без подписи они схлопнулись бы в одну строку.

### 4.5. `fedstat_ipc`

```sql
product       LowCardinality(String),  -- имя товара/услуги из Excel
indicator_type LowCardinality(String), -- 'К предыдущему месяцу'
region        LowCardinality(String),
date          Date,
value         Float64
ENGINE = ReplacingMergeTree ORDER BY (product, indicator_type, region, date)
```

## 5. Импортёры: источники и поведение

### 5.1. Общий транспорт

- `fedstatPostExcel(ctx, client, indicatorID, body)` — POST `downloadData.do?format=excel`, проверка `Content-Type`, `Content-Length`, первых байтов BIFF (`D0 CF 11 E0 A1 B1 1A E1`); HTML «Нет данных» — не ошибка парсера, а сигнал «комбинация невалидна».
- `fedstatPostForm` (SDMX) остаётся для 37426; новый импортёр использует Excel.
- Пауза между POST — параметр импортёра (по умолчанию 10 с; `31074` — 30 с), backoff 30/60/120 с, 3 попытки; при обрыве GET — пауза 300 с и повтор.
- Порядок `selectedFilterIds`: indicator → unit → регион → год → fixed-измерения → остальные. Тело собирается вручную, не `url.Values.Encode()` (стандарт §15.2).
- Регион: `regionsFor(year)` — для 2023+ сначала `1849012`, затем `1688487`; для старых — `1688487`.

### 5.2. ИПП (`ipp.go`)

- `43046`: годы 2000–2016, `3_{year}`, `57831_1688487`, `58071_1702101`, все 3 типа показателя; раскладка **long** (периоды — строки).
- `57806`: годы 2015–2026, оба кода РФ, все ОКВЭД2 (128–140 с данными), 3 типа; раскладка **matrix** (периоды — колонки).
- Дата — первое число месяца; `indicator_type` — из подписи; `okved_version` — из индикатора.
- No-op: `SELECT max(date) FROM fedstat_ipp FINAL`; если новых дат нет — `Imported 0 rows`. Первый прогон — полная история; повторный — только годы/месяцы после max(date) с перекрытием 1 месяц.

### 5.3. Розница (`retail.go`)

- `31066`: 2000–2026, оба кода РФ, 2 типа × 3 субъекта; тип «к предыдущему месяцу» — 12 месяцев (`period_type='M'`), тип «к соответствующему периоду предыдущего года» — месяцы и накопительные периоды (`M`/`CUM`); в ключ входят `indicator_type` и `period`.
- `31260`: 2000–2026, оба кода РФ, 3 субъекта, месячные + накопительные периоды; `period_type='M'`/`CUM`, `period` — подпись периода.
- No-op по `max(date)`; накопительные периоды не смешивать с месячными и не терять: `date` у них — 1 января, различает их `period`.

### 5.4. Сельхоз (`agri.go`)

- `34128`: 2018–2026, оба кода РФ, категории; Q.
- `59001`: 2017–2025, оба кода РФ, 3 деятельности × 4 категории; Y.
- `31062`: 1991–2016, РФ, 3 деятельности × 4 категории; Y.
- `43337`: 1990–2011 (фактический максимум; 2023/2024 не отдаются), РФ, 4 категории; Y.
- No-op по `max(date)`; `series` различает `index_q`/`index_y`/`value_y`.

### 5.5. Инвестиции (`investment.go`)

- `58089`: 2017–2026, оба кода РФ, ОКВЭД2 «Всего» `1692933`, свод `1704497` «Полный круг», все кварталы/накопительные периоды; `series='index'`.
- `58090`: 2017–2026, оба кода РФ, ОКВЭД2 «Всего», ОКФС «ВСЕГО» `1704559`, ОКОФ «ВСЕГО» `1704611`, свод `1704497`; `series='value'`, тыс. руб.
- `34129`: 2000–2024, годовой индекс; `40562`: 2005–2025, годовой объём, млн руб.; `34475`: 1998–2016, годовой объём, млн руб.
- **Нули `58090` 2024 Jan–Jun/Q2 = 0.0** сохраняются как в источнике, но в `series_meta` помечены «0.0 = нет публикации/не подтверждено»; в витрине не фильтруются (данные не искажаем).
- No-op по `max(date)`; `indicator_id` различает источники.

### 5.6. ИПЦ 31074 (`ipc.go`)

- 2002–2026, один POST на год, оба кода РФ, все 1 105 товаров/услуг, тип «К предыдущему месяцу», 12 месяцев.
- Раскладка matrix: `region`, `product` + 12 месячных колонок; парсер берёт имена продуктов из Excel (не SDMX-коды).
- No-op по `(max(date), count())`; 2026 — 9 месяцев (январь–сентябрь).
- Полный прогон — 204 038 точек, 1 105 продуктов, ~25 POST; первый импорт ~10–15 мин с паузой 30 с.

## 6. Каталог, витрины, гранты

- `series_meta.go`: каталог генерируется из справочников, разобранных из Excel (product/OKVED2/категории), с `title`, `unit`, `frequency`, `origin` (ID индикатора + коды фильтров), `description` (что измеряет, дата — начало периода, 2023+ — другое определение РФ). Для 31074 — 1 105 рядов; для 57806 — 128–140 × 3; для остальных — десятки.
- `source='fedstat'`, имена рядов с префиксом блока (`ipp/`, `retail/`, `agri/`, `investment/`, `ipc31074/`) — чтобы не столкнуться с 158 рядами `fedstat_weekly_prices`.
- `afterFedstatMacro(meta)` — `util.UpsertSeriesCatalog` + `util.CreateView` для пяти витрин:
  - `v_fedstat_ipp`, `v_fedstat_retail`, `v_fedstat_agri`, `v_fedstat_investment`, `v_fedstat_ipc` — long-форма `source, series, date, value` с комментариями таблицы и колонок.
- `GRANT SELECT` на пять витрин в `sql/mcp_kimi_reader.sql`; сырые таблицы агенту закрыты.
- `scripts/mcp_check.py`: непустота каждой витрины, число рядов каталога, отказ `497` на сырые таблицы.
