# P0.4a — веса ИПЦ 2026 из месячной публикации `ipc_spr`: импортёр `rosstat_cpi_spr`

> **Пункт:** `key-rate/phase-4-cb-comp-88-groups-live` P0.4a, зонтик [#419](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/419), issue [#569](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/569), `role:go`.
> **Статус:** протокол до кода. Критерий приёмки не пересматривается после результатов.
> **Связанные:** research по доступности книги 2026 (issue [#481](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/481)); импортёр книг — P0.4 [#479](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/479); стандарт [IMPORTER_PACKAGE_STANDARD.md](../../IMPORTER_PACKAGE_STANDARD.md) §14; [ARCHITECTURE.md](../../../ARCHITECTURE.md) §6.2/§6.3.

## 1. Гипотеза

Месячная публикация Росстата «Индексы потребительских цен и структура потребительских расходов по РФ (с 2025 г.)» (`ipc_spr_MM-YYYY.xlsx`) содержит ту же структуру потребительских расходов, что и годовые книги весов, по каждому месяцу. Значит, пока книги `CPR_*` недоступны (404 с 2026-11-13), веса 2026 года можно публиковать из неё — с отдельным провенансом, не подменяя книги.

Проверяемые следствия:

1. лист января 2026 совпадает с книгой групп 2026 по всем 742 кодам (сверка research, допуск 1e-9);
2. месяцы идут без пропусков, коды уникальны, веса и индексы проходят валидацию;
3. повторный прогон на том же файле — no-op, новый выпуск добавляет месяц;
4. витрина и каталог читаются агентом, сырая таблица закрыта.

## 2. Данные

- **Источник:** страница `https://rosstat.gov.ru/statistics/price`, ссылка `a[href*="ipc_spr_" i]` (имя файла несёт месяц и год, поэтому адрес берётся со страницы; регистр — через флаг `i`, как у книг весов).
- **Файл:** 2026-11-13 — `ipc_spr_09-2026.xlsx`, 901 812 байт, 22 листа: «Содержание» + `012025`…`092026`. Лист сентября 2025 **ошибочно назван `0922025`** — месяц и год берутся из заголовка листа «… за сентябрь 2025 г.», а не из имени.
- **Лист:** строки 3 — заголовок выпуска; 5–6 — шапка: `Наименование групп товаров (услуг) и товаров (услуг)-представителей`, `Локальный код группы / товара (услуги)-представителя`, `Структура потребительских расходов населения, в % к итогу`, `Индексы потребительских цен, в %` с тремя подписями (`к предыдущему месяцу`, `к декабрю предыдущего года`, `к соответствующему месяцу предыдущего года`); данные — с 7-й строки.
- **Объём:** 745 кодов в каждом листе 2025, 778 — в каждом листе 2026; сумма весов листа 986,65 / 989,43 (в файле все уровни: товары, группы, агрегаты). 9–11 строк на лист без одного или нескольких индексов — хранятся как NULL.
- **Семантика:** вес — проценты структуры, не доли; индексы — проценты (100 = без изменений).
- **Ревизии:** структура внутри года постоянна, кроме одной замены в 2026 (`9551` ОАЭ → `9547` Китай, 0,177 %), поэтому годовая структура — лист января. Файл месячный, кумулятивный (содержит всю историю с 2025-01).

## 3. Импортёр `rosstat_cpi_spr`

**Пакет `rosstat/`, файлы** `cpi_spr.go` (импортёр, DDL, витрина, каталог), `cpi_spr_parse.go` (разбор), `cpi_spr_test.go`, `testdata/cpi_spr.xlsx` (урезанная реальная книга), `testdata/price_page_spr.html`.

**Собственный `Import()`** (прецедент `rosstat_ppi_ved`): ссылка берётся со страницы; режим восстановления отклоняется (версия архива привязана к месячному URL). Дальше — полный цикл шаблона: DDL до сети → HEAD-префлайт → скачивание → батч → каталог/витрина → строка версии.

**Таблица** (`%s`-шаблон в коде; канон — `ARCHITECTURE.md` §6.2):

```sql
CREATE TABLE IF NOT EXISTS rosstat_cpi_spr (
    year       UInt16,
    month      UInt8,
    code       LowCardinality(String),
    name       LowCardinality(String),
    weight     Float64,
    index_prev Nullable(Float64),
    index_ytd  Nullable(Float64),
    index_yoy  Nullable(Float64)
) ENGINE = ReplacingMergeTree
ORDER BY (year, month, code);
```

Ключ `(year, month, code)` — месячный снимок структуры; индексы — `Nullable(Float64)`, потому что «нет индекса» ≠ 0 (у 9–11 строк на лист индекса нет).

**Витрина** `v_rosstat_cpi_spr` — широкая (`year, month, code, name, weight, index_prev, index_ytd, index_yoy`) с комментариями таблицы и всех колонок: `month` — месяц публикации, вес — проценты структуры, индексы — проценты (100 = без изменений), NULL — индекс не публиковался.

**Каталог.** Четыре ряда на код: `cpi-spr:<код>:weight` (unit `% (структура потребительских расходов)`), `:index_prev` (`%, к предыдущему месяцу`), `:index_ytd` (`%, к декабрю предыдущего года`), `:index_yoy` (`%, к соответствующему месяцу предыдущего года`); frequency `M`; title — название позиции + метрика; origin — файл, лист; description — годы, коды, правило месячного снимка.

**Идемпотентность.** HEAD-отпечаток файла (`util.HeadFingerprint`) + `util.PublicationKnown`/`SavePublication` (source `rosstat_cpi_spr`, name — имя файла) + `count() FROM rosstat_cpi_spr FINAL`: тот же файл и тот же счёт → no-op без скачивания; новый выпуск (новое имя) — полный импорт, который перезаписывает совпавшие месяцы по ключу и добавляет новый.

**Регистрация/обвязка:** `rosstat/importers.go` (12-я запись + энфорсер), 12-й шаг в хвосте `dagu/rosstat.yaml`, `GRANT SELECT ON default.v_rosstat_cpi_spr`, проверка в `scripts/mcp_check.py`, `docs/IMPORTERS.md`, `ARCHITECTURE.md` §2/§6.1/§6.2/§6.3/§7, `README.md`, `docs/LIMITATIONS.md`, строка P0.4a в `docs/ROADMAP_KEY_RATE.md`.

## 4. Валидация (fail-fast, до записи)

1. Листов-месяцев ≥ 2; месяц и год читаются из заголовка (фолбэк — имя листа `MMYYYY`); месяцы в окне идут без пропусков.
2. Кодов на лист ≥ 700; код уникален в листе; пустые строки пропускаются.
3. Вес — число 0 < w ≤ 100; сумма весов листа 900…1100 (в файле все уровни, ~987–989); выход за диапазон — ошибка «макет изменился».
4. Индексы, если заданы, — число 0 < x < 1000; `-`/пусто → NULL; нечисловой текст — ошибка.
5. Дубль кода с разными значениями — ошибка.

## 5. Гейт

| Условие | Как проверяется |
|---|---|
| Файл разобран, месяцы без пропусков | 12 офлайн-тестов: реальная урезанная книга (2 листа 2026), типографский лист `0922025`, отсутствие месяца, дубль, сумма, индексы NULL |
| Ссылка на странице | `TestCPISPRFindLink` на `price_page_spr.html` (флаг `i`, месячное имя) |
| Повтор — no-op | HEAD + `source_publications` + `count()` по таблице |
| Витрина и каталог | `AfterImport`; `make mcp-check` (витрина ≥700 кодов и ≥20 месяцев, каталог ≥3 000 рядов `cpi-spr:`, сырая таблица — 497) |
| Сборка | `make all`, `make docs-check`, `dagu validate dagu/rosstat.yaml` |
| Живой импорт | `make import STAT=rosstat_cpi_spr` дважды: строки и `Imported 0 rows` |

## 6. Stop-rules

- Сумма листа вне 900…1100 или кодов < 700 → импорт падает, данные не пишутся.
- Нет ни одного листа-месяца или месяц/год не читаются → падение до записи.
- Ссылка `ipc_spr_*` не найдена → падение до записи, а не «0 rows».

## 7. Границы

- Публикация — снимок того, что Росстат печатает в месячном выпуске; вес 2026 в ней совпадает с книгой групп 2026 на 742/742 кода, но книга товаров 2026 недоступна — прямое сравнение товарных строк невозможно (косвенно: 550/550 кодов 2025 в месячном листе совпали с товарной книгой 2025).
- Замена не отменяет P0.4: когда книги `CPR_*` вернутся, канонический источник весов — они; `ipc_spr` остаётся месячным провенансом и источником индексов по позициям.
- Индексы в таблице — публикация Росстата как есть, без пересчёта.

## 8. Воспроизводимость

```bash
make import STAT=rosstat_cpi_spr          # строки; повтор — no-op
make mcp-user && make mcp-check
go test ./rosstat/ -run CPISPR -v
```
