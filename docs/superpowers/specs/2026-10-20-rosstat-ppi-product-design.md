## 1. Контекст и границы

T1 дал сырой ИЦП Росстата по ВЭД (совокупный ряд «Промышленность»). T2 добавляет второй срез источника — **ИЦП по товарам и товарным группам (ОКПД2)** — и **официальные веса по ВЭД**. Это вход для T3 (versioned mapping `ОКПД2 → КИПЦ` и веса ИПЦ), T4 (SA-слой `ppi_sa`) и T5 (витрина `v_rosstat_ppi`, каталог, грант MCP).

В T2 **не входят**:

- mapping `ОКПД2 → КИПЦ`, веса ИПЦ и калибровка паритета (T3, #278);
- SA-слой `ppi_sa` (T4, #279);
- витрина `v_rosstat_ppi`, `GRANT SELECT`, MCP-проверка витрины (T5, #280);
- окончательное расписание «после 16-го рабочего дня», проверка свежести и приёмка dagu (T6, #281).

Две таблицы в одном PR — исключение, заданное самим issue #277: каждая таблица — отдельный импортёр, отдельный шаг `dagu/rosstat.yaml` и отдельная строка реестра.

### 1.1. Решения по объёму (согласованы с владельцем)

1. **Товарные ряды — только месячные листы 2021–2026, все четыре типа индексов** (`m/m`, `ytd`, `y/y`, `period`). Годовые срезы 1998–2025 **не импортируются**:
   - листы `1` (1998–2009) и `2` (2010–2016) не содержат колонки кода ОКПД2 — code-keyed таблицу из них не построить без изобретённых кодов или name-join (это уже mapping, зона T3);
   - лист `3` (2017–2025) содержит коды, но за 2021–2025 дублирует месячные листы, а 2017–2020 добавил бы только годовые ytd-точки. Владелец выбрал не импортировать годовые срезы в T2; ограничение фиксируется в `LIMITATIONS.md`, `IMPORTERS.md` и PR.
2. **Веса — только листы `3` и `4`** файла `vesa_2006-2026.xlsx`: 2017–2026, 38 кодов ОКВЭД2, две базы — `domestic` (внутренний рынок) и `domestic_export` (внутренний + экспорт). Листы `1`–`2` — ОКВЭД-2007, 43 кода, вне issue.
3. Витрина `v_rosstat_ppi`, grant и MCP-проверка витрины — T5. T2 публикует только `series_catalog` (отступление от §10.2 стандарта, как в T1).

## 4. Схема

Канонический DDL — в `ARCHITECTURE.md` §6.2; в коде — `%s`-форма шаблона `util.ClickHouseImport`.

### 4.1. `rosstat_ppi_product`

```sql
CREATE TABLE IF NOT EXISTS rosstat_ppi_product (
      date Date
    , okpd2 LowCardinality(String)
    , name LowCardinality(String)
    , index_type LowCardinality(String)
    , value Float64
) ENGINE = ReplacingMergeTree
ORDER BY (date, okpd2, index_type);
```

- `date` — последний день отчётного месяца UTC.
- `okpd2` — код из колонки «Код товара на основе ОКПД2»; имя колонки совпадает с research handoff `(date, okpd2, index_type)`.
- `name` — название товара из строки источника, которая дала значение. У 44 кодов название может меняться по годам; `name` — атрибут точки, не стабильный ключ. T3 нормализует названия сам.
- `index_type` — `m/m` | `ytd` | `y/y` | `period`.
- `value` — индекс, `%`; 100 = без изменения. `Float64`, не `Float32`.
- Ключ `(date, okpd2, index_type)` перезаписывает ревизию месяца; `ReplacingMergeTree` без версии — как у соседних рядов пакета.

### 4.2. `rosstat_ppi_weights`

```sql
CREATE TABLE IF NOT EXISTS rosstat_ppi_weights (
      year UInt16
    , code LowCardinality(String)
    , name LowCardinality(String)
    , weight_type LowCardinality(String)
    , value Float64
) ENGINE = ReplacingMergeTree
ORDER BY (year, code, weight_type);
```

- `year` — 2017…2026.
- `code` — код ВЭД (ОКВЭД2), включая агрегаты `B+C+D+E`, `B`, `C`, `D`, `E`, подклассы и классы.
- `name` — название строки источника.
- `weight_type` — `domestic` | `domestic_export`.
- `value` — доля, `%`.

**Исправление research handoff.** В research таблица весов описана ключом `(year, code)` и «вес domestic/domestic+export». У одного `(year, code)` два разных значения (например, 2017 `B`: 19.61 domestic и 23.08 domestic+export), поэтому ключ обязан включать `weight_type`. Это зафиксировано здесь, в `ARCHITECTURE.md` §6.2 и в PR.

## 5. Разбор

### 5.1. Общие правила

- `excelize/v2`, только `GetRows(..., excelize.Options{RawCellValue: true})`.
- Переиспользуются проверенные хелперы T1: `ppiVedValue`, `ppiVedCell`, `ppiVedNormalizeLabel`, `ppiVedMonth`, `ppiVedYear`, `ppiVedYearFromTitle` (они generic по смыслу; переименование в T2 не делается, чтобы не трогать T1).
- Пустая ячейка и маркеры `…`, `...`, `-`, `—`, `х`, `X` — **не точка**, а пропуск; нечисловой текст — ошибка с листом/строкой/колонкой; `NaN`/`Inf` — ошибка.
- `panic` запрещён; выход за границы среза — пустая ячейка.
- Даты — `time.Date(year, month+1, 0, 0, 0, 0, 0, time.UTC)`.
- Сноски источника снимаются с подписей месяцев (`октябрь1)`), годов (`20221)`), заголовков и значений (`97,511)` → 97,51).

### 5.2. Товарный лист

- Лист отбирается **по шапке** `Код товара` (нормализация регистра и пробелов), а не по номеру. Новые годы (`28`, `29`, …) подхватятся без правки кода.
- Год — из заголовка `в YYYY г.` (`ppiVedYearFromTitle`).
- Тип индекса — из строки 3:
  - `к предыдущему месяцу` → `m/m`;
  - `к декабрю предыдущего года` → `ytd`;
  - `к соответствующему месяцу предыдущего года` → `y/y`;
  - `за период с начала года, в % к соответствующему периоду предыдущего года` → `period`;
  - иначе — ошибка (неизвестная разметка, а не молчаливый пропуск).
- Колонка кода — колонка шапки `Код товара` (обязана быть ≥ 1); название — колонка 0; месячные колонки — после кода, распознанные по `util.MonthsToNum`. В шапке должны быть все месяцы листа (12 для 2021–2025, 8–12 для 2026).
- Блок товара:
  - строка с непустыми `name` и `code` (кроме заголовка) открывает блок и, если в ней есть значения, даёт точки — формат 2021–2023;
  - следующая строка `Российская Федерация` даёт точки тому же коду — формат 2024–2026 — и закрывает блок;
  - строки регионов и разделов без кода пропускаются.
- Дубли ключа `(date, okpd2, index_type)` с разными значениями — ошибка; одинаковые значения допустимы. Это ловит и переименования строк, и смену разметки.
- Для каждого листа с `Код товара`: ≥ 1 000 кодов, ≥ 1 строка `Российская Федерация` для 2024+; иначе ошибка.
- Глобальные проверки: все 4 типа дали точки; набор месяцев каждого типа непрерывен `2021-01 … max(date)` и совпадает между типами; ≥ 1 000 кодов; 0 точек — ошибка.

### 5.3. Веса

- Листы `3` и `4`; тип базы — по заголовку: содержит `и на экспорт` → `domestic_export`, иначе `domestic`.
- Шапка — строка с `Код` и ≥ 5 годами в колонках 2+; годы — regexp `(20\d{2})` (сноски `20221)` снимаются); код — колонка 1, имя — колонка 0.
- Пропуски — по общим правилам; строки без кода, `Код` и сноска `1)` пропускаются.
- Проверки: ровно 2 базы, по 38 кодов, 10 лет 2017–2026; единственный пропуск источника — код 38 за 2017 год (`-` в обеих базах); `B+C+D+E` = 100 ± 0.05 в каждом году/базе; дубль ключа с разным значением — ошибка.

## 6. Импортёры

### 6.1. `rosstat_ppi_product`

- Файлы `rosstat/ppi_product.go`, `rosstat/ppi_product_parse.go`; `Name()` = `TableName` = `rosstat_ppi_product`.
- `PPIProductStat` встраивает `util.ClickHouseImport`; override `Import()` вычисляет `DataUrl` со страницы и вызывает шаблон (как `PPIVedStat`).
- `ImportFunc` разбирает книгу и пишет одним батчем `PrepareBatch` → `Append` (с проверкой) → `Send`; на ошибке разбора — `Abort` (это делает шаблон).
- Режим `ARCHIVE_ACTION=restore` явно отклоняется: `DataUrl` вычисляется со страницы и содержит месяц, поэтому версия архива привязана к конкретному месячному URL.
- Точка контроля публикации: `PublicationCountPoints = SELECT count() FROM rosstat_ppi_product FINAL`. Файл месячный, шаг недельный → HEAD-префлайт, no-op без скачивания, `source_publications` и винтажный архив — общим механизмом шаблона.
- `AfterImport` публикует только каталог: `util.UpsertSeriesCatalog` с 5 308 записями `(okpd2, index_type)`.

### 6.2. `rosstat_ppi_weights`

- Файлы `rosstat/ppi_weights.go`, `rosstat/ppi_weights_parse.go`; `Name()` = `TableName` = `rosstat_ppi_weights`.
- `PPIWeightsStat` — тот же override `Import()` со ссылкой со страницы и отказом restore.
- `PublicationCountPoints = SELECT count() FROM rosstat_ppi_weights FINAL`; повтор — HEAD-префлайт и no-op; `source_publications` и архив.
- `AfterImport` публикует 76 записей каталога `(code, weight_type)`.

### 6.3. Каталог

- Товары: `series = "okpd2:<code>:<index_type>"`, `title` = последнее по дате название + тип, `frequency = "M"`, `unit` — по типу, `source = "rosstat"`.
- Веса: `series = "ved-weight:<code>:<weight_type>"`, `title` = название + база, `frequency = "A"`, `unit = "% (доля в структуре весов ИЦП)"`, `source = "rosstat"`.
- Каталог строится в `AfterImport` запросом к своей таблице: `argMax(name, date)` для товаров, `argMax(name, year)` для весов. Чистая функция построения `[]util.SeriesMeta` из строк запроса тестируется без ClickHouse.
- Контракт T1 «`series` == `name` точки» для товаров не выполняется: 1 273 кода не помещаются в человекочитаемый ключ, а T3 маппит по названиям. Это осознанное отличие; каталог даёт устойчивый технический ключ и последнее название.
