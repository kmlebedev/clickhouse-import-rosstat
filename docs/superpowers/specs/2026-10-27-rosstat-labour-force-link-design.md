## 1. Дефект

`make import STAT=rosstat_labour_force_mes` (и группа `key_rate_sources`) падает на поиске ссылки:

```text
labourForce: ссылка на trud-1_15-s.xlsx не найдена на https://rosstat.gov.ru/labour_force:
FindLink: по селектору "a[href$=\"trud-1_15-s.xlsx\"]" ссылка не найдена
```

Импортёр ищет на странице `https://rosstat.gov.ru/labour_force` файл `trud-1_15-s.xlsx` (issue #61). Дефект найден живым прогоном `make import STAT=key_rate_sources` 2026-10-21 (PR #333).

## 2. Разведка (2026-10-27, живые запросы)

| Проверка | Результат |
|---|---|
| Страница `https://rosstat.gov.ru/labour_force` | `HTTP 200`, 869 649 байт; карточка «Занятость и безработица» на месте |
| Ссылки карточки | `Trud-1_15-s.xlsx`, `trud_1_15-72.xlsx`, `Trud-2_15-72.xlsx`, `Trud-2_15-s.xlsx`, `Trud-3_15-72.xlsx`, `Trud-3_15-s.xlsx`. Ссылки `trud-1_15-s.xlsx` (строчная `t`) на странице больше **нет** |
| Причина падения | Регистр первой буквы имени файла: Росстат публикует `Trud-1_15-s.xlsx`. `goquery`/`cascadia` сопоставляют `[href$="…"]` с учётом регистра, поэтому строчный селектор не совпадает. Файл не пропал и не переехал — менялась только запись имени |
| Сам файл | `HEAD https://rosstat.gov.ru/storage/mediabank/Trud-1_15-s.xlsx` → `200`, `Content-Length: 345320`, `ETag: "6acf7350-544e8"`, `Last-Modified: Wed, 14 Oct 2026 12:19:28 GMT`. HEAD отдаёт ETag и Last-Modified — префлайт работоспособен |
| Печатная версия страницы | `https://rosstat.gov.ru/labour_force?print=1` — 95 305 байт, те же шесть ссылок с тем же регистром; источник прежней HTML-фикстуры |
| Книга | Листы `Содержание`, `1`…`7`; лист «5» — шапка в строках 5–6 (`Рабочая сила`, `в том числе`, три уровня; строкой ниже `занятые`/`безработные`), секции `2017`…`2026`, месяцы со сносками, сноски в строках 133–134. Данные до **августа 2026**: 116 месяцев × 6 рядов = **696** точек (прежняя редакция — 115 / 690) |
| Базовая линия dev-БД (`v_rosstat_macro`) | 690 строк, 6 рядов, `2017-01-31 … 2026-07-31` |
| Поддержка флага `i` | `cascadia v1.3.3` (`parser.go:411–420`, `selector.go:421–434`) разбирает CSS4-флаг регистронезависимости у `$=`, `*=` и `=`; нового кода не требуется |

## 3. Решение

Селектор ссылки становится регистронезависимым и по-прежнему привязан к полному имени файла:

```go
labourForceLinkSelector = `a[href$="trud-1_15-s.xlsx" i]`
```

Почему так:

- **Полное имя, а не хвост.** Хвост `1_15-s.xlsx` совпал бы и с будущим `Trud-11_15-s.xlsx` — это другой разрез возраста, и его значения молча легли бы под нашими именами рядов. С полным именем такая ошибка невозможна: чужой файл даёт «ссылка не найдена», а не чужие данные.
- **Флаг `i`, а не перечисление регистров.** Прецедент `rosstat/ipc_weeks.go:44` (два варианта в списке селекторов) здесь не годится: регистр источник уже менял, третья смена снова уронила бы импорт. Флаг покрывает любое написание `trud-1_15-s.xlsx` независимо от регистра.
- **Соседи карточки отсекаются** самим селектором: `trud_1_15-72.xlsx` (подчёркивание и другой диапазон), `Trud-2_15-s.xlsx`, `Trud-3_15-s.xlsx` не совпадают.
- **Иное переименование** (подчёркивание в `trud_1_15-s`, суффикс) даёт громкую ошибку «ссылка не найдена» — это осознанный fail-fast, а не регрессия.

Сообщение об ошибке уточняется: `labourForce: ссылка на trud-1_15-s.xlsx (любой регистр) не найдена на …` — оператор по тексту видит, что регистр ожидается любой.

## 4. Что не меняется

- Схема `rosstat_labour_force_mes (name, date, value)`, `ReplacingMergeTree`, `Float64`, имена шести рядов, единицы и привязка даты (последний день отчётного месяца) — без изменений.
- Разбор листа «5» (`parseLabourForce`), проверки fail-fast, поиск листа по имени, запись батчем — без изменений: разметка новой редакции книги совпадает с прежней.
- Точка контроля публикации (`PublicationCountPoints`), HEAD-префлайт, `source_publications`, винтажный архив — без изменений. Отпечаток версии включает URL и basename, поэтому первый прогон после фикса — полный импорт, повтор — no-op.
- `dagu/rosstat.yaml`, `Makefile`, `main.go`, реестр `rosstat/importers.go`, гранты `sql/mcp_kimi_reader.sql` — без изменений.
- `origin` каталога: имя файла приводится к текущему написанию (`Trud-1_15-s.xlsx`) с оговоркой, что регистр источник менял. Текст `origin` обновляется полным импортом (no-op-путь `AfterImport` не зовёт).

## 5. Тесты и фикстуры

- `rosstat/testdata/labour_force_page.html` — свежий фрагмент живой страницы (печатная версия, карточка «Занятость и безработица» целиком, 2026-10-27). Заглавная `T` в ссылке и соседние файлы карточки — то, на чём держится проверка селектора.
- `rosstat/testdata/labour_force.xlsx` — свежая редакция книги (2026-10-14, данные до августа 2026), урезанная «хирургией zip» по стандарту §11.2 до листов `Содержание` и `5`; значения листа «5» совпадают с исходным архивом.
- `TestLabourForceFindLink` — `FindLink` по константе находит `/storage/mediabank/Trud-1_15-s.xlsx` (строчный селектор + заглавная `T` в фикстуре доказывают регистронезависимость); фикстура проверяется на наличие соседа `trud_1_15-72.xlsx`; отрицательный кейс на странице без выгрузки сохраняется.
- Тесты разбора переводятся на новую редакцию: 696 точек, 116 месяцев на ряд, последняя дата `2026-08-31`, споты августа 2026, строка-замыкание — 132, сноски — 133–134.
- Новых синтетических фикстур не заводится (§11.1).

## 8. Риски

| Риск | Мера |
|---|---|
| Росстат снова сменит регистр | Флаг `i` покрывает любое написание; проверяется тестом на живой фикстуре |
| Росстат переименует файл иначе (подчёркивание, суффикс) | Громкая ошибка «ссылка не найдена» до записи в БД; новый follow-up, а не молча чужие данные |
| Первый прогон после фикса — не no-op | Ожидаемо: отпечаток версии включает URL/basename; полный импорт идемпотентен (`ReplacingMergeTree`) |
| Книга сменила разметку вместе с именем | Проверено: шапка, якоря, сноски и привязка дат те же; тесты на свежей фикстуре это фиксируют |
