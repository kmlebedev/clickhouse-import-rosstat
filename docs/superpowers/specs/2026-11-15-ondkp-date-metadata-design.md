# ОНДКП: дата объявления и безопасное обновление метаданных

Пункт key-rate/phase-4-ondkp-publication-refresh, #598, role:go. Depends on #597
принят merge ac40f61 (#599). Основание: research/2026-11-15-ondkp-publication-audit.md.

## Решение и граница доказательств

Новость14277 явно датирована 2 ноября 2022 года. Это подтверждённая дата
объявления итогового ОНДКП-2023. Исторические байты PDF неизвестны; совпадение
сегодняшнего PDF с SHA в БД не доказывает их доступность в день новости.
Поэтому реализуется NULL→date для **announcement_date**, а не механическая
подстановка в published_at. Это конкретизация условного go из аудита: дата
выбранной исторической версии остаётся непроверенной. published_at и прогнозы
при обновлении известного артефакта сохраняются. Полноценный PIT не заявляется.

## Данные

В существующий cbr_ondkp добавляются три колонки через идемпотентный ALTER:
- announcement_date Nullable(Date): дата из .news-info-line_date;
- announcement_url String: официальная новость;
- announcement_evidence String: JSON с версией1, observed_at UTC, artifact_sha256,
  news_sha256, release_page_sha256, release_page_url. Это снимок текущей ассоциации.

Канонический DDL — ARCHITECTURE.md, до кода. Движок/ключ прежние. Исторические
строки имеют NULL/пустую provenance. Витрина v_cbr_ondkp_forecast раскрывает эти
колонки плюс artifact_sha256 и publication_status: announcement_only /
legacy_unverified / unknown. Ни один статус не разрешает автоматический PIT.
Новые ряды/таблицы/гранты не вводятся, существующий каталог поясняет семантику.

## Алгоритм

1. Четыре проверенных соответствия release_year→news URL:2023/14277,
   2024/17174,2026/28050,2027/32941. Даты извлекаются из HTML, не захардкожены.
2. Строгий парсер одной .news-info-line_date (русские месяцы); ссылка новости
   должна вести на ожидаемую страницу выпуска, заголовок — ОНДКП нужного года.
   Нельзя брать дату из footer/первого совпадения или дату проекта из тела новости.
3. Страница выпуска выбирает PDF; проект on_project_* не получает дату финала.
   При заполнении метаданных повторно скачать PDF через util и проверить SHA
   и размер против сохранённых. Несовпадение/ошибка HTTP/разметки — ошибка,
   никакой записи данного выпуска. Время наблюдения — после успешной проверки.
4. Читать полную сохранённую строку реестра. При прежнем URL и отсутствии
   announcement_date обновить её копию; все старые поля сохранены. Новый выпуск
   использует существующий путь загрузки прогноза; изменение URL уже известного
   выпуска останавливает прогон до записи: требуется отдельная проверка версии.
5. Метаданные пишутся тем же батчем реестра, не отдельным INSERT по строкам;
   прогнозы для metadata-only пути не вставляются. Ошибки батча возвращаются.
6. Повторный прогон с заполненной provenance — no-op без скачивания PDF/новости.
   Это не мониторинг изменения байтов на том же URL; доказательства относятся
   к сохранённому SHA и времени наблюдения. Изменённый URL известного выпуска вызывает ошибку до записи.
7. Убрать перенос даты Вестника на другой артефакт по одному году и глобальный
   fallback даты страницы. Ранее заполненные published_at не переписываются.
8. После записи сверить счётчики прогнозов и записанные метаданные реестра.
