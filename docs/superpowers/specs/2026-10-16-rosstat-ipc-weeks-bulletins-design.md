## 1. Зачем

ML-трек nowcast месячного ИПЦ (фаза 4 контура ставки) ограничен глубиной недельных данных: `rosstat_ipc_weeks` начинается 2022-01-10, потому что табличный ряд (`Nedel_ipc.xlsx`) существует только с 2022 года. Разведка 2026-10-16 ([research/2026-10-16-cpi-weekly-pre2022-probe.md](research/2026-10-16-cpi-weekly-pre2022-probe.md)) установила: официальная недельная оценка ИПЦ существует с 01.01.2016 (методология, приказ № 519), публиковалась **HTML-бюллетенями** «Оперативной информации» до 2022 года, и часть этих бюллетеней физически доступна: живой буфер Росстата отдаёт 48 живых недельных выпусков (47 недель 2021 + неделя 22–28.12.2020), Wayback хранит 2017 (19 выпусков) и **все 4 недели 2021, удалённые из живого буфера** (найдены этой спекой, §2.2).

Буфер плавающий: он «переживал» годами по остаточному принципу, пару слотов уже потеряно — если его вычистят, восстановить 2021 будет нечем. Поэтому первым действием пункта выполнен **спасательный дамп** всех 71 документа с манифестом sha256 (шаг 0 плана), а импортёр работает **через винтажный архив шаблона** (стандарт §9.6): версия каждого документа сохраняется в объектном хранилище и `registry.jsonl` тем же прогоном.

Результат пункта: недельные ряды ИПЦ (агрегат + товары) за 2021 полностью (52 недельных точки, 26.12.2020…27.12.2021) и фрагменты 2017 (19 точек, март–сентябрь) — в той же семантике и под теми же именами товаров, что и `rosstat_ipc_weeks` (2022+), так что товарные ряды непрерывны через границу 2022 года.

### 2.4 Структура выпуска (одинакова у живых и Wayback-версий)

- **Титул**: «Об оценке индекса потребительских цен с X по Y <месяца> <года>» (встречается опечатка источника «ценс 25» — разбор заголовка терпим к пробелам/склейкам слов). Дата точки — **последний день периода** (конвенция «на конец недели», как у XLSX-колонок).
- **Шапка-таблица** («в процентах»): одна числовая строка «Индекс потребительских цен (оценка)» с пятью значениями — [к предыдущей дате регистрации, с начала месяца, среднесуточный прирост, справочно месяц, справочно год]. Дальше «Продовольственные товары», «Потребительские товары», «Услуги» — **заголовки повествовательных разделов без числовых строк** (проверено по 144.htm, 19.htm, 100.htm).
- **Детальная таблица** («Изменения цен»): строка = товар/услуга; колонки: [имя, недельное значение «к предыдущей дате регистрации», далее предыдущие недели, «к концу месяца», «к концу года»]. Первая колонка данных несёт метку даты («9 августа» в 2021, «22 мая» в 2017) — пригодна для сверки с заголовком. 2021 — ~103–106 строк товаров (источник декларирует «106 видов»), 2017 — ~40.
- Разметка Word-HTML: стековые шапки с colspan/rowspan, вложенные таблицы, возможны непарные теги, десятичная запятая, «…» как «данных не имеется», тире и сноски после таблицы («____», «Информация подготовлена…», «1) Оценка…»); в 2021 году строка-заметка может содержать знак «#», «№» — терминатор ищется по признаку, а не по позиции.
- **Имена товаров в бюллетенях — без единиц** («Говядина (кроме бескостного мяса)»), в `Nedel_ipc.xlsx` — с единицами («…, кг») → канонизация (§3.2).

## 3. Решения по дизайну

### 3.1 Таблица и импортёр

`rosstat_ipc_weeks_bulletins` (Name() = TableName; CLICKHOUSE_IMPORT_STAT и id шага dagu — то же имя, стандарт §7.1–7.2):

```sql
CREATE TABLE IF NOT EXISTS %s (
    name LowCardinality(String),
    date Date,
    percent Float64
) ENGINE = ReplacingMergeTree ORDER BY (name, date);
```

`Float64` — правило 5 AGENTS.md для новых ценовых значений (у legacy-соседа `rosstat_ipc_weeks` — `Float32`; витрина уже оборачивает в `toFloat64`, типы не смешиваются). Схема повторяет соседнюю таблицу — данные обеих таблиц не пересекаются по датам и складываются витриной в один ряд.

### 3.2 Ряды: агрегат + товары; канонизация имён кодом

1. **Агрегатный ряд** — `Индекс потребительских цен (недельная оценка)` (значение строки «Индекс потребительских цен (оценка)», колонка «К предыдущей дате регистрации цен»; 100 = без изменения). Это недельный ИПЦ, ради которого пункт и делается; в XLSX 2022+ агрегатной строки нет, поэтому ряд существует только за 2017/2021 — это фиксируется в `description`.
2. **Товары** — имена приводятся к каноническим (именам `ipcWeeksProducts`, §3.2.1) картой в коде `ipcWeeksBulletinsSeriesBySourceName` (стандарт §6.8: имена объявляет код, не заголовок источника). Карта построена по реальным фикстурам (144.htm/19.htm/100.htm); имена, которых нет в `ipcWeeksProducts`, получают собственные меты импортёра — их список тоже объявлен кодом.
3. Незнакомое имя строки — **warn и импорт под исходным именем** (§6.6, прецедент `ipcWeeksKnownProducts`): источник заморожен, но пере-нумерация буфера/дрейф разметки не должен молча терять строки. Тест «полнота карты» пинит покрытие всех имён фикстур (двусторонний контракт: разобрано == описано на фикстурах).

**Совместимость каталога.** Мета товара генерируется **одной функцией пакета**, которую используют оба недельных импортёра (`rosstat_ipc_weeks` и новый): текст меты для одного и того же товара идентичен, upsert идемпотентен и не зависит от порядка прогонов. `origin`/`description` товаров дополняются глубиной и провенансом (бюллетени 2021 + Wayback-фрагменты 2017 + XLSX 2022+), включая оговорку «в 2016–2020 непрерывного ряда нет».

### 3.3 Привязка даты и значение

- Дата точки = последний день периода из заголовка; сверяется с ожидаемой датой записи списка URL (§3.5) — несовпадение = ошибка (буфер пере-нумеровался / отдал чужой документ).
- Дополнительная сверка: метка даты в шапке детальной таблицы (первая колонка данных) должна совпадать с последним днём периода.
- Значение — первая колонка данных (недельный индекс); «…», пустая ячейка и ячейка с одним знаком «-» — не точка (§6.7); нечисло — ошибка (§6.4). Десятичная запятая.

### 3.4 Разбор (стандарт §6)

- HTML из cp1251 → UTF-8 через `golang.org/x/net/html/charset` (кодировка объявлена в `<meta>` страницы), дерево — `goquery`. Никакой сети внутри разбора (§6.1): функция принимает `[]byte`.
- Детальная таблица ищется **по признаку**: таблица, в шапке которой есть «к предыдущей дате регистрации» (нормализованный текст) и «Изменения цен». Строки данных — строки с непустым первым текстом, не совпадающим с якорями/терминаторами; терминаторы — строка из подчёркиваний, строки сносок («Информация подготовлена…», «Оценка индекса…», «1)»); пустой первый столбец — конец таблицы.
- Каждая ячейка берётся как текст после нормализации пробелов (§6.3 — по признаку, не по индексу; индекс колонки значений выводится из якоря шапки).
- Агрегат берётся из шапки-таблицы по якорю «Индекс потребительских цен (оценка)» (текст якоря может быть склеен из нескольких элементов — сравнение по нормализованной склейке).
- Fail-fast: заглушка (нет якоря/титула), нет детальной таблицы, нет строк данных, ноль точек — ошибка с URL и причиной (§6.4). `panic` запрещён (§6.5).

### 3.5 Цикл `Import()` — по прецеденту `cbr_dip_bulletin` (PR #69)

1. **Список URL — литералы кода**: 80 записей `{url, ожидаемая дата точки}` (приложения А/Б; девять найденных расширением 2026-10-16 — приложение В), отсортированные по дате; тест-инвариант: 48 живых + 4 Wayback-2021 + 25 Wayback-2017 + 3 Wayback-2020, даты строго возрастают внутри семейств, URL уникальны.
2. DDL → **гейт** `SELECT DISTINCT date FROM rosstat_ipc_weeks_bulletins FINAL` → для каждой недостающей даты — локальная копия `util.ClickHouseImport` (`DataUrl` + `BodyFunc`, §4) → post-check «даты этой недели записаны» → ошибки копятся `errors.Join`, сбой одной недели не отменяет остальные.
3. Все даты на месте → 0 строк, ни одного сетевого обращения, лог «все недели на месте»; производные (каталог, витрина) публикуются и на этом пути — `AfterImport` идемпотентен (каталог — upsert, витрина — `CREATE OR REPLACE`), поэтому сбой публикации прошлого прогона лечится следующим.
4. Самолечение: пропавшие из таблицы даты пере-качиваются (источник у Wayback стабилен; у живого буфера — если он ещё жив).

### 3.6 Точка контроля публикации и винтажный архив (стандарт §9, §9.6)

- `PublicationCountPoints = SELECT count() FROM rosstat_ipc_weeks_bulletins FINAL`, `PublicationSource` пусто (`Source == Name()`); объявление включает **архив версий** и строки `source_publications` (имя = basename URL, у Wayback-записей имя слота совпадает с живым — версии различает отпечаток, ключ `(source, name, fingerprint)`; ключ архива тоже включает отпечаток). Строк в `source_publications` — до 71: у части Wayback-выпусков HEAD отдаёт 429, и версия пишется без отпечатка или не пишется вовсе — это штатная деградация «полный импорт без записи версии» (факт приёмки 2026-10-16 — 56 строк), объект в архиве при этом есть.
- No-op повторного прогона держит гейт (как у `cbr_dip_bulletin`): `PublicationCountPoints` считает точки всей таблицы и у известной версии не сошёлся бы ни разу. Это **второй прецедент** отступления «объявление есть, решение о no-op — у гейта»; фиксируется в ARCHITECTURE §8 п. 13 и стандарте §9.6.
- Архив — общим механизмом шаблона: байты качает шаблон (`GetFileBytes`), тот же срез идёт в разбор и в `save` → объект + строка `registry.jsonl`. Сбой архива не роняет прогон, но отменяет строку версии (§3.6 плана-спеки архива). **Следствие гейта:** у уже записанной недели ни сбой архивации/строки версии, ни включение `ARCHIVE_BACKEND` задним числом следующим прогоном не доливаются — гейт видит неделю записанной и шаблон для неё не зовёт; лечение ручное: удалить строки даты этой недели из `rosstat_ipc_weeks_bulletins` и повторить прогон (ARCHITECTURE §8 п. 13).
- **Производные публикуются и на no-op-пути** гейта: `Import()` зовёт `AfterImport` и когда все даты на месте (идемпотентно: каталог — upsert, витрина — `CREATE OR REPLACE`), поэтому сбой публикации одного прогона лечится следующим, а устаревшие каталог/витрина не зависают до ручного вмешательства.
- Восстановление из архива (наполнение пустой БД) — инфра-пункт 1.2 `docs/ROADMAP_INFRA.md`, вне объёма.

### 3.7 Шаблон `util.ClickHouseImport`: новое поле `BodyFunc`

`BodyFunc func(body []byte, batch driver.Batch) error` — разбор **байтов** вместо xlsx-книги: шаблон качает файл шаблонным путём (архив, префлайт, строка версии — без отступлений), а разбор отдаёт HTML-парсеру. Изменения минимальны:

- новая ветка в `Import()`: `ImportFunc`/`BodyFunc` качают байты одинаково; различается только вызов разбора;
- guard проверки архива на no-op-пути расширяется до `(s.ImportFunc != nil || s.BodyFunc != nil)`: у BodyFunc-импортёра объект в архиве есть, и «версия известна, но объекта нет» должен приводить к полному импорту так же, как у ImportFunc;
- CrawFunc не трогается (его байтов шаблон не видит — стандарт §9.6, без изменений).

### 3.8 Производные: каталог и витрина (стандарт §10)

- `afterRosstatMacro(<мета>)`: каталог (агрегат + канонические товары; для общих товаров текст совпадает с XLSX-метой) + витрина.
- `v_rosstat_macro`: `UNION ALL SELECT 'rosstat', name, date, toFloat64(percent) FROM rosstat_ipc_weeks_bulletins FINAL`; таблица добавляется в `View.Tables`; комментарий витрины дополняется. Грант `kimi_reader` не меняется (сырая таблица агенту не выдаётся).

### 3.9 Расписание (стандарт §12)

Шестой шаг `dagu/rosstat.yaml` — **последним** (четверг 12:17, `type: chain`): падение нового шага не лишает данных уже проверенные пять; после первого прогона шаг всегда no-op по гейту, поэтому исчезновение буфера цепочку не ломает.

### 3.10 Тесты и фикстуры (стандарт §11)

Фикстуры — **реальные артефакты дампа**: `testdata/ipc_weeks_bulletins_144.htm` (живой 2021-08-09), `testdata/ipc_weeks_bulletins_2.htm` (новогодний 2021-01-11 — недельное значение во второй колонке данных), `testdata/ipc_weeks_bulletins_19_wayback.htm` (восстановленная 2021-02-01), `testdata/ipc_weeks_bulletins_100_2017_wayback.htm` (2017-05-22), `testdata/ipc_weeks_bulletins_stub.htm` (заглушка). Тесты: число точек/дат и spot-значения (агрегат + 2–3 товара каждого семейства), полнота карты канонизации, двусторонний контракт каталога, fail-fast (заглушка, сдвиг даты, отсутствие якоря, нечисло), инварианты списка URL, харнесс `appendRecorder`.

## 4. Отступления от стандарта

Нет. Особенности, не являющиеся отступлением: no-op держит гейт по данным (прецедент `cbr_dip_bulletin`, стандарт §9.6), транспорт — шаблонный (`GetFileBytes` + `BodyFunc`), архив — общий механизм шаблона.

## 6. Границы скоупа (явно вне пункта)

## 7. Риски

1. Буфер исчезнет до/во время приёмки → дамп уже снят (шаг 0 плана), Wayback-адреса стабильны, гейт делает повторные прогоны независимыми от живого источника.
2. Нестабильность Wayback (наблюдались 503/офлайн) → дедлайн `fileTimeout` 120 с, ошибка с URL; живой источник — основной для 48 выпусков.
3. Дрейф разметки 2017 vs 2021 → фикстуры обоих семейств, поиск по якорям.
4. Коллизии basename (82.htm, 100.htm, 111.htm, 130.htm у 2021 и 2017) → версии и объекты архива различает отпечаток.
5. Семантическое равенство с XLSX-колонками не проверяемо на пересечении недель → канонизация имён и единый смысл «к предыдущей дате регистрации» остаются единственной точкой сопоставления; ограничение фиксируется в отчёте.
