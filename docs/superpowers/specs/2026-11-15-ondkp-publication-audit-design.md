# ОНДКП: происхождение даты публикации

Пункт `key-rate/phase-4-ondkp-publication-audit`, issue #597, role:research,
Depends on #593/#594 (оба merged). Основание — P0 handoff аудита каналов.

## Вопрос и границы

Можно ли безопасно заполнить NULL published_at для уже сохранённых прогнозов
ОНДКП, используя текущий код и официальный сайт? Нужно отделить дефект гейта
обновления от отсутствия/неоднозначности исходных дат. Проверяется main 90e0484,
локальный dev через read-only MCP и публичные страницы ЦБ. Прод-код, DDL,
данные, модель, свежесть других рядов и forecast_resolve не меняются.

## Критерии

1. Снимок всех 66 прогнозных строк и группировка 2020–2027 с датами/URL.
2. Для страниц 2021–2027: HTTP evidence, ссылка выбранного PDF, наличие двух
   селекторов текущего парсера, отдельно дата обновления страницы.
3. Различить дату карточки, выпуска Вестника, новости, изменения страницы и
   фактическую доступность конкретных байтов PDF. Совпадение года не достаточно.
4. Проверить связку официальной новости о выпуске как альтернативного источника.
   Текущий URL не доказывает историческую неизменность байтов. Не объявлять PIT.
5. Решение go/no-go для механического догона и контракт отдельного Go-пункта:
   ключи/даты/транспорт/идемпотентность/ошибки/фикстуры/приёмка.
6. Независимое source-review (sol) и финальное review (terra), docs-check.

## Артефакты

`docs/research/2026-11-15-ondkp-publication-audit.md`, компактные JSON evidence
в `docs/research/ondkp-publication-audit/`, регистрация страницы, LIMITATIONS,
владеющий roadmap и GitHub. Повторные HTTP-пробы +1/+3 дня остаются будущими:
одна проверка не доказывает стабильность. Сохраняются только минимальные
метаданные и локаторы; права на массовую перепубликацию PDF не устанавливаются.
