# Task 4 (#424): недельный ИПЦ на h1 поверх `combo3` — протокол

> **Пункт:** `key-rate/phase-4-cb-comp-88-groups-live`, зонтик [#419](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/419), Task 4 [#424](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/424), `role:ml`. Базовая спека пункта — [2026-10-30-cb-comp-88-groups-live-design.md](2026-10-30-cb-comp-88-groups-live-design.md) (§12 цель `T_LIVE`, §15 протокол Task 3). База Task 4 — `combo3` из PR [#437](https://github.com/kmlebedev/clickhouse-import-rosstat/pull/437) (спека [2026-10-31-cb-comp-h1-bs-combo-design.md](2026-10-31-cb-comp-h1-bs-combo-design.md)).
> **Статус:** протокол записан и закоммичен **до** кода и до любых результатов Task 4. Отдельная спека, а не §17 базовой, — чтобы не конфликтовать с открытым PR #435 (§16 базовой спеки). Решения владельца 2026-10-31: база — `combo3`; арена 2022+ — ежемесячный expanding walk-forward; два co-primary кандидата (`combo3_wk`, `wk_mix`) с Holm α = 0,025.

## 1. Зачем

`combo3` (Task 9) закрыл разрыв на h1 к CB_COMP до 1,035, но у CB_COMP нет недельного ИПЦ, а у нас он есть. Росстат публикует недельный ИПЦ за месяц M к началу M+1 (точка `date + 2`), месячный ИПЦ за M — 10–16-го M+1. В контуре CB_COMP cutoff — 8-е M+1 (конвенция `late`): полный месяц M по неделям уже известен, месячная цель — ещё нет. Task 4 проверяет, улучшает ли это недельное знание h1-прогноз поверх `combo3`:

1. на уровне 88 групп — недельные признаки в компонентные CatBoost;
2. на уровне агрегата — смешивание `combo3` с недельной оценкой.

Оценка — на окне CB_COMP (справочно) и на walk-forward 2022+ (основная арена). Гейт — только на 2022+.

## 2. Что известно до протокола (и поэтому не доказывается заново)

- Недельные ряды: `v_rosstat_macro` (`source='rosstat'`, `frequency='W'`) — 148 товарных + агрегат «Индекс потребительских цен (недельная оценка)», 2009-04-06…2026-10-19, 49 513 точек. Плотность: 2016–2019 — 41–47 рядов/год, 2020 — 99, 2021–2026 — 109–114.
- Task 3 #236: 118 из 148 рядов сопоставлены с весами 2024 (все — листовые позиции уровня 7), покрытие весов 39,299 %; остальные 30 — дженерики/снятые позиции.
- `combo3` на окне CB_COMP (normal-54, h1, frozen): RMSE 0,1643265897, отношение к CB_COMP 1,034768; `live_cb` 0,1894308455; `bs_econ16` 0,1667057796; `bs_rozn16` 0,1689297155 (Task 9, прогон `2ffb7e8`).
- Контур CB_COMP использует `cm.cutoff_for(origin)` в конвенции по умолчанию (`late` — 8-е `M+1`) и origin `M−(h−1)`; для h1 origin = M. Месячный ИПЦ M к cutoff недоступен (`available_from_mes` — конец M+1), недельные точки M доступны.
- Разведка маппинга (2026-10-31, словарь 2024): 118 листьев → 112 в 88 группах, 52 группы с недельными данными, 36 групп без (NaN), 6 листьев вне 88 групп. Это ожидание, R11 проверяет его в прогоне.

## 3. Данные и as-of

- **Недельные ряды** читаются `cpi_public_panel_audit.load_weekly()` (только чтение ClickHouse; `kimi_reader`/env-путь скрипта). Агрегат — `WEEKLY_AGGREGATE`.
- **Маппинг 148 → 88.** Matching — `cpi_public_panel_audit.match_mode(products, weights_2024, "extended")` (как Task 3): имя недельной позиции → `weight_code` листа. Лист → группа: `dictionary_cpi.xlsx` 2024, для каждого из 88 кодов `model.xlsx` берутся его листья (уровень 7), обратное отображение «лист → глубочайший предок среди 88 групп». Использовать `l3` нельзя: у 88 групп уровни 3 (58), 4 (19), 5 (3), 7 (8). Вложенных групп среди 88 нет (проверено), поэтому лист принадлежит не более чем одной группе.
- **Веса.** Листовые веса по годам 2016–2024 (`cb_comp_groups_panel.load_leaf_weights`); для месяца M — год M, вне окна — ближайший (`cpi_weekly_component_panel.weight_year_for`). Знаменатель группы — `cb_comp_bottomup.load_weights` + `weight_for_month`. Недельное изменение группы — взвешенное среднее по покрытым позициям с ренормировкой на покрытый вес; `NaN`, если покрытых позиций нет; 0 вместо изменения не подставляется.
- **As-of.** Точка недельного ряда доступна `date + 2`. Cutoff строки — `cm.cutoff_for(origin)` в конвенции контура CB_COMP (по умолчанию `late`, 8-е `M+1`). Для h1 origin = M; используются только точки с `date + 2 ≤ cutoff`. Месячный ИПЦ M к cutoff недоступен. При `late` полный месяц M по неделям доступен — это и есть информационное преимущество; вариант `publication` (9-е M, частичный месяц) считается только диагностикой R12 и в моделях не участвует.
- **NaN-политика.** Группа/месяц без покрытых недельных позиций: `wk_g_mtd = NaN`, `wk_g_cov = 0,0`. Признак не заменяется нулём и не импутируется вне CatBoost (CatBoost обрабатывает NaN нативно).
- **Винтажей нет** (ЕМИСС/Росстат ревизий недельных рядов не публикует): используется последняя редакция; это ограничение, а не PIT.

## 4. Признаки (предзарегистрированы)

На каждую группу и месяц M:

- `wk_g_mtd` — накопленное недельное изменение за месяц M: для каждой сопоставленной позиции — лог-прирост по периодам, пересекающимся с `[начало M, конец M]` (`cpi_weekly_aggregate._periods/_log_and_days`, индекс делится по дням), взвешенно листовым весом; `(exp(Σ w·log / Σ w) − 1)·100` по позициям с покрытием > 0.
- `wk_g_cov` — `Σ w` покрытых позиций / вес группы (доля веса группы, покрытая недельными точками в месяце).

Агрегат (официальный ряд «Индекс потребительских цен (недельная оценка)»):

- `wkagg_mtd`, `wkagg_4w`, `wkagg_cov` — `cpi_weekly_aggregate.wkagg_features(points, M, cutoff)`.

Других недельных признаков нет; окна и периоды не подбираются. `month` остаётся категориальным признаком CatBoost.

**R12 (диагностика, не модель).** Те же признаки при `publication`-cutoff (частичный месяц M): покрытие, корреляция и MAE между `late` и `publication` вариантами по группам/месяцам 2010–2026. Цель — показать, сколько даёт более поздний cutoff; в выборе модели не участвует.

## 5. Модели (равные веса, без тюнинга)

| id | определение |
|---|---|
| `live_cb` | Task 3/9 без изменений: 88 компонентных CatBoost на дефолтах (`seed 20261018`), МП по листам у групп с BSU |
| `live_cb_wk` | тот же CatBoost, но к признакам группы добавлены `wk_g_mtd`, `wk_g_cov` |
| `bs_econ16`, `bs_rozn16` | OLS статьи Task 9: `T_LIVE[1](t) ~ X(t−1) + T_LIVE[1](t−1)`, окно 2016+, переобучение на каждом месяце, `t ≤ M−1` |
| `combo3` | `(live_cb + bs_econ16 + bs_rozn16)/3` — база |
| `combo3_wk` | `(live_cb_wk + bs_econ16 + bs_rozn16)/3` — co-primary |
| `wk_agg` | OLS с константой на `[wkagg_mtd, wkagg_4w]`, цель `T_LIVE[1]`; NaN → медиана train, пустая колонка → 0 |
| `wk_mix` | `0,5·combo3 + 0,5·wk_agg` — co-primary |

Справочные строки: `live_cb`, `bs_econ16`, `bs_rozn16`, `wk_agg`; frozen-варианты `combo3`/кандидатов на 2022+.

Веса комбинаций равные и не подбираются. `bs_*` обучаются на нашей цели `T_LIVE` (как Task 9), оцениваются на `TARGET_FULL` (окно CB_COMP) и `T_LIVE` (2022+).

## 6. Окна и режимы

**Окно CB_COMP (справочно).** Train — целевые месяцы 2010-03…2018-12 без выбросов статьи (2014-12…2015-03), test — 2019-01…2024-07, normal-54 (без 2020-04 и 2022), истина `TARGET_FULL`, origin `M−(h−1)`. Модели — frozen, точно как Task 9. Служит R10 и справочной таблицей; в гейт не входит.

**Арена 2022+ (primary).** Месяцы 2022-01…2026-09 (57), истина `T_LIVE[1]` (спека §12). Для каждого тестового M — **ежемесячный expanding walk-forward**: train — целевые месяцы `t` с 2010-03 по `M−1` включительно, без шоков (2014-12…2015-03, 2020-04, 2022-01…12), с непустой целью; признаки строки `t` — на origin `t`; строка M в train не входит. Минимум 20 строк на группу (как в Task 2/3). Перефит на каждом M для `live_cb`/`live_cb_wk` и `wk_agg`; `bs_*` переобучаются на каждом M по своему правилу (`t ≤ M−1`).

Все кандидаты арены 2022+ пересчитываются в одном режиме; frozen-строки на 2022+ — справочно. В walk-forward CatBoost `thread_count = 1` (детерминизм при параллельных группах); frozen-строки — дефолты репозитория.

## 7. Оценка и гейт

Метрики: RMSE, MAE, bias; `cpi_v4_leaderboard.compare_pair` (DM-HLN с поправкой на h, 95 % блочный бутстрап ΔRMSE, MDE); MCS 90 % по всем кандидатам; подпериоды 2022 / 2023–24 / 2025–26. На окне CB_COMP — классификация W5b (`cpi_two_stage_cb_comp.compare_to_cb`) против CB_COMP и попарно против `combo3`; справочно.

**G10 (предзарегистрирован).** На арене 2022+, h1, на общих 57 месяцах хотя бы у одного из двух co-primary кандидатов (`combo3_wk`, `wk_mix`):

1. 95 % CI ΔRMSE против `combo3` целиком ниже 0;
2. Holm по двум кандидатам: `min(1, 2·p_min) < 0,05` (эквивалент `p_min < 0,025` для победителя).

MCS 90 % — справочно, в гейт не входит. G10 не пройден — недельные признаки не входят, отрицательный результат публикуется; `combo3` остаётся базой.

## 11. Что не доказывается

- **Не PIT/винтажи.** Недельные ряды — последняя редакция; ревизий нет. SA групп — вся выборка, как у `combo3`; честный as-of SA — robustness Task 2, здесь не повторяется.
- **Не паритет с CB_COMP по SA ЦБ.** На 2022+ истина — наша `T_LIVE`, а не `TARGET_FULL` (после 2024-07 её нет); на окне CB_COMP — справочная таблица.
- **Не production.** `forecast_log`, shadow/canary, промоушен и h3/h6 не заявляются.
- **Маппинг фиксирован словарём 2024.** Смена состава/названий недельных позиций — риск поддержки; 36 групп без недельных данных и 6 листьев вне 88 групп фиксируются в отчёте.
- **Cutoff `late` ≠ `publication`.** Основной вариант — `late` (как `combo3`); цена альтернативы — только R12.
- **Выбор после просмотра.** Признаки и кандидаты выбраны по постановке #424, а не по результатам; веса равные, тюнинга нет. Независимое подтверждение — только live-период после 2026-09.
