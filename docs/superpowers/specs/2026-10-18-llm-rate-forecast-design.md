## 1. Пробел

Фаза 4 роадмапа закрыла фундаментальный контур (`scripts/key_rate_model.py`) и ML-трек nowcast'а ИПЦ (`scripts/cpi_nowcast.py`). Третий, **экспериментальный** трек — независимый прогноз LLM: модель получает срез данных на дату и разметку каналов резюме ЦБ и выдаёт распределение по классам `{cut, hold, hike}` и ожидаемый шаг в базисных пунктах. Такой прогноз нужен как независимый cross-check статистического и рыночного контуров; он **не заменяет** их и не публикуется как единственный источник вероятностей.

Пункт зависит от #127: без записи в `forecast_log` прогноз нельзя сверить с фактом. Пока #127 не готова, скрипт обязан работать полностью (снимок, промпт, три повтора, артефакты) и **подготовить** payload для ingest, не изобретая второй путь записи.

## 2. Цель и объём

**Цель:** `scripts/key_rate_llm_forecast.py` — офлайн-воспроизводимый экспериментальный трек: снимок данных as-of, промпт фиксированной версии, три вызова OpenAI-совместимого провайдера, медианный прогноз, JSON- и markdown-артефакты, payload для `forecast_log`.

**В объёме:**

- снимок as-of через `ch_query` из `scripts/extrapolation_aisc.py` — тот же транспорт, что у `key_rate_model.py` (маскирование секретов, HTTP-порт 8123);
- входы: ключевая ставка, ИПЦ (месячный м/м Росстата и базовый ИПЦ ЦБ), инфляционные ожидания, мониторинг предприятий ЦБ, рыночный контур (KEYRATE, ОФЗ, RUONIA), консенсус макроопроса, последнее доступное резюме обсуждения и его каналы;
- строгий as-of: ни одна точка с датой позже даты среза не попадает в промпт; для месячных и рыночных рядов применяются консервативные лаги публикации;
- промпт-редакция `prompt_version = 1`, фиксированный system-промпт и детерминированная JSON-сериализация снимка;
- OpenAI-совместимый `POST <base>/v1/chat/completions`: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `temperature=0`, `response_format=json_object` с фолбэком на провайдера без поддержки JSON-режима;
- три независимых повтора, медиана вероятностей и шага, разброс между повторами;
- валидация схемы: сумма вероятностей 100 %, неотрицательные числа, допустимый шаг, непустые `rationale`/`risks`;
- артефакты `key_rate_llm_forecast.json` и `key_rate_llm_forecast_report.md`, gitignore;
- режим `--log` — только payload для ingest #127 (файл `key_rate_llm_forecast_log_payload.json`), без записи в ClickHouse;
- офлайн-тесты с замоканным транспортом и Makefile-цель `key-rate-llm-forecast`;
- README, ARCHITECTURE, docs/CONFIGURATION.md, docs/DEVELOPMENT.md, docs/LIMITATIONS.md, роадмап.

**Вне объёма:**

- запись в `forecast_log` и резолвер `cbr_rate` — issue #127;
- прямое включение LLM-прогноза в ансамбль статистического контура;
- DM/encompassing-тесты против статистического и рыночного контуров — первая публикация по правилу [KEY_RATE_PUBLICATIONS.md](../../KEY_RATE_PUBLICATIONS.md) §2 п. 10;
- тюнинг промпта по результату заседания, few-shot примеры из будущих данных;
- новые таблицы, витрины, DAG-шаги и расписание: трек запускается вручную;
- batch API провайдера, стриминг и tool-calling.

## 3. Входные данные и правила as-of

Единица наблюдения — ближайшее заседание Совета директоров ЦБ строго позже даты среза. Дата среза (`data_asof`) — дата прогона или явный `--as-of YYYY-MM-DD`. Все запросы читают витрины `v_*` и получают строки не позже `data_asof`; дополнительно Python применяет правила доступности.

| Блок | Источник | Правило доступности |
|---|---|---|
| Ключевая ставка | `v_cbr_macro`, `series='cbr_key_rate'` | в день действия лага нет |
| RUONIA (RUONIA, p25/p75, объём) | `v_cbr_macro`, `cbr_ruania_*` | `date + 1` |
| Курс USD | `v_cbr_macro`, `cbr_currency_usd` | `date + 1` |
| Базовый ИПЦ ЦБ, м/м | `v_cbr_macro`, `series='Базовый ИПЦ'` | конец месяца `M+1` (M — отчётный) |
| Наблюдаемая и ожидаемая инфляция, г/г | `v_cbr_macro` | конец месяца `M+1` |
| ИПЦ Росстата, м/м (общий, продовольствие, непродовольственные товары, услуги) | `v_rosstat_macro` | конец месяца `M+1` |
| Ценовые ожидания, ИБК, загрузка мощностей, кредитные условия, персонал | `v_cbr_survey` | конец месяца `M+1`; квартальные — по дате точки |
| Консенсус: ставка и ИПЦ на 2026–2027 | `v_cbr_mo_br`, `*_median` | волна + 7 дней (консервативно; публикация через 2–6 дней) |
| Рынок KEYRATE | `v_keyrate_expectations` | `date + 1`; серия выбирается по `decision_date` целевого заседания |
| Кривая ОФЗ | `v_ofz_curve` | `date + 1` |
| Резюме ЦБ, сигнал, каналы | `v_cbr_mp_summary`, `v_cbr_mp_summary_channels` | `published <= data_asof`; каналы — только `method='regex'` |

Правила зафиксированы в коде (`available_from_*`) и проверяются тестами: точка, опубликованная позже даты среза, не участвует, даже если её период раньше.

**Каналы резюме.** В промпт попадают только детерминированные регрекс-строки (`method='regex'`) последнего опубликованного резюме: `channel`, `kind` (`risk_pro`/`risk_dez`/`prose`), `text`. LLM-слой каналов не используется: он зависит от модели и редакции промпта, а вход экспериментального трека должен быть воспроизводим без второго LLM-вызова.

**Рыночный контур.** Для целевого заседания берётся последняя серия KEYRATE с `decision_date = meeting_date`; если точной серии нет — ближайшая серия с `decision_date > meeting_date` и пометка `exact_match=false`. В снимок входят `settle`, `expected_change_bp`, `volume`, `openposition`: ликвидность обязательна рядом со вменённой ставкой (KEY_RATE_PUBLICATIONS §9).

**Консенсус.** Берутся медианы последней доступной волны: `key_rate_avg_2026_median`, `key_rate_avg_2027_median`, `cpi_dec_2026_median`, `cpi_dec_2027_median`. Если волна не опубликована к дате среза, блок помечается `null`, а в отчёте — «нет обновления».

**Версия снимка.** `data_version` — первые 12 hex SHA-256 от канонической JSON-сериализации снимка (`sort_keys=True`, UTF-8). Одинаковые данные и дата среза дают одинаковую версию.

## 4. Промпт-редакция 1

`prompt_version = 1`. Системный промпт фиксирован в коде и содержит:

- роль: аналитик ДКП, прогноз решения ЦБ на ближайшем заседании;
- запрет использовать знания после даты среза и домысливать отсутствующие данные;
- требование вернуть **строго один JSON-объект** без текста вокруг:
  ```json
  {"probabilities":{"cut":<0..100>,"hold":<0..100>,"hike":<0..100>},"expected_step_bp":<число>,"rationale":"<2–5 предложений>","risks":["<риск>", "..."]}
  ```
- сумма вероятностей — 100 (валидатор нормализует и проверяет);
- `expected_step_bp` — ожидаемый шаг ставки в базисных пунктах относительно текущей ставки (`cut < 0`, `hold = 0`, `hike > 0`);
- `rationale` и `risks` — по-русски, без инвестиционных рекомендаций;
- вероятности должны быть согласованы с `expected_step_bp` и с классами решения.

User-промпт — детерминированный JSON снимка с явными единицами и датами точек. Промпт не содержит примеров ответа, привязанных к конкретному заседанию, и не меняется по результату события.

## 5. Выходная схема и валидация

Ответ провайдера приводится к структуре:

```json
{
  "probabilities": {"cut": 0.0, "hold": 100.0, "hike": 0.0},
  "expected_step_bp": 0.0,
  "rationale": "...",
  "risks": ["...", "..."]
}
```

Валидация одного ответа:

- ровно три ключа `cut`/`hold`/`hike`, значения — конечные числа `>= 0`;
- сумма строго больше нуля; нормализация к 100 % с точностью до 0,01 п.п. и корректировкой остатка на наибольшей компоненте;
- `expected_step_bp` — конечное число в диапазоне `[-1000, 1000]` б.п.;
- `rationale` — непустая строка; `risks` — непустой список непустых строк (строка приводится к списку из одного элемента), не более 10 рисков;
- неизвестные поля игнорируются, отсутствие обязательного — ошибка формата.

Ответ, не прошедший валидацию, считается ошибкой формата: повтор запроса (до двух попыток на один из трёх повторов). Отказ провайдера (не-2xx), обрыв транспорта и таймаут — не ошибка формата: прогон завершается ошибкой, потому что подставлять медиану из меньшего числа повторов при отказе провайдера нельзя без явного решения владельца.

## 6. Три повтора и агрегация

- `REPEATS = 3` — три независимых запроса при `temperature=0`.
- Каждый повтор даёт нормализованный вектор вероятностей и шаг.
- Медиана: по каждому классу — медиана трёх (или двух) значений; медианный вектор повторно нормируется к 100 %.
- `expected_step_bp` — медиана шагов.
- Разброс: `probability_spread_pp` — `{cut, hold, hike}` как `max − min` по валидным повторам; `expected_step_spread_bp` — `max − min` шагов. Разброс публикуется в JSON и отчёте.
- `rationale`/`risks` берутся из репрезентативного повтора: минимальное L1-расстояние вектора вероятностей до медианного вектора, тай-брейк — ближайший шаг, затем первый по порядку.
- Если валидных повторов меньше двух — прогноз не строится, артефакты прошлого прогона удаляются, код возврата 1. Один валидный повтор — недостаточно для медианы и разброса.

JSON детерминирован при одинаковых данных, ответах провайдера и дате среза: ни времени запуска, ни путей, ни случайных идентификаторов. `samples` содержит только числа и служебные флаги; `rationale`/`risks` повторов не дублируются.

## 8. Режим `--log` и ingest #127

`--log` **не пишет в ClickHouse** и не создаёт второй путь записи. Режим формирует `key_rate_llm_forecast_log_payload.json` — канонический payload для будущего ingest-endpoint #127:

```json
{
  "status": "pending_ingest_127",
  "todo": "TODO(#127): ingest endpoint is not implemented; wire this payload to forecast_log when ready",
  "row": {
    "metric": "cbr_rate",
    "forecast_date": "2026-10-18",
    "target_date": "2026-10-23",
    "predicted": 13.875,
    "actual": null,
    "error_pct": null,
    "error_bp": null,
    "probabilities": {"cut": 62.0, "hold": 33.0, "hike": 5.0},
    "expected_step_bp": -12.5,
    "model": "...",
    "prompt_version": 1,
    "data_version": "..."
  }
}
```

`predicted` — ожидаемая ставка после заседания (`current_rate + expected_step_bp / 100`), `error_bp` — будущая колонка резолвера #127 (ошибка в базисных пунктах, не `error_pct`). Payload печатается в stdout и пишется в файл; путь и статус сообщаются в консоли. Явный TODO живёт и в коде, и в файле, и в спеке: молчаливая запись в `forecast_log` при отсутствующем endpoint была бы нарушением контракта §7 KEY_RATE_PUBLICATIONS.

## 9. Ошибки и деградация

- Нет `LLM_BASE_URL`/`LLM_API_KEY`/`LLM_MODEL` — `warn` с **именами** переменных, код возврата 1 (это ручной экспериментальный прогон, а не ежедневный импортёр: молчаливый зелёный результат без прогноза вводил бы в заблуждение). Секреты не печатаются.
- Нет будущего заседания, нет ставки, нет обязательного входа — код 1 с прямым сообщением; артефакты прошлого прогона удаляются.
- Отказ провайдера/таймаут — код 1 с компактной ошибкой `http status <код>: <фрагмент тела ≤512 байт>`; текст проходит через `mask`-подобную функцию не требуется, ключ уходит заголовком `Authorization: Bearer`, но тело всё равно режется до фрагмента.
- Ответ не JSON/не та схема — до двух попыток на повтор; после — прогноз не строится. `max_tokens=8192`: reasoning-модели (наблюдение на `deepseek-flash`) тратят бюджет на `reasoning_content`, и при малом пределе `message.content` приходит пустым; если `content` пуст, ответ берётся из `reasoning_content` и всё равно проходит валидацию, а если пусты оба — ошибка формата с `finish_reason` в тексте (без содержимого ответа).
- ClickHouse недоступен — транспорт поднимает `ClickHouseError`; скрипт печатает ошибку и возвращает 1, не поднимая сервер.

## 10. Тесты

`scripts/key_rate_llm_forecast_test.py` — офлайн, `unittest`, без pytest и без сети:

- `ch_query` и HTTP-вызов замоканы; env-переменные LLM/ClickHouse удаляются на время набора;
- нормализация вероятностей: сумма 100, отрицательные/NaN/нулевая сумма отвергаются, округление не теряет 0,01;
- схема: отсутствие ключа, не-число, шаг вне диапазона, пустой rationale, пустые risks — ошибки;
- три повтора: ровно три вызова при успехе; медиана и разброс на заранее заданных ответах; репрезентативный rationale;
- ошибка формата: повтор запроса; два провала подряд — повтор выпадает; меньше двух валидных — прогон падает;
- отсутствие env: `MissingEnvError` до сетевого вызова, имена переменных в сообщении, значения не печатаются;
- as-of: точки позже даты среза не попадают в снимок; месячная точка с неистёкшим лагом не попадает;
- JSON-артефакт детерминирован (два вызова с одинаковыми данными и ответами дают одинаковый текст), `probabilities` суммируются к 100, `model`/`prompt_version`/`data_version` на месте;
- `--log`: payload не пишет в ClickHouse, содержит `metric='cbr_rate'`, `target_date`, `predicted`, TODO #127;
- провал не оставляет устаревших артефактов.

`make key-rate-llm-forecast` поднимает `uv run --python 3.12`; тесты запускаются той же командой с `ARGS="--self-test"`? Нет: тесты — отдельный прямой вызов `python3 scripts/key_rate_llm_forecast_test.py` (конвенция репозитория), цель Makefile — прогон скрипта. В `docs/DEVELOPMENT.md` — команда запуска тестов.

## 12. Риски и ограничения

| Риск | Митигация |
|---|---|
| LLM недетерминирована даже при `temperature=0` | три повтора, медиана и публикуемый разброс; `prompt_sha256` и `data_version` в артефакте |
| Провайдер не поддерживает `response_format=json_object` | один фолбэк без JSON-режима; ответ всё равно валидируется и повторяется при ошибке формата |
| Провайдер отвечает медленно | таймаут 180 с на запрос, общий прогон — не больше трёх повторов |
| Промпт «подглядывает» в будущее | as-of правила и тесты; резюме — только `published <= data_asof`; рыночные ряды — `date + 1` |
| Промпт тюнится по факту заседания | `prompt_version` фиксируется; изменение — новая редакция и новая строка журнала, а не правка старой |
