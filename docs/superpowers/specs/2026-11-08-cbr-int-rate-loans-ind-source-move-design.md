## 1. Зачем

Пункт 4.2 №8 закрыт 2026-11-03 тремя импортёрами, в том числе `cbr_int_rate_loans_ind` —
ставки по кредитам физлицам (16 рядов, 2 096 точек, 2014-01-30 … 2025-12-30). На 2026-11-08
ЦБ перенёс раздел: `https://www.cbr.ru/statistics/pdko/int_rat/` отдаёт **404**, рабочий
адрес — `https://www.cbr.ru/statistics/bank_sector/int_rat/`. Импортёр при этом качает
прежний `loans_ind.xlsx`, замороженный на 2025-12, — отсюда отставание ряда на 11 месяцев.

Разбор нового файла текущим парсером невозможен: он проверяет ровно две группы по 8 сроков
и падает с «источник изменил структуру листа». Юрлица (`cbr_int_rate_loans`,
`loans_nonfin.xlsx`) не затронуты: файл обновлён 07.10.2026 (данные по 2026-08), отставание —
публикационный лаг ЦБ ≈2 месяца, а не дефект.

### Разметка листа

- Строка 3, колонка A — `% годовых` (якорь шапки, как раньше).
- Строка 4 — группы: `B4:I4` «в разрезе сроков», `J4:K4` «по всем срокам» (merged; текст
  стоит только в первой колонке группы).

- Данные: 10 × 152 ячейки, все — числа; пустых ячеек, литеральных `-` и `0` нет.

## 3. Решения по дизайну

### 3.1 URL и имена рядов

- `DataUrl` → `https://www.cbr.ru/vfs/statistics/pdko/int_rat/loans_ind_new.xlsx`. Ссылка
  по-прежнему прямая и без даты, поэтому шаблон `util.ClickHouseImport` качает те же байты,
  что разбирает, и сохраняет версию в винтажном архиве (стандарт §9.6).
- 8 прежних имён не меняются — это идентификаторы в `series_catalog` и `v_cbr_macro`;
  переименование оборвало бы ряды (стандарт §7.3/§7.4).
- Два новых имени: `Всего (кредиты физлицам): по всем срокам` и `Автокредиты: по всем срокам`.
  Разрез назван явно («по всем срокам»), потому что ось новой группы — срок, а не тип кредита
  (дословное «все виды кредитов» для автокредитов читалось бы как другая совокупность).
  Префикс `Всего (кредиты физлицам): ` сохраняет отличие от рядов `cbr_int_rate_loans` (юрлица)
  в общем `source='cbr'`.
- 8 прекращённых имён `Автокредиты: <срок>` остаются как есть: их точки (944) уже в таблице,
  `v_cbr_macro` их отдаёт, и переименование оставило бы историю без описания.

### 3.2 Разбор шапки — объявленная раскладка 10 колонок

Модель «две группы × 8 сроков» больше не описывает лист: население перестало быть свойством
группы (в группе «по всем срокам» две разные совокупности — все кредиты и автокредиты).
Вместо неё — таблица колонок в порядке листа, у каждой три факта:

```go
type cbrIntRateLoansIndColumn struct {
    Series string // имя ряда, объявляет код (стандарт §6.8)
    Group  string // подпись группы в строке 4 — позиционный якорь
    Header string // ожидаемый текст заголовка в строке 5 — проверка структуры (§6.4)
}
```

Раскладка собирается из трёх объявлений, чтобы тексты не дублировались: `cbrIntRateLoansIndTerms`
(8 сроков — единственная запись их текстов, используются и в заголовке, и в имени),
префикс `Всего (кредиты физлицам): ` для сроковых рядов и `cbrIntRateLoansIndAggregate`
(2 записи `{Header, Series}`).

Алгоритм `cbrIntRateLoansIndColumns` (магических индексов нет, §6.3):

1. якорь — первая строка, где колонка A равна `% годовых`;
2. строка групп — первая после якоря, где найдены обе подписи в порядке раскладки
   (`cbrIntRateLoansIndGroupStarts`, без изменений); `base` = колонка первой подписи;
3. **новая проверка**: для каждой группы `starts[g]-base` равен смещению её первой колонки
   в раскладке — вставка/удаление колонки внутри листа ловится, а не читается как сдвиг
   значений под правильными именами;
4. строка заголовков = строка групп + 1 (границы проверяются, §6.5);
5. каждая из 10 колонок: `cbrIntRateLoansIndHeaderKey(ячейка)` == ключ `Header`; расхождение —
   ошибка «источник изменил структуру листа» с подписью группы, фактическим и ожидаемым
   текстом; имя ряда берётся из `Series`;
6. инвариант `base+len(names) <= len(headerRow)` сохраняется — разбор данных считает колонку
   как `base+i`.

Разбор данных (`cbrIntRateLoansIndImport`) по логике не меняется: пропуск пустой ячейки,
литерального `-` и `0` («данных не имеется», §6.7), отказ на нечисле и NaN/Inf, завершение
на сноске `*…`, ошибка при нуле точек. В текущем файле пропусков нет — правила остаются
защитой на будущее.

### 3.3 Каталог `series_catalog` — 18 рядов

| Группа | Рядов | `origin` | `description` |
|---|---|---|---|
| живые (B…K) | 10 | `cbr.ru/vfs/statistics/pdko/int_rat/loans_ind_new.xlsx, лист «ставки_руб», группа «…», срок «…»` / `колонка «…»` | уровень, а не темп; пропуск ≠ ноль; файл месячный, на снимке 08.11.2026 данные до 2026-08 (лаг источника ≈2 месяца); с 01.02.2026 автокредиты без разбивки по срокам, продолжение — `Автокредиты: по всем срокам` |

Каталог собирается из раскладки (10) и списка сроков (8) в двух переменных —
`cbrIntRateLoansIndLiveMeta` и `cbrIntRateLoansIndRetiredMeta`; `AfterImport` получает

контракт §11.4 применим только к живым рядам, замороженные проверяются отдельно (они есть
в таблице и в витрине, поэтому обязаны остаться и в каталоге — правило 11 AGENTS.md).

### 3.4 Точка контроля публикации

`PublicationCountPoints` не меняется: `SELECT count() FROM cbr_int_rate_loans_ind FINAL`.
Счётчик считает всю таблицу, а не прогон: на текущей БД после импорта — 2 464 точки
(1 520 новых + 944 замороженных), на чистой после импорта нового файла — 1 520. Шаблон
записывает фактическое число после импорта, поэтому no-op работает в обоих случаях.

Строку версии в `source_publications` удалять не нужно: в ключ версии входит basename URL,
а он сменился на `loans_ind_new.xlsx` — префлайт увидит неизвестную версию и сделает полный
импорт. Если первый прогон всё же скажет no-op — удалить строку по ключу
`cbr_int_rate_loans_ind` и повторить (стандарт §9.7).

### 3.5 Тесты и фикстура

- Фикстура — новый файл целиком (`cbr/testdata/loans_ind_new.xlsx`, 71 КБ, 6 листов);
  §11.2 разрешает коммитить книги в десятки килобайт как есть. Прежняя фикстура удаляется:
  после смены URL её не читает ни один тест.
- Ожидания разбора: 10 рядов × 152 месяца = 1 520 точек, 2014-01-30 … 2026-08-30; spot-значения
  из файла (28.04 / 18.31 / 19.06 / 15.32 за 2014-01-30, 18.25 / 18.65 за 2026-08-30);
  ветки fail-fast: нет `% годовых`, нет подписи группы, заголовок срока не совпал,
  заголовок агрегата не совпал, метка не месяц, значение не число/NaN.
- Двусторонний контракт каталога — по живым 10; отдельный тест — 8 прекращённых описаны,
  их origin указывает на ретро-файл, description называет прекращение и ряд-продолжение.
- Мутации живой фикстуры (пропуск ячейки, короткая строка) — по новым номерам колонок B…K.

### 3.6 Документация и MCP-проверки

- `scripts/mcp_check.py`: две проверки вместо одной — живые ряды по origin
  `%/int_rat/loans_ind_new.xlsx%` (ровно 10) и прекращённые по origin `%/int_rat/loans_ind.xlsx%`
  (ровно 8; экранированные `_` не дают шаблону совпасть с `loans_ind_new.xlsx`).
- `docs/IMPORTERS.md`, `ARCHITECTURE.md` (§4, §6.1, §6.3, §7), `README.md`,
  `docs/ROADMAP_KEY_RATE.md` — числа 18/10/8, новый URL, приёмка.

## 5. Отступления от стандарта

Нет. Второй файл источника (ретро-`loans_ind.xlsx`) импортёр не читает — это решение
зафиксировано в §6, а не отступление от §9.6: версия скачанного файла архивируется штатно.

## 6. Границы скопа (явно вне пункта)

- Чтение старого `loans_ind.xlsx` для воспроизведения 944 замороженных точек: они уже в БД,
  а восстановление из архива новой версии даст 1 520 точек — осознанный размен (второй файл

  отдельные пункты.
- Пересчёт/миграция имён рядов не выполняется: имена стабильны (§7.3).
