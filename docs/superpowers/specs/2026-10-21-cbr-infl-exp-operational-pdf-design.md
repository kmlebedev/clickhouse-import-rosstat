# Спека: оперативная точка инфляционных ожиданий из PDF «Оперативная справка» (`cbr_infl_exp_op`)

**Дата:** 21 октября 2026 г.
**Пункт роадмапа:** вне роадмапа, по прямому указанию владельца (прецедент — PDF-выпуски `cbr_mt_forecast`, [ROADMAP_KEY_RATE.md](../../ROADMAP_KEY_RATE.md) §4.2 №19).
**План:** [2026-10-21-cbr-infl-exp-operational-pdf.md](../plans/2026-10-21-cbr-infl-exp-operational-pdf.md).
**Статус документа:** спека дизайна. Нормативные правила не пересказываются — ссылки вида «стандарт §6.4» ([IMPORTER_PACKAGE_STANDARD.md](../../IMPORTER_PACKAGE_STANDARD.md)).

---

## 1. Зачем

Книга `Infl_exp_ГГ-ММ.xlsx` со страницы `https://www.cbr.ru/statistics/ddkp/inflationary_expectations/` — единственный источник рядов `cbr_infl_exp` («наблюдаемая инфляция», «ожидаемая инфляция»). Но ЦБ публикует PDF «Оперативная справка» (`inFOM_ГГ-ММ.pdf`) **раньше книги**: на 2026-10-21 свежий XLSX — `Infl_exp_26-09.xlsx` (данные по сентябрь), а PDF — `inFOM_26-10.pdf` с октябрьской точкой на рис. 1.

Контур ключевой ставки (`v_key_rate_dashboard`, ML-модели, публикации) получает инфляционные ожидания с задержкой в 1–3 недели. Нужен шаг, который забирает **только оперативную точку** из свежего PDF и ничего не делает, если файл не обновился.

## 2. Источник и проверка (живая, 2026-10-21)

| Артефакт | Свежий | Содержимое |
|---|---|---|
| `Infl_exp_26-09.xlsx` | 2026-09 | «Данные для графиков», медианы по 2026-09 |
| `inFOM_26-10.pdf` | 2026-10 (опубликован 21.10.2026) | рис. 1 «Прямые оценки годовой инфляции», точка за 2026-10 |

PDF 26-10 — векторный документ Aspose с текстовым слоем. `pdftotext -bbox -enc UTF-8 -f 1 -l 1 - -` отдаёт XHTML с координатами каждой подписи:

```xml
<word xMin="494.11" yMin="273.97" xMax="504.19" yMax="283.53">14,5</word>
```

Ось рис. 1 — 34 подписи `янв.24 … окт.26` с шагом ≈12.48 pt. Разбор всех колонок по координатам даёт 33 исторических месяца, **совпадающих с `cbr/testdata/infl_exp.xlsx` до 0.1 п.п.** (сен.26: 15,1 / 14,2 / 10,7 = 15.0898 / 14.1617 / 10.748). Значения за 2026-10: **14,5 / 13,2 / 12,2** (наблюдаемая / через год / через пять лет).

Порядок подписей в колонке сверху вниз на всей истории: наблюдаемая ≥ ожидаемая через год ≥ ожидаемая через пять лет.

Старые PDF (`inFOM_26-09.pdf`, `inFOM_25-10.pdf`) — сканы без текстового слоя; `pdftotext` на них даёт пустой/почти пустой вывод.

## 3. Решение

### 3.1. Импортёр `cbr_infl_exp_op` (отдельный шаг)

- `Name()` = `cbr_infl_exp_op`; `TableName` = `cbr_infl_exp` — **общая таблица двух писателей**: XLSX-импортёр (`cbr_infl_exp`, точные значения) и PDF-импортёр (оперативная точка, 0.1 п.п.). Ключ `ReplacingMergeTree (name, date)` даёт «последняя запись побеждает»: пришедшая позже книга перезаписывает округлённое значение.
- `PublicationSource` = `cbr_infl_exp_op` — своя строка версии в `source_publications` (xlsx-версии того же файла не смешиваются с pdf).
- `PublicationCountPoints` = `SELECT count() FROM cbr_infl_exp FINAL` — архив PDF и строка версии на полном пути.
- `BodyFunc` — байты PDF → `pdftotext -bbox` → чистый разбор → 2 строки батчем.
- `AfterImport` = `afterCbrMacro(cbrInflExpSeriesMeta)` — каталог и `v_cbr_macro` после точек.
- Собственный `Import()` (прецедент `cbr_form101`):
  1. DDL `cbr_infl_exp` (общая константа с xlsx-импортёром);
  2. `util.GetPage` + `util.FindLink` по селектору `a.versions_item[href*="inFOM_"][href$=".pdf"]`;
  3. месяц — из имени файла (`inflExpArchiveRe`);
  4. **гейт** `SELECT max(date) FROM cbr_infl_exp FINAL`: если `месяц-14 <= max(date)` — `Imported 0 rows`, без скачивания;
  5. иначе `DataUrl` и стандартный цикл `util.ClickHouseImport` (префлайт → скачивание → архив → каталог → версия).

### 3.2. Разбор (чистая функция, без сети и exec)

1. Регекс `<word xMin="…" yMin="…" xMax="…" yMax="…">текст</word>`.
2. Подписи оси — `^(янв|фев|мар|апр|май|июн|июл|авг|сен|окт|ноя|дек)\.(\d{2})$`; выбрать верхнюю группу по y с ≥ 6 подписями (рис. 1; у рис. 2 ось ниже), дедуп по x (1 pt), шаг по крайним.
3. Значения — `^\d{1,2},\d$` выше оси (`y < yMin` оси); в полосе рис. 1 других десятичных чисел нет.
4. Привязка к колонкам `round((xCenter-x0)/step)`, внутри колонки сортировка по y (сверху вниз).
5. Fail-fast: нет текстового слоя/оси/значений; в последней колонке не ровно 3 значения; нарушен порядок `v0 ≥ v1 ≥ v2`; месяц последней подписи ≠ month из имени файла; значение вне `(0, 100)`.
6. Импортируются первые два значения; дата — 14-е число месяца (существующая конвенция: 1-е число книги + 13 дней).

### 3.3. exec-обёртка

`exec.CommandContext(ctx с таймаутом 2 мин, inflExpPdfTool, "-bbox", "-enc", "UTF-8", "-f", "1", "-l", "1", "-", "-")`, stdin — байты; до `exec` — проверка сигнатуры `%PDF-` в первых 1024 байтах (WAF/HTML-заглушка); ошибка запуска называет `poppler-utils`. `inflExpPdfTool` — переменная пакета ради тестов.

## 4. Границы

- Схема `cbr_infl_exp`, имена рядов, `v_cbr_macro`, `v_key_rate_dashboard`, гранты и `sql/mcp_kimi_reader.sql` **не меняются**.
- Пятилетний ряд из PDF **не импортируется** (решение владельца); используется только как индикатор порядка подписей.
- История из PDF не переписывается: пишется только месяц новее `max(date)`.
- В dagu — новый шаг **в хвосте** цепочки: сбой оперативного PDF не лишает данных проверенные шаги.

## 5. Тесты

Офлайн, `pdftotext` не вызывается: фикстура — дословный `-bbox`-вывод страницы 1 PDF 26-10.

1. Фикстура → 34 колонки, последняя `2026-10` и `14.5 / 13.2 / 12.2`.
2. Все 33 исторические колонки против `cbr/testdata/infl_exp.xlsx` (сверка до 0.1) — доказательство координатной привязки и назначения рядов.
3. Пустой XHTML (старые сканы) → ошибка «нет текстового слоя», не `0 rows`.
4. Колонка без третьего значения / нарушенный порядок / месяц оси ≠ имя файла → ошибка.
5. HTML вместо PDF → ошибка до `exec`.
6. Отсутствующий `pdftotext` → ошибка с подсказкой `poppler-utils`.
7. Гейт: пустая БД, тот же месяц, прошлый, будущий.
8. Ссылка на обновлённой странице-фикстуре — `inFOM_26-10.pdf`; xlsx-ссылка по-прежнему находится.
9. Приёмник: ровно две строки `(наблюдаемая инфляция, 2026-10-14, 14.5)`, `(ожидаемая инфляция, 2026-10-14, 13.2)`; ошибка `Append` не проглатывается.

## 6. Приёмка

- `make import STAT=cbr_infl_exp_op` → `Imported 2 rows`; `v_cbr_macro` отдаёт `2026-10-14`: 14.5 и 13.2.
- Повтор → `Imported 0 rows`, PDF не скачивается.
- `make import STAT=cbr_infl_exp` — зелёный (полный путь из-за изменившегося `count()`), повтор — no-op.
- `make all`, `make docs-check`, `dagu validate dagu/cbr.yaml`, `make mcp-check` — без новых провалов.

## 7. Риски

- **Вёрстка PDF.** При смене генератора (скан, другая ось) шаг падает с явной ошибкой — данные не подменяются. Лечение — правка парсера, а не тихий пропуск.
- **Два писателя в одну таблицу.** Правило «`Name()` = `TableName`» ослабляется точечным allowlist'ом теста реестра — прецеденты: общая `macro_series` и `company_financials` (скил `go-engineer` §5.1, стандарт §8.2/§8.3).
- **Лишний полный прогон XLSX.** После вставки PDF-точки `count()` меняется, поэтому ближайший `cbr_infl_exp` один раз идёт полным путём (1.9 МБ), затем снова no-op.
