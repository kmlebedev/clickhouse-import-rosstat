# Спека: H2O AutoML как генератор challenger'а для CPI v4

**Дата:** 2026-11-01

**Роль:** `ml`
**Зависит от:** #396 — движок `scripts/models/cpi/cpi_v4_grid.py` и `cpi_v4_leaderboard.py` уже в `main` (коммит `2bc348c`)

## 1. Вопрос и гипотеза

**Вопрос.** Даёт ли H2O AutoML что-то сверх дефолтных CatBoost-моделей на нашей задаче прогнозирования ИПЦ — при том же информационном наборе, той же структуре (bottom-up) и тех же фолдах?

**H1.** Замороженный по до-тестовым данным H2O-оценщик (GBM/XGBoost/DRF/GLM) на признаках v3 снижает RMSE `T_NSA` h1 на `S_L09` относительно `v3_bottomup` — той же модели с тем же набором признаков, но learner'ом CatBoost.

**H0.** Разницы нет или она в пределах MDE; тогда вывод — `reject`/`iterate`, и AutoML в этом контуре остаётся инструментом генерации challenger'ов, а не заменой дефолтному CatBoost.

Ожидание до прогона: выигрыш **маловероятен** — выборка маленькая (≈76–128 origin'ов), CatBoost с дефолтами на таких данных силён, а AutoML не является time-series-специфичным. Отрицательный результат считается полноценным.

## 2. Арена и цель

| Параметр | Значение |
|---|---|
| Выборка | `S_L09` (2009-06…2026-08), primary-окно origin'ов — 2016-01+; robustness — `S_L13`, `S_W22` |
| Таргет | `T_NSA` — накопленный m/m ИПЦ (`rosstat_ipc_mes`) за `O+1…O+h`, п.п. |
| Горизонты | h1, h3 (primary), h6 (отрицательный контроль) |
| Фолды | expanding walk-forward, purge `O' ≤ O − h − 1`; `min_train=60` (`S_L09`/`S_L13`), 24 (`S_W22`) — ровно как в v4 |
| Признаки | `v3.feature_names_v3()` (v2 + `wkagg_*` + diffusion), для `S_L09` — с `feature_override(("usd_mm","key_rate"))` |
| Единицы | п.п. накопленного прироста |

Все числа — на тех же origin'ах, что сетка #396: `build/cpi-v4/S_L09/cell_T_NSA_h*.json` служит ориентиром, но **не** эталоном gate (данные «последней редакции», сравнение — на общих фолдах текущего прогона).

## 3. Этап 1 — селектор (только до-тестовые данные)

**Кадр селектора.** Origin'ы `S_L09`, у которых цель `O+1…O+h` наблюдена до начала primary-окна: `O + h ≤ 2015-12`, то есть `O ≤ 2015-12 − h`. Для h1 — 76 origin'ов, для h3 — 74. Цель — `cpi_all`, признаки — набор v3. Селектор **не видит** ни одного месяца из primary-окна; это фиксируется тестом (`O ≤ 2015-12 − h`).

**Внутренняя валидация.** `fold_column` — 3 последовательных блока по времени (по трети отсортированных origin'ов, целые границы), значения 0/1/2. Случайный CV запрещён: `nfolds` выводится из `fold_column`; значение по умолчанию H2O (random 5-fold) не используется.

**Параметры `H2OAutoML`** (фиксируются до прогона):

| Параметр | Значение | Почему |
|---|---|---|
| `max_models` | 20 | воспроизводимость; `max_runtime_secs` не задаётся |
| `max_runtime_secs` | не задан (0) | иначе лидерборд зависит от машины |
| `seed` | 20261018 (`lb.SEED`) | общий seed контура |
| `sort_metric` / `stopping_metric` | RMSE | метрика задачи |
| `exclude_algos` | `["DeepLearning","StackedEnsemble"]` | DL не воспроизводим; SE требует CV-стекинга и в refit не переносится |
| `fold_column` | `sel_fold` | временные блоки вместо случайного CV |
| `keep_cross_validation_predictions` | False | не нужны; экономия памяти |
| `verbosity` | `warn` | не засорять лог |
| `H2O.init` | `nthreads=1`, `max_mem_size="4G"`, `ice_root`/`log_dir` → `build/cpi-v4-h2o/tmp` | воспроизводимость и чистый корень |

**Правило заморозки.** Победитель — лучший **базовый** алгоритм лидерборда (SE исключён). Сохраняются: семейство, `model_id`, фактический RMSE-CV, топ-10 лидерборда, полный набор `actual_params`, версии `h2o`/Java, sha256 кадра, `seed`. Пишется в `build/cpi-v4-h2o/select.json` **до** любых прогонов на 2016+. Копия JSON — в `docs/research/2026-11-01-cpi-h2o-automl.json`.

**Стабильность.** Селектор повторяется со вторым seed'ом (`SEED+1`) на том же кадре. Если семейство победителя совпало — `selection_stable=true`. Если нет — фиксируется семейство с меньшим средним CV-RMSE по двум прогонам, `selection_stable=false`, оба лидерборда и причина попадают в отчёт. Повторный выбор по тесту запрещён.

## 4. Этап 2 — frozen refit в walk-forward

**Что переобучается.** Оценщик выбранного семейства с замороженными гиперпараметрами (whitelist по семейству; всё, что не входит в whitelist, отбрасывается и перечисляется в `select.json`). Никакого нового поиска гиперпараметров на фолдах.

**Модели (состав фиксирован до прогона):**

| Модель | Структура | Роль |
|---|---|---|
| `h2o_bottomup` | 3 компоненты × замороженный H2O-оценщик, агрегат — `cm.nnls_weights(train)` | primary |
| `h2o_direct` | замороженный H2O-оценщик на `cpi_all` | разведочно, не gate |
| `v3_bottomup` | CatBoost-дефолты, тот же feature set | primary reference |
| `v2_bottomup` | CatBoost-дефолты, v2-признаки | справочно |
| `B1`, `B2`, `B3` | как в v4 | бенчмарки |

`h2o_bottomup` и `h2o_direct` проходят через тот же `run_walk_forward`, что и модели сетки, — значит, сравниваются на общих фолдах (`lb.common_folds`).

**Один замороженный конфиг на все компоненты.** Селектор обучается на `cpi_all` и даёт один конфиг; раздельный выбор по трём компонентам на 74–76 origin'ах был бы шумом и добавил бы множественность. Это ограничение называется явно.

**Отсечка.** Если кадр селектора меньше 60 строк или в любом блоке меньше 10 — прогон останавливается (`insufficient_selector_frame`), а не «добирает» данные из primary-окна.

## 5. Метрики и предрегистрированный gate

**Метрики.** RMSE (primary), MAE, DM-HLN с поправкой на перекрытие (h−1 лагов), 95 % блочный бутстрап-CI разницы RMSE (блок 3, n=2000, `lb.BOOTSTRAP_*`), MDE (`lb._mde_ratio`), MCS 90 % — справочно. Фолды — только общие.

**Условия gate** (каждое — против `v3_bottomup`, на общих фолдах):

1. `S_L09` h1: RMSE(`h2o_bottomup`) < RMSE(`v3_bottomup`) по точечной оценке.
2. `S_L09` h1: DM-HLN p < 0,05 **и** 95 % CI ΔRMSE не содержит 0.
3. `S_L09` h3: ΔRMSE < 0 (только знак; мощность на h3 ниже).
4. Robustness: знак ΔRMSE < 0 на `S_L13` h1 и `S_W22` h1 (h3 — справочно).
5. `S_L09` h6: нет пары с `dm_p < 0,05` и ΔRMSE > 0 (значимой деградации).
6. MCS-90 %: кандидат входит в доверительное множество — **справочно**, решающим не является (в #396 MCS включил все 7 моделей).

**Решение.**

| Условия | Решение |
|---|---|
| 1–5 выполнены | `promote` (кандидат для следующего пункта/ансамбля, не production) |
| условие 1 не выполнено | `reject` |
| иначе (1 выполнено, 2–5 — нет) | `iterate` с перечнем невыполненных условий и числами |
| нет ячеек/фолдов | `incomplete` |

Множественность: two seeds селектора + 2 модели refit; поправка не применяется, число спецификаций указывается в отчёте. `promote` ≠ deployment; `forecast_log` не пишется.

**Вторичное сравнение (разведочно, не gate).** `h2o_bottomup` vs `v2_bottomup`, `h2o_direct` vs `v3_bottomup` — чтобы отделить эффект learner'а от эффекта признаков.

## 6. Риски и стоп-условия

| Риск | Реакция |
|---|---|
| H2O не бит-в-бит воспроизводим даже при `nthreads=1` | два прогона refit, сверка sha256 `predictions.csv`; при расхождении — max \|Δpred\| в отчёт, детерминизм **не** заявляется |
| Семейство лидера меняется между seed'ами | `selection_stable=false`, оба лидерборда в отчёт, заморозка по среднему CV-RMSE |
| Java 21/8 отсутствует или версия вне 8–17 | make-цель падает с явным сообщением до запуска H2O |
| Порт 54321 занят / кластер не поднялся | `h2o.init(port=…)` с поиском свободного порта, `shutdown` в `finally` |
| Утечка через случайный CV | `fold_column` + тест на монотонность блоков |
| Маленькая выборка селектора → нестабильный выбор | отчёт с `selection_stable`, вывод формулируется как «на до-тестовых данных выбран X», без заявления о превосходстве |
| `h2o` ставится из sdist (~266 МБ) | пин `h2o==3.46.0.12`, первый прогон дольше; версия — в паспорте |
| MCS неинформативен (как в #396) | MCS только справочно, gate на DM/CI |

**Стоп:** если `make cpi-v4-h2o-test` не зелёный или селектор видит данные после 2015-12 — дальше не идём.

## 7. Что не проверяется

- Per-fold AutoML (каждый фолд заново ищет модель) — другой вопрос и другой бюджет; отдельный пункт при необходимости.
- `T_SA`, `T_CORE`, `h2`, live 88 групп (`combo3`, `T_LIVE`) — вне объёма.
- Винтажи/PIT: данные «последней редакции», как в #396.
- Production, `forecast_log`, shadow/canary, dagu, MLflow registry, промоушен — не заявляются.
