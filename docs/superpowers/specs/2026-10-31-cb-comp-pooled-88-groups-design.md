## 1. Зачем

После Task 9 лучшая live-модель — `combo3` (1,035 / 0,957 / 1,010 / 0,894 к CB_COMP на h1/h2/h3/h6). Остаточный разрыв на h3/h6 и смещение `live_cb` (+0,57 п.п. на h6) объясняются режимом обучения: 88 отдельных CatBoost на окне 2016+ видят ~36 строк каждый. Гипотеза Task 10: одна pooled-модель на строках `(группа, месяц)` с признаками группы (id, вес, лист МП) использует ~3 000–8 000 строк, учится на том же коротком окне и либо бьёт `combo3` на h3/h6, либо даёт отрицательный результат.

## 2. Что известно до протокола

- `live_cb` (Task 3, C0-панель): 1,1929 / 1,0127 / 1,0758 / 1,0617 к CB_COMP на h1/h2/h3/h6.
- `combo3` (Task 9): 1,0348 / 0,9571 / 1,0102 / 0,8940; значимо лучше `live_cb` только на h1 (DM p = 0,008, 95 % CI ΔRMSE [−0,045; −0,005]); h6 ΔRMSE −0,163, DM p = 0,069 (не значимо по правилу p < 0,05 + CI < 0).
- `live_cb` на h6 имеет смещение +0,57 п.п.; у BS_ECON16/BS_ROZN16 (окно 2016+) — +0,05…+0,08.
- Проба pooled до этого Task не считалась; параметры и правило переподготовки фиксируются здесь, до результатов.

**Окна.**

## 4. Признаки pooled-строки

Строка — `(группа g, целевой месяц M)`; признаки берутся на origin `O = M − (h − 1)` из `cb_comp_live_en.prepare()` (`per_sheet`, as-of правила v2).

| группа | признак | тип |
|---|---|---|
| база `live_cb` | `y_lag1`, `y_lag2`, `usd_mm`, `key_rate`, `fao_mm` | numeric |
| база `live_cb` | `month` | cat |
| id группы | `group_code` — код группы строкой | cat |
| лист МП | `sheet_profile` — `"|".join(spec.sheet_slugs)` или `none` | cat |
| лист МП | 11 листов × 3 индикатора × (уровень, `_chg`) = **66** колонок `mp_sheet_<slug>_<indicator>[_chg]` | numeric |
| вес | `weight_share` — вес СПР группы / Σ весов групп с SA **в origin `M−(h−1)`**, год `origin.year − 1` | numeric |

- В 66-колоночном блоке заполняются только колонки листов **своей** группы; остальные — NaN (CatBoost обрабатывает NaN нативно). Значения других листов в строку не подставляются.
- Для групп без BSU/листов все 66 колонок — NaN; `sheet_profile = none`.
- Веса архива есть только за 2016–2024. `weight_share` берётся строго за год `origin.year − 1`; если такого года нет (ранние main/control-строки), значение — NaN, fallback на другой год **не используется**. Агрегат тестовых месяцев 2019-01…2024-07 корректен: веса года `M−1` (2018–2023). Ограничение — в паспорт и отчёт.

**Hyperparameters** — дефолты `live_cb`/`bu.CATBOOST_DEFAULTS`: `loss_function=RMSE`, `random_seed=20261018`, `verbose=False`, `allow_writing_files=False`, без тюнинга. `cat_features = [month, group_code, sheet_profile]`. При необходимости детерминизма — `thread_count=1` (фиксируется в паспорте; модели и пороги не меняются).

## 5. Годовая переподготовка (no-leakage)

Для каждого тестового года `Y` и горизонта `h` — **один фит на год** в первом origin года:

`O_min = 1 января Y − (h − 1)`.

Обучение — целевые месяцы `t` от начала окна (`2016-01` / `2010-03`) до последнего `t`, для которого

`cm.available_from_mes(cm.month_end(t)) < cm.cutoff_for(O_min)`,

конвенция `late` (как Task 2/3), без шоковых месяцев §3. Модель применяется ко всем тестовым месяцам года `Y`; прогноз строки `(g, M)` использует признаки на `M − (h − 1)`.

Свойства:

- ни один тестовый месяц года `Y` не входит в обучение;
- для `h ≥ 2` ранние origin года не видят таргетов, опубликованных после их origin (Task 9 уже исправлял такую утечку у авторов);
- каждый фит используется ровно на 12 последовательных origin (для h1 — Jan…Dec Y, для h6 — Aug Y−1…Jul Y); следующий фит — через 12 месяцев;
- 6 фитов на горизонт (2019…2024), 4 горизонта, 2 окна — 48 моделей.

Строки, у которых origin раньше доступного начала признаков (control, h ≥ 2 у начала окна), отбрасываются; фактические границы и число строк — в паспорте.

## 7. Оценка

Истина — `TARGET_FULL`, normal-54; h2 — справочно.

1. **Против CB_COMP** — `cpi_two_stage_cb_comp.compare_to_cb` для `pooled_main`, `pooled_control`, `combo3`, `combo3_pooled`, `live_cb`: RMSE, отношение, 90 % CI отношения, DM-HLN, класс W5b («лучше / хуже / паритет / не определено»).
2. **Попарно** — `cpi_v4_leaderboard.compare_pair`:
   - `pooled_main` vs `combo3` для h1/h2/h3/h6 — DM-HLN p и 95 % бутстрап-CI ΔRMSE;
   - `pooled_main` vs `live_cb` — справочно;
   - `combo3_pooled` vs `combo3` — справочно.
3. **MCS 90 %** — `cpi_v4_leaderboard.mcs_included` по `pooled_main`, `combo3`, `live_cb`, `cb_comp` на h1/h3/h6 (потери — квадраты ошибок против `TARGET_FULL`).
4. **Справочно** — RMSE против `T_LIVE`, все 67 месяцев, подпериоды 2019–2021 / 2023–2024, `pooled_control` на тех же метриках.

«Лучше» в отчёте — только по правилу репозитория: DM p < 0,05 и 95 % CI ΔRMSE целиком ниже 0. Для G10 порог softer (p < 0,10), как задан в issue; это оговаривается отдельно.

## 8. Гейт G10 (предрегистрирован)

`pooled_main` проходит, если одновременно:

1. на h3 **или** h6: `RMSE_pooled < RMSE_combo3` и DM-HLN p < **0,10**;
2. на h1: `RMSE_pooled ≤ RMSE_combo3` (не хуже по точке; DM/CI h1 сообщаются).

MCS — обязательная отчётная проверка, но не дополнительное условие G10. G10 не пройден — отрицательный результат публикуется, `combo3` остаётся базой Task 4/5/7. G10 пройден — pooled рекомендуется как кандидат в базу/компонент для Task 4/5/7; замена `combo3` — решение владельца, не автоматическое.

## 12. Что не доказывается

- **Не паритет дизайна с CB_COMP:** у них frozen-обучение и per-code МП; у нас другая цель обучения и публичные листовые МП.
- **Не PIT:** SA групп — полная выборка (как Task 2/3), винтажей SA/весов/ожиданий нет.
- **Не walk-forward 2022+** (критерий #419) — отдельная задача; здесь окно статьи 2019–2024.
- **Выбор после Task 9:** pooled предложен владельцем в issue как ответ на смещение `live_cb`; независимого подтверждения нет.
- **Годовой фит для h6** использует меньше данных, чем `live_cb`; если pooled проиграет, вывод — «короткое окно/годовой режим не помогают», а не «pooled хуже по идее».
- **`group_code`** — high-cardinality cat-признак на 87 группах; дефолты CatBoost не тюнились, переобучение — часть проверяемой гипотезы.
- **Вес** — доля, а не абсолют; для ранних строк `weight_share` = NaN (весов года `origin−1` нет).

## 13. История первого прогона 2026-10-31: R10d до ревью

> **Уточнено в §14.** Ниже — первая формулировка R10d; после ревью PR #447 проверка заменена на «предсказанное 87 + взвешенное равно весовому покрытию», поэтому буквальный провал 87 больше не блокирует прогон. G10 не менялся.

Записана после прогона `b30a83a`, до отчёта; **G10 и его пороги не меняются**.

- **R10d буквально не пройдена:** взвешенное покрытие агрегата — 85 групп в 2019–2022, 86 в 2023, 87 в 2024. Причина — у групп `803` и `930.АГ` нет весов СПР до 2023 и 2022 соответственно; `cb_comp_bottomup.aggregate` (и `live_cb`, и `combo3`) использует то же взвешенное покрытие.
- **Предсказанное покрытие — 87 групп** в каждом тестовом месяце на всех горизонтах (`--check-data`): pooled-модель не теряет ни одной группы, отсутствие весов — свойство архива.
- Правило §9 «любая R10 не пройдена — прогон останавливается, G10 не считается» оставлено в силе: G10 формально не засчитан. По числам он не пройден независимо от R10d — h1 хуже `combo3`, h3/h6 не ниже (§8). Вывод — отрицательный, следующий шаг не начинается.

## 14. Поправки после ревью PR #447 (2026-10-31, до перепрогона)

8 инлайн-замечаний; **G10 и его пороги не меняются**, меняются признаки, состав train-строк и проверки R10. Перепрогон выполняется после этих правок; числа в отчёте и PR заменяются.

1. **`weight_share` — as-of origin.** Доля считается на `origin = M−(h−1)`: веса года `origin.year−1`, знаменатель — группы с SA в origin. Прежняя формула брала состав панели в целевом месяце и вес года `M−1`, то есть для h ≥ 2 смотрела вперёд.
2. **Шоки в окне цели.** Train-строка исключается, если окно `M−h+1…M` пересекает шоковый месяц статьи, а не только если шоковый сам конечный месяц. Для h6 это убирает, например, цели 2023-01…05 в фите 2024.
3. **R10c независима.** Для каждого train `t` и каждого тестового `M` проверяется `available_from_mes(month_end(t)) < cutoff_for(M−(h−1))`; `training_cutoff` в проверке не участвует.
4. **R10d измерима.** Проверяются предсказанное покрытие 87 групп и равенство взвешенного покрытия числу групп с SA и весом (85/86/87 по годам). §13 — история первой формулировки.
5. **Leak-guard на тесте.** `fit_predict_pooled` вызывает `bu.assert_no_leakage_bottomup(year_months, horizon)` перед прогнозом.
6. **Общие хелперы.** `sha256`, `git_sha`, `_jsonable` берутся из `cb_comp_live_bottomup`; `_jsonable` расширен date-значениями, дубли удалены.
7. **Пересчёты.** `train_months` принимает уже посчитанный cutoff; `weight_shares` считается один раз на горизонт и окно.
8. **Опечатка §4:** тест — 2019-01…2024-07, годы весов — 2018–2023.

Перепрогон: `make cb-comp-pooled ARGS="--archive …"`; повтор для детерминизма; отчёт и PR обновляются.
