# T+1 золото из bold.report — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Новый пакет `bold/` с двумя импортёрами — ежедневный T+1 ETF-контур (7 рядов `etf_bold_*` в `macro_series` + таблица `bold_fund_snapshot` по 73 фондам) и ежедневная цена золота (площадка `bold` в `gold_prices`) — с инкрементом вместо ежедневной перезаписи истории.

**Architecture:** Разбор и конверсии — чистыми функциями (`bold/parse.go`), импортёры — тонкая обвязка: чтение сохранённого максимума из ClickHouse, выбор «инкремент или полная история», `util.GetJSON`, один батч на таблицу, каталог после `Send`. Витрины объявляются в `views/` (как `v_gold_etf_flows`), гранты — в `sql/mcp_kimi_reader.sql`.

**Tech Stack:** Go, `encoding/json`, `net/http/httptest`, `logrus`, ClickHouse (`clickhouse-go/v2`, `PrepareBatch → Append → Send`), `util.GetJSON` / `util.CreateView` / `util.UpsertSeriesCatalog`, dagu (yaml).

**Spec:** `docs/superpowers/specs/2026-10-12-bold-t1-gold-design.md`

## Global Constraints

- Новых внешних зависимостей не добавлять; HTTP — только через `util.GetJSON` (проверка статуса, дедлайн 60 с).
- Запись в ClickHouse — только батчами: `PrepareBatch` → `Append` (с проверкой `err`) → `Send`; каждый `err` проверять.
- Секреты — только `os.Getenv` (в этом пункте их нет); логирование — `logrus`, без `fmt.Print`.
- Тесты офлайн: в `go test` нет обращений в сеть — только `httptest` и фикстуры `bold/testdata/`.
- Константа конверсии: `31.1034768` г/унция (та же, что в `gold/gold.go`), `1 т = 1e6/31.1034768 = 32150.74656862…` унции.
- Имена 7 рядов и `source` — дословно из спеки §4.1: `etf_bold_flow_tonnes`, `etf_bold_flow_usd_mln`, `etf_bold_flow_7d_tonnes`, `etf_bold_flow_30d_tonnes`, `etf_bold_flow_90d_tonnes`, `etf_bold_holdings_tonnes`, `etf_bold_aum_usd_bn`; `source='bold'`; цена — `venue='bold'` в `gold_prices` и запись каталога `source='gold'`, `series='bold'`.
- Знак потока: рост `units` — приток (плюс).
- Сетевые запросы: `bold_etf_flows` — обычный инкремент **4** (`units-latest`, `aum-latest`, `flows/all-latest`, `summary`), первый прогон и восстановление после пропуска — **8** (те же 4 «последнего дня» нужны, чтобы узнать дату для сравнения и получить пер-фондовый срез, плюс 3 файла истории и `summary`); `bold_gold_price` — 1 запрос в любом режиме (`price-latest` / `price.json`). Штатный суточный итог контура — 5 запросов. Счётчики закрепляются тестами.
- Пины фактов (2026-10-09) запрещено «поправлять»: `units` 113 180 843 oz → `3520.318` т; `aum` 476 677 811 738 → `476.678` млрд $; `culm7day` 43 740 → `1.360` т; `culm30day` 991 060 → `30.825` т; `culm90day` 5 376 055 → `167.214` т; `price` `4216.3`; Δ(09.10 к 08.10) = 136 080 oz → `+4.233` т и `573.75` млн $ (допуск сравнения — 1e-6 относительной).
- Коммиты — по-английски, в духе истории репозитория.

## Review Focus

1. **`units`/`aum` = `null`** в первых 64 строках истории (2015-01-01 … 2015-03-31) — точки нет, не ноль: иначе нулевой сток попал бы в ряды как факт (Task 1).
2. **Расхождение дат `*-latest`** (price / units / aum / flows) и **отсутствие даты** в пер-фондовом срезе — ошибка, а не запись под чужой датой (Task 1, Task 2).
3. **Инкремент обязан ловить пропуск дней**: если дата `*-latest` ушла вперёд больше чем на 4 календарных дня от сохранённого максимума — полный путь; при равных датах — no-op с 0 строк, а не ошибка (Task 2).
4. **Δ потока на границе истории**: у первой точки ряда потока нет; на инкременте предыдущие `units` читаются из ClickHouse (не из ответа «последнего дня»), иначе поток молча равен нулю или цене дня (Task 2).
5. **Масштабы и конвенции окон**: унции → тонны (÷32150.74656862), USD-поток = Δунции × цена дня; окна берутся из `culm7/30/90day` **как опубликованы** (календарные окна), а не как сумма пяти торговых дней (Task 1).
