## Задачи

### Task 1: `cbr_bop_est` — импортёр, витрина, фикстура, тесты

- `cbr/bop_parse.go`: общие хелперы разбора по спеке §3.5 — якорь строки единиц (`долларов США`),
  первая строка данных по первой ожидаемой подписи агрегата, строки шапки между ними, подпись
  колонки снизу вверх, нормализация подписей (снять `(оценка)`, свернуть пробелы и переносы,
  `–`/`—` → `-`), разбор периода (`месяц ГГГГ`, `[IVX]+ квартал ГГГГ`, `месяц - месяц ГГГГ` с
  обязательным январем, `ГГГГ`) и привязка даты (последний день месяца/квартала, 31 декабря,
  последний месяц итога). `util.MonthsToNum`; никакого `panic`; индексация с проверкой.
- `cbr/bop_est.go`: список 17 подписей источника и имён кода (спека §3.3, таблица оценки),
  `util.ClickHouseImport` с `TableName: cbr_bop_est`, DDL из спеки §3.1 (`%s`-форма),
  `DataUrl: https://www.cbr.ru/vfs/statistics/credit_statistics/bop/bop_est.xlsx`,
  `ImportFunc` — разбор листа по префиксу `Оценка ПБ`, `PublicationCountPoints:
  SELECT count() FROM cbr_bop_est FINAL`, `AfterImport: afterCbrBop(cbrBopEstSeriesMeta)`
  (мета и витрина появляются в этой же задаче — иначе пакет не компилируется).
  Последовательный поиск подписей; ненайденная ожидаемая подпись — ошибка с именем таблицы;
  ноль — точка, пустая ячейка — не точка; нечисловая ячейка, `NaN`/`Inf` — ошибка.
- `cbr/views.go`: `cbrBopView` (`v_cbr_bop`: пока одна ветка — `cbr_bop_est` с `source` = имя
  таблицы, комментарии таблицы и колонок) + `afterCbrBop(meta)` (каталог + витрина, стандарт §10.2).
- `cbr/bop_meta.go`: секция `cbr_bop_est` — 51 запись `util.SeriesMeta` (17 агрегатов × 3 вида),
  `Source: cbr_bop_est`, `Unit: млрд долларов США`, `Frequency: M/Q` (у «накопленным итогом» — `M`),
  `Origin` — файл, лист и подпись строки источника, `Description` — что измеряет, знак, привязка
  даты, ноль как значение, «оценка» ревизуется следующим выпуском (спека §3.7).
- Фикстуры оценки — **два живых винтажа**: `cbr/testdata/bop_est.xlsx` (текущий, 15.10.2026,
  114 411 байт: подписи строк сменились 15.10.2026, колонок 17 × 10) и
  `cbr/testdata/bop_est_prev.xlsx` (прошлый, 14.09.2026, 115 017 байт, 17 × 14) — второй нужен,
  потому что у винтажей разные наборы подписей строк и колонок, и приём обоих наборов иначе
  не покрыт. Скачать оба `curl`-ом со стабильной ссылки (текущий) и из истории ветки
  (прошлый — это файл, который лежал в `bop_est.xlsx` до правки).
- `cbr/bop_est_test.go`: двусторонний контракт каталога (`checkCbrSeriesMeta`); у текущего винтажа
  — 170 точек (17 × 10) и даты по правилам спекы §3.4, у прошлого — 238 (17 × 14); spot-значения
  (текущий: `Счет текущих операций (накопленным итогом)` 2026-08-31 = 35; `Счет текущих операций
  (месяц)` 2026-08-31 = 3,3; `Товары: экспорт (месяц)` 2026-08-31 = 40,9; `Услуги: импорт
  (квартал)` 2026-06-30 = 25,1; `Счет операций с капиталом (квартал)` 2026-06-30 = 0;
  `Счет текущих операций (накопленным итогом)` 2025-08-31 = 21; прошлый: 33,9 / 1,7 / 37,7 / 25,2);
  fail-fast ветки из спекы §3.9; мутированная копия живой фикстуры — смена даты в имени листа
  разбор не ломает; нуль-точка против пустой ячейки; запись `float64`.

## Порядок диспатча

T1 → ревью (haiku) → T2 → ревью (haiku) → T3 → ревью (haiku) → T4 → ревью (haiku).
Задачи идут по одной, потому что делят файлы `cbr/bop_meta.go` (секции) и `cbr/views.go` (ветки
витрины): каждая следующая правит файл, оставленный предыдущей, и после каждой пакет собирается и
тесты зелёные. После зелёного `make all` — T5 (живая приёмка контроллером через `make`/MCP),
затем T6. Fix-round'ы: до 3 на задачу, далее эскалация контроллеру.

## Чек-лист жёстких правил для ревью-промптов

Батч одним `PrepareBatch`; HTTP только `util.GetXlsx`; сети в `init()` нет; DDL
`CREATE TABLE IF NOT EXISTS`/`ReplacingMergeTree`/`LowCardinality(String)`/Float64; все
`strconv`/`batch.Append` с проверкой ошибок; logrus, не `fmt.Print*`; секретов нет; имена рядов из
кода (стандарт §6.8); фикстуры — реальные файлы, не синтетика; реестр — литералами (§8.2);
разбор изолирован от сети (§6.1).
