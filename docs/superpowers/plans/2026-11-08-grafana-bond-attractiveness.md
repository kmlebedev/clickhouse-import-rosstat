# План: дашборд «Привлекательность облигаций» (`ofz-market/1.8`)

**Спека:** [2026-11-08-grafana-bond-attractiveness-design.md](../specs/2026-11-08-grafana-bond-attractiveness-design.md). **Ветка:** `feat/bond-attractiveness-dashboard`.

## Шаги

1. **Пункт роадмапа и спека** — `docs/ROADMAP_OFZ_MARKET.md` §4 (`ofz-market/1.8`), спека в `docs/superpowers/specs/`. Сделано первыми коммитами ветки.
2. **SQL-контракт на живых данных.** Каждый запрос прогнан через MCP под `kimi_reader` до фиксации в коде: ставка и средневзвешенная, реальная ставка, кривая ОФЗ и спреды, вклады, кредиты (юрлица/физлица отдельно), спред вклад−ОФЗ по месяцам, ряды SORS. Результаты — §2 спеки.
3. **Builder `grafana/bond_attractiveness.go`.** Константа uid, `NewBondAttractiveness()`, SQL-константы, помощники `baPanelDefaults` (графики) и `baStatDefaults` (снимки), 21 панель в 6 рядах (первый ряд — чек-лист «Все триггеры статьи»: десять stat-плиток: вердикты «облигации/акции» и спред ставок «вторичка − первичка»). Ловушки: розничные кредиты — отдельный таргет (ряд кончается 2025-12), SORS — отдельный таргет на ряд (разные начала), спред вклад−ОФЗ — по месяцам.
4. **Тесты `grafana/bond_attractiveness_test.go`:**
   - 21 панель, 6 рядов, уникальные id;
   - каждый таргет — `FROM v_*`, графики — `$__timeFilter`, `LIMIT` на графиках нет;
   - розничные кредиты не смешаны с юрлицами в одном запросе (отдельный таргет);
   - спред вклад−ОФЗ содержит `toStartOfMonth` и `INNER JOIN`;
   - темпы вкладов — `lagInFrame` снаружи фильтра (`$__timeFilter` один раз, после подзапроса);
   - пороги 10.43 и 0 присутствуют;
   - детерминизм сборки (существующий CI-шаг `git diff --exit-code`).
5. **Регистрация:** `grafana/main.go` (упорядоченный слайс), `DASHBOARDS` в `Makefile`, списки `gcx dev lint run` и upload в `.github/workflows/dashboards.yml`.
6. **Артефакт:** `make grafana-build` → `dashboard/bond-attractiveness.json`; повторный прогон не меняет файл.
7. **Проверки:** `make grafana-validate`, `make all`, `make docs-check`; `gcx dev lint run` по артефакту.
8. **Живой SQL:** все таргеты через MCP под `kimi_reader`; пустые ответы — только там, где ряд ещё не начался (эскроу до 2019-02, розница после 2025-12).
9. **Smoke:** `make grafana-deploy-test` + `make grafana-check` (локальный стенд); staging — owner-assisted. Протокол — комментарием в PR.
10. **Доки:** очередь миграции в `ROADMAP_INFRA` 2.2, `docs/GRAFANA.md`, README/ARCHITECTURE при необходимости (скил `sync-readme-architecture`); `docs/site-pages.json` для новой спеки/плана — если требуется сборкой docs.

## Риски

- **Розничные ставки обрываются в декабре 2025** — панель показывает разрыв, а не ноль; в описании дата последней точки.
- **Средневзвешенная в SQL считается по полному ряду на момент запроса** — значение меняется при добавлении новых дней; это ожидаемо и подписано в описании.
- **SORS «средства клиентов» ≠ «депозиты населения»** — разные контуры; в дашборде используется только SORS, подпись панели это фиксирует.
