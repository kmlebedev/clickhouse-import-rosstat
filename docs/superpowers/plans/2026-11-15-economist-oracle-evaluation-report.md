# План публикации результатов economist-oracle

Дата: 2026-11-15. Пункт: `key-rate/phase-4-oracle-quality`.

Спецификация: [контракт публикации](../specs/2026-11-15-economist-oracle-evaluation-report-design.md).

1. Создать изолированную ветку от свежего `main`, не включать коммит кандидата или чужие untracked-файлы. Проверить baseline `make docs-check`.
2. Зафиксировать в роадмапе пункт исправлений со статусом `Todo`; создать issue с шестью дефектами и проверяемой приёмкой. Не заявлять начало реализации исправлений.
3. Перенести отчёт и необходимый пакет доказательств. Указать tested revision, происхождение 22 локальных критериев, хеши и пределы проверки. Оригинальные прогнозы не исправлять.
4. Зарегистрировать отчёт в `docs/site-pages.json`. Проверить ссылки, JSON, отсутствие локальных путей и совпадение копий; воспроизвести арифметические контрпримеры на включённом снимке помощника.
5. Выполнить `make docs-check` и `make all`, проверить состав diff и временные файлы. Коммитить только перечисленные документы и доказательства.
6. Открыть один PR с `Refs #<issue>` (без автозакрытия, по решению владельца), опубликовать протокол проверок комментарием, связать issue и Project V2. Исправления остаются `Todo`; merge не выполнять.

## Уже имеющаяся проверка

Три eval-прогона и независимое ревью выполнены до публикации. Их не запускать повторно: эта работа переносит доказательства, а не получает новые макроданные. Сценарий без БД был симуляцией; точность будущего решения ЦБ не оценивалась.
