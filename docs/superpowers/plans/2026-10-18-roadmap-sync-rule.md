# План: автосинхронизация роадмап → issue после мержа PR (`infra/3.5`)

**Цель:** после мержа PR, изменившего `docs/ROADMAP_INDEX.md` или владеющий файл роадмапа, агент сам сверяет открытые пункты с issue, создаёт отсутствующие и обновляет поля Project; issue автоматически не закрывает.

**Границы:** только процесс и документация; GitHub Actions/webhook не добавляются. «Автоматически» означает обязательный шаг агента в той же сессии или при следующем старте по merge-коммиту. **Транспорт GitHub:** MCP `mcp__github__*`; `gh` CLI — фолбэк, если MCP-инструменты недоступны.

## Шаги

1. `AGENTS.md` правило 12 — добавить обязанность синхронизации после мержа (создать/обновить, не закрывать, отчёт, идемпотентность).
2. `docs/ROADMAP_INDEX.md` — шаг 4 в §4 и `3.5` в схеме `infra`.
3. `.kimi-code/skills/github-tracker/SKILL.md` — новый §10 с точным порядком: определить изменённые файлы, собрать открытые пункты, найти issue по заголовку, создать отсутствующие, обновить заголовок/тело/поля Project, отчёт `created/updated/OK/stale`, не закрывать.
4. `docs/superpowers/specs/2026-10-17-github-tracker-design.md` §12 — зафиксировать, что синхронизация после мержа запускается сразу, а не только периодически.
5. `docs/ROADMAP_INFRA.md` — пункт `3.5` и ссылка на этот план.
6. Issue `[infra/3.5]`, label `roadmap:infra`, Project #11: `Todo` → `In Review` после PR.
7. Проверка: сухой прогон на `infra` — все открытые пункты имеют issue, повтор не создаёт дублей; `make docs-check`.
8. Коммит, push, PR с `Closes #<issue>`, протокол приёмки комментарием.

## Критерий приёмки

`AGENTS.md`, `ROADMAP_INDEX.md`, спека и скил содержат правило; сухой прогон на `infra` не создаёт дублей и не находит отсутствующих issue; `make docs-check` зелёный; PR смержен, статус `3.5` — `✅`.
