## 1. Резюме

Исследование отвечало на один вопрос: **дают ли данные e-disclosure.ru значимое улучшение точности DCF/NAV по PLZL и стоит ли ради этого покупать платный канал.**

Короткий ответ:

1. **Для точности NAV — нет.** Официальные shares и net debt 2025 меняют NAV/акция на **−75,7 ₽ (−0,7…−1,8 %)** в зависимости от дека. Разрыв NAV с рынком остаётся **3–10x** (P/NAV 0,097–0,248) и определяется допущениями по активам (Сухой Лог, профиль запуска, цена золота, дисконт), а не мостом net debt/shares.
2. **Для качества данных, аудита и событийного слоя — да.** Официальные МСФО/РСБУ, дивиденды, record date, решения СД, финансовые и операционные результаты, списки аффилированных лиц и материалы собраний. У PLZL закрываются пробелы 2015–2018 и 2025FY, у CHMF появляется официальная МСФО 2019–2021 и 2023–2026, которой в проекте нет.
3. **Единственный структурно значимый числовой факт — дробление 10:1:** 94 922 тыс. акций до → **949 217 тыс. после**. Если модель использует досплитовое число, NAV/акция завышается в 10 раз. Текущая модель, судя по 12 500 ₽ против 103 832 ₽ pre-split, уже post-split; это нужно держать под проверкой.
4. **Платные каналы не подключались.** По критерию «улучшение точности NAV» не покупаем: email 13 200 ₽/год, FTP 9 000 ₽/мес и API 27 000 ₽/мес не оправданы. Email остаётся кандидатом только если приоритетом станет аудит/событийный слой, а не NAV.
5. **Финальное решение владельца:** платный пилот не подключать, делать **scraping-only MVP** для документов и винтажного архива; события и полный текст `event.aspx` — следующим пунктом. Это решение реализовано в PR #187.

## 2. Что такое e-disclosure.ru и зачем он проекту

[e-disclosure.ru](https://e-disclosure.ru/) — официальный агрегатор обязательного раскрытия акционерных обществ: карточки эмитентов, существенные события, бухгалтерская отчётность (МСФО/РСБУ), списки аффилированных лиц, материалы общих собраний, прочие документы.

Для контура DCF по Полюсу источник ценен тремя слоями:

| Слой | Что даёт | Ценность для проекта |
|---|---|---|
| Документы | Официальные МСФО/РСБУ, аудиторские заключения, списки аффилированных лиц, решения собраний | Сверка допущений, закрытие пробелов `polyus/`, аудит и backtest; PDF/Excel-парсинг — отдельная задача |
| События | Финансовые и операционные результаты, дивиденды, record date, решения СД, ОСА, сделки, рейтинги | Календарь триггеров, событийный слой, дедуп с Telegram; полный текст события требует `event.aspx` |
| Винтажный архив | Версии файлов по `sha256` и дате публикации | Point-in-time: какой именно документ действовал на дату расчёта |

Ограничение: публичная страница показывает **текущее** состояние. История версий событий (`Publish/Change/Delete/Exclude/Restore`) скрейпингом назад не восстанавливается — только вперёд с момента первого опроса; для истории нужен API/FTP или регулярный опрос.

## 3. Антибот и транспорт

### 3.1. Матрица проверок

| Проверка | Результат |
|---|---|
| `curl` с простым UA | `403 Forbidden` (Angie) |
| `curl` с браузерным UA | `200`, ≈415 КБ JS-challenge; данных компании в HTML нет |
| Chrome `--headless=new` / `--headless=old` + маскировка UA | `Forbidden` или страница `sp_rotated_captcha` |
| Playwright + системный Chrome, `headless=False`, свежий профиль | та же ротационная капча; автоматический ползунок не сработал |
| Playwright + **сохранённый Chrome-профиль** после ручного решения капчи | страницы карточек и разделов читаются |
| `event.aspx` с сохранённым профилем | ротационная капча: полный текст события недоступен |
| `FileLoad.ashx?Fileid=…` | скачивается **без браузера и cookies**; 287 zip + 3 rar на 290 документов |
| Kimi desktop browser (живой профиль) | проходит; карточки и документы доступны |

### 3.2. Вывод для MVP

- Полностью автоматический скрапинг (headless/Playwright без человека) **не подтверждён**: капча ротационная, критерий «≥90 % страниц без капчи, ≥50 страниц/час» не выполнен.
- Рабочий режим MVP — **полуавтоматический**: headed Chrome + сохранённый профиль, владелец решает капчу вручную, коллектор обходит карточки и разделы. Это не DAG и не production-скрапер в смысле «без человека».
- Тела документов качаются обычным HTTP без cookies; поэтому Go-импортёр детерминирован и тестируем офлайн.
- Капча на `event.aspx` — причина, по которой полный текст событий вынесен в следующий пункт.

**Ограничения пилота:** SBER — только последние ~2 недели событий; CHMF — 2026 год; PLZL — 2025–2026; документы — все годы, которые отдаёт страница раздела (2009–2026). Это репрезентативный срез, а не полный экстракт за всю историю.

## 6. Винтажный архив

### 6.1. Пилотный архив

В `build/edisclosure-probe/archive/` — **20 версий документов, 54 701 575 байт**:

| Эмитент | Объектов | Покрытие |
|---|---:|---|
| PLZL | 8 | МСФО 2015, 2016, 2017, 2018, 2025, 1П2026; РСБУ 2кв2026 и 2025 |
| CHMF | 9 | МСФО 2019, 2020, 2021, 2023 (две версии), 2024, 2025, 1П2026; РСБУ 2025 |
| SBER | 3 | МСФО 2025; МСФО 2024 (две версии) |

Формат:

```
archive/
  registry.jsonl   # archive.Entry: source, name, fingerprint, sha256, size, url, key, first_seen
  metadata.jsonl   # sidecar: issuer, company_id, inn, doc_type, period, version, fileid, published_at, note
  files/<key>      # байты объекта; key = edisclosure/<sha256[:16]>_<sanitized name>
```

- `registry.jsonl` совместим с `archive.Entry`; объект кладётся в `archive.LocalStore`/`YandexDisk` через `Put`, строка — через `Registry.Ensure`.
- `sha256` — версия содержимого; `key` содержит первые 16 hex, поэтому разные версии одного документа не схлопываются.
- `published_at` — дата публикации на e-disclosure; `first_seen` — когда версию увидел пилот. Для point-in-time использовать `published_at`.
- Две пары версий: SBER 2024FY (2025-11-07 и 2025-11-20); CHMF 2023FY (2024-02-02 и 2024-08-23, перевыпуск).
- Все объекты — ZIP с PDF внутри; XBRL/Excel в проверенных файлах нет.
- Целостность: у всех 20 объектов sha256 и размер совпали; `registry.jsonl`/`metadata.jsonl` разбираются как JSONL.

### 6.2. Версии событий

Публичная страница показывает текущее сообщение, а не историю `Publish/Change/Delete/Exclude/Restore`. Варианты:

- **API «Шлюз данных»:** `GET /v1/disclosure/events`, `entity=Messages|Files`, `fromEventId`/`toEventId`, `fromEventDate`/`toEventDate` (минимум 01.07.2020), `subjectCode` (до 5), `type` (до 5). Ответ: `uid`, `date`, `type`, `subject`, `message` (text, agency, publicUrl, attachments, header).
- **FTP:** ежедневный XML за предыдущие сутки: `EVENT_TYPE`, `MESSAGE_ID`, `REG_TYPE` (0 добавление, 1 обновление, 2 удаление, 4 уведомить биржи), `TIMESTAMP`, `EVENT_HEADER`, `EVENT_DATE`, `TEXT_RUS`; отдельный XML `SignificantEventInfo` с `OperationType="Exclusion"`.
- **Публичный сайт:** только текущее состояние; регулярный опрос фиксирует изменения **вперёд** (`first_seen` + хеш), историю до первого опроса не восстановить.

Предлагаемая схема event-винтажа — `archive.Entry` плюс sidecar с `event_uid`, `action`, `event_type`, `event_date`, `publication_ts`, `issuer`, `company_id`, `inn`, `document_uid`, `text_sha256`; в ClickHouse — `corporate_events` с ключом `(event_uid, action, publication_ts)`. Детали — `build/edisclosure-probe/archive/EVENTS_VINTAGE.md`.

## 7. Проверка точности (accuracy gate)

### 7.1. Baseline

| Показатель | Значение | Источник |
|---|---:|---|
| Последний прогон модели | 2026-10-10 02:06 МСК | `v_model_inputs` |
| NAV/акция модели | **12 500 ₽** | `model_runs.nav_per_share` |
| Цена PLZL | **1 006,8 ₽** (2026-10-09) | `v_stock_prices` |
| P/NAV модели | **0,081** | расчёт |
| USD/RUB | 83,9153 (2026-10-13) | `v_cbr_macro` |
| Акций после дробления | **949 217 тыс.** | МСФО 2025, прим. 17 |
| Акций до дробления | 94 922 тыс. | МСФО 2025, прим. 17 |
| Net debt 2024FY (БД) | 6 233 млн USD | `v_company_financials` |
| Net debt 2025 (официальный) | **7 088,7 млн USD** | МСФО 2025: 788 271 − 139 061 − 94 686 = 554 524 млн ₽ / 78,2267 |

**Lineage-разрыв:** `last_run_id` из `v_model_inputs` (7f3c2a10…) отсутствует в `v_dcf_assumptions` (там пять других run_id). Число 12 500 ₽ нельзя воспроизвести из DCF-таблицы репозитория; это внешний вход плагина. Для эксперимента мост считается отдельно.

### 7.2. Мост NAV/акция

Формула: `(NAV_total_usd − NetDebt_usd) / Shares × USD/RUB`.

| Дек / контур | NAV рудников, млн USD | NAV/акция, ₽ (офиц. ND 2025) | NAV/акция, ₽ (ND 2024) | Δ от ND 2025 | Pre-split NAV/акция, ₽ | P/NAV к рынку | Разрыв к рынку |
|---|---:|---:|---:|---:|---:|---:|---:|
| own_scenario / industrial | 124 539,5 | **10 383,2** | 10 458,9 | −75,7 (−0,7 %) | 103 832,1 | 0,097 | +931 % |
| spot_flat / industrial | 103 347,8 | **8 509,8** | 8 585,4 | −75,7 (−0,9 %) | 85 097,6 | 0,118 | +745 % |
| consensus_lt / industrial | 52 954,6 | **4 054,8** | 4 130,4 | −75,7 (−1,8 %) | 40 547,7 | 0,248 | +303 % |

Что это значит:

- Обновление net debt 2024 → 2025 даёт **−75,7 ₽/акция** (≈−0,7…−1,8 % в зависимости от дека). Это меньше шума цены золота/акций.
- **Дробление 10:1** — единственный факт, который меняет NAV/акция на порядок (10x). Если он не учтён, ошибка катастрофическая; если учтён — это разовая проверка, а не постоянное улучшение.
- Разрыв с рынком (3–10x) не закрывается мостом. Он создан допущениями по активам: Сухой Лог ~45 % NAV, профиль запуска, цена золота, дисконт. e-disclosure этих входов не даёт.

### 7.3. Полнота входов

`v_company_financials` PLZL: 265 строк, 2013FY–2026H1, 23 метрики. Пропущены:

- 2015FY, 2016FY, 2017FY;
- 2018H1/H2, 2019Q1/Q2, 2020Q1/Q2, 2021Q1/Q2, кварталы 2022–2024;
- 2025FY, 2025H1/H2 net debt (есть только revenue);
- shares, dividends, affiliates.

e-disclosure даёт официальные МСФО за 2015–2025 (45 документов) и РСБУ 2009–2026 (74 документа), то есть **документы для закрытия пробелов есть**, но нужен PDF-парсинг. Это улучшает полноту/аудит, а не обязательно NAV.

### 7.4. Gate

| Критерий | Результат |
|---|---|
| Значимое улучшение NAV/акция от официальных shares/net debt | **FAIL**: −0,7…−1,8 %, разрыв с рынком 3–10x структурный |
| Защита от структурной ошибки (дробление 10:1) | **PASS**: факт найден; риск 10x |
| Полнота входов (периоды, официальные МСФО/РСБУ) | **PASS по доступности документов**, требует парсинга |
| Событийная полнота/латентность | **PASS**: официальные события эмитента не покрыты Telegram |
| Окупаемость платного канала | email 13 200 ₽/год — да, если ценен событийный/аудиторский слой; API 27 000 ₽/мес — нет |

## 8. Экономика каналов

Допущения: 3 эмитента — текущий пилот; 8 эмитентов — расширенный; стоимость часа 2 000 ₽.

| Канал | Цена | Нужно сэкономить, чтобы окупиться | Оценка |
|---|---|---|---|
| Email 6–20 компаний | 13 200 ₽/год ≈ 1 100 ₽/мес | 0,55 ч/мес | **Окупается** уже при 2–4 ч/мес |
| FTP ≤100 компаний | 9 000 ₽/мес | 4,5 ч/мес | Маргинально для 3 эмитентов; реалистично для 8 |
| API (всё) | 27 000 ₽/мес | 13,5 ч/мес | Не окупается на 3–8 эмитентах |
| Скрапинг | 0 ₽ | — | Бесплатно, но капча; ручной проход 30–40 мин на 3 эмитента |

Решение: **платные каналы не подключать**. Email остаётся единственным кандидатом, если приоритетом станет аудит/событийный слой; API на текущем объёме не окупается.

## 9. Решение и реализация

### 9.1. Хронология решения

1. **Первичный gate (пилот):** ценность данных подтверждена, но полностью автоматический скрапинг — нет; платные каналы не подключаем.
2. **Решение владельца:** платный пилот не подключать; делать **scraping-only MVP**; первый срез — документы и винтажный архив; события — следующим пунктом. Капчу для MVP решает владелец вручную.
3. **Реализация PR #187:** полуавтоматический коллектор + Go-импортёр + таблица/витрина + архив + dagu + MCP. Живая приёмка 2026-10-18.
4. **PR #187 смержен**, issue #182 закрыт; пункт роадмапа — ✅.

Важно: «scraping-only MVP» — это **не** production-скрапер без человека, который gate отклонил. Это полуавтоматический сбор документов с ручным решением капчи и детерминированным Go-импортом.

## 10. Ограничения и риски

- **Капча.** Сбор зависит от ручного решения; коллектор не входит в расписание. При недоступности источника импортёр работает со старым снапшотом (манифест не перезаписан).
- **Полный текст событий.** `event.aspx` trigger-ит ротационную капчу; доступны тип/дата события/дата публикации/URL. Текст и версии событий — следующий пункт.
- **Версии событий.** История `Publish/Change/Delete/Exclude/Restore` скрейпингом назад не восстанавливается; только вперёд или платный API/FTP.
- **PDF.** Документы — ZIP с PDF; числовые ряды нужно извлекать парсером. XBRL/Excel в проверенных файлах нет.
- **SBER.** Полный МСФО не раскрывается; числовая дельта слабая, поток событий облигационный.
- **CHMF.** Нужен PDF-парсинг; в `ROADMAP_DCF_METALS.md` зафиксировано «PDF-парсер для металлургов не пишем» — это отдельное решение владельца.
- **Источник.** HTML может измениться; коллектор fail-fast, а не «документов нет». `FileLoad.ashx` может вернуть HTML-заглушку с HTTP 200 — импортёр отвергает `<` и пустое тело.
- **Архив.** 290 документов ≈ 414 МБ; скачивание последовательное, без параллелизма. Пилотный архив — выборочные 20 версий, production — 290.
- **10x split.** Проверить, что модель/плагин использует 949 217 тыс. акций, а не 94 922 тыс.
- **Право/этика.** Только публичные раскрытия; без обхода капчи, без платных подписок, без параллельных загрузок.

## 12. Воспроизводимость

```bash
# 1. Логин: headed Chrome, решить капчу
make edisclosure-login

# 2. Сбор документов
make edisclosure-collect          # build/edisclosure/{manifest.json,documents.jsonl}

# 3. Импорт с архивом (make-переменные важны: env-файл может задавать yandex)
make import STAT=edisclosure_documents \
  ARCHIVE_BACKEND=local ARCHIVE_LOCAL_DIR="$PWD/build/edisclosure-archive"

# 4. Повтор — no-op
make import STAT=edisclosure_documents \
  ARCHIVE_BACKEND=local ARCHIVE_LOCAL_DIR="$PWD/build/edisclosure-archive"

# 5. Глубокий прогон
EDISCLOSURE_RECHECK=1 make import STAT=edisclosure_documents \
  ARCHIVE_BACKEND=local ARCHIVE_LOCAL_DIR="$PWD/build/edisclosure-archive"

# 6. Архив и MCP
make archive-list ARCHIVE_LIST_SOURCE=edisclosure_documents \
  ARCHIVE_BACKEND=local ARCHIVE_LOCAL_DIR="$PWD/build/edisclosure-archive"
make mcp-user
make mcp-check

# 7. Расписание
dagu validate dagu/edisclosure.yaml
```

Для staging снапшот доставляется в `/root/dagu/build/edisclosure`; без каталога шаг dagu пропускается (`EDISCLOSURE_ALLOW_MISSING=1`).
