# ОНДКП: даты публикации и безопасный догон (2026-11-15)

> **Пункт:** `key-rate/phase-4-ondkp-publication-audit`, [#597](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/597), role:research.
> **База:** main `90e0484`, после мержа #596. [Спека](../superpowers/specs/2026-11-15-ondkp-publication-audit-design.md), [план](../superpowers/plans/2026-11-15-ondkp-publication-audit.md).
> **Метод:** read-only MCP dev, код импортёра, 12 публичных HTML-проб ЦБ и независимая проверка источников.

## 1. Вывод и решение

**Механический догон дат — no-go.** У 60/66 прогнозных строк `published_at=NULL`.
Простой запуск текущего импортёра их не исправит: прежний URL вызывает ранний
`continue`. Но снятие этого гейта недостаточно: парсер не находит даты ни на одной
из семи страниц 2021–2027, а дата Вестника подставляется по году без проверки
идентичности выбранного PDF. Это отдельный риск ошибочной даты даже при успешной записи.

**Go для отдельного исправления с проверяемым происхождением даты — условный:**
[#598](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/598), после
приёмки этого контракта. Подтверждены текущие цепочки ссылок для четырёх официальных
новостей. Исторические байты PDF и соответствие сохранённому SHA не проверены;
заполнять даты на основании одной этой цепочки пока нельзя. Исследование не меняет
БД, код, витрину или расписание. Наличие ненулевой даты само по себе не доказывает PIT.

| Новость о финальном документе | `/press/event/?id=…`, HTML, без auth | события; проверены 2023, 2024, 2026, 2027 | periodic (консервативная классификация) | Импортёр этот источник дат не использует | Дата новости пригодна как отдельный факт; историческая неизменность не доказана |

[HTTP evidence](ondkp-publication-audit/http-probes.json): UTC, полный URL/final URL,
status, duration, bytes, SHA256 HTML, заголовки без cookie, attempts=1, retries=0.
Все 12 ответов — 200, `text/html; charset=utf-8`, `Cache-Control: private`;
ETag/Last-Modified отсутствовали. Rate limit не объявлен в сохранённых ответах;
это не разрешение на неограниченную частоту. Пробы последовательные, timeout 30 s.
Страницы +1/+3 дня ещё не проверены; стабильность не заявляется.

Воспроизвести отдельную HTTP-пробу (URL взять из JSON):

```sh
curl -sS -L --max-time 30 -D /tmp/ondkp-headers.txt -o /tmp/ondkp-page.html \
  -w 'status=%{http_code} seconds=%{time_total} bytes=%{size_download}\n' \
  'https://www.cbr.ru/about_br/publ/ondkp/on_2027_2029/'
shasum -a 256 /tmp/ondkp-page.html
```

Первичная серия выполнена Python urllib с timeout=30; это альтернативная команда
для повторной проверки, не утверждение о побайтовом повторении HTML. Исходные
страницы с динамической навигацией целиком в репозиторий не копируются.
[MCP snapshot](ondkp-publication-audit/mcp-snapshot.json) содержит точный SQL,
колонки и все 66 строк. Проверка значений прогноза и их единиц с PDF в этот пункт
не входит; единицы указаны по существующему каталогу.

повышается до статуса подтверждённого PIT.

Имя `on_project_2022…` сигнализирует риск смешения проекта и финала, но не
доказывает статус сегодняшнего содержимого PDF: файл мог быть заменён.
Ни дата Вестника 08.12.2021, ни имя файла не достаточны для автоматической записи.

## 4. Диагноз кода и контракт as-of

В `cbr/ondkp.go`:

- `ondkpReleases` переносит `vestnikDates[year]` на лучший артефакт того же года,
  включая другой URL/формат. Связь по году не доказывает версию документа.
- `Import` получает страницу, пытается извлечь дату, затем при равенстве URL
  делает `continue`, даже если в БД дата NULL.
- `ondkpKnownYears` читает только год, URL и SHA; для безопасного обновления всей
  строки реестра нужны также сохранённые дата, format, bytes и forecast_rows.
- Синтетические тесты `TestCbrOndkpPageDate` покрывают выдуманные для теста формы
  HTML, которых нет в живых семи страницах. Они не доказывают покрытие сайта.
- `v_cbr_ondkp_forecast` ошибочно советует as-of по `release_year`. Это год политики,
  не дата доступности. MCP-комментарий должен явно запрещать такую подстановку.

Нужно хранить различимые понятия: дата объявления/публикации документа,
дата выпуска Вестника, дата обновления страницы, дата наблюдения текущих байтов.
`published_at` — только подтверждённая дата выбранной версии. Неизвестная дата
остаётся NULL. Для date-only данных внутридневная доступность не установлена:
консервативная граница — конец даты в Europe/Moscow, строго раньше cutoff.
Это правило использования, не восстановленный час публикации. Новости 2021,
2022 и 2025 не установлены в ограниченном поиске; это не утверждение об их отсутствии.

## 5. Решения и риски

| Вариант | Решение / порог | Оценка |
|---|---|---|
| Повторить текущий импорт ради заполнения NULL | no-go: URL-гейт и отсутствие дат на 7/7 страниц | запуск не решает причину |
| Взять footer / первую дату / Вестник того же года | no-go: нет доказанной связи с версией | риск неверного исторического as-of |
| Источник даты + проверка версии + обновление только NULL | условный go для #598: 100% обновляемых строк имеют проверяемую provenance; остальные NULL | 1–2 инженерных дня после источников |
| Подтвердить исторические байты и оставшиеся объявления | отдельная source-задача внутри подготовки #598; отсутствие архивов явно блокирует PIT | 1–3 исследовательских дня, без гарантии результата |
| Объявить 66 строк исторически PIT-готовыми | no-go: NULL и ненулевые даты требуют проверки версии | оценка неизвестна |

Оценки — ориентир объёма, не срок обещанного завершения. Ключ `release_year`
хранит один артефакт на год, поэтому сам по себе не различает последовательные
проекты/финалы. Исправление дат не создаёт отсутствующий архив ревизий.

## 7. Что не проверено и приёмка

PDF не скачивались, сохранённые SHA реестра через эту витрину недоступны,
исторические байты/первые даты/время суток не восстановлены. Ранее установленный
статус проекта 2022 не подтверждён повторным чтением содержимого. Полный поиск
новостей 2021/2022/2025, условия массовой перепубликации, staging, +1/+3 дня и
реальный догон не выполнены. Никаких записей в ClickHouse не было.

Независимое source-review: gpt-6.1-sol, проверены 7 страниц, индекс и 4 новости.
Финальное независимое ревью gpt-6.1-terra — **PASS**, блокирующих замечаний нет;
сверены сохранённые evidence и код, повторных live-запросов ревьюер не выполнял.
`make docs-check` — **60 страниц, 33 теста, OK**. Go-код не менялся,
`make all` и новый общий MCP-smoke в этом docs-only пункте не запускались.
