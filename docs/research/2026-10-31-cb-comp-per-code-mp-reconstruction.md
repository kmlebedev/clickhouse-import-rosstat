## 1. Короткий вывод

**No-go: per-code МП из 11 публичных листовых агрегатов не восстанавливается.**

| гейт | результат | |
|---|---|---|
| **G-R1** forward: медиана OOS R² «лист на кодах» | costs **0,766**, ibk **−0,698**, price_exp **0,449**; порог 0,7 и ≥ 0,5 по каждому | ❌ (ibk, price_exp) |
| **G-R2** inverse: лучший поиск vs identity | см. §5; поиск не бьёт статический offset на costs/price_exp, на ibk улучшает, но остаётся < 0 | ❌ |
| **G-R3** downstream | не запускался — G-R2 не пройден | — |

Причина не в качестве конкретного алгоритма, а в идентифицируемости: лист — это 11 линейных агрегатов на 87 кодов. Матрица `W` имеет ранг 11, нуль-пространство — **76 измерений**; лист не содержит информации о внутрилистовом разложении. Статическая (межкодовая) часть отклонения «код − лист» — всего **15–22 %**; остальные 78–85 % меняются во времени и не восстанавливаются. Любой «перебор» — это выбор prior; лучший prior — статический offset, и он же остаётся потолком.

## 3. Данные

87 кодов × 3 индикатора (ИБК, издержки, ценовые ожидания); train 2010-01…2022-12, holdout 2023-01…2024-09 (21 месяц), 176 полных месяцев. Пропуски — по кодам; ряды с < 60 общими месяцами не анализировались.

## 4. Forward-оператор

Вес `W` оценён на train блочно-диагонально (лист ← свои коды), ridge с неотрицательностью, строка нормирована на 1. Проверка «лист на кодах» OOS:

| индикатор | медиана OOS R² | провалы (примеры) |
|---|---:|---|
| ibk | **−0,698** | почти все листы, кроме agriculture 0,71, trade_retail 0,70, trade_wholesale 0,71 |
| costs | **0,766** | mining −10,7, manufacturing_investment −0,55 |
| price_exp | **0,449** | mining −14,5, manufacturing_investment −12,0, transport −5,46 |

G-R1 не пройден: два индикатора из трёх ниже порога 0,5. То есть даже агрегат как функция кодов нестабилен во времени — восстановление обратной задачи начинается с нестабильного оператора.

## 5. Обратная задача

`W` имеет ранг 11, нуль-пространство 76. На каждый месяц holdout решалась `W x = s` с prior; все методы — в JSON. Сводка (медиана OOS R² по кодам, normal-54 не применялся — holdout 21 месяц):

| индикатор | identity | offset (статический) | лучший поиск | static share |
|---|---:|---:|---|---:|
| ibk | −0,365 | −0,434 | **−0,129** (`ridge_prior:0,01` / `elim:0,005`) | 21,8 % |
| costs | 0,056 | **0,108** | 0,044 (`coord:0,1`) | 14,7 % |
| price_exp | −0,258 | **−0,115** | 0,063 (`coord:0,1`) | 17,5 % |

- `omp`, `coord`, `elim`, `factor`, `ridge_prior` (AR(1)-prior) — все методы поиска проверены; ни один не даёт медиану R² > 0 и выше identity на всех трёх индикаторах.
- На costs и price_exp **статический offset лучше любого поиска**: внутрилистовая динамика не даёт полезного сигнала, кроме среднего сдвига кода.
- На ibk поиск улучшает identity (−0,365 → −0,129), но остаётся отрицательным: даже лучший prior не предсказывает внутрилистовую динамику.
- G-R2 не пройден: положительная медиана только у 2 из 3 индикаторов, и ни один метод не бьёт offset там, где offset положителен.

## 6. Почему поиск не помогает

Если лист — агрегат `s = W x`, то разложение `x` на «среднее по листу + отклонение» имеет 76 свободных измерений на месяц: любое отклонение из нуль-пространства `W` даёт тот же лист. Никакой алгоритм поиска (исключение, активный набор, координатный спуск) не может выбрать истинное отклонение без prior. Prior из архива даёт только статическую часть — 15–22 % дисперсии отклонения; остальное время-зависимо. Отсюда потолок: R² восстановления не выше ~0,1–0,2, что подтверждают все методы.

Это не артефакт реализации: даже оракульный статический offset (средний сдвиг кода, оценённый на train) даёт лишь 0,108 на costs, −0,115 на price_exp и −0,434 на ibk. Ошибка forward-оператора (G-R1) добавляет второй слой неопределённости.

## 7. Риски и режимы отказа

- Публичная книга могла сменить методику/веса после 2022 — OOS-провал 2023–2024 может быть структурным, а не шумовым; это не меняет вывод (в live-периоде оператор как раз нестабилен).
- Винтаж архива — 2024-09; более поздних меток для проверки нет.
- 16 листов `cbr_mp_survey` шире 11; без mapping 87 → 16 их нельзя использовать в forward-тесте. Не проверено.
