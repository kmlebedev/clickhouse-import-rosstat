# e-disclosure — пилотный винтажный архив

**Дата:** 2026-10-18
**Что это:** 20 версий документов по трём эмитентам (PLZL, CHMF, SBER), скачанных с публичного e-disclosure.ru и разложенных в формате архива проекта.

## Структура

```
archive/
  registry.jsonl   # строки archive.Entry: source, name, fingerprint, sha256, size, url, key, first_seen
  metadata.jsonl   # sidecar: issuer, company_id, inn, doc_type, period, version, fileid, published_at, ...
  files/<key>      # байты объекта; key = edisclosure/<sha256[:16]>_<sanitized name>
```

`registry.jsonl` совместим с `archive.Entry` (пакет `archive/`): ключ относительный, объект можно положить в `archive.LocalStore` или `archive.YandexDisk` через `Put(ctx, key, body)`, а строку — через `Registry.Ensure(ctx, entry)`.

## Винтажная семантика

- `published_at` — дата публикации документа на e-disclosure (из колонки «Дата размещения»).
- `first_seen` — когда пилот увидел версию (2026-10-18; у добавленных позже — своё время). Это не дата события; для point-in-time использовать `published_at`.
- `version` — порядковый номер версии в рамках `(issuer, doc_type, period)`. Две пары версий:
  - SBER 2024FY: 2025-11-07 (v1) и 2025-11-20 (v2);
  - CHMF 2023FY: 2024-02-02 (v1) и 2024-08-23 (v2, перевыпуск).
- `sha256` — хеш содержимого; `key` содержит первые 16 hex, поэтому разные версии одного документа не схлопываются.
- `fingerprint` в пилоте равен `sha256` содержимого. В production лучше использовать тот же отпечаток, что и `source_publications` (HEAD/версия), чтобы архив и таблица версий называли версию одинаково.

## Чего архив пока не содержит

- **Версии событий.** Публичная страница показывает текущие сообщения, а не историю `Publish/Change/Delete/Exclude/Restore`. Регулярный опрос с `first_seen` и хешем фиксирует изменения **вперёд**; история до первого опроса скрейпингом не восстанавливается.
- **Полный бэкфилл.** В пилоте — выборочные ключевые документы. Публичный сайт отдаёт документы с 2009 года; их можно добрать скрейпингом и `FileLoad.ashx`, события — только вперёд.
- **XBRL/Excel.** Документы — PDF в ZIP; числовые ряды нужно извлекать парсером.

## Как расширять

1. `parser.py` собирает списки документов (`parsed/documents.jsonl`); `add_docs.py` качает выбранные `Fileid` и дописывает архив.
2. `build_archive.py` — ручной список уже скачанных файлов (имя в `~/Downloads`, `Fileid`, эмитент, тип, период, `published_at`, версия).
3. Для production — перенести объекты в `archive.LocalStore`/`YandexDisk` и записать строки через `Registry.Ensure`; `build/` в git не коммитится.

## Ограничения

- SBER МСФО раскрывается не полностью (решения ЦБ); в архиве только то, что опубликовано.
- Пилотный архив лежит в `build/edisclosure-probe/archive/` и не является production-хранилищем.
- Юридически это обязательные раскрытия эмитентов; собственные материалы ЦРКИ не архивируются.
