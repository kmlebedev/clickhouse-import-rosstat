# LLM-разметка RSS-потока батчами на `zai-org/GLM-5.3-Flash` — стоимость и бэклог

**Дата:** 18 октября 2026 г.
**Пункт:** `key-rate/phase-2-rss-llm-annotation` — [ROADMAP_KEY_RATE.md](../ROADMAP_KEY_RATE.md) §4.2 №24, issue [#122](https://github.com/kmlebedev/clickhouse-import-rosstat/issues/122).
**Спека:** [2026-10-18-rss-llm-annotation-design.md](../superpowers/specs/2026-10-18-rss-llm-annotation-design.md).
**План:** [2026-10-18-rss-llm-annotation.md](../superpowers/plans/2026-10-18-rss-llm-annotation.md).

## 1. Зачем считать

Пункт 1.10 размечал только Telegram-молнию — 44 сообщения. RSS-поток в `v_news_events` оставался без `sentiment`/`relevance`/`summary`/тегов. Для RSS нужна оценка стоимости: сколько позиций в бэклоге, сколько запросов и токенов уходит на батч, укладывается ли штатный прогон в 30-минутное расписание.

## 2. Охват и объём

Снимок `v_news_events` на 2026-10-18 до разметки: **312 строк** — 283 RSS (tass 92, cbr 92, smartlab 38, rbc 34, interfax 27) и 29 Telegram. Кандидаты — все Telegram-сообщения (поведение 1.10) + RSS, проходящие `newsFilter`; аннотируемые — только строки с непустым `content_hash` (строки до миграции 1.9 не аннотируемы).

Текст RSS неоднороден: у smart-lab — полный пост (до ≈31 КБ, 38 позиций), у новостных лент — краткое описание (≈100–500 байт), у ЦБ описания нет (только заголовок). Поэтому батч ограничен не только 10 сообщениями, но и 40 КБ текста: длинный пост становится батчем из одного элемента.

## 3. Конфигурация

| Параметр | Значение |
|---|---|
| Модель | `zai-org/GLM-5.3-Flash` |
| Профиль | `NEWS_LLM_PROFILE=glm`, `GLM_LLM_*`; OpenAI-совместимый `/v1/chat/completions`, `response_format=json_object`, `reasoning_effort=none` |
| Промпт | редакция 2, реестр 46 тегов |
| Батч | ≤10 сообщений и ≤40 КБ текста |
| Бэклог | штатно 50 позиций за прогон; приёмка — `NEWS_LLM_BACKLOG_LIMIT=500` |
| Расписание | без изменений: `dagu/news.yaml`, каждые 30 минут, `since` |

## 4. Тариф

| Модель | Input, $/1M | Output, $/1M | Источник |
|---|---|---|---|
| `zai-org/GLM-5.3-Flash` (Joingonka Gateway) | 0,0076 | 0,023 | [gate.joingonka.ai](https://gate.joingonka.ai/), тариф от 2026-10-17; шлюз добавляет 10% network cost и 5% конвертации |

Тариф — тот же, что в отчёте сравнения моделей [2026-10-17-mp-summary-llm-comparison.md](2026-10-17-mp-summary-llm-comparison.md) §7. Фактический счёт провайдера может отличаться на наценку шлюза; ниже — оценка по опубликованному тарифу.

## 5. Оценка до прогона

- Кандидатов: ≈400–430 (все аннотируемые RSS + Telegram; Telegram переразмечается с `prompt_version=1` на 2).
- Input: ≈140–170K токенов (средний RSS-текст ≈0,5–1 КБ + длинные посты smart-lab).
- Output: ≈50–70K токенов (summary + до пяти тегов на позицию).
- Стоимость: 140K × 0,0076/1M + 50K × 0,023/1M ≈ **$0,0022**; 170K/70K — ≈ **$0,0029**. Округлённо **$0,002–0,003** за бэкфилл, **≈$0,007 за 1000 позиций**.
- Время: 32 батча в живом прогоне (10 сообщений / 40 КБ), ~35–60 с на батч → ≈20–30 мин на весь бэклог при лимите 500. Штатный прогон 50 позиций — 5–10 батчей, укладывается в 30 минут.

## 6. Фактический прогон

Команда:

```bash
NEWS_LLM_PROFILE=glm NEWS_LLM_BACKLOG_LIMIT=500 make import STAT=news_watch
```

Прогон 2026-10-18 на dev-ClickHouse (`NEWS_LLM_PROFILE=glm`, `NEWS_LLM_BACKLOG_LIMIT=500`):

| Показатель | Значение |
|---|---|
| Батчей (основной прогон) | 32 (10 сообщений / 40 КБ; батчи с длинными постами — 1–8 сообщений) |
| Размечено | 239 сообщений, 276 тегов |
| Догон | 1 батч, 3 сообщения, 3 тега (отложенные версии URL) |
| Prompt-токены | 175 620 |
| Completion-токены | 29 325 |
| Стоимость по тарифу | 175 620/1M × 0,0076 + 29 325/1M × 0,023 = **$0,0020** |
| С наценкой шлюза (10% network + 5% conversion) | ≈ **$0,0023** |
| Время | основной прогон 21 мин 16 с; догон 21 с; no-op 4 с |
| Итог в витрине | 339 строк, 221 аннотируемая, 221 размечена; RSS 191/191, Telegram 30/30 |
| `news_annotation` v2 | 242 doc + 279 tag строк; v1 (1.10) — 44 doc + 39 tag |
| `news_events.sentiment` | 0 непустых (остаётся NULL) |
| `make mcp-check` | ПРОВЕРКА ПРОЙДЕНА, `LLM-разметка RSS: 191 из 191` |

Первый прогон вскрыл дефект кандидатного SQL: `newsFilter` начинается с `(?i)`, и драйвер ClickHouse считал `?` внутри регулярки позиционным плейсхолдером (4 `?` при 2 аргументах). Исправлено коммитом `86a6350` — фильтр передаётся SQL-параметром (`match(title, ?)`, `match(description, ?)`), после чего прогон прошёл штатно. Этот дефект — причина, по которой стоимость в отчёте считается по фактическим usage-строкам, а не по числу кандидатов.

## 7. Вывод

Штатный предел 50 позиций за прогон сохраняется как основной контроль стоимости; `NEWS_LLM_BACKLOG_LIMIT` — только для разового бэкфилла после простоя или смены `prompt_version`. Стоимость разметки пренебрежима по сравнению с временем и зависит от провайдера; ограничение — не деньги, а 30-минутное расписание и 300-секундный дедлайн запроса.
