# Аналитика ДОМ.РФ: источник машиночитаемых рядов рынка жилья

**Дата:** 2026-10-23
**Объект:** `xn--d1aqf.xn--p1ai` (дом.рф) — раздел «Аналитика», индекс цен, книга «Топ ипотечных банков»; `xn--80az8a.xn--d1aqf.xn--p1ai` (наш.дом.рф, ЕИСЖС).
**Задача:** для контура «кредит → недвижимость как инвестиционный актив» (не потребительский спрос) выбрать источники, которые можно забирать live и машиночитаемо, и дать go/no-go до реализации.
**Метод:** живые HTTP-пробы 2026-10-23 (`curl`, браузерный UA), разбор встроенных JSON-блоков страницы, пробные POST/POST-панели, сверка с уже импортированными рядами ЦБ/Росстата.
**Границы:** не проверялись платные продукты ДОМ.РФ, «продома.дом.рф» (TLS-обрыв), исторические винтажи публикаций, условия лицензии за пределами `robots.txt` и пользовательского соглашения сайта.

**Как устроен антибот.** Сайт отдаёт на часть запросов HTTP 200 с JS-оболочкой ServicePipe (`<js-challenge-loader>`, 1 787–1 795 байт) вместо страницы. Замеры 2026-10-23 (браузерный UA, `curl`):

```
/analytics/                  full=4  challenge=4   (8 попыток)
/analytics/mortgage/         full=3  challenge=5   (8 попыток)
/price-index/                full=5  challenge=3   (8 попыток)
/analytics/mortgage/ + jar   full=1  challenge=19  (20 попыток)
наш.дом.рф /                 full=0  challenge=20  (20 попыток)
```

Выводы: (1) challenge вероятностный, а не постоянный; (2) cookie-jar ухудшает результат — cookie `spid` без решённого JS-токена помечает клиента; (3) файлы `/api/v2/content/download/...` отдаются **без UA и без cookie** (проверено: 200, `application/vnd.openxmlformats…`, 435 079 байт), WAF на них не распространяется; (4) `HEAD` и `Range` на файл **вероятностно** дают 307 на тот же URL — когда HEAD проходит, версия файла строится по `ETag`/`Last-Modified`/`Content-Length` и повторный импорт становится no-op (наблюдалось 2026-10-23: версия `2255ad1c…`, 4 612 точек), когда 307 — версии нет и прогон полный.

## 3. Покрытие и качество данных

### A. Общая таблица по РФ

225 датированных строк, дублей и дыр нет; 2006–2008 — квартальные строки, с 2009-01 месячные. Покрытие колонок (проверено по файлу):

| Колонка | С какой даты |
|---|---|
| объём выдачи, всего | 2006-01 |
| количество выдачи, всего; средний размер кредита | 2009-01 |
| количество и объём **в т.ч. ДДУ** | 2016-02 |
| разбивка рубли/валюта: объём | 2006-01 |
| разбивка рубли/валюта: количество | 2009-01 |
| ставки «месяц» / «с начала года» | 2009-02 / 2006-01 |
| ставки «первичный/вторичный рынок» | 2016-02 |
| портфель, просрочка | 2006-01 (портфель ДОМ.РФ — 2011-01) |
| просрочка 90+ | 2010-02 … 2026-08 |

«Нет данных» записано литералами `X`, `x`, `-` и пустой ячейкой — точкой не становится; часть ячеек — текст с десятичной запятой («14,9»), часть — числа, поэтому разбор читает сырые значения и нормализует разделители. Заголовок — 3 строки с merged-диапазонами; путь колонки после заполнения merged и схлопывания повторов уникален. Блок задолженности даёт три разных итога (верхний «всего», «на балансе банков / всего» и «Банковский портфель») — пути различаются уровнем, и все три импортируются.

Сверка с уже импортированным: значения 2026-09 — 662 658 кредитов на 2 959 618 млн руб., из них ДДУ 234 004 на 1 349 429 млн руб. (45,6 % объёма), ставка 10,08 % (месяц), 7,33 % первичка, 12,45 % вторичка — согласуется с публичной риторикой ДОМ.РФ о перетоке в первичку.

### B. Недельные ставки

254 даты, по убыванию; `values` — CSV на продукт. «Льготная ипотека» короче (138 значений, программа завершилась) — короткий ряд, не ошибка. Первая точка 03.09.2021: Новостройка 8,37 %, Вторичный рынок 8,54 %; последняя 16.10.2026: 18,76 % и 18,69 %. Значения — **проценты**, не доли (в `domrf_mortgage` — доли; см. §6).

### C. Индекс цен

69 месяцев × 75 регионов; ключ `(region, room_count)`; `class` всегда «Общий» (`estateClass` игнорируется). Предел одного запроса — 120 слотов (400 «Поле Regions не должно превышать 120»): панель 75 × 4 забирается тремя чанками; ответ на 75 регионов — 1,8 МБ. Сделки: РФ за 2026-09 — 63 779, сумма по субъектам — ровно 63 779 (регионы не дублируются, строку РФ нельзя складывать с субъектами). Экспорт `deals` даёт 68 601 за месяц — расхождение ≈7 % с `index_count_deal`: разные определения выборки (экспорт — все ДДУ, индекс — наблюдения, попавшие в расчёт). Для моделей использовать один источник, предпочтительно `index_count_deal` (он же в панели с ценой).

### D. «Долевое строительство»

`наш.дом.рф` — 20/20 challenge, включая `/robots.txt`; текст «Доступ заблокирован [403]» на статике дом.рф без cookie. Машиночитаемого доступа с обычным HTTP-клиентом нет. На дом.рф раздел `/analytics/housing-construction/` содержит только PDF (3 блока).

## 4. Винтажи, ревизии, PIT

- Винтажного архива у ДОМ.РФ нет: файл по фиксированному `/api/v2/content/download/<id>/<token>/` отдаёт текущую версию. Токен файла, вероятно, меняется при обновлении (наблюдение одного выпуска), поэтому ссылка берётся со страницы каждый прогон.
- XLSX A ревизуется: источник пересчитывает историю (например, просрочка 90+ обрывается на 2026-08, тогда как остальные ряды идут до 2026-09).
- Индекс C может пересчитываться за прошлые месяцы; `ReplacingMergeTree` хранит последнюю версию — истории ревизий нет.
- **PIT**: до первого прогона `published_at` не фиксируется. Для честного as-of нужен `loaded_at`/`published_at` (дата публикации блока `props.file.date`, у A — `01.10.2026`; у B — дата последней недели; у C — `month_dt` максимума). В этом пункте PIT не заявляется: append-only снимков нет, ряды ревизуются на месте.

## 5. Риски и режимы отказа

| Риск | Проявление | Митигация |
|---|---|---|
| Антибот вероятностный | 200 + 1,8 КБ JS-оболочка вместо страницы | 20 попыток с паузой 2 с и джиттером; детект по размеру и маркеру; ошибка, а не «0 строк»; шаг dagu повторяется 3×300 с |
| Полный блок (как наш.дом.рф) | 20/20 challenge | смена источника решением владельца; файлы `/api/` при этом остаются доступны |
| HEAD/Range вероятностно закрыты | 307 на тот же URL в части запросов | префлайт fail-open: нет версии — полный идемпотентный прогон; прошёл — no-op |
| Внутренний API без контракта | смена `v2`-схемы | fail-fast разбора, тесты на реальной фикстуре |
| `date_from`/`date_to` не работают | 400 в любом формате | история тянется целиком, инкремент — на стороне импортёра |
| `estateClass` игнорируется | всегда «Общий» | разрез по классу не обещаем |
| PDF-only блоки | 3 блока housing-construction | не импортируем; отдельный пункт при появлении машиночитаемого формата |
| robots `Crawl-delay: 30` | — | 1–3 запроса в неделю, расписание dagu |

## 6. Рекомендация и критерий приёмки

**Go** по A, B, C; **go позже** по книге банков (P2); **no-go** по ЕИСЖС и PDF.

- Таблицы: `domrf_mortgage_market` (24 ряда, `series/date/value`), `domrf_mortgage_weekly` (`product/date/rate`, % годовых), `domrf_price_index` (`region/room_count/date/index_value/index_diff_month/deals`).
- Витрины: `v_domrf_mortgage` (long, A+B), `v_domrf_price_index` (панель).
- Каталог: 24 + 5 рядов; единицы и стартовые даты — в `v_series_catalog`.
- Единица ставок: новые таблицы — **проценты**; `domrf_mortgage` (bank) остаётся в долях, витрины не смешиваются.
- **Критерий приёмки:** три живых прогона дают 4 612 / 1 154 / 20 700 точек с крайними датами 2026-09-01 / 2026-10-16 / 2026-09-01; повтор `domrf_price_index` — no-op; `make all`, `make mcp-check`, `dagu validate`, `make docs-check` зелёные; протокол — в PR.

Оценка объёма: спека+документы — 0,5 дня; пакет и три импортёра с тестами — 2 дня; приёмка — 0,5 дня. Зависимостей нет.

## 7. Что не проверено

- Поведение антибота вне окна 2026-10-23 (2 часа, одна машина) и на staging/прод-IP.
- Стабильность токена файла между месячными выпусками (наблюдение одного выпуска).
- Полнота ревизий истории A и C между выпусками (нужен второй снимок через месяц).
- Машиночитаемость «продома.дом.рф» (TLS-обрыв) и платных продуктов ДОМ.РФ.
- Условия лицензии сверх `robots.txt`: пользовательское соглашение сайта не разбиралось юридически; в репозиторий копируются только значения рядов, не PDF/графики.
- Альтернативы для «долевого строительства» (ЦБ «проектное финансирование», ввод жилья Росстата) — не проверялись, отдельный пункт `real-estate/1.3` (Blocked).
