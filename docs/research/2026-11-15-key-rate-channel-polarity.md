## Воспроизведение

Через MCP прочитать `v_cbr_mp_summary`, `v_cbr_mp_summary_blocks` и
`v_cbr_mp_summary_channels`, сохранять локально вне git. Формат входа replay:
`{observed_at, documents:[{meeting_date, blocks:[{block,subsection,kind,seq,text}],
annotations:[{channel,kind,method,model,prompt_version,seq,text}]}]}`.
Порядок текстовых блоков восстанавливается по `mpSummaryBlocks`, затем seq;
алфавитная сортировка названий блоков не является порядком документа.

```sh
make mp-channel-replay MP_CHANNEL_REPLAY_INPUT=/tmp/key-rate-polarity-replay.json MP_CHANNEL_REPLAY_OUT=/tmp/key-rate-polarity-result.json
```

Harness не делает сетевых вызовов/SQL/записей в БД; при потерянной/добавленной
идентичности цитаты падает. Полный корпус не коммитится. Минимальные fixtures —
`cbr/testdata/mp_summary_polarity.json` с URL источников.

## Оставшийся гейт: точное обновление dev

`kind` входит в ключ ReplacingMergeTree; вставка исправленных строк оставит старые.
Обычный импорт известные резюме пропускает. Поэтому no-op — проверка поведения
импортёра, не приёмка исправленных исторических меток.

Предлагаемый объём — ровно **10 regex-строк** четырёх дат из replay.json, модель
пустая, prompt_version=0. Остальные 3650 regex-строк и 2932 LLM-строки сохраняются.
Перед применением: повторный MCP-снимок и сверка полных ключей/хешей, резервная
копия всех затрагиваемых строк; расхождение со снимком прерывает процедуру.
После: старые 10 ключей отсутствуют, новые 10 присутствуют, полный набор прочих
строк совпадает; повтор — no-op. Сбой между удалением и вставкой должен иметь
предусмотренное восстановление из резервной копии. Схема и версии не меняются.

Процедура реализована с plan/apply/rollback, прошла safety-review; запись ещё не запускалась. До разрешения
этого гейта #594 не закрывается и итоговый PR не открывается. Связанный дефект GLM
остаётся известным evaluation-case; его переоценка — отдельный версионированный прогон.


### Реализация ограниченного refresh

Ранний режим `cbr_mp_summary` до DDL/HTTP/LLM, фиксированные 10 identities.
`plan` на dev: original=10, corrected=0, Imported 0 rows.
`apply`/`rollback`: только тот же hostName, loopback DSN, база default;
постоянный flock inode в /tmp, проверка незавершённых мутаций, проверка всех
физических версий без FINAL. Совпадающие физические дубли допустимы, отличающийся
текст одной идентичности запрещает запись. O_EXCL backup 0600, fsync файла/каталога.

До INSERT создаётся durable intent с operation_id (-insert/-delete в query ID).
Любой неопределённый исход оставляет маркер и запрещает последующие изменения,
даже если system.mutations пуст: запрос мог ещё не зарегистрироваться. Маркер
снимается только после успешных постусловий либо оператором после доказанного
завершения/отмены запросов и мутаций и сверки данных с backup. Не удалять /tmp
lock/marker внешней очисткой; автоматического снятия по времени нет. Параллельные
ручные SQL-писатели на время процедуры исключаются.

Safety-review gpt-6.1-terra: исходно найдены гонки и скрытые физические версии;
после flock/raw preflight/durable intent замечания закрыты. Тесты отказов,
конкурентного запуска, неизменности backup и apply/rollback идемпотентности — pass.
Полный `make all` повторяется после последней правки режима.
