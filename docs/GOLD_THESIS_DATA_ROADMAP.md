**Выводы оценки:**

1. **~80% количественных тезисов статьи верифицируемо уже сегодня** — при совместном использовании MCP-витрин и плагина kimi-datasource. Проект как «сопроцессор» прогнозной сессии состоялся: цена, ставки, инфляция, календарь, бюджет РФ — свежие и читаются одним запросом.
2. **Жёсткие пробелы закрываются:** ETF-потоки WGC — 20 структурных рядов и витрина `v_gold_etf_flows` (фаза 3 и follow-up, 11.10; канонический источник — импортёр `wgc_etf_flows`; сессионный ввод `source='webbridge'` — фолбэк), FedWatch остаётся ручным (фаза 0). **Запасы EIA закрыты фазой 2 (11.10.2026):** импортёр `eia` обновляет `distillate_stocks` (и `refinery_utilization`) по средам без ручного ввода.
3. **Операционный пробел `v_gold_dashboard` устранён 11.10.2026 (фаза 0):** все пять индикаторов `stale=0`, три порога пробиты (crack 107, FedWatch 81% — зона алерта, DXY 102,2) — детали и runbook в фазе 0. Регламент повторного заполнения зафиксирован там же.
4. **Плагин kimi-datasource — сессионный канал, не ETL.** Go-импортёр напрямую в Yahoo с этой сети невозможен (HTTP 429, см. ARCHITECTURE.md §6.1 `lbma_gold`); datasource работает, потому что запросы идут через сервис Kimi. Поэтому роль плагина — выборки внутри прогнозной сессии и запись результатов через `manual_series`, а не автономные импортёры.

### Фаза 0 — операционная — ✅ выполнен 2026-10-11 (без кода)

**Пробел (на момент оценки):** `v_gold_dashboard` пуста — верификация дизельного канала, FedWatch и ETF-потоков не работает.
**Что даёт:** тезисы 1, 5, 6 статьи становятся проверяемыми по факту, а не по памяти автора.
**Метод (регламент сессионного заполнения):** значения пяти рядов пишутся в `manual_series` через `POST /v1/manual_series` (ingest-endpoint):

| Ряд | Источник значения | Частота (триггер `v_events_calendar`) |
|---|---|---|
| `crack_ulsd_proxy` | `HO=F` × 42 − `CL=F` через datasource (сессия) | еженедельно, среда (EIA) |
| `distillate_stocks` | **автоматически** — импортёр `eia` (EIA API v2, серия WDISTUS1, `dagu/eia.yaml`); ручной ввод из WPSR — только фолбэк, если импортёр не отработал (приоритет источника: `eia > webbridge > manual`) | еженедельно, среда (импортёр) |
| `fedwatch_dec_hike` | ручной ввод с CME FedWatch | еженедельно + перед CPI/FOMC |
| `etf_flows_month` | ручной ввод из WGC ETF Flows Commentary | ~10-е число месяца |
| `dxy` | `DX-Y.NYB` через datasource | еженедельно |

**Runbook (проверено 11.10.2026):**

1. Поднять ingest-сервис: `make run-ingest` (localhost:8081) — `INGEST_TOKEN` берётся из `~/.config/rosstat/env` (`make` подключает файл сам), в репозитории значение не хранится. Проверено end-to-end 11.10.2026: без токена — `401`, с токеном — `200 {"inserted":N}`.
2. Снять значения: crack — datasource `HO=F` и `CL=F`; dxy — `DX-Y.NYB`; distillate_stocks — **не нужно** (с фазы 2 приходит из импортёра `eia`, `dagu/eia.yaml` по средам); fedwatch_dec_hike — CME FedWatch; etf_flows_month — WGC Gold ETF Flows. Если импортёр `eia` не отработал, ручное значение всё равно подхватится как фолбэк (приоритет `eia > webbridge > manual`).
3. Записать одним POST: `curl -X POST $INGEST_URL/v1/manual_series -H "Authorization: Bearer $INGEST_TOKEN" -H "Content-Type: application/json" -d '[{"series":"...","date":"YYYY-MM-DD","value":N}, ...]'` — ответ `{"inserted": N}`.
4. Проверить через MCP: `SELECT * FROM v_gold_dashboard` — у всех рядов `stale=0`, флаги считаются.
5. Описания рядов (единицы, частота, происхождение — правило 11 AGENTS.md): сид [sql/gold_dashboard_manual_series_catalog.sql](../sql/gold_dashboard_manual_series_catalog.sql), применение `make ch-sql FILE=...` (идемпотентен).

**Результат — приёмка 11.10.2026:** все пять индикаторов `stale=0`; три порога пробиты:

- `crack_ulsd_proxy` = **107,16** USD/барр (10-09) → `flag=1` — медвежий сигнал дизельного канала жив (статья: >$100 при норме $15–25);
- `fedwatch_dec_hike` = **81%** (на 05.10, CME FedWatch) → `flag=1`, выше уровня алерта 80%;
- `dxy` = **102,21** (10-09) → `flag=1` — порог модели >102 (путь к $3 750–3 800 по §8 статьи) пробит;
- `distillate_stocks` = **105 100** тыс. барр (неделя 02.10; −12% к 5-летней средней — статья §6 писала −14%);
- `etf_flows_month` = **+$10 млрд** (сентябрь; WGC: рекордный квартал Q3 +$31 млрд).

**Наблюдение для статьи:** два из трёх пробитых порогов (FedWatch 81%, DXY 102,2) — прямые факты в пользу медвежьего сценария 35% из §7; сентябрьский ETF-поток (+$10 млрд) — против версии «август был техническим отскоком»: проверка тезиса §2 статьи пройдена положительно.

### Фаза 1 — datasource → контур — ✅ выполнен 2026-10-11 (полуавтомат; ограничение по IMF)

**Пробел (на момент оценки):** «пол» $4,000 тестируется по MOEX-прокси (лаг выходных, зависимость от курса ЦБ); DXY и покупки ЦБ отсутствуют в БД.
**Что даёт:** тезисы 2–4 обновляются по настоящему споту и резервам; расхождение прокси/спот становится измеримым.
**Метод:** запись в контур через ingest-endpoint — новые `POST /v1/gold_prices` (venue `comex_front`) и поле `source` в `POST /v1/manual_series` (`manual`/`webbridge`/`imf`); витрина `v_imf_macro` (импортёр `gold_views`); каталоги — `gold/series_meta.go` (comex_front) и сид `sql/imf_ra_gold_catalog.sql`.

**Runbook (проверено 11.10.2026):**

1. `make run-ingest` (токен из env-файла).
2. GC=F через datasource (`yahoo_finance`, period `2y`) → JSON `[{"venue","date","usd"}]` → `POST /v1/gold_prices` одним батчем.
3. Резервы: `imf_irfcl_data` (RA_GOLD, `frequency=M`) → `POST /v1/manual_series` с `source='imf'`, дата — первый день месяца.
4. `make import STAT=gold_prices` — без него на чистой БД витрины `v_gold_prices` нет: её создаёт импортёр (`util.CreateView`), `EnsureTables` ingest'а витрину не создаёт. Затем `make ch-sql FILE=sql/imf_ra_gold_catalog.sql`; `make import STAT=gold_views`; `make mcp-user`.
5. Проверка: `SELECT count(), min(date), max(date) FROM v_gold_prices WHERE series='comex_front'` (витрина появляется только после шага 4; на уже наполненной dev-БД она существует и раньше); `SELECT * FROM v_imf_macro ORDER BY date DESC`; `make mcp-check`.

**Результат — приёмка 11.10.2026:**

- `comex_front`: **502 точки**, 2024-10-11 … 2026-10-09 (close $4 216,3); «пол» тестируется по фьючерсу: минимум с 01.06 — **$3 992,1 (16.07)**, т.е. по COMEX-закрытиям «пол» уже пробивался, а не только внутридневно (MOEX-прокси давал $3 976 внутри дня 15.07);
- `v_imf_macro`: **заполнен только Китай** (`ra_gold_chn`, 22 месячных точки 2024-01…2025-10); дельты читаются одним запросом (`argMaxIf` по годам: −312 млн USD за 2025);
- DXY — настоящий `DX-Y.NYB` уже введён фазой 0 (`v_gold_dashboard.dxy` = 102,21);
- `make mcp-check` — ПРОВЕРКА ПРОЙДЕНА; сырая `gold_prices` под `kimi_reader` — `ACCESS_DENIED` (497).

**Ограничение (важное):** IRFCL через datasource отдаёт золото одним индикатором `IRFCLDT1_IRFCL40_USD`, и по наблюдаемым 7 странам данные есть только у Китая: POL/CZE/TUR — нули (не пишем: читались бы как «резервов нет»), RUS/KAZ — индикатор отсутствует, UZB — данных нет. Тезис «Польша +98 т YTD» рядом IMF **не закрывается**; резервы/покупки ЦБ по остальным странам — follow-up на WGC (WebBridge/ручной ввод; вне объёма фазы 3 — отдельный пункт). Юнит ряда CHN — как отдаёт IRFCL (USD), не тонны и не млн; тонны — делением на цену золота.

### Фаза 2 — автоматизация EIA (~2–3 дня, код) — ✅ выполнена 2026-10-11

**Пробел:** запасы дистиллятов — единственный индикатор дизельного канала без автоматического источника.
**Что даёт:** дашборд верификации §6 статьи (пункт 1: «прирост запасов = кризис снимается») работает без ручного ввода.
**Метод:** вернуть в план импортёр `eia` (был вычеркнут, ARCHITECTURE.md §6.1): EIA API v2, Weekly Petroleum Status (запасы дистиллятов; опционально — загрузка НПЗ), ключ `EIA_API_KEY` в env → `macro_series`; dagu-расписание под среду; по правилу 11 — catalog + комментарии + грант.
**Приёмка:** `distillate_stocks` в `v_gold_dashboard` обновляется без ручного ввода, `stale=0` после каждой среды; `make mcp-check` зелёный.

**Реализовано (ветка `feat/eia-importer`, спека [docs/superpowers/specs/2026-10-11-eia-importer-design.md](superpowers/specs/2026-10-11-eia-importer-design.md)):**

- пакет `eia/` (`Name()` = `eia`): EIA API v2, два ряда — `distillate_stocks` (WDISTUS1, тыс. барр.) и `refinery_utilization` (WPULEUS3, %) → `macro_series` (`source = 'eia'`); ключ обязателен, маскируется в ошибках; пагинация по `response.total`;
- расписание `dagu/eia.yaml` — среда 19:43 МСК, retry 3 × 300 с; витрина `v_eia_petroleum` (комментарии + грант `kimi_reader` в `sql/mcp_kimi_reader.sql`); каталог рядов `series_catalog` (source `eia`, 2 ряда);
- `v_gold_dashboard` читает значение по приоритету источников `eia > webbridge > manual` (ручной ввод — фолбэк); коды серий подтверждены фасетами API 11.10.2026 (ожидавшийся `WUPRUUS2` в фасетах отсутствует — используется `WPULEUS3`).

**Результат — приёмка 11.10.2026:** `make import STAT=eia` → 810 строк (405 + 405, 2019-01-04…2026-10-02); `v_gold_dashboard`: `distillate_stocks` = **105 138 тыс. барр. (EIA, 02.10)**, `stale=0` — значение переключилось с ручного 105 100 на автоматическое; `make all` зелёный (тесты `eia/`, `views/`); `make mcp-check` — ПРОВЕРКА ПРОЙДЕНА (добавлены проверки витрины, каталога и дашборда); повторный импорт идемпотентен (`ReplacingMergeTree`).

**Осталось для полной автономности (вне объёма фазы):** витрину `v_gold_dashboard` создаёт импортёр `gold_views`, а он не в расписании dagu — после merge новые ряды приходят автоматически, но новую логику приоритета источников на staging надо применить один раз вручную (`make import STAT=gold_views`); расписание dagu считает cron в локальной TZ хоста (как и в остальных DAG).

### Фаза 3 — спрос, консенсус и обратная связь (~3–5 дней, код) — ✅ выполнена 2026-10-11

**Пробел:** ETF-потоки WGC и банковские цели хранятся только в тексте статьи; ошибки прошлых прогнозов не считаются.
**Что даёт:** тезис 1 (ETF-цикл), блок «Сравнение с консенсусом» и раздел «Проверка прошлого прогноза» обновляются данными.
**Метод:**
- полуавтомат WGC ETF Flows (ежемесячный сид/ручной ввод структурированных рядов: поток $, тонны, AUM по регионам);
- таблица `gold_forecasts` (DDL уже описан в ARCHITECTURE.md §6.2, не реализована): цели Goldman/JPM/HSBC/UBS/Citi, ввод через ingest/сид;
- автозаполнение `forecast_log.actual` после `target_date` (сверка с `gold_prices`).
**Приёмка:** `v_forecast_accuracy` показывает ошибки прогнозов Q3/Q4 (`is_resolved`, `error_pct`); консенсус банков читается запросом к одной таблице.

**Реализовано (ветка `feat/gold-phase3-demand-consensus`, спека [docs/superpowers/specs/2026-10-11-gold-phase3-demand-consensus-design.md](superpowers/specs/2026-10-11-gold-phase3-demand-consensus-design.md)):**

- **WGC ETF Flows — 20 структурированных рядов** в `macro_series` (`source='webbridge'`): поток USD и тонн, запасы (holdings) в тоннах, AUM — по миру и 4 регионам WGC (`world/north_america/europe/asia/other`; имена `etf_<метрика>_<регион>`; дата точки — конец отчётного месяца). Каталог — сид `sql/wgc_etf_flows_catalog.sql` (20 записей); витрина `v_gold_etf_flows` (строка на месяц×регион, приоритет источников `webbridge > manual`, невведённая метрика — NULL, не 0). Ввод — существующим `POST /v1/manual_series` (`source='webbridge'`): канал сессионный (полуавтомат), код ingest в этой части не менялся.
- **`gold_forecasts`** — DDL §6.2 реализован (копии: `ingest/schema.go` и сид — совпадают). Новый валидирующий endpoint `POST /v1/gold_forecasts` (author/published/horizon/scenario/low/high/point/probability; `scenario` расширен значением `range` — банковский диапазон). **Пробел:** геополитика и новостной фон — вне контура; GRAM-атрибуция и режимная детекция — только в плане.

## 3. Roadmap аналитических витрин (токен-экономия)

**Проблема (замерено 2026-10-11):** типовые вопросы прогнозной сессии сегодня требуют выгрузки рядов в контекст LLM и арифметики «в уме»:
- «Сколько тестов пола $4,000 и ближайший минимум» → 93 строки `v_gold_prices` (~2k токенов) + подсчёт в сессии (факт: минимум режима $3 917,9 на 01.06; 28 дней ниже $4 100);
- «CPI YoY и сюрприз к прошлому выпуску» → 13 строк `v_bls_macro` + ручной YoY/MoM;
- аналогично: тренд реальных доходностей, недельная волатильность, drawdown от пика, дельты резервов ЦБ.

При регулярных сессиях это повторяющийся расход токенов и невоспроизводимая арифметика. Решение — перенести расчёты в код ClickHouse (window functions в view): однострочная аналитическая витрина заменяет ad-hoc SQL + выгрузку десятков строк одним запросом ~150 токенов, а результат становится детерминированным.

**Реализация (по конвенциям проекта):** пакет `views/` — расширить импортёр `gold_views` или завести `gold_analytics`; витрины через `util.CreateView` с гейтом по таблицам-источникам; комментарии таблицы и каждой колонки (`ALTER TABLE ... MODIFY COMMENT` / `COMMENT COLUMN`); `GRANT SELECT` для `kimi_reader` в `sql/mcp_kimi_reader.sql`; обновление ARCHITECTURE.md §6.3 и README.md тем же PR; проверка `make mcp-check`.

### Сырые таблицы или витрины — рекомендация: витрины

- **Один источник истины для текста и графика.** Статью обновляет агент через MCP по витринам `v_*`; если панели строить по сырым таблицам с собственным SQL, логика (FINAL-дедупликация, YoY, окна, пороги) начнёт расходиться: «в статье одно число, на графике другое». ## 5. CatBoost как конкурентный ML-трек прогноза

**Фактура (проверено на ClickHouse 26.10.1):** функции `catBoostEvaluate` в сервере **нет** — нативный инференс CatBoost-моделей был экспериментальным и из современных версий ClickHouse удалён (`system.functions` не содержит `*catboost*`). Встроенные ML-функции, которые есть: `stochasticLinearRegression`, `stochasticLogisticRegression` (in-DB базлайн), плюс time-series функции §4. Следствие: **ClickHouse — это feature store и хранилище прогнозов, но не движок инференса**; CatBoost живёт снаружи (Python).

**Место в контуре:** ROADMAP_DCF_POLYUS.md (фаза 5) уже предусматривает «ML-ансамбль как конкурентный трек прогноза (DM-тест против экспертного)». CatBoost — кандидат на этот трек: градиентный бустинг по табличным признакам хорошо ложится на структуру `macro_series` (лаги макро-рядов, пороговые флаги, календарные признаки), нативно работает с категориями и пропусками, не требует масштабирования признаков.

### Архитектура интеграции

```
ClickHouse (витрины/ряды)  ──выгрузка обучающей матрицы (clickhouse-connect / CSV)──▶  Python + CatBoost (обучение, walk-forward)
        ▲                                                                                      │
        └──── прогнозы: macro_series (source='catboost') или forecast_log через ingest ────────┘
Grafana читает оба трека (экспертный из model_runs, ML из macro_series/forecast_log) — сравнение на v_forecast_accuracy
```

- **Feature store — витрины §3:** `v_macro_releases`, `v_rates_snapshot`, `v_gold_technicals`, `v_scenario_state` уже дают готовые признаки (темпы, дельты, флаги) — матрица собирается одним SQL, а не ручной инженерией в pandas. Версия набора признаков фиксируется определением витрины.
- **Целевая переменная:** средняя цена квартала / недели из `gold_prices` (та же метрика `xau_q_avg`, что в `forecast_log`, — треки сопоставимы).
- **Запись прогнозов:** через существующий ingest-endpoint (`forecast_log`, metric с суффиксом трека) или батчем в `macro_series` с `source='catboost'` — оба пути не требуют новых таблиц.
- **Сравнение треков:** `v_forecast_accuracy` / `v_forecast_accuracy_live` (§3) считает ошибки обоих треков; Diebold–Mariano тест — в Python-скрипте поверх выгрузки.

### Шаги (отдельная фаза после §2 фазы 3 и §3)

1. **C1. Обучающая матрица:** скрипт выгрузки признаков из витрин + таргета из `gold_prices` (walk-forward сплиты, без look-ahead: признак строго раньше целевой даты). Приёмка: воспроизводимый датасет, дата-срез в метаданных.
2. **C2. In-DB базлайн:** `stochasticLinearRegression` поверх тех же признаков — бесплатная точка отсчёта внутри ClickHouse. Приёмка: ML-базлайн виден в `v_forecast_accuracy`.
3. **C3. CatBoost-трек:** обучение в Python, прогнозы в БД по расписанию (dagu), версионирование модели (файл модели + дата + набор признаков). Приёмка: ML-прогноз публикуется тем же конвейером, что экспертный.
4. **C4. Оценка:** DM-тест CatBoost vs эксперт vs in-DB базлайн на истории прогнозов; решение о роли ML-трека (советник / замена) — по результатам. Приёмка: задокументированное сравнение, статус в этом файле.

**Осторожности (зафиксировать при реализации):** макроряды короткие (месячные, ~20 лет ≈ 240 точек) — высок риск переобучения; обязательны walk-forward валидация, ограничение глубины/числа признаков и сравнение с наивным базлайном. ML-трек не заменяет сценарную рамку статьи: вероятности сценариев остаются экспертными, ML — независимый измеритель точности.
