# Git-зеркало реестра винтажного архива

`registry.jsonl` в этом каталоге — **копия** реестра версий файлов источников. Сам реестр живёт
в хранилище винтажного архива (Яндекс.Диск, `disk:/rosstat-archive/registry.jsonl`); истина —
файл там. Здесь он лежит, чтобы реестр был виден и версионировался в репозитории: по нему видно,
какие версии файлов сохранены, без доступа к Диску и без ClickHouse.

Файлы архива (`key` из реестра) в git **не хранятся** — только реестр: версии файлов могут весить
сотни мегабайт, и их место в хранилище, а не в истории репозитория. Реестр читается без ClickHouse:
таблицы для него нет намеренно (он обязан быть доступен при пустой БД).

## Как обновлять

```bash
make archive-registry                        # ARCHIVE_BACKEND берётся из окружения
make archive-registry ARCHIVE_BACKEND=yandex # явный бэкенд; нужен ARCHIVE_YANDEX_TOKEN
make archive-registry ARCHIVE_BACKEND=local ARCHIVE_LOCAL_DIR=build/archive-dev
```

Цель собирает бинарник и запускает его в режиме `ARCHIVE_ACTION=registry`: режим скачивает
`registry.jsonl` из хранилища и пишет его в `docs/archive/registry.jsonl` (`ARCHIVE_REGISTRY_OUT`
переопределяет путь). ClickHouse этому режиму не нужен — подключения к базе не происходит.

Пустой `ARCHIVE_BACKEND` — ошибка этого режима, а не пустое зеркало: выключенный архив неотличим
от очищенного, и затирать зеркало нельзя. Пустой реестр в **настроенном** хранилище — наоборот,
законный результат: архив ещё не наполнялся, и зеркало пишется пустым.

## Коммит

Коммит зеркала — **ручной/периодический**: на staging нет git-дерева, автокоммит там невозможен.
Обновлённый `registry.jsonl` коммитится обычным коммитом вручную (или периодической задачей на
машине, где дерево есть). Содержимое зеркала не критично для конвейера — это витрина реестра.

## Формат строки

Одна строка = одна сохранённая версия файла источника (JSONL). Поля записи `archive.Entry`:

| Поле | Смысл |
|---|---|
| `source` | имя импортёра-источника (например `cbr_m2`) |
| `name` | имя файла у источника |
| `fingerprint` | отпечаток HEAD (как в `source_publications`: архив и таблица версий называют версию одинаково) |
| `sha256` | хеш фактического содержимого (при неизменных заголовках тело могло смениться) |
| `size` | размер объекта в байтах |
| `url` | URL, откуда файл скачан (аудит) |
| `key` | объект в хранилище; идентичность строки (upsert по нему) |
| `first_seen` | когда конвейер впервые увидел версию (RFC 3339) |

Пример строки:

```json
{"source":"cbr_m2","name":"monetary_agg_SA.xlsx","fingerprint":"8f3c…","sha256":"b7d1…","size":583746,"url":"https://www.cbr.ru/vfs/…","key":"cbr_m2/8f3c…_monetary_agg_SA.xlsx","first_seen":"2026-10-14T09:20:11+03:00"}
```

Секретов в реестре нет: `source`/`name`/`url`/`sha256` и есть весь его состав.
