## 2. Что реализовано (интерфейсы для Task 4–6)

* `mpSummaryRef{Published time.Time; Href string}`, `parseMPDecIndex(page []byte) ([]mpSummaryRef, error)` — карточки `div.document-regular`, отбор по `a[href*="summary_key_rate_"]` **и** видимому имени `span.document-regular_name_visible` == «Резюме обсуждения ключевой ставки» (селектор не требует `">` сразу после имени класса — у 6 карточек есть `referenceable`+`id`); дата — `document-regular_date` (`02.01.2006`, UTC); порядок — как на странице; 0 совпадений / битая дата → ошибка `индекс: …`. `Href` отдаётся как в разметке (относительный) — по конвенции `findLink` домен навешивает вызывающий (Task 6 → `cbrUrl + href`).
* `mpSummaryBlock{Block, Subsection, Kind string; Seq int; Text string}`, `mpSummaryDoc{MeetingDate, Action, Rate, EffectiveFrom, Signal, Blocks}`, `parseMPSummary(page []byte)` — линейный обход `h2, div.title_20, p, li`; пять обязательных h2 (набор + однократность), всё остальное (в т.ч. «Дополнительные материалы» в двух вариантах разметки) закрывает контент; `Subsection` — текущий `div.title_20` до следующего h2; `Kind` = `paragraph`/`bullet`; `Seq` — сквозной 1..N по блоку; `Text` — нормализованный дословный.
* Решение: ядро `Совет директоров Банка России <D> <месяц> <YYYY> года (сохранил|повысил|снизил)` → `MeetingDate`+`Action` (`hold|hike|cut`); `Rate` — `(\d+(?:,\d+)?)\s*%\s*годовых` в остатке предложения после глагола; `EffectiveFrom` — `с <D> <месяц> <YYYY> года` после ставки, только для cut/hike, отсутствие → `nil`; фолбэк даты заседания — `данных, доступных (к|на) … года` из абзацев до первого h2 (обязательно оба предлога: 07052026 пишет «доступных **на** 24 апреля 2026 года»). Если узнаваемого ядра нет, но есть предложение с `(сохранил|повысил|снизил) ключевую ставку` — берутся глагол+ставка+«с …», дата — из фолбэка.
* `Signal` — предложения блока 5 со словом «сигнал» (регистронезависимо), склейка `\n`; разбиение предложений — точка + заглавная/кавычка (закрывает `14,00%`, `б.п.,`).
* `normMPText` — любая пробельная серия (`unicode.IsSpace`: NBSP U+00A0, узкий NBSP U+202F, «волосяной» U+200A) → один обычный пробел, U+2011 → `-`, обрезка краёв; сочетаемые знаки (U+0301 в «бóльшая») сохраняются.
* fail-fast с указанием места: `резюме: не найден блок %q` / `блок %q встречается N раза` / `в блоке %q нет ни одного абзаца` / `не распознано решение по ключевой ставке`.

## 4. Сомнения и расхождения (важно для ревью/следующих задач)

1. **Brief vs факты (порядок в индексе):** в `task-3-brief.md` Step 1 (и в плане) первая ссылка описана как `2024-02-27/…27022024/`, последняя — `2026-09-23/…23092026/`, тогда как задание и Task 2 §2 (§8.2, блок B) говорят обратное. Факт страницы (проверен пробой и пинами): **первая — `summary_key_rate_23092026` (2026-09-23), последняя — `summary_key_rate_27022024` (2024-02-27)** — так и зафиксировано в тесте. Формулировку в брифе стоит поправить.
2. **Счётчики Task 2 — это открывающие теги, а в DOM узлов больше.** В `06112024` часть `<li>` закрыта `</p>`, поэтому html-парсер создаёт пустые `<p>`: DOM даёт блок 2 = 10 `p` и блок 4 = 8 `p` (ровно +4 и +5 — столько «неправильных» `</p>`). Чтобы пины Task 2 (6/4 и 3/5) сошлись, парсер **пропускает пустые узлы** `p`/`li` — это зафиксировано комментарием и тестом `Hike` (проверка «нет пустого текста»), а мутация «не пропускать» валит тест.
3. **Узкий NBSP (U+202F) в фикстурах отсутствует** (0 вхождений во всех четырёх файлах) — нормализация U+202F покрыта контрактным unit-кейсом, а «фактический» экзотический пробел фикстур — U+200A (волосяной, вокруг тире) и `&nbsp;`-сущности (`&nbsp;` → U+00A0 декодирует goquery; сырых U+00A0 в файле 0/7/7). U+00A0/U+200A/U+2011 покрыты парами, реально присутствующими в текстах.
4. **Добавлен тест вне списка брифа** — `TestParseMPSummaryDecisionFallback`: он единственный покрывает фолбэк даты («данных, доступных к/на …»). Без него фолбэк-ветка была бы непокрытой; mutation-check этой ветки не делался (тест проходит, мутация не проверялась).
5. **Тексты ошибок пиннуются только по подстрокам** («индекс», имя блока, «решение», «нет ни одного абзаца») — чтобы ревью Task 4–6 не ломалось от правки формулировок.
6. `golangci-lint` v2 (default=standard) в этом окружении включает staticcheck QF-проверки — линт зелёный (`0 issues`) только после выноса `mpSentenceStart`.
7. `mcp__jetbrains__*` доступны: `get_file_problems` для обоих новых файлов — `{"errors":[]}`. `mcp__clickhouse__*` в задаче не требовались (SQL не выполнялся).
