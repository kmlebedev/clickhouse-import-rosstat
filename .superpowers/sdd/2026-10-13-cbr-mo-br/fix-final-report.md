# Fix-раунд по финальному ревью ветки `feat/cbr-mo-br` — отчёт

**Статус:** DONE. BASE `583e82d` → коммит `4cd4338`, ровно 6 файлов из списка фикса.

## Находка (Important) и суть фикса

`SavePublication` писался сразу после `Send`, а каталог и витрина — после него. Сбой
`UpsertSeriesCatalog`/`CreateView` (или убитый процесс) после успешного `SavePublication` оставлял
известную версию с совпавшим числом точек → все следующие ежедневные прогоны уходили в no-op →
каталог/витрина отсутствуют у агента до следующей волны (~6 недель), при зелёном dagu.

Решение контроллера (сделано): **строка версии пишется последней** — после точек, каталога и
витрины. Любая ошибка пост-шагов оставляет версию незаписанной, следующий прогон повторяет полный
путь (все шаги идемпотентны).

## Живой импорт не перезапускался

Версия в `source_publications` остаётся валидной, перезапуск не нужен и не делался: путь no-op не
менялся (префлайт + количественный чек), а содержимое витрины подтверждено чтением под агентом —
`v_cbr_mo_br` = **9348** строк по **642** рядам (2021-05-01 … 2026-09-01), то есть число точек
по-прежнему сходится с записанной версией. Изменён только порядок пост-шагов при **новой** версии
(следующая волна), поэтому текущее состояние БД и строка версии остаются корректными.
